# Jev 1.14

Jev 1.14 (`jev-1.14.0`) is TypeSafe AI's second public System One model, a decision model released on
2026-10-14 [ts-models] [ts-jev114]. Like Jev 1.13, it reads a `state` and answers typed questions with
probabilities: Choice, Score and Noul; it adds Box, a preview type that returns one bounding box in an
image [ts-primitives] [ts-box]. It is for fast, cheap classification, routing, ranking and gating
inside software, not for chat, code or explanation. It was released as `jev-preview`, with
`jev-latest` announced to follow a week later [ts-jev114]; on 2026-10-27 both aliases pointed to it
and `jev-1.13.0` was still listed [ts-models]. The previous generation is
[jev-1.13.0.md](jev-1.13.0.md), maker-level facts are in [README.md](README.md), and the category is in
[../../practices/decision-models.md](../../practices/decision-models.md).

## How to instruct it

TypeSafe documents one request format and one set of question types for both versions, and has
published no guidance written for 1.14 alone [ts-primitives] [ts-llms]. The detailed advice, read on
2026-10-04, is in [jev-1.13.0.md](jev-1.13.0.md#how-to-instruct-it); what follows is what was checked
for 1.14 and what differs.

### Setting up the prompt

A request has a `state`, a `model` and named questions; there is no system prompt. The primitives page
read on 2026-10-28 documents Choice, Score and Noul, says that every answer is independent and that
the questions in a request are evaluated in parallel, and sets no limit on the number of questions
apart from the context length [ts-primitives]. The advice in the 1.13 file on one snap judgement per
question, literal wording, a filtered state and the choice of question type is TypeSafe's general
guidance, not tied to a version (L, read 2026-10-04).

### Reasoning and effort

None. TypeSafe documents no effort setting or reasoning output for 1.14 [ts-models] [ts-jev114]. Work
that needs several steps is split across questions or requests, with code between them, as for 1.13.

### Output: format, length, tone

Choice returns the chosen option, a probability for every option and a `confidence`; Score returns a
position along the levels, a legend, the probabilities and a `confidence`; Noul returns the
probability of yes and no `confidence` [ts-primitives]. Box returns four edges as fractions of the
image, measured from the top-left corner, with a `confidence` that the page does not call a
probability. Box has no "not found" answer: a question about something absent still returns a box,
so the page pairs it with a Noul question [ts-box].

### Tools and agents

Not an agent model. Its documented uses are as a component that chooses, routes, screens or scores;
see [jev-1.13.0.md](jev-1.13.0.md#tools-and-agents) (L, read 2026-10-04).

### Coding

Jev cannot write code. The library's coding benchmarks do not apply (see the card).

### Long context and retrieval

By default a request holds 64k tokens and each question 32k. With the header
`TypeSafe-Danger-Zone-Long-Context: true`, both limits rise to 262k tokens at the same price per
token; TypeSafe says long context is off by default, slower and less accurate [ts-models], and its
release post advises keeping context short [ts-jev114].

### Structured output

Every answer is typed. Values cannot be generated, so extraction is a Choice over candidates that code
found, as for 1.13 ([jev-1.13.0.md](jev-1.13.0.md#structured-output)).

### Images, audio, other inputs

Images are a preview behind an opt-in header. A request that holds an image or a Box question sends
`TypeSafe-Danger-Zone-Images: true`. The images page accepts PNG or JPEG still images up to 16 MiB,
with each side from 280 to 1,568 pixels and a 32 MiB request body; it says Jev 1.13 and 1.14 both
accept images, Box needs 1.14, and neither images nor Box are ready for production [ts-images]. The
release post adds that all models, Jev included, do worse on images than on text alone [ts-jev114].
TypeSafe's System One concept page still said on 2026-10-28 that Jev accepts text only and that
images, audio and video are not supported [ts-system-one]; the two pages conflict. No audio or video
input is documented.

### Sampling and API parameters

No temperature or sampling parameter is documented. The aliases `jev-latest` and `jev-preview` both
point to `jev-1.14.0`; TypeSafe says an alias moves when a release ships and advises sending a
versioned id once thresholds are tuned [ts-models]. The release arrived as `jev-preview`, and the
post announced that `jev-latest` would follow a week later [ts-jev114]; the day of that switch was
not observed.

### Migrating from the previous generation

TypeSafe calls the changes small improvements across the board and expects the largest gain in
multilingual input; it gives no number for the multilingual gain [ts-jev114]. Its overall charts
are under Benchmarks. It says it intends to give 60 days'
warning before `jev-1.13.0` is formally deprecated and 30 days before `jev-1.14.0`, and to publish a
deprecation policy before then [ts-jev114]. In one practitioner's test on 107 labelled value pairs,
the upgrade changed the threshold routing of 6 cases [classmethod] (A). Only a labelled test set run
on both versions shows whether tuned thresholds still hold (inference).

## What the system card reports

TypeSafe publishes no system or model card. Its docs index of 2026-10-27 lists a weakness
("jaggedness") page for `jev-1.13` only [ts-llms], so the nine weaknesses in
[jev-1.13.0.md](jev-1.13.0.md#what-the-system-card-reports) are the latest list; whether each holds
for 1.14 is not documented. The release post describes an internal measurement of intelligence that
covers only open-weight comparison models, may favour TypeSafe's models and may not stay consistent
across releases [ts-jev114]; its charts are under Benchmarks (L).

## Behaviour observed in practice

- **Version drift.** On 107 labelled pairs of values (is this the same date, the same company), a
  practitioner found that re-asking one version four weeks later barely moved the probabilities, but
  that the upgrade from 1.13 to 1.14 changed the threshold routing of 6 cases [classmethod] (A, one
  task, one author).
- **Availability.** Netlify's AI Gateway serves `jev-1.14.0` with credentials handled by the gateway
  and usage billed to Netlify credits [netlify-jev114] (L, a reseller's page).

## Benchmarks

- **Maker.** The charts in the release post, marked with a warning not to trust benchmarks, give
  TypeSafe's internal intelligence measure as 60.0 for 1.14 against 58.9 for 1.13 (higher is better),
  and its calibration error as 1.6 against 1.8 (lower is better, units not stated). The same charts
  place six other decision models, which the post calls open-weight, from 33.8 to 46.7 on intelligence and from 10.3 to 35.0 on
  calibration error. The post calls the measure a best guess that is likely biased towards
  TypeSafe's models and may not stay consistent between releases [ts-jev114-charts] [ts-jev114] (L).
- **Independent.** None recorded. The JevBench page could not be read on 2026-10-27; see the card.

## Open questions

- TypeSafe's deprecation policy, and the dates on which 1.13.0 and 1.14.0 will be retired.
- Whether image input and Box leave preview, and which of TypeSafe's two pages on input types is
  corrected.
- How large the multilingual gain is; no measurement was published.
- Whether the weaknesses listed for 1.13 hold for 1.14.
- Whether OpenRouter and Vercel AI Gateway serve `jev-1.14.0` by its versioned id; this was not
  confirmed. A gateway that passes the alias `jev-latest` through to TypeSafe would reach 1.14
  (inference from [ts-models]).
