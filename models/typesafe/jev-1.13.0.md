# Jev 1.13

Jev 1.13 (`jev-1.13.0`) is TypeSafe AI's first public System One model, a decision model announced in
early access on 2026-09-15 [ts-announcement]. It does not generate text. It reads a text `state` and
answers typed questions with probabilities: Choice (one of the options you supply), Score (a level on
a scale you describe) and Noul (the probability that a yes/no statement holds) [ts-primitives]. It is
for fast, cheap classification, routing, ranking and gating inside software, not for chat, code or
explanation. It replaced no earlier public model; the cookbooks set `jev-1.12`, which TypeSafe does not list or
describe [ts-extraction]. The category and how to use it are in
[../../practices/decision-models.md](../../practices/decision-models.md); maker-level facts are in
[README.md](README.md).

## How to instruct it

A Jev request has no system prompt and no messages. It has a `state`, a `model` and a map of
`questions`, each with a `type`, `instructions` and `criteria` (the options or levels; for Noul,
optional true and false descriptions) [ts-api]. The guidance below is TypeSafe's, in our words, read on 2026-10-04 (L).

### Setting up the prompt

- **One snap judgement per question.** TypeSafe's test is a judgement that a knowledgeable person
  makes in about a second with the right context. A task that needs reasoning is split into narrow
  questions, and code combines the answers; the build guide calls decomposition probably the most
  important concept in it [ts-build].
- **The whole question goes in `instructions`.** Question ids stay in your code and are not sent to
  the model. Jev reads literally: it answers "the question you wrote, not the one you meant"
  [ts-jagged]. State the exact condition, and avoid double negatives and multi-hop wording.
- **State.** A string for one text; an object for most requests, so that each part has a name. Name
  the field a question is about with a backticked path such as `ticket.messages[0].text`. Put in only
  what the current questions need: accuracy falls as unrelated material grows ("context rot"). Supply
  current facts; do not rely on what the weights know [ts-state] [ts-jagged].
- **Choose the type by the shape of the answer.** Choice for an unordered closed set; Score for an
  ordered scale you can describe in steps; Noul for a clean yes/no where the probability is the
  signal. Where two fit, prefer the one your code can act on directly [ts-primitives].
- **Choice.** Give the full list of options (up to 255), not a shortlist. Add an `other` or `none`
  option when the list may not cover every input. Names and descriptions are both sent, so write
  descriptions that separate the options; for options the model confuses, give each an object with
  the same fields (what it covers, what it is not for, examples) [ts-choice] [ts-advanced]. Jev
  leans toward the first option in some cases, so check that the answer survives a reordering
  [ts-jagged].
- **Noul.** One condition per question; do not join two with "and". Phrase it so that a high value
  means yes. Add `criteria.true` and `criteria.false` only for a subtle boundary, and keep them
  aligned with the question: inverted criteria do worse [ts-noul] [ts-jagged]. A Noul value is a
  probability, not a degree of the thing asked about; use a Score for degree.
- **Score.** Describe situations, not degrees: TypeSafe's example level is "Broken or degraded
  feature, but workaround exists", not "Moderately severe". The model does not see a level's number or its neighbours, so a level such as "worse than
  the previous" means nothing to it; number-only levels scored badly in TypeSafe's own example. Two
  to 10 levels, low to high, one dimension per Score; weight several Scores in code [ts-score].
  Examples in a level help only when they look like real inputs.

### Reasoning and effort

None. Jev has no effort setting and no thinking output; TypeSafe says System One models do not
generate explanations of their reasoning [ts-system-one]. Work that needs several steps is split
across questions or across two requests, with code between them [ts-primitives].

### Output: format, length, tone

The response holds `model` (the versioned id that answered), `answers` keyed by your question ids, and
`usage`. A Choice answer has `choice`, `probabilities` for every option (they sum to 1) and
`confidence`; a Score answer has the probability-weighted `score`, the distribution, `confidence` and
a `legend`; a Noul answer is one number, the probability of yes, with no confidence field [ts-choice]
[ts-noul] [ts-score]. There is no free text to format.

### Tools and agents

Jev is not an agent model, and TypeSafe says it does not replace the model behind a coding agent
[ts-coding-agents]. Its documented agent uses are as a component: choosing a function and its
closed-set arguments as Choice questions, routing intents, screening input and output as a guardrail,
scoring retrieved passages, and choosing what to keep in context [ts-llms]. Practitioner builds use it
the same way: an indexed list of the actions legal now, with code checking freshness and budgets
before each action ([../../practices/decision-models.md](../../practices/decision-models.md),
section 4).

### Coding

Jev cannot write code. The library's coding benchmarks do not apply (see the card).

### Long context and retrieval

TypeSafe gives 64k tokens per request for the state plus every question, and 32k for the state plus
the longest question [ts-models]; OpenRouter lists 32K [openrouter-jev]. Long, noisy state costs
accuracy before it reaches the limit, so filter first [ts-jagged]. For retrieval, TypeSafe's
cookbooks use one Noul per query and passage pair to rerank, and a Score per passage to decide what
reaches a generating model [ts-llms].

### Structured output

Every answer is typed; TypeSafe's point is that software can use it directly. Values cannot be
generated: for extraction, code finds candidate spans (tuned to over-find), Jev picks the span that
plays the role, and code copies and normalises it. TypeSafe says the value you get back is always one
of those spans, copied unchanged, so a value the candidate finder missed cannot come back
[ts-extraction]; that a missed value cannot come back follows from this (inference). The cookbook
gives every pick a `none` option.

### Images, audio, other inputs

Text only: a string, a JSON object or an array of text. No image, audio or video [ts-models].
English is the main training language; other languages, CJK scripts included, work less well
[ts-models].

### Sampling and API parameters

TypeSafe documents no temperature or sampling parameter. It says all probabilities come out in parallel,
not token by token [ts-announcement]. The parameters are the model id, the state and the questions.
The aliases `jev-latest` and `jev-preview` both point to `jev-1.13.0` today. TypeSafe says an alias
moves when a release ships, so answers can change with no change on the caller's side, and it advises
pinning the versioned id once thresholds are tuned [ts-models].

### Migrating from the previous generation

No earlier public generation exists. The cookbooks set `jev-1.12`; TypeSafe documents neither that
id nor any difference from 1.13. TypeSafe's CEO said in an interview that new models will come faster
than people expect and that long-term support is not promised, though 1.13.0 might get it for a time
[latent-space] (A). Only a labelled test set re-run on the new version shows whether tuned thresholds
still hold (inference).

## What the system card reports

TypeSafe publishes no system card or model card. Its two nearest documents are the Models page and a
"jaggedness" page of known weaknesses for this version, last reviewed 2026-10-02 [ts-models]
[ts-jagged]. The jaggedness page lists nine weaknesses (L):

1. Literal reading: scope words, negations and implied conditions are taken at face value.
2. Maths and numbers: "Jev is not a calculator"; it does not count reliably, and Score expectations
   are weak in numerical calibration. Keep arithmetic in code.
3. Dates and times: read as text, not as ordered quantities. Extract date parts with Choice and compare
   in code.
4. Indirection: double negatives and multi-hop questions are answered less reliably.
5. Large state with unrelated detail lowers accuracy.
6. Adversarial content: state is data, and Jev does not treat it as hostile by default; injected
   instructions or misleading framing can move an answer.
7. Contradictory instructions and criteria can confuse it.
8. Choice option order can move the answer toward the first option (added in the 2026-10-02 review).
9. Generation: it is not trained to generate text.

On 2026-09-29 the same page also had a section saying that separate questions need not obey logical
identities (its example gave 0.72 for a statement and 0.47 for its negation). The live page of
2026-10-04 no longer has it, and it gives no reason ([ts-jagged], earlier text read in a Wayback
capture of 2026-09-29). The removal does not show that the model now obeys those identities.

Data use and retention are in [README.md](README.md).

## Behaviour observed in practice

- **Option names carry meaning the rubric does not.** A preprint (not peer reviewed) swapped which
  option name was bound to which definition, with question, state and definitions unchanged. On hosted
  Jev, binding "yes" and "no" the other way flipped 32.5% of 1,200 decisions, 30.4 points more than
  neutral names (0/1), against a run-to-run floor of at most 1.33%; AUC fell from 0.815 to 0.581.
  Outputs stayed 100% type-valid. Neutral names and random strings barely moved answers [arxiv-typesafe]
  (M, one point in time, Choice only, English only).
- **Probabilities can be confident where the truth is uniform.** Asked 400 times which face a hidden
  fair die showed, Jev picked "1" every time, with a mean probability of 83% and a hit rate of 19%
  [hayashi] (A, one practitioner, code and data public). The same author notes another reader found
  good calibration on a 1,200-item MMLU sample.
- **Arithmetic and ordered rules are its weak side; plain triage is not.** Distil Labs reports 200 of
  200 on synthetic inbox triage, and 0.77, 0.75 and 0.84 on a 100-invoice pay-or-hold task across
  three request formulations, with 2 to 3 points of movement between identical runs [distil] (A, a
  competing vendor, synthetic data, one run each).
- **In one replay, missing state caused the regression.** In Entagl's replay of 402 real routing decisions, Jev
  did better than the original frontier setup at deciding what to do with a message (91.2% to 94.0%,
  87.4% to 93.0%) and worse at choosing which specialist answers (98.1% to 91.4%, 97.8% to 83.7%),
  because it saw the last eight messages but not who owned the chat. Gating on confidence 0.90
  brought specialist choice to within 1 point of the original in one workspace (97.1% against 98.1%)
  and above it in the other (98.9% against 97.8%), but made one message decision worse (93.0% to
  86.7%) [entagl] (A, one vendor's own data, no raw corpus).
- **High confidence was reliable on authored cases.** In Entagl's first round, all 986 decisions at
  confidence 0.97 or more were correct, and decisions under 0.60 were 73.2% correct; a gate at 0.85
  sent 12% to a backup model [entagl] (A).

## Benchmarks

TypeSafe publishes no public-benchmark scores, by policy; its announcement says it will run one-off
evaluations at product updates instead [ts-announcement]. Every figure below is in the card with its
qualifiers.

- **Independent.** JevBench v1.5.6 puts Jev 1.13.0 first on its capability score at 80.0
  (Intelligence 72.0, Calibration 88.0) over 1,624 decisions, among systems within 2x of Jev's cost and
  latency, and third on its official four-axis ranking; Cloudflare's Clef-Flash scored 70.3
  [jevbench] (M).
- **Maker.** TypeSafe's four workflow evaluations give Jev 67.8% agreement with labels averaged from
  GPT-6 Astra and Claude Fable 5.1, at about $0.0004 and 0.4 s a case; the post says the workflows were
  built by its own team, so some bias could exist [typesafe-evals] [ts-announcement] (L).
- **Third parties that sell a competing or adjacent product.** Entagl 98.5% on authored cases against
  99.0% for an unnamed Gemini model at low effort [entagl]; Distil Labs 0.79 on invoice decisions
  [distil]; the Kev project 54.0 on its breadth-v1 index, against 52.3 for its own Kev-27B
  [kev-release] (A).

## Open questions

- The exact context limit: TypeSafe's 64k per request against the 32K that OpenRouter and Cloudflare
  list.
- Whether separately asked questions are now consistent with each other, after TypeSafe removed that
  warning without a reason.
- How long `jev-1.13.0` will stay served once a newer version ships; no deprecation policy is
  published.
- Whether Jev's probabilities are calibrated on any given user's data; only that user's labels can
  show it (see [../../practices/decision-models.md](../../practices/decision-models.md), section 2).
