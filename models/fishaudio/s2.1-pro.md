# Fish Audio S2.1 Pro

Fish Audio S2.1 Pro is the current generation of the Fish Audio S Pro speech synthesis class. It reads natural-language cues in square brackets, such as whispering sweetly or laughing nervously, and it takes several speakers in one request. Fish Audio released it on 2026-06-23 and recommends it for production. The cue set is open, so it is an instruction-directed model. Family-wide rules are in the [Fish Audio README](README.md).

## How to instruct it

### Setting up the prompt

- **No system prompt.** The input is `text`, a voice (`reference_id` or `references`) and options. The model is the `model` header: `s2.1-pro`, `s2.1-pro-free`, `s2-pro` or `s1` [fish-openapi].
- **Recommended model.** Fish Audio calls `s2.1-pro` its recommended production model, an improvement of S2 Pro in quality, latency and throughput. `s2.1-pro-free` is the same model for development, without TTFA or DPA guarantees [fish-models].
- **Natural-language control.** Bracket cues, described in the voice section [fish-models] [fish-emotions].

### Reasoning and effort

None.

### Output: format, length, tone

- **Formats.** See the card [fish-openapi].
- **Tone.** Set by the voice, bracket cues, `temperature` and `prosody` [fish-emotions] [fish-openapi].

### Tools and agents

Not applicable. Fish Audio publishes a coding-assistant skill and quickstart for SDK code. The model has no tool use [fish-index].

### Coding

Python and JavaScript SDKs and an OpenAPI schema. The JavaScript SDK defaults to `s1`, so the code names the model explicitly. The model is chosen by a `model` HTTP header and not by a body field [fish-tts-guide] [fish-openapi].

### Long context and retrieval

Long text goes through chunked processing (`chunk_length` 100 to 300) with `condition_on_previous_chunks`, or through the WebSocket [fish-openapi].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. Cloning takes reference audio [fish-openapi].

### Voice: turn-taking, interruption and speech style

Fish Audio S2 models are not conversation models. They have no turn detection and no barge-in. A client stops its own playback. Fish Audio's agent platform is a separate product [fish-index].

**How to direct delivery.**

- **Syntax.** A cue in square brackets inside the text. Fish Audio states that S2 models treat bracket text as ordinary text and not as dedicated control tokens. They learned mappings between descriptions and sound, so any descriptive phrase may work, such as whispering sweetly or laughing nervously. The set is open [fish-models] [fish-emotions].
- **Reference lists.** The docs list these groups. The model card of S2 Pro says the model accepts more than 15,000 distinct tags [fish-emotions] [fish-hf-s2].
  - 24 basic emotions, such as happy, sad, angry, excited, calm, nervous, confident and sarcastic.
  - 25 advanced emotions, such as disdainful, hysterical, nostalgic and resigned.
  - 6 tone markers: hurried, shouting, screaming, whispering, soft and emphasis.
  - 11 sound effects, such as laughing, chuckling, sobbing, sighing, gasping and clearing the throat.
  - A few crowd effects and pause markers.
- **Placement.** Sentence-level emotion cues work best at the start of a sentence, close to the sentence they control. Tone cues and sound effects can sit anywhere. The advice is one main emotion per sentence [fish-emotions].
- **Layering and transitions.** Cues can stack (`[sad][whispering]`), change from line to line, and take intensity words such as slightly, very or extremely [fish-emotions].
- **Illustration, written for this library and not taken from the maker.** `[tired but trying to sound cheerful] Morning. [sighs] Coffee first, then the report.` This shows free-form cues; it is not a sample from the docs. It was not run against the model.
- **What to avoid.** Fish Audio lists: too many tags in short text, conflicting emotions, bracket descriptions long enough to hurt readability, forgetting the brackets, and placing a sentence-level cue far from its sentence. A sound effect works best with a matching written sound after it, such as "Ha ha" after a laugh tag [fish-emotions].
- **Strength.** The docs give no figure for tag adherence. The S2 Pro model card describes reinforcement-learning alignment but the page read gives no adherence score. Higher `temperature` (0 to 1, default 0.7) makes output more varied and lower makes it more consistent [fish-openapi] [fish-hf-s2].
- **Speed and volume.** A `prosody` object adjusts speed and volume [fish-openapi].
- **Pauses.** `[break]` and `[long-break]` markers, and written pause words such as um and uh [fish-emotions] [fish-fine].

**Voice design and cloning.**

- **Design.** `POST /v1/voice-design` takes a natural-language `instruction` (for example a warm, confident studio narrator), a `reference_text` and a candidate count, and returns short candidate voices as base64 WAV. It is stateless and does not create a saved voice [fish-voice-design].
- **Cloning.** A voice model is created from reference audio, or inline `references` are sent per request (this needs MessagePack, not JSON) [fish-openapi].

**Multi-speaker dialogue.** The S2 family takes several speakers in one request. `reference_id` is an array of voice model ids, and the text marks speakers with `<|speaker:0|>`, `<|speaker:1|>` and so on. Zero-shot dialogue passes an array of reference arrays [fish-openapi].

**Long-form consistency.** `condition_on_previous_chunks` (default true) uses earlier audio as context for voice consistency across chunks. The `latency` field takes `normal` (best quality), `balanced` or `low` [fish-openapi].

**Pronunciation and text normalisation.** Phoneme tags `<|phoneme_start|>` and `<|phoneme_end|>` carry CMU Arpabet for one English word, tone-number Pinyin for a Chinese syllable, or romaji with pitch accent for a Japanese word. Phoneme tags survive normalisation. `normalize` (default true) normalises English and Chinese text. Pronunciation dictionaries can be built in the web app and used in requests [fish-fine] [fish-openapi].

**Turn-taking.** Not applicable to a synthesis model.

### Sampling and API parameters

- `temperature` (0 to 1, default 0.7), `top_p` (default 0.7), `repetition_penalty` (default 1.2), `max_new_tokens`, `chunk_length`, `min_chunk_length`, `normalize`, `latency`, `condition_on_previous_chunks`, `prosody`, `format`, `sample_rate`, `mp3_bitrate` and `opus_bitrate` [fish-openapi].
- If the `model` header is missing or not recognised, the request is served by `s2.1-pro` [fish-openapi].

### Migrating from the previous generation

From S2 Pro [fish-models] [fish-blog-s21]:

- Same natural-language bracket control and multi-speaker support. The maker reports improved quality, latency and throughput, and 83 languages against 80+.
- S2 Pro has open weights under a research licence. S2.1 Pro is hosted only.
- From S1: S1 uses parentheses, not brackets, and a fixed list of 64+ expressions; it does not support multi-speaker dialogue [fish-models] [fish-openapi].

## What the system card reports

Fish Audio publishes no system card for the hosted model in the pages read. The free tier terms say data may be retained for model improvement and that products above US$1M in annual revenue should contact the maker first [fish-blog-s21].

## Behaviour observed in practice

- **Rank (M).** Artificial Analysis gives a quality Elo of 1141.15 for S2.1 Pro, against 1117.15 for S2 Pro [aa-tts-board].
- **Throughput (M).** About 80 characters a second for S2.1 Pro and about 107 for S2 Pro in the same data [aa-tts-board].
- No practitioner report was read.

## Benchmarks

Independent: Artificial Analysis quality Elo 1141.15 [aa-tts-board]. No maker benchmark for S2.1 Pro was read.
