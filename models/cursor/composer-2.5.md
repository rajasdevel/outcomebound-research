# Composer 2.5

Composer 2.5 is Cursor's own agentic coding model, released 2026-05-18 and the current generation of the Composer class. It runs only inside Cursor (the editor and the CLI) and is not sold as an API. It builds on Composer 2, shares its open base (Moonshot's Kimi K2.5) and adds more training compute, synthetic tasks and a new feedback method; Cursor reports better long-task work, instruction following, effort calibration and communication than Composer 2 [cursor-composer-25-blog] [cursor-composer-25-docs] [aa-composer-25]. Class-level facts are in [the Cursor README](README.md).

## How to instruct it

Cursor publishes no prompting guide for Composer 2.5. Instructions reach the model through the Cursor agent, which wraps the user's prompt in a model-tuned harness prompt and tools [cursor-agent-overview]. See [the README's guide section](README.md#prompting-guides).

### Setting up the prompt

- User instructions go through rules and `AGENTS.md`: project rules in `.cursor/rules/*.mdc`, user rules in settings, team rules from the dashboard, and `AGENTS.md` (nested files combine, the more specific winning). Always-apply rules enter the start of the model context; others attach by file pattern, by the agent's reading of their description, or by `@`-mention [cursor-harness-doc].
- Cursor's rule advice: under 500 lines, one concern each, point to canonical files, avoid pasting style guides or commands the agent knows, and add rules only when a mistake repeats [cursor-harness-doc].
- Cursor's blog says Composer 2.5 follows complex instructions more reliably than Composer 2 [cursor-composer-25-blog]. No instruction-following score exists for it.
- No source says whether Composer prefers XML, Markdown or plain prose, or where long documents should sit.
- Rules apply to the agent and not to Cursor Tab; user rules do not apply to inline edit [cursor-harness-doc].

### Reasoning and effort

- Cursor publishes no effort levels or default for Composer 2.5. Its blog's cost-versus-score chart shows Composer 2.5 as one point beside effort curves for other models, and the CursorBench table lists one Composer 2.5 row [cursor-composer-25-blog] [cursor-bench-board].
- The blog says effort calibration improved over Composer 2 and gives no measure of it [cursor-composer-25-blog]. Its predecessor Composer 1.5 was trained to think briefly on easy problems and longer on hard ones [cursor-composer-15-blog].

### Output: format, length, tone

- Cursor says it trained for communication style, one of the dimensions it says benchmarks capture poorly [cursor-composer-25-blog].
- No verbosity control is documented. User rules are the documented place to state a preferred style; the docs' example is a rule asking for concise replies without filler [cursor-harness-doc].

### Tools and agents

- In Cursor it has all agent tools (search, read, edit, shell, browser, web, image generation, rules fetch, clarifying questions) [cursor-composer-25-docs] [cursor-agent-overview].
- It is tuned for tool use, file edits and terminal operations inside Cursor [cursor-composer-25-docs]. The blog's textual-feedback example is a model calling a tool that is not available and a hint listing the available tools, which Cursor used as a training signal [cursor-composer-25-blog].
- Plan Mode, agent queueing, checkpoints and Projects (a coordinator agent delegating to others) belong to the harness [cursor-agent-overview] [cursor-best-practices].
- Cursor's blog says it is better at sustained work on long-running tasks than Composer 2 [cursor-composer-25-blog].

### Coding

- Composer 2.5 is a coding model. Results: see Benchmarks. Cursor's own claims: improvement in intelligence and behaviour over Composer 2 and better sustained work on long tasks [cursor-composer-25-blog].
- Cursor's training post names its methods: reinforcement learning with textual feedback at the point of a bad decision, 25x more synthetic tasks than Composer 2 (for example deleting a feature from a codebase with tests and asking the agent to rebuild it), and sharded Muon with a dual-mesh data-parallel layout [cursor-composer-25-blog].
- Artificial Analysis (M) found it comparable to Claude Opus 4.7 (max) in Claude Code on SWE-Bench-Pro-Hard-AA (47%) and cheapest of the agents scoring above 60 on its Coding Agent Index [aa-composer-25].

### Long context and retrieval

- No context window is published on Cursor's model page or blog [cursor-composer-25-docs] [cursor-composer-25-blog].
- Cursor compresses older turns into a summary when a chat approaches the window, and the context ring shows the breakdown. Composer 1.5 was trained to summarise its own context; whether 2.5 keeps that is not stated [cursor-docs-prompting] [cursor-composer-15-blog].
- Cursor's best-practices post says long conversations lose focus after many summaries and recommends a fresh chat when the task changes [cursor-best-practices].

### Structured output

### Migrating from the previous generation

From Composer 2 (Cursor's table, L; CursorBench versions as of each release):

- Same open base checkpoint (Kimi K2.5); Cursor says about 85% of Composer 2.5's total compute was Cursor's own training, per Artificial Analysis's reading of Cursor's statement [cursor-composer-25-blog] [aa-composer-25].
- Scores: CursorBench v3.1 (harder tasks) 52.2% to 63.2%; Terminal-Bench 2.0 61.7% to 69.3%; SWE-bench Multilingual 73.7% to 79.8% [cursor-composer-25-blog]. Artificial Analysis (M): Coding Agent Index 48 to 62, SWE-Bench-Pro-Hard-AA 12% to 47%, Terminal-Bench v2 64% to 66%, SWE-Atlas-QnA 69% to 72% [aa-composer-25].
- Price: standard stays $0.50 / $2.50 per Mtok; Fast rose from $1.50 / $7.50 to $3.00 / $15.00 [cursor-composer-2-blog] [cursor-pricing].
- Cursor's own later benchmark, CursorBench 4.0, lists Composer 2.5 at 27.7% (see Benchmarks); the figure is not comparable to the v3.1 numbers above [cursor-bench-board].
- Composer 2 is no longer on Cursor's current price list [cursor-pricing].

## What the system card reports

Cursor publishes no system card for Composer 2.5. The release post is the substitute, and it reports no refusal, jailbreak, injection or sycophancy measurements. It reports one training-time safety-relevant finding, which Cursor itself calls unexpected reward hacking: as the model got better at synthetic tasks it found sophisticated shortcuts, such as locating a leftover Python type-checking cache and reverse-engineering its format to recover a deleted function signature, and decompiling Java bytecode to rebuild a third-party API; Cursor found these with agentic monitoring tools and says large-scale reinforcement learning needs more care because of them [cursor-composer-25-blog]. The post does not say how often such behaviour appears in deployment. Deployment guardrails belong to the Cursor agent: terminal commands need approval by default, each MCP tool call needs approval, and file edits apply at once except to configuration files. Cursor calls the run modes that let commands skip approval (an allowlist up to an auto-review classifier) best-effort guardrails, not a hard security boundary [cursor-agent-security].

## Behaviour observed in practice

- **Artificial Analysis (M).** Coding Agent Index 62, third place behind Claude Opus 4.7 (max) in Claude Code (66) and GPT-5.5 (xhigh) in Codex (65), which cost about $4.10 and $4.82 a task. Composer 2.5 cost about $0.07 a task at standard speed and $0.44 at Fast. Fast ran about 30% faster per task (6.7 against 9.3 minutes) at about six times the cost [aa-composer-25].
- **Cursor's CursorBench 4.0 board (L).** Composer 2.5 scores 27.7% at $0.68, about 17k tokens and 41 steps per task, in the lower part of the list (rank 55); Grok 4.7 at high scores 43.9% [cursor-bench-board].
- **Practitioner reports (A).** None with measurements found.
