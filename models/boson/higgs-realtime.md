# Higgs Realtime

Higgs Realtime is Boson AI's end-to-end speech-to-speech model. It listens and speaks in one full-duplex session over a WebSocket. The event protocol is compatible with the GA version of the OpenAI Realtime API. A trade article of 2026-07-27 says Boson was preparing the release then. The docs show the model live and priced on 2026-10-03. Maker-wide facts are in the [Boson README](README.md) [boson-overview] [boson-migrate] [cryptobriefing-higgs].

## How to instruct it

### Setting up the prompt

`instructions` in `session.update` is the system prompt. Boson's migration guide says that rules written to work around another model's faults are usually not needed here. It advises a brief, plain prompt to start with, and adding rules back only when a test shows the need [boson-migrate]. Boson says to control delivery (pace, tone, energy) with `instructions`, for example "Speak slowly and calmly" [boson-audio]. The docs give no longer prompting guide.

### Reasoning and effort

The model has no documented reasoning mode or effort control [boson-sessions].

### Output: format, length, tone

`output_modalities` must be exactly `["audio"]` (the default) or `["text"]`. A mixed list is rejected. `max_output_tokens` is an integer or `"inf"`, and integers are clamped to 4096. `temperature` is a session field with a default of 0.3 [boson-sessions].

### Tools and agents

Tools are `function` tools with JSON-schema parameters. `tool_choice` takes `auto` (default), `none`, `required` or a named function. The flow is: the server streams `response.function_call_arguments.delta` and `.done`, then `response.done` with the completed call. The client runs the function, returns a `function_call_output` item with the same `call_id`, and sends `response.create`. The model then continues and speaks the answer. MCP tools, tool approvals and the `mcp_*` events are not supported [boson-tools] [boson-migrate].

### Coding

Boson gives no coding guidance.

### Long context and retrieval

With `truncation` set to `auto` (default), the server summarises older messages in the background before the conversation reaches the context window. It keeps the originals retrievable and sends `conversation.context.summarized`. `truncation` set to `disabled` opts out. OpenAI's API drops old messages instead. The docs state no context size [boson-migrate].

### Structured output

Boson documents no structured-output setting for the realtime model.

### Images, audio, other inputs

Input is audio or text. `conversation.item.create` takes text content only: `input_audio` and `input_image` parts are skipped and `system` messages are rejected. One `input_audio_buffer.append` event holds at most 1 MiB of base64 audio, so send small chunks. Input transcription is optional: set `audio.input.transcription.model` to `higgs-stt-3.1`. Only the `completed` transcription event is sent. `audio.input.noise_reduction` takes `near_field` or `far_field` to clean the input before the model hears it [boson-sessions] [boson-migrate].

### Voice: turn-taking, interruption and speech style

**Turn detection.** `audio.input.turn_detection` takes [boson-turn] [boson-migrate]:

- `server_vad`: `threshold` 0.55, `prefix_padding_ms` 300, `silence_duration_ms` 500 and `min_speech_duration` 0.125 seconds (all defaults). The model replies when the user stops speaking.
- `semantic_vad`: the same settings plus a semantic judgment of whether the user has finished. Boson says it reduces cut-offs in natural pauses.
- `null`: manual mode, with `input_audio_buffer.commit`.

`create_response`, `interrupt_response` and `eagerness` are accepted but do nothing. A response always follows the end of a turn, and barge-in always interrupts. `idle_timeout_ms` is rejected with an error [boson-migrate].

**Interruption.** User speech during playback cancels the response, stops the audio and truncates the assistant item at the interruption point. A new user turn starts at once. The client must stop local playback when `input_audio_buffer.speech_started` arrives. `conversation.item.truncate` with `audio_end_ms` makes the stored transcript match what the user heard [boson-turn].

**Voices.** `audio.output.voice` is `default`, a named preset from the Higgs TTS API, or a custom `voice_<id>`. An unknown voice fails the `session.update`. OpenAI voice names do not exist here [boson-audio] [boson-migrate].

**Audio and delivery.** Internal processing runs at 24 kHz, so PCM at 24 kHz both ways avoids resampling; lower rates save bandwidth. WebSocket is the only transport. WebRTC is in progress. Browser and mobile clients should use ephemeral keys, minted on a server with `POST /v1/realtime/client_secrets`. The TTL runs from 10 to 7200 seconds (default 600) [boson-sessions] [boson-migrate].

**Sessions.** The server closes a session after 5 minutes without user speech. It also enforces a maximum session duration and sends `session.max_duration_reached` before it closes. The pages read give no number. Code 1013 means the concurrency limit was exceeded. Code 4429 means the quota ran out [boson-migrate] [boson-limits].

### Sampling and API parameters

`temperature` (default 0.3) and `max_output_tokens` are session fields. The pages list no `top_p` [boson-sessions].

### Migrating from the previous generation

There is no earlier Higgs Realtime model. To move an OpenAI Realtime integration, change the URL to `wss://api.boson.ai/v1/realtime`, change the key, and set the model to `higgs-realtime`. Compatibility notes: `session.created` follows your first `session.update` and is not sent on connect; `conversation.created` is never sent; `response.done` reports only `completed` or `cancelled` and its `usage` is null; OpenAI's WebRTC, SIP and MCP features are missing; `audio/pcma` is not supported; and `session.update` rejects the fields `include`, `prompt` and `tracing` [boson-migrate].

## Behaviour observed in practice

Artificial Analysis measured the model on its Speech to Speech page (read 2026-10-03) [aa-s2s]:

- Speech reasoning (Big Bench Audio): 68.6%.
- Conversational dynamics: 92.8%. The parts are pause handling 86.1, turn-taking 99.2, interruption handling 96.0 and backchannel handling 89.8.
- Agentic performance (tau-Voice, full-duplex models only): 18.6%. The parts are airline 46.0, retail 5.3 and telecom 4.7.
- Time to first audio: 1.47 seconds on average.

On this page the model scores high on conversational dynamics and low on tau-Voice, most of all in the retail and telecom domains. No practitioner report was read beyond the community Pipecat integration page, which lists voice activity detection, interruption handling, transcripts, function calling and text-only replies [pipecat-boson].
