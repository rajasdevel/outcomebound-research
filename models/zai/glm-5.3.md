# GLM-5.3

GLM-5.3 is the flagship text model of Z.ai's GLM class, generation 5.3, released on 2026-08-18. It uses the same
base model as GLM-5.2 and takes its gains from post-training for long, multi-step software engineering and agent
work; Z.ai also reports a sharp rise in cyber capability. It replaced GLM-5.2 as the model behind the GLM Coding
Plan. Rules that hold for every GLM model (endpoints, parameters, guides, safety practice) are in the
[Z.ai README](README.md); this file says what is specific to GLM-5.3.

## How to instruct it

Z.ai publishes no prompting guide written for GLM-5.3. Its advice is the general coding-agent guidance summarised
in the [README](README.md#prompting-guides), the GLM-5.3 docs page and the migration guide. Everything below is
labelled as what Z.ai says (L), what was measured (M) or what one observer reported (A).

### Setting up the prompt

- **Frame.** Z.ai's best-practice page describes a task as goal, context, constraints and a "done when" condition,
  and says to plan before editing on complex work (L) [zai-best-practice]. Its GLM-5.3 docs examples use a one-line
  role system prompt (a senior full-stack engineer) and a plain user request. [zai-glm53-docs]
- **How much to specify.** Z.ai says it trained GLM-5.3 on production-like environments, some of them several days
  of work for an experienced engineer, to push the model toward owning substantial work end to end instead of waiting
  for the user to decompose the problem (L) [zai-glm53-docs]. It does not advise against step-by-step instructions, and the best-practice page
  still recommends planning first. One hands-on review of a single end-to-end feature task described a "decide once,
  then execute" style without repeated second-guessing (A, one tester, 2026-08-20). [mindstudio-glm53]
- **Where rules live.** Durable rules belong in the repository's instruction file, written as checkable directives and
  kept short; rules held only in the conversation are lost when context is compacted (L). [zai-memory-mechanism]
  Claude Code reads `CLAUDE.md`. ZCode, Z.ai's own agent, reads only a user-global `~/.zcode/AGENTS.md` and the
  workspace `AGENTS.md`, appended in that order; it does not keep reading `CLAUDE.md` after onboarding (L).
  [zcode-agents]
- **Structure and examples.** Z.ai gives no preference between XML tags and Markdown and no few-shot guidance for
  GLM-5.3. The SGLang cookbook (a third-party hosting guide) shows the model emitting XML-like `<tool_call>` blocks,
  which is a serving format, not a prompting rule. [sglang-glm53]
- **Constraint durability.** A benchmark co-authored by Zhipu found that, on GLM-5.2, constraints in the repository
  policy file decayed less over a long session than the same constraints in user turns, and that revising an existing
  constraint was followed worse than adding one (M, GLM-5.2 only; see the [README](README.md#family-wide-behaviour)).
  GLM-5.3 has not been run on it. [mtac-ifbench]

### Reasoning and effort

- **The control.** `reasoning_effort` takes `low`, `high` or `max`; the default is `max` when the field is absent.
  Thinking is always on, and `thinking.type` accepts only `enabled`. The docs say "Disabling reasoning is no longer
  supported", and a request with `type: disabled` fails on the Z.ai API (L). [zai-glm53-docs, zai-deep-thinking]
- **What each level is for (Z.ai's agent guide).** Low: simple questions and small, well-defined edits, fastest.
  High: everyday development, balancing speed and quality. Max: complex architecture work, hard bug hunts and
  long-running tasks. The GLM-5.3 docs recommend max for coding. [zcode-agents, zai-glm53-docs]
- **What the levels cost and buy (Z.ai, private Code Bench).** Max reached 34.5% at about 75K output tokens a task;
  high 31.4% at about 50K; low about 24 to 25% at about 48K (the low figure is read from Z.ai's chart, not stated in
  text). Z.ai's chart, captioned as run in Claude Code 2.1.207, puts GLM-5.2 at 23.4% and about 96K tokens at max,
  and Claude Opus 4.8 at 29.5% with about 120K tokens at max (L). [zai-glm53-docs, zai-flash-blog]
- **What the levels cost and buy (Artificial Analysis).** At max the Intelligence Index is 44.8 against 34.3 at low;
  Terminal-Bench 4.0 is 41.9 against 34.8. Running the index took about 210M output tokens at max against about
  88M at low, about 769 seconds a task against 421, and about US$2,503 against US$1,012 (M). The AA-Omniscience
  hallucination rate was 29.6% at max and 64.0% at low with equal accuracy (33.9%), so a lower effort gave more wrong
  answers where the model did not know (M). High was not measured by Artificial Analysis. [aa-glm-5-3, aa-glm-5-3-low]
- **Thinking visibility and continuity.** Reasoning is returned in `reasoning_content`, apart from `content`.
  Interleaved thinking (reasoning between tool calls) is on. For coding and agent work Z.ai recommends preserved
  thinking: `clear_thinking: false` and every earlier `reasoning_content` sent back unedited and in order. It is the
  default on the Coding Plan endpoint and off on the standard API, where `clear_thinking` defaults to `true`. The
  Hugging Face chat template does the opposite: `clear_thinking` defaults to `false` there, and the model card asks
  for `clear_thinking=true` in plain chat, so a self-hosted server keeps the earlier reasoning a caller sends back
  unless told not to (L).
  [zai-thinking-mode, hf-glm53, zai-chat-api]
- **Prompts that ask for reasoning.** Z.ai publishes nothing on adding "think step by step" to GLM-5.3 and nothing
  for or against it; the effort field is its documented control.
- **Budgets.** There is no token-budget field. `max_tokens` (up to 131072) caps reasoning and answer together, so a
  small cap can end a reply in `length` before the answer (L). [zai-chat-api]

### Output: format, length, tone

Z.ai documents no verbosity setting, formatting default, tone control or prefill for GLM-5.3. What exists: output
streams as `reasoning_content` then `content`; `stop` takes one stop word; `finish_reason` can be `length`,
`sensitive`, `model_context_window_exceeded` or `network_error`. Observed length: the model is wordy at max (about
210M output tokens to run the Artificial Analysis index, which AA compares with a median of 140M among comparable
models; about 71k tokens a task) (M). A single practitioner review found canvas-based creative output
repetitive within one prompt (A). [aa-glm-5-3, mindstudio-glm53]

### Tools and agents

- **Definitions.** Up to 128 function tools. Z.ai advises one responsibility per function, meaningful names, full
  function and parameter descriptions, and input validation, permission limits and call logging in the caller's
  code (L).
  [zai-chat-api, zai-function-calling]
- **Tool choice.** Only `auto`; "must call X" can be stated only in the prompt. Parallel tool calls are not
  documented by Z.ai; OpenRouter's parameter list for the model includes `parallel_tool_calls` (A).
  [zai-function-calling, openrouter-models]
- **Streaming arguments.** `stream: true` with `tool_stream: true` returns tool-call arguments as they are
  generated; concatenate the fragments by index. Off by default (L). [zai-migrate, zai-stream-tool]
- **Long-horizon behaviour.** Z.ai says reinforcement learning on 5.2 and 5.3 included compaction of long traces, so
  gains should hold on long tasks (L). Independent runs: in Artificial Analysis's Coding Agent Index a GLM-5.3 task
  averaged 107 steps, about 48 minutes of wall time and a 97% cache-hit rate; on tbench.ai a Terminal-Bench 4.0 trial
  averaged about 97 minutes (M). [zai-glm53-docs, aa-coding-agent, tbench-4]
- **Harness.** Z.ai's own runs use Claude Code 2.1.207 with Tool Search disabled for Terminal-Bench 3.0 and Agents'
  Last Exam, and mini-swe-agent for DeepSWE (L). Artificial Analysis ran OpenCode; Scale ran mini-swe-agent. The
  Terminal-Bench 4.0 gap between Claude Code (41.8, plus or minus 3.2) and OpenCode (39.9) is inside the noise.
  [hf-glm53, tbench-4, aa-coding-agent]
- **Context management and subagents.** Z.ai's guides recommend a session per task, summaries when history grows,
  rules in files, and delegating exploration or test runs to separate agents (L). ZCode's goal mode sets an
  objective for a session and verifies each round before the task closes; ZCode reads only the two `AGENTS.md` files
  named above and does not expand `@import` lines or scan child directories (L).
  [zai-best-practice, zai-memory-mechanism, zcode-agents]
- **Computer use.** GLM-5.3 takes no images, so it cannot act on screenshots; Z.ai's computer-use and browser-use
  features run on Flash. [zai-glm53-docs, zai-flash-docs]

### Coding

- **What Z.ai advises.** Use max effort; give goal, context, constraints and a completion check; state the bounds
  (no new dependencies, no API-contract changes, no unprompted commits) and ask for build, lint and test results and
  residual risks. Its GLM-5.2 page names out-of-scope edits, invalid dependencies, skipped verification and
  unauthorised commits as the risks those bounds address (L). [zai-glm52-docs, zai-best-practice]
- **Measured.** Scale's SWE-Bench Pro V2 (642 tasks, endpoint-only access, every diff re-graded on a clean image): 84.3
  on the HARD tab and 95.6 on the Full tab, both under mini-swe-agent at max. Terminal-Bench 4.0: 41.8 on
  tbench.ai (Claude Code, 330 trials), 41.9 in Artificial Analysis's run. Coding Agent Index 53.6 under OpenCode
  (DeepSWE v1.1 61.4, Terminal-Bench 4.0 39.9, SWE-Atlas-QnA 59.4) (M). [scale-swe-pro-v2, tbench-4, aa-coding-agent]
- **Reward hacking and special-casing.** Z.ai saw more hacking in GLM-5.2's reinforcement learning than in 5.1's and
  added a guard; GLM-5.3 reuses 5.2's base with different post-training, and whether it hacks more or less is not
  measured by Z.ai. Artificial Analysis's audit of passing Terminal-Bench 4.0 attempts flagged 1 of 80 reviewed
  (judged by a model against a rubric) (M). Whether it special-cases tests in everyday use is unmeasured.
  [zai-glm52-blog, aa-coding-agent]

### Long context and retrieval

- **Limits.** 1M tokens of context and 131072 of output (L). OpenRouter and Vercel list 1,048,576 tokens. A
  self-hosted FP8 server reaches the full 1M only on eight B200 cards with an FP8 KV cache; eight H200 or H20 cards
  hold the weights (A). [zai-glm53-docs, vllm-glm53]
- **Placement.** Z.ai's only placement advice is in its caching guide: it recommends putting a long document in the
  system message and keeping that prefix unchanged, so repeated questions about it hit the cache (L). It says nothing
  about putting the question before or after the document. Its evaluation footnotes ran DeepSWE and Terminal-Bench 3.0
  at 400K context and NL2Repo, SWE-Marathon, FrontierSWE, PostTrainBench and Agents' Last Exam at 1M. [zai-cache, hf-glm53]
- **Quality at length.** Artificial Analysis's AA-LCR (long-context reasoning) is 79.7% at max and 72.7% at low (M).
  Z.ai says the 1M window was trained for coding-agent trajectories; no independent needle or degradation test of
  GLM-5.3 was found. [aa-glm-5-3, zai-glm52-docs]
- **Caching.** Implicit prefix caching, cached input at US$0.26 per million tokens against US$1.40; cache storage is
  free for a limited time (L). Preserved thinking raises hit rates. [zai-cache, zai-pricing, zai-thinking-mode]

### Structured output

JSON mode only (`response_format: {"type": "json_object"}`) with the schema written in the system message and
validated in the caller's code; no schema-enforced mode is documented (L). Z.ai's structured-output page names
earlier models in its text. Microsoft Foundry's catalogue entry and OpenRouter's parameter list both show structured
output for GLM-5.3 (A). Strict (schema-enforced) tool calls are not documented either.
[zai-struct-output, foundry-glm53, openrouter-models]

### Images, audio, other inputs

Text in, text out. Z.ai's Cline setup note tells users to untick image support for GLM-5.3 and tick it for Flash.
Image, video and file input go to [GLM-5.3-Flash](glm-5.3-flash.md); audio is a separate Z.ai speech model, not
this one. [zai-switch-models, zai-models-overview]

### Sampling and API parameters

Temperature 1.0 and top_p 0.95 are the defaults; the range for temperature is 0 to 1; the migration guide advises
tuning one of the two, not both. `do_sample: false` turns sampling off, and then temperature and top_p have no effect.
Z.ai's evaluations used temperature 1.0 (0.95 for DeepSWE) and top_p 0.95 to 1.0, with `max_new_tokens` between 64K
and 128K (163,840 for HLE with tools). No top_k, penalty or seed fields are in Z.ai's reference. [zai-chat-api, hf-glm53, zai-migrate]

### Migrating from the previous generation

From GLM-5.2 (same base model; every difference is post-training and API rules):

- **Thinking can no longer be disabled.** A request with `thinking.type: disabled` fails on GLM-5.3. Z.ai's notice
  says to switch it to `enabled` with `reasoning_effort: low` before changing the model id. [zai-glm53-docs]
- **Effort values are stricter.** GLM-5.2 accepted `xhigh`, `medium`, `minimal` and `none` and mapped them; GLM-5.3 on
  the API accepts only `low`, `high` and `max`, and `low` is now a real level (on 5.2 it meant high). The Coding Plan
  still maps the other words. [zai-deep-thinking, zai-switch-models]
- **Results moved a lot with no architecture change.** Artificial Analysis: Terminal-Bench 4.0 from 1.0 to 41.9 and
  the Intelligence Index from 33.7 to 44.8 (M). Z.ai: Terminal-Bench 3.0 from 4.6 to 28.3, DeepSWE v1.1 from 46.2 to
  66.9, Agents' Last Exam from 23.8 to 28.5, Code Bench from 23.4% to 34.5% (L). Z.ai's migration guide says to
  re-test randomness, tool streaming and latency; it says nothing about removing older prompt text. [aa-glm-5-2, aa-glm-5-3, zai-glm53-docs]
- **Token use.** Z.ai says 5.3 used fewer tokens than 5.2 on its Code Bench at every effort level; in Artificial
  Analysis's index run 5.3 used more (about 210M output tokens against about 178M, from its cost figures). [zai-glm53-docs, aa-glm-5-3, aa-glm-5-2]
- **Hallucination rate rose** on AA-Omniscience from 26.3% to 29.6% at max (M). [aa-glm-5-2, aa-glm-5-3]
- **Unchanged.** Price (US$1.40 in, US$4.40 out, US$0.26 cached), 1M context, 128K output, text-only input, and the
  default sampling values. The weights licence changed from MIT to a custom licence. The Coding Plan sends 5.2
  requests to 5.3. [zai-pricing, hf-glm53-license, zai-coding-plan]
- **Instruction following.** MTAC-IFBench covers 5.2 only, so whether 5.3 decays the same way over turns is open.

## What the system card reports

Z.ai publishes no system card or safety report for GLM-5.3, so there is none to summarise. The release materials (a
blog post, the docs page and the Hugging Face card) report the following; every number is Z.ai's own. [zai-glm53-blog,
zai-glm53-docs, hf-glm53]

- **Capabilities measured.** Terminal-Bench 2.1 88.2, Terminal-Bench 3.0 28.3, DeepSWE v1.1 66.9, NL2Repo 58.0,
  ProgramBench 19.0, FrontierSWE 78.1, SWE-Marathon 42.5, PostTrainBench 39.8, Toolathlon Verified 73.0,
  AutomationBench 48.2, Agents' Last Exam 28.5, HLE with tools 62.5, GDPval-AA v2 1769 (see Benchmarks for settings).
- **Cyber capability, which Z.ai calls emergent.** CyberGym 84.5% (GLM-5.2: 77.2%); ExploitBench 54.4% (GLM-5.2:
  24.4%); ExploitGym tasks solved 105 in a two-hour budget and 130 in six (GLM-5.2: 29 and 39). Z.ai's table puts
  two closed models ahead on the exploitation benchmarks (ExploitBench 76.5% and 78.0%; ExploitGym 181 and 216 tasks in
  two hours, 247 and 293 in six) and GLM-5.3 ahead on CyberGym. Z.ai reports 2,436 vulnerabilities found with
  security teams in China in 269 projects. Its text calls 1,097 of them medium to high severity, while the blog's
  tracker labels the same count critical and high; the text puts the oldest at about 40 years, and the tracker dates
  the oldest flaw to 1981. The tracker showed 53 findings publicly disclosed and 2,383 under embargo when read. Z.ai
  says the cyber gains came faster than it expected as post-training scaled, and its launch post said the weights
  would follow in about two weeks; a newsletter reported that the delay was for safety evaluation with vetted
  security partners (A). [zai-glm53-blog, batch-glm53]
- **Reward-hacking controls in training.** Verifiers are synthesised without the reference solution and must pass
  oracle, no-op and unsolved-state checks; solver trajectories are used to find and close shortcuts. The 5.2 online
  guard (see the [README](README.md#system-card-practice)) carries over.
- **Not reported.** Refusal and over-refusal rates, sycophancy, deception or sandbagging tests, agentic-safety or
  prompt-injection results, bio or cyber classifiers that stop requests. The API has only the generic `sensitive`
  finish reason and error 1301. Artificial Analysis recorded no refusals in 909 GLM-5.3 coding-agent attempts (M).
  [aa-coding-agent, zai-errors]

## Behaviour observed in practice

- **Speed and cost (M, Artificial Analysis, max effort).** About 71 output tokens a second, 3.18 seconds to the
  first token, about 769 seconds and US$2.01 a task on the index. Low effort took 421 seconds a task. [aa-glm-5-3, aa-glm-5-3-low]
- **Agent runs (M).** Coding Agent Index: 107 steps and about 48 minutes a task, a 97% cache-hit rate, US$4.24 a
  task, no refusals, 1 of 80 reviewed passing terminal attempts flagged for reward hacking. tbench.ai: 138 of 330
  trials passed, pass@5 57.6%, an average trial of 5,831 seconds. [aa-coding-agent, tbench-4]
- **A single hands-on review (A, 2026-08-20).** A real-time viewer counter was added end to end in a containerised
  app without manual fixes; a defensive code review listed six issues tied to line numbers and avoided flagging code
  that needed no change; creative canvas output reused one shape. The review reports nothing on tool-calling error
  rates, latency, verbosity or reward hacking. [mindstudio-glm53]
- **Weights hold (A).** A newsletter (2026-08-28) reported that Z.ai held the weights for two weeks of safety
  evaluation because of the cyber gains, and it attributed the cyber scores to Z.ai's own tests. [batch-glm53]
- **Hosts.** OpenRouter, Vercel AI Gateway (21 providers) and Microsoft Foundry (a Fireworks-published listing) serve
  it; reseller prices differ from Z.ai's (Vercel's page showed prices from US$0.56 in and US$2.50 out per million
  tokens when read). [openrouter-models, vercel-glm53, foundry-glm53]

## Open questions

- Whether GLM-5.3 special-cases tests or hacks rewards at deployment: Z.ai measured it only in training for 5.2.
- How effort `high` compares with `low` and `max` on independent benchmarks.
- Instruction-following decay over turns for GLM-5.3, and whether placing rules in a policy file helps as it did for
  GLM-5.2.
- What the safety evaluation before the weights release tested (Z.ai published no results), and whether any request
  classifier exists on the API.
- Whether the Hugging Face and API defaults for `clear_thinking` produce different results in chat.
