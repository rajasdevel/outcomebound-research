# GLM-5.2

GLM-5.2 is the previous generation of Z.ai's GLM class (generation 5.2), released on 2026-06-16 as the line's first
model with a 1M-token context and a reasoning-effort field. Its weights are MIT-licensed. It was Z.ai's flagship
until GLM-5.3, which keeps its base model, and Z.ai still lists and prices it on the API while the GLM Coding Plan
routes its requests to GLM-5.3. Rules that hold for every GLM model are in the [Z.ai README](README.md); this file
says what is specific to GLM-5.2 and where it differs from [GLM-5.3](glm-5.3.md).

## How to instruct it

Z.ai publishes no prompting guide written for GLM-5.2. The advice below is from the GLM-5.2 docs page, the general
coding-agent guides in the [README](README.md#prompting-guides) and the one benchmark paper that tested this model.

### Setting up the prompt

- **Standards-and-bounds prompt (Z.ai's own example).** The docs page tells users to keep lint rules, build commands,
  test requirements, commit conventions and prohibited actions in `CLAUDE.md` or `Agent.md`, then to ask for the
  change with a prompt such as: "Do not introduce new dependencies, do not modify API contracts, and do not commit
  changes proactively." It follows with a request to run build, lint and tests and report the results and any
  uncovered risks. Z.ai says 5.2 holds engineering standards better across long, multi-round runs than earlier
  GLM models, reducing out-of-scope changes, invalid dependencies, skipped verification and unauthorised commits (L).
  [zai-glm52-docs]
- **Other prompts on the page.** Start a large codebase with an audit request (architecture map, module
  responsibilities, key contracts, data flows, debt, constraints for later refactors); for a refactor, ask for a
  plan, impact scope, risk boundaries and verification method first, with the goal mode of Z.ai's agent; for mobile
  and device work, give the model the debugging tools (ADB, logs, screenshots). (L) [zai-glm52-docs]
- **Constraint durability (measured on this model).** MTAC-IFBench (co-authored by Zhipu): GLM-5.2 satisfied 80.4% of
  constraints under Claude Code v2.1.14 but met every constraint in only 12.7% of turns, falling from 27.6% in turns
  1 to 2 to 2.6% in turns 9 to 10. Constraints in the repository policy file decayed less than the same ones in
  user turns; replacing an existing constraint was followed worse than adding a new one; on a 30-instance sample the
  policy file beat the system prompt and the first user turn. (M) [mtac-ifbench]
- **Structure, examples, long-document placement.** Z.ai gives no guidance for any of these.

### Reasoning and effort

- **The control.** `reasoning_effort` accepts `max` (default and recommended), `xhigh` (mapped to max), `high`,
  `medium` and `low` (both mapped to high), and `minimal` or `none`, which stop thinking. `thinking.type: disabled`
  also stops thinking on this model; GLM-5.3 removed that option. With `thinking.type: enabled` the model decides
  for itself whether to think (L). [zai-deep-thinking, zai-chat-api]
- **Levels in practice.** The GLM-5.2 release speaks of High and Max for the Coding Plan. Z.ai's Code Bench chart shows
  a non-thinking run, high and max at about 19.5%, 21% and 23.4% (the first two read from the chart), with max using
  about 96K output tokens a task; that chart is on the GLM-5.3 page and is captioned as run in Claude Code 2.1.207
  (L). Artificial Analysis measured only the max setting (index 33.7), so independent effort curves do not exist for
  this model (M). OpenRouter's model list gives high as its default effort and offers only `xhigh` and `high`,
  against max on Z.ai's own API (A). [zai-glm52-blog, zai-glm53-docs, aa-glm-5-2, openrouter-models]
- **Continuity.** Interleaved thinking is on. Preserved thinking works as on 5.3: `clear_thinking: false` and the
  earlier `reasoning_content` returned unchanged (L). [zai-thinking-mode]
- **Step-by-step prompting.** Z.ai says nothing for or against it.

### Output: format, length, tone

No verbosity, formatting, tone or prefill controls are documented. Maximum output is 131072 tokens (Z.ai: 128K).
Observed: about 178M output tokens to run Artificial Analysis's index, about 15% fewer than GLM-5.3's 209M; a 2026-06 practitioner post quoted 43k tokens a task for 5.2 against 26k for GLM-5.1 on the index
version then current (A, an earlier version, so not comparable with today's figures). [aa-glm-5-2, willison-glm52]

### Tools and agents

Same API rules as the family: up to 128 function tools, `tool_choice` accepts only `auto`, and `tool_stream` is
supported (L). [zai-chat-api] Z.ai's page positions 5.2 for long-chain, cross-file work: it breaks a goal into
parts, identifies dependencies and risks, then implements and verifies in stages (L, a description, not a measure).
Independent agent data is thin: Artificial Analysis's Coding Agent Index has no GLM-5.2 row, and tbench.ai has
none. [zai-glm52-docs, aa-coding-agent]

### Coding

- **Measured by Z.ai.** Terminal-Bench 2.1: 81.0 under Terminus-2 and 82.7 in Claude Code 2.1.167 (average of 5
  runs). SWE-bench Pro 62.1 with OpenHands and a tailored prompt; the card does not name the task set, and the result
  was published in June 2026, before Scale's V2 split, so it is not comparable with V2 scores. DeepSWE 46.2, NL2Repo
  48.9, FrontierSWE 74.4, SWE-Marathon 13.0, PostTrainBench 34.3, MCP-Atlas 76.8 (L). Z.ai's later GLM-5.3 table
  lists different GLM-5.2 values for some of the same benchmarks (FrontierSWE 67.5, SWE-Marathon 19.4,
  PostTrainBench 31.7, and ProgramBench 9.5 on an "Almost Solved" measure against 63.7 here), so the two tables use
  different runs or settings. [hf-glm52, hf-glm53]
- **Measured independently.** Artificial Analysis: Terminal-Bench 2.1 77.9 and Terminal-Bench 4.0 1.0, so the
  newer, harder benchmark was nearly unsolved by this model (M). Scale lists no GLM-5.2 row. [aa-glm-5-2,
  scale-swe-pro-v2]
- **Reward hacking.** Z.ai says GLM-5.2 showed more potential hacking than 5.1 in reinforcement learning, and added a
  guard (see the [README](README.md#system-card-practice)). Z.ai gives no deployment-time rate. [zai-glm52-blog]

### Long context and retrieval

1M tokens of context and 131072 of output; GLM-5.1 has 200K (L) [zai-models-overview]. Z.ai's page calls it a "solid 1M"
window, trained for coding-agent work, and says a shared-indexer design cut long-context compute; it ranks 5.2 among
the top models on three long-horizon benchmarks (FrontierSWE, PostTrainBench, SWE-Marathon) while trailing Opus 4.8
(L). Artificial Analysis's AA-LCR is 78.3% (M). Z.ai's benchmark runs used 400K context for most coding suites. No
placement advice is published. Caching and pricing are as on GLM-5.3. [zai-glm52-docs, zai-glm52-blog, aa-glm-5-2,
hf-glm52]

### Structured output

JSON mode only, as for the family; Z.ai's structured-output page names GLM-5 and earlier models, not GLM-5.2.
[zai-struct-output]

### Images, audio, other inputs

Text in, text out. [zai-glm52-docs]

### Sampling and API parameters

Defaults temperature 1.0 and top_p 0.95 for the GLM-5.x series; Z.ai's 5.2 page does not state them itself. Z.ai's
evaluation notes use temperature 1.0 with top_p 0.95 or 1.0. HLE and reasoning-set runs used 163,840 tokens of
output. [zai-chat-api, hf-glm52]

### Migrating from the previous generation

From GLM-5.1: context rises from 200K to 1M tokens; `reasoning_effort` is new (before, thinking was a toggle); the
model decides whether to think when thinking is enabled; the licence stays MIT; the price is the same
as GLM-5.1's (US$1.40 in, US$4.40 out per million tokens). Z.ai says 5.2 follows engineering standards more reliably and gives its
own standards-and-bounds prompt as the way to use that. [zai-glm52-docs, zai-pricing] Moving on to 5.3 is covered in
the [GLM-5.3 file](glm-5.3.md#migrating-from-the-previous-generation): thinking becomes forced and the effort set
shrinks to three values.

## What the system card reports

Z.ai publishes no system card or safety report for GLM-5.2. The release blog is the nearest document and reports one
safety-relevant finding: in reinforcement learning on coding tasks GLM-5.2 showed more potential hacking behaviour
than GLM-5.1 (agents reading protected evaluation files, copying answers from upstream commits, fetching solutions by
URL). Z.ai answered with a two-stage guard (rule-based filter, then a model judge of intent) that blocks the call and
returns dummy output so the rollout continues; it gives no rate of hacking before or after and no advice for users.
The MIT licence carries no use restrictions. Not reported: refusals and over-refusal, sycophancy, deception, prompt
injection, request classifiers. The API's generic `sensitive` finish reason and error 1301 apply. [zai-glm52-blog,
zai-errors]

## Behaviour observed in practice

- **Instruction decay (M).** See the MTAC-IFBench numbers above; the paper is co-authored by Zhipu, so it is not
  fully independent. [mtac-ifbench]
- **Index versions differ (A).** A June 2026 practitioner post reported Artificial Analysis scores of 51 for GLM-5.2
  and 44 for MiniMax-M3 on index v4.1; on today's v4.3.2 they are 33.7 and 29.2. Scores from different index
  versions cannot be compared. The same post found one SVG test worked well and another was worse than GLM-5.1
  (anecdote). [willison-glm52, aa-glm-5-2]
- **Status (M).** Artificial Analysis marks the model deprecated in favour of GLM-5.3; Z.ai still lists it and
  publishes no retirement date. [aa-glm-5-2, zai-pricing]

## Benchmarks

Independent (Artificial Analysis, max effort, index v4.3.2): Intelligence Index 33.7; Terminal-Bench 4.0 1.0;
Terminal-Bench 2.1 77.9; IFBench 73.3; AA-Omniscience 4.4 with a 26.3% hallucination rate; AA-LCR 78.3; GPQA Diamond
89.5; Humanity's Last Exam (no tools) 41.1; SciCode 51.2. No row on Scale's SWE-Bench Pro V2 page, the tbench.ai
Terminal-Bench 4.0 board, Artificial Analysis's Coding Agent Index or METR's page.

Maker-reported (Z.ai's Hugging Face card, with its footnotes): Terminal-Bench 2.1 81.0 (Terminus-2, 4 h timeout, 256K
context) and 82.7 (Claude Code 2.1.167); SWE-bench Pro 62.1 (OpenHands, 400K context); NL2Repo 48.9; DeepSWE 46.2
(mini-swe-agent, 2 h, no internet); ProgramBench 63.7 (200 instances, Claude Code 2.1.156, effort max); FrontierSWE
74.4; PostTrainBench 34.3; SWE-Marathon 13.0; MCP-Atlas 76.8; Tool-Decathlon 48.2; HLE 40.5 (text-only subset) and 54.7
with tools; CritPt 20.9; AIME 2026 99.2; HMMT February 2026 92.5; GPQA Diamond 91.2. Judge for reasoning sets: GPT-5.5
(medium). MTAC-IFBench (co-authored by Zhipu): all-constraints rate 12.7% under Claude Code and 6.7% under OpenCode.
[hf-glm52, aa-glm-5-2, mtac-ifbench]

## Open questions

- Effort curves: no independent run of 5.2 below max.
- Whether 5.2 or 5.3 follows a policy file better in long sessions; only 5.2 was tested.
- When Z.ai will retire GLM-5.2, if at all.
