# Eleven v4 Turbo

Eleven v4 Turbo is the low-latency variant of Eleven v4. It belongs to the Eleven Realtime class, generation 4, and ElevenLabs released it with v4 on 2026-09-28. It is for agents and interactive voice, where audio must start before the full text exists. It replaced Eleven v3 Conversational as the model the docs name for the most expressive live delivery. ElevenLabs says it built Turbo to work with its agent platform, transcription and turn-taking models as one stack [el-changelog-v4] [el-v4-page] [el-blog-v4-agents]. Family-wide rules are in the [ElevenLabs README](README.md). The text rules for tags, punctuation and pronunciation are in the [Eleven v4 file](eleven_v4.md).

## How to instruct it

### Setting up the prompt

The text is the prompt, as for v4. Audio tags work on Turbo [el-tags-help]. The tag, punctuation and IPA advice of the v4 guide is written for v4, and the maker calls Turbo the same model family, so it applies. The pages read do not test every tag on Turbo [el-tts-practices] [el-v4-page].

In an agent, the language model writes the text that Turbo speaks. The agent guide says to write numbers and symbols as words, or to let the platform normalise them [el-agents-prompting]. The agent settings `expressive_mode` and `suggested_audio_tags` are described for v3 models, and the API reference says expressive mode is switched off for non-v3 models. Whether Turbo uses them is not stated [el-api-agents].

### Reasoning and effort

None. ElevenLabs describes no reasoning or effort control for a speech synthesis model.

### Output: format, length, tone

- **Formats.** The Text to Dialogue WebSocket takes an `output_format` query value from the same list as the other speech models. ElevenAgents defaults to PCM 16 kHz and accepts PCM 8 to 48 kHz and mu-law 8 kHz [el-ws-ttd] [el-api-agents].
- **Length.** The models page gives no character limit for Turbo. The WebSocket sends audio after about 40 characters and 8 words, or at `flush` [el-models] [el-ws-ttd].
- **Tone.** Both v4 variants use stability and similarity. Lower stability gives more varied delivery. Higher similarity holds closer to the reference voice [el-v4-page].

### Tools and agents

- **Where it runs.** The Text to Dialogue WebSocket and ElevenAgents. The models page points to the WebSocket for Turbo. It says to use Turbo in agents for the most expressive delivery [el-models] [el-choose].
- **In agents.** The agent speech model setting takes `eleven_v4_turbo`. Additional call minutes cost US$0.08 each on the pricing page, and the language model is billed on top [el-api-agents] [el-pricing-agents].
- **Languages.** The maker says Turbo supports 90+ languages, and that an agent follows a caller who switches language mid-call, keeping the voice or changing it [el-blog-v4-agents].
- **Professional clones.** A news site reports that the launch material says Turbo supports the same professional clone through a call (evidence class A) [pr-testingcatalog].

### Coding

The WebSocket guide builds its example on `eleven_v4_turbo`, with one registered voice. The guide gives Python and TypeScript examples [el-ws-ttd].

### Long context and retrieval

Not applicable to the model. The agent platform holds the conversation history and sends the model each reply.

### Structured output

Not applicable. The WebSocket query option `sync_alignment=true` returns timing data on chunks when it is available [el-ws-ttd].

### Images, audio, other inputs

Text only. Voice rules for cloning, accent and Voice Design are in the [Eleven v4 file](eleven_v4.md). The accent change across languages is described for the v4 family [el-v4-page] [el-blog-v4].

### Voice: turn-taking, interruption and speech style

- **Latency.** The docs give a median inference latency of about 100 ms, without application and network time. The launch post gives a median time to first speech of about 150 ms. Its footnote says the maker measured it in September 2026 over WebSocket streaming, with network latency measured and removed for every system compared. A news site relays the maker's chart: 262 ms for Cartesia Sonic 3.6 and 814 ms for GPT-4o mini TTS [el-models] [el-blog-v4] [pr-testingcatalog].
- **Streaming in.** The client opens the WebSocket and sends a first message with `voices` (exactly one for Turbo) and credentials. It then sends `inputs` with `text`, `voice_id` and an optional `new_turn`. `voice_settings` and pronunciation dictionaries go in the first message only. A `flush` message ends a turn, `close_socket` finishes the stream, and `keep_alive` resets the 20-second timeout [el-ws-ttd] [el-api-ttd-ws].
- **Connections.** An open connection holds a dialogue session for its whole life, from a pool of 14 (Free) up to 105 (Scale and Business). If the pool is full, a new connection fails with `too_many_concurrent_requests` [el-models].
- **Turn-taking in an agent.** The platform decides when the agent speaks. Settings: turn timeout (1 to 30 seconds, default 7), turn eagerness (`patient`, `normal`, `eager`), soft timeout, `speculative_turn` (start the language model during silence, which can raise cost), `spelling_patience` and the `turn_model` choice (`turn_v2` or `turn_v3`, default `turn_v3`). The maker's guide pairs patient eagerness with phone numbers and addresses [el-agents-flow] [el-api-agents].
- **Interruption in an agent.** Users can interrupt by default. A tool can switch interruptions off while it runs or for the whole turn. `interruption_ignore_terms` lists words such as "gotcha" that must not count as an interruption. The `skip_turn` tool lets the agent stay silent when the user asks for a moment [el-agents-tool-int] [el-api-agents] [el-agents-skip].
- **Fillers.** The soft timeout speaks a filler when the language model is slow. The maker's example is "Hhmmmm...yeah." It advises against time words such as "One second..." [el-agents-flow].
- **Speech style.** The tag rules of v4 apply. For live agents, the agent guide asks for concise prompts, and for numbers and symbols written out as words or normalised by the platform [el-agents-prompting].
- **A custom pipeline.** The docs describe no cancel message for this WebSocket. Stopping playback on a user interruption is left to the client (inferred from the missing message) [el-ws-ttd].

### Sampling and API parameters

First-message `voice_settings` on the WebSocket, with `stability` and `similarity` for the v4 family, and `pronunciation_dictionary_locators`. `sync_alignment` returns timing. In agents, `stability` defaults to 0.5, `similarity_boost` to 0.8 and `speed` to 1 (range 0.7 to 1.2) [el-api-ttd-ws] [el-api-agents] [el-agents-speed].

### Migrating from the previous generation

The previous generation is Eleven v3 Conversational. What changes [el-models] [el-agents-expressive] [el-blog-v4-agents]:

- Median inference latency drops from about 280 ms to about 100 ms, by the maker's figures.
- Languages grow from 70+ to 90+.
- Professional clones: v3 Conversational does not keep them well. A news site says Turbo supports them.
- The list price stays at US$0.04 per 1,000 characters, with a promotion to 2026-10-12 [el-pricing-api].
- The v3 Conversational page ties expressive mode to the model. The pages read do not say how v4 Turbo uses it.

## What the system card reports

ElevenLabs publishes no system card for Eleven v4 Turbo in the pages read. The platform safeguards are in the [README](README.md) [el-safety].

## Behaviour observed in practice

- No independent measurement was found. Artificial Analysis lists no entry for Turbo on its text-to-speech pages (read 2026-10-03) [aa-tts-board].
- **Maker claims.** About 100 ms median inference latency, about 150 ms median time to first speech, and high reliability on long calls. The pages read give no method or data for reliability [el-blog-v4-agents].
- **Practitioner view (A).** One author says Flash v2.5 still wins on price until ElevenLabs publishes a credit rate for Turbo, and notes that the old warning about Turbo models does not apply to v4 Turbo [pr-raxxo].

## Benchmarks

None independent. Maker figures: a median inference latency of 100 ms and a median time to first speech of 150 ms, the second with network latency removed [el-models] [el-blog-v4].
