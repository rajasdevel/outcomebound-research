# ElevenLabs models

ElevenLabs is a voice AI company. It trains speech synthesis models (the Eleven line), transcription models (Scribe) and other audio models. It sells them through one API, a web app (ElevenCreative) and an agent platform (ElevenAgents). This file holds what is true across the ten ElevenLabs models in this library. Each model file says only what differs for its model. Everything here was read on 2026-10-03.

ElevenLabs models are voice models. A speech synthesis model takes text and gives audio. A transcription model takes audio and gives text. No ElevenLabs model listens and answers in one step. The voice changer models turn one recording into another voice, but they do not hold a conversation. The agent platform joins a transcription model, a language model, a speech synthesis model and a turn-taking model [el-agents-overview] [el-models]. All ten cards carry the `voice` object. The model files of the speech synthesis models carry the voice subsection.

**Lineage.**

- Multilingual v2 is the oldest model in scope. Its launch post is dated 2023-08-22, the date Artificial Analysis also gives, and names 29 languages. It became the default model of the Text to Speech endpoint in the changelog entry of 2025-05-12 [el-blog-ml2] [aa-tts-ml2] [el-changelog-0512].
- Turbo v2 and v2.5 were the first low-latency models (Artificial Analysis dates Turbo v2.5 2024-07-19). Flash replaced them in December 2024 (launch post 2024-12-18, changelog entry 2024-12-19). The models page now lists the Turbo models as deprecated and says to use Flash in all cases [el-changelog-flash] [el-models] [aa-tts-board].
- Eleven v3 added audio tags and multi-speaker dialogue. The launch post said a real-time version was in development. Eleven v3 Conversational is that version [el-blog-v3] [el-agents-expressive].
- Eleven v4 and v4 Turbo came on 2026-09-28. The docs call v4 a net upgrade over v3 in almost every case and tell the reader to test both with their own voices and text [el-v4-page] [el-changelog-v4].
- Scribe v2 Realtime launched on 2025-11-11 (changelog entry 2025-11-12), before the batch model. Scribe v2 followed in January 2026 (the launch post and Artificial Analysis give 2026-01-09; the changelog entry is dated 2026-01-12). Scribe v2 Medical became generally available on 2026-09-11 [el-changelog-scribe-rt] [el-changelog-scribe-v2] [aa-stt-board] [el-changelog-scribe-med].

**What the maker advises by use.** For top quality, use `eleven_v4`. For low latency, use `eleven_v4_turbo`. For agents, use `eleven_v4_turbo` for the most expressive delivery, or `eleven_flash_v2_5` and `eleven_flash_v2` for the lowest latency, with v2.5 for any language but English. For transcription, use `scribe_v2` for batch work, `scribe_v2_medical` for clinical audio and `scribe_v2_realtime` for live audio [el-choose]. The models page also names `eleven_multilingual_v2` for quality and for content creation [el-models].

**Not in scope, and why.**

- Turbo v2 and v2.5 (`eleven_turbo_v2`, `eleven_turbo_v2_5`). Deprecated. The agent configuration still accepts both ids [el-models] [el-api-agents].
- Multilingual v1 and Monolingual v1. The changelog first set removal for 2025-12-15 (entry of 2025-09-29), then for 2026-07-09 (entry of 2026-06-08). The model tables of the models page no longer list them, but its character-limit table still names `eleven_multilingual_v1` [el-changelog-0929] [el-changelog-0608] [el-models]. No call was made to confirm removal.
- Scribe v1. The same changelog entry sets its removal for 2026-07-09. The models page lists it as deprecated, with Scribe v2 as the replacement [el-changelog-0608] [el-models].
- The voice changer models (`eleven_multilingual_sts_v2`, `eleven_english_sts_v2`). They change the voice of a recording and do not hold a conversation. They are candidates for a later pass [el-models].
- Music, sound effects, voice design (text to voice), dubbing, voice isolation and image and video models. They are not speech synthesis, transcription or conversation models [el-models] [el-pricing-api].
- The turn-taking model of ElevenAgents. The agent configuration has a `turn_model` setting with the values `turn_v2` and `turn_v3` (default `turn_v3`), and the platform page calls it a proprietary turn-taking model. ElevenLabs does not sell or price it apart from the call minute, and the pages read describe nothing else about it [el-api-agents] [el-changelog-0608] [el-agents-overview].

## API surface

- **Base URLs and regions.** `https://api.elevenlabs.io`, with global routing to clusters in the USA, the Netherlands and Singapore; the `x-region` response header names the cluster. `https://api.us.elevenlabs.io` keeps traffic in the USA. Enterprise customers can use isolated environments with data residency in the EU, India and Singapore, each with its own host and API key [el-latency-opt] [el-residency].
- **Authentication.** An API key in the `xi-api-key` header. A key can have a scope limit, a credit quota and an IP allowlist. A single-use token (valid 15 minutes) lets a browser connect without the key [el-api-auth] [el-stt-client].
- **Text to Speech.** `POST /v1/text-to-speech/{voice_id}` returns a finished file, and a stream variant sends audio as it is made. The default model is `eleven_multilingual_v2` [el-api-tts] [el-audio-streaming].
- **Text to Speech WebSocket.** `wss://api.elevenlabs.io/v1/text-to-speech/{voice_id}/stream-input`. One voice for each connection. It does not accept `eleven_v3` or `eleven_v4`. A multi-context variant runs up to five parallel contexts on one connection for barge-in [el-ws-tts] [el-ws-multi].
- **Text to Dialogue.** `POST /v1/text-to-dialogue` takes a list of text and voice pairs (at most 10 distinct voices). The default model is `eleven_v3`. A stream variant exists. The WebSocket `wss://api.elevenlabs.io/v1/text-to-dialogue/stream-input` takes models whose id starts with `eleven_v3` or `eleven_v4` [el-api-ttd] [el-ws-compare].
- **Speech to Text.** `POST /v1/speech-to-text` (multipart; `model_id` is required) with an optional webhook for asynchronous results. The realtime WebSocket is `wss://api.elevenlabs.io/v1/speech-to-text/realtime` [el-api-stt] [el-api-stt-rt].
- **Output formats.** MP3, PCM, WAV, Opus, mu-law and A-law, named `codec_samplerate_bitrate`. The default is `mp3_44100_128`. Higher-quality formats need a paid plan [el-api-tts] [el-tts-overview].
- **ElevenAgents.** A hosted agent platform. A call joins four parts: a fine-tuned transcription model, a language model of the customer's choice, or a custom one, a speech synthesis model, and a proprietary turn-taking model [el-agents-overview]. The agent WebSocket is `wss://api.elevenlabs.io/v1/convai/conversation?agent_id=...` [el-agents-ws]. Agents run in the browser and in mobile apps through SDKs, and on the phone through SIP trunks, Twilio and other telephony routes [el-agents-overview]. The agent speech models are `eleven_flash_v2`, `eleven_flash_v2_5`, `eleven_multilingual_v2`, `eleven_v3_conversational`, `eleven_v4` and `eleven_v4_turbo`, plus the two deprecated Turbo ids. New agents default to `eleven_flash_v2`. The speech recognition defaults to `scribe_realtime`. Default audio is PCM 16 kHz in both directions [el-api-agents].
- **Agent language models.** The platform lists models of Google, OpenAI and Anthropic, and four models hosted by ElevenLabs (DeepSeek Flash 4.1, GLM 5.2, and two Qwen models). It also takes a custom endpoint, which must copy the OpenAI Chat Completions or Responses format and stream server-sent events [el-agents-custom-llm]. A backup chain moves a call to another model if the first fails. Reasoning is a token budget or an effort level, depending on the model. The system prompt can be 2 MB at most. ElevenLabs passes language model cost through at the provider's rate; selected Gemini and Claude models carry a 10% regional uplift [el-agents-llm] [el-agents-cascade].
- **Speech Engine.** A separate product launched on 2026-05-25. ElevenLabs does the transcription, turn-taking and speech, and the customer's server supplies the language model and streams text back over a WebSocket. The SDK cancels the model request when the user interrupts [el-speech-engine] [el-changelog-engine].
- **Voices.** Library voices, instant voice clones, professional voice clones and designed voices. See Family-wide behaviour for how each works [el-voices] [el-cloning].
- **SDKs.** Python (`elevenlabs`) and JavaScript (`@elevenlabs/elevenlabs-js`) clients, a browser client and React packages, React Native, Swift and Kotlin SDKs for agents, and a CLI [el-changelog-v4] [el-agents-overview].
- **Docs for models.** Add `.md` to a docs page URL to get Markdown. The docs publish `llms.txt` and an MCP server [el-llms].
- **Pricing units.** Speech synthesis: US$ per 1,000 characters on the API, and credits on subscriptions (credits were once called characters). Flash models cost 1 credit for 2 characters. Transcription: US$ per hour of audio. Agents: US$ per call minute. Voice only calls get a 95% discount for silence longer than 10 seconds. Burst calls cost twice the rate. The model cards give the prices [el-billing] [el-blog-flash] [el-pricing-api] [el-pricing-agents] [el-agents-cost] [el-agents-burst].
- **Plans.** Free, Starter, Creator, Pro, Scale, Business and Enterprise. Pay As You Go prepaid balance is available on self-serve plans. Credits roll over for up to two months' worth [el-billing] [el-payg].
- **Data retention.** By default, ElevenLabs keeps generations in history, and a customer can delete them through the API. Deleted items stay in backups for up to 30 days. ElevenLabs uses some customer data to improve its audio models until the customer turns off the data-use toggle. It does not train on Enterprise customer data by default. Zero Retention Mode (Enterprise, API only, `enable_logging=false`) deletes text, audio and transcripts when the request ends. Agents keep transcripts and audio for 2 years by default, and an agent can have its own Zero Retention Mode, a retention of 0 days or no audio saving [el-zrm] [el-data-use] [el-agents-retention] [el-agents-zrm] [el-agents-audio].

## Prompting guides

ElevenLabs publishes guides for four kinds of use. This section sums up what each guide says, so that a model file can say only what differs.

**Text to Speech best practices** [el-tts-practices]. The page covers controls, text normalisation and prompting for v4 and v3.

- Pauses. For models before v3, the guide gives `<break time="x.xs" />` for pauses up to 3 seconds. It warns that many tags in one request can make the voice speed up or add artefacts. It calls dashes and ellipses weaker substitutes. v3 and v4 do not support break tags.
- Pronunciation. v4 reads IPA between forward slashes (for example `/fəˈnɛtɪks/`). Flash v2 takes SSML `phoneme` tags (CMU Arpabet or IPA). Other models take alias tags in a pronunciation dictionary, or a respelled word. A dictionary is a `.pls` or text file. Its search is case sensitive, and the first match wins. A request can carry up to three dictionaries [el-api-tts].
- Emotion and delivery. Narrative context and explicit dialogue tags steer older models, and the model speaks those words aloud. Audio tags in square brackets steer v3 and v4.
- Pace. The voice sample sets the pace. The `speed` setting runs from 0.7 to 1.2. Extreme values can reduce quality.
- Normalisation. Smaller models read numbers, dates, currencies, URLs and abbreviations badly. The guide names three fixes. One is a model trained for it. Another is an instruction to the language model to write text in spoken form. The third is preprocessing with code. It gives a sample prompt and example conversions.
- Voice settings. They are stability, similarity, style, speed and speaker boost. v4 uses stability and similarity only.

**Prompting Eleven v4 and v3** [el-tts-practices] [el-v4-page].

- Voice choice. A delivery already in the voice's training audio is easier to reproduce. The guide says v4 follows tags more reliably than v3, even on a voice that never whispered or shouted. It adds that results vary.
- Explicit tags. A tag can be read as a sound effect instead of a voice direction. The guide advises writing the voice quality wanted (a low, gravelly voice) and testing it.
- Punctuation. Ellipses add pauses and weight. Capital letters add emphasis. Normal punctuation sets rhythm.
- Tag choice. The guide matches tags to the voice's character and allows combined tags. It lists voice tags, sound-effect tags and experimental tags (for example `[strong X accent]` and singing).
- Several speakers. Each speaker has a distinct voice.
- Enhance. A button in the web app adds tags with a language model. The guide prints the prompt. The prompt tells the model to keep the words unchanged. It allows only tags that describe sound from the voice. It allows emphasis only through capitals and punctuation.

**Agents prompting guide** [el-agents-prompting].

- Structure. The guide splits a prompt into sections under Markdown headings. It names Personality, Environment, Tone, Goal, Guardrails and Tools. It says the models pay extra attention to a heading named Guardrails.
- Concision. Each instruction is short and action-based. Tone guidance appears once.
- Emphasis. The guide adds "This step is important" to critical lines, and repeats the one or two most important instructions.
- Text normalisation. The agent setting `text_normalisation_type` has two values. `system_prompt` (the default) adds instructions for the language model. It adds no latency, and transcripts hold spoken forms. `elevenlabs` runs a normaliser after the language model. It is more reliable, adds a little latency, and transcripts keep symbols.
- Tools. The guide describes every parameter and gives the exact format with an example, because spoken forms ("john at gmail dot com") enter the context. The prompt says when and how to use each tool, and what to do when a tool fails: admit it, do not guess, retry once or escalate.
- Architecture. The guide keeps agents specialised. It describes an orchestrator that routes to specialists, with clear hand-off rules and a human escalation path.
- Model choice. The guide names GLM 5.2 or GPT-6 Luna as a starting point, DeepSeek Flash 4.1 or Gemini 3.5 Flash-Lite for the lowest latency, and Claude Sonnet 5.5 for complex reasoning. It says to test two or three models on the real prompt and to measure latency, accuracy and tool success.
- Iteration. The guide sets evaluation criteria, studies failures, changes one thing at a time and runs simulated conversations before release.

**Voice and turn-taking guides** [el-agents-flow] [el-agents-expressive] [el-agents-voice-design] [el-agents-speed] [el-agents-pron] [el-agents-skip] [el-agents-tool-int].

- Turn timeout (take turn after silence): 1 to 30 seconds, default 7. The guide gives 5 to 10 seconds for casual talk and 10 to 30 when users need time to think.
- Soft timeout: a filler such as "Hhmmmm...yeah." spoken if the language model is slow. It is off by default (`-1`). The range is 0.5 to 8 seconds, and the guide recommends 3 seconds. The guide says it fires once a turn. Since the changelog entry of 2026-06-08 the API also has `max_soft_timeouts_per_generation` (1 to 8, default 1) and up to 7 additional filler messages [el-changelog-0608]. A language model can write the filler. The guide advises against time words such as "One second...".
- Turn eagerness: `eager`, `normal` (default) or `patient`. The guide pairs `patient` with phone numbers, addresses and email addresses, and `eager` with customer service. A `spelling_patience` setting waits longer when a user spells.
- Interruptions: on by default. The guide disables them for legal disclaimers and safety text. Each tool has `interruption_mode`: `allow`, `disable_during_tool` or `disable_during_tool_and_turn`.
- `skip_turn` system tool: the agent stays silent when the user says they need a moment.
- Expressive mode: with `eleven_v3_conversational`, the language model may emit tags such as `[laughs]`, `[whispers]`, `[sighs]`, `[slow]` and `[excited]`. Each tag affects about the next four to five words. System-prompt rules can set the tone for specific triggers.
- Voice settings for agents: the guide gives stability 0.30 to 0.50 for dynamic delivery and 0.60 to 0.85 for steady delivery, and speed 0.9 to 1.1 for natural talk. It tests with one prompt and small changes.
- Pronunciation dictionaries for agents: phoneme tags work with `eleven_v4`, `eleven_flash_v2` and `eleven_v3`. Other models need alias tags [el-agents-pron].

**Transcription guides** [el-stt-overview] [el-stt-keyterm] [el-stt-commit]. Keyterm prompting biases the model toward given words, and the model still uses context to decide. `no_verbatim` removes fillers and false starts. Entity detection and redaction, transcript editing with a natural-language instruction, speaker diarisation, audio-event tags and word timestamps are options. For realtime audio, the guide recommends 16 kHz mono PCM in chunks of 0.1 to 1 second, with a commit at silence or at a turn boundary.

**Latency and streaming guides** [el-latency-opt] [el-latency-concept] [el-audio-streaming] [el-ws-tts] [el-stitching]. The guide gives four principles: use Flash models, stream, stay near a server region, and choose a fast voice type. It streams over HTTP when text is ready, and over a WebSocket when a language model feeds the speech model. `auto_mode` decides when speech starts, or `chunk_length_schedule` sets it. The guide sends `flush: true` at the end of an agent turn. For long text, it splits the text and passes `previous_text` and `next_text`, or request ids, to keep the voice steady across parts.

**How the advice moved.**

- Before v3, delivery came from SSML breaks, the style slider and narrative context. With v3 (June 2025) the guide moved to square-bracket audio tags and to punctuation. With v4 (2026-09-28) it adds IPA between slashes. It says Style and Speed sliders are gone, and that break tags and SSML are not supported [el-v4-page] [el-tts-practices].
- Agent speech advice moved from Flash as the default (2025-01-16) to v3 Conversational with expressive mode (2026-02) and then to v4 Turbo (2026-09-28) [el-changelog-0116] [el-agents-expressive] [el-blog-v4-agents].
- The models page still carries an older warning to use Flash instead of Turbo. It is about the old Turbo v2 and v2.5 and not about v4 Turbo. A practitioner notes that the two are easy to confuse [el-models] [pr-raxxo].

## System-card practice

ElevenLabs publishes no system card or model card for any model in this library in the pages read. A release is a blog post, a docs page and a changelog line. The nearest thing to a model card is the intended-purpose note on Scribe v2 Medical: it says the model makes draft transcripts for review by a health professional and does not interpret clinical information or give advice [el-models].

The safety page describes safeguards at platform level. They are red-teaming before release, customer vetting at sign-up, and a block on cloning celebrity and other high-risk voices. They also include voice verification for professional voice clones and monitoring by classifiers and reviewers under a Prohibited Usage Policy. An AI Speech Classifier detects ElevenLabs audio, and ElevenLabs supports the C2PA standard [el-safety]. ElevenAgents adds guardrails: Focus and Manipulation guardrails and Content guardrails at no extra cost, and Custom guardrails that cost extra language model calls [el-agents-guardrails].

How to read the maker's claims.

- Accuracy and preference claims come without method on the pages read. Examples: "over 98%" accuracy for Scribe v2, 35% fewer errors on clinical audio for Scribe v2 Medical, and about 75% listener preference for v4 [el-pricing-api] [el-models] [el-blog-v4-agents].
- The per-language word error bands for Scribe v2 are the only per-language data. They give a band, not a number [el-stt-overview].
- Latency figures are model inference time and leave out network and application time [el-models].
- The blog, the docs and the pricing page differ in places. See Open questions.

## Family-wide behaviour

- **Output is not deterministic.** A `seed` makes a best effort at repeating a result. The website gives up to two free regenerations of identical content. The maker says that regeneration fixes about half of the quality faults, and that the rest come from poor training audio [el-tts-overview] [el-api-tts].
- **Narration is spoken.** On older models, emotion words in the text are read out and must be cut by hand. On v3 and v4, a tag can sometimes be read as a sound effect [el-tts-practices].
- **Normalisation depends on the model.** The best-practices page says it is on by default for all models. The models page says Flash v2.5 does not normalise numbers by default, to save time, and that only Enterprise customers can turn it on with `apply_text_normalization`. A changelog line of 2025-09-08 says normalisation was enabled for v3, Flash and Turbo. The API reference default is `auto` [el-tts-practices] [el-models] [el-changelog-0908] [el-api-tts].
- **Long text.** The docs say to send text in parts. Request stitching uses up to three previous or next request ids, no older than two hours. It is not available for `eleven_v3`, and it does not work with Zero Retention Mode [el-stitching] [el-api-tts]. On Text to Dialogue, `previous_text` and `future_text` can hold 100 characters at most [el-api-ttd].
- **Timeouts.** The Text to Speech WebSocket closes after 20 seconds without input. The Text to Dialogue WebSocket has a fixed 20-second limit. A multi-context socket can wait up to 180 seconds. The realtime transcription server closes a connection after 15 seconds without client messages [el-ws-tts] [el-ws-ttd] [el-ws-multi] [el-stt-commit].
- **Concurrency.** A plan sets how many requests run at once. An HTTP request counts while it runs. A Text to Speech WebSocket counts only while it generates audio. A Text to Dialogue WebSocket holds one session for as long as it is open. Limits for Free, Starter, Creator, Pro, Scale and Business: Multilingual v2 2, 3, 5, 10, 15, 15; Flash 4, 6, 10, 20, 30, 30; Speech to Text 8, 12, 20, 40, 60, 60; realtime Speech to Text 6, 9, 15, 30, 45, 45; dialogue sessions 14, 21, 35, 70, 105, 105. Enterprise limits are higher. A limit of 5 can serve about 100 simultaneous broadcasts, the maker says, because speech is made faster than it plays [el-models].
- **Latency adds up.** The figures of ~75 ms (Flash) and ~100 ms (v4 Turbo) exclude the network and the application. Time to first audio adds a network round trip of 20 to 200 ms and often a player buffer of about 500 ms. Instant voice clones and library voices are faster than professional clones [el-latency-concept] [el-latency-opt].
- **Voice cloning.** An instant clone uses the sample as a live reference and updates no weights. It needs under two minutes of audio (the v4 launch post says 10 seconds can be enough) and can be less steady in styles far from the sample. A professional clone fine-tunes the model, needs about 30 minutes of clean audio and a Creator plan or above, and is slower per request. Both pass a voice verification step [el-cloning] [el-voices] [el-blog-v4]. v4 keeps the accent only when the generated language equals the sample language; for another language it speaks natively in that language. v3 Conversational does not keep professional clone character well. v3 is not fully tuned for professional clones [el-v4-page] [el-agents-expressive] [el-tts-practices].
- **Voices expire and move.** Default voices expire on 2026-12-31. Voice Library voices are not available through the API on the free plan. In agents, voices with live moderation cannot be used [el-voices] [el-agents-voice].
- **Counts differ.** Voice counts differ by page (3,000+, 5,000+, 10,000+; a practitioner says 17,500+). Language counts also differ (31, 32 or 70+ in places, 90+ for v4). A claim is only as good as its page and date [el-tts-overview] [el-voices] [el-agents-overview] [pr-raxxo].

## Open questions

- Whether `eleven_v4_turbo` and `eleven_v3_conversational` work on the plain Text to Speech endpoint. The models page ties v4 Turbo to the Text to Dialogue WebSocket and agents, and the pages read do not say.
- The Text to Dialogue WebSocket reference still says it takes `eleven_v3` models only, with `eleven_v3_conversational` as the default. The guide and the changelog say it takes v4 and v4 Turbo [el-api-ttd-ws] [el-ws-ttd] [el-changelog-v4].
- Whether an existing instant voice clone must be made again for v4. The docs say an instant clone needs no separate training step, and that an existing professional clone is trained on v4 by a fine-tune started from the My Voices page. A news site says older instant and professional clones need retraining [el-v4-page] [pr-testingcatalog].
- The maximum length of a realtime transcription session. The error exists, and no value is given [el-stt-events].
- The file size limit of Scribe v2 (3 GB on the capability page, under 5 GB on the API reference), and the limit of multichannel mode (10 hours of combined audio in the FAQ, 1 hour in the key facts) [el-stt-overview] [el-api-stt].
- Entity detection categories (65 entity types on the models page, 56 categories in the launch post) and keyterm limits (100 words in the launch post, 1,000 in the docs). The docs are newer [el-models] [el-blog-scribe2] [el-stt-keyterm].
- What `turn_v2` and `turn_v3` are, how they differ, and whether the turn-taking system of expressive mode is `turn_v3` [el-api-agents] [el-agents-expressive].
- Whether Multilingual v1 and Scribe v1 are now removed. The changelog gave a removal date that has passed [el-changelog-0608].
- Independent latency and word-error measurements for agent calls, for Eleven v4 Turbo and for Scribe v2 Medical. None were found.
