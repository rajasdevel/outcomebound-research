# Scribe v2 Realtime

Scribe v2 Realtime is the streaming transcription model of the Scribe Realtime class, generation 2. It takes audio over a WebSocket and returns partial and committed transcripts about 150 ms behind speech, in 90+ languages. ElevenLabs launched it on 2025-11-11 (launch post; the changelog entry is dated 2025-11-12), before the batch Scribe v2 [el-blog-scribe2rt]. It is the default speech recognition of ElevenAgents, and its live signals feed the turn-taking system of expressive mode [el-changelog-scribe-rt] [el-models] [el-api-agents] [el-agents-expressive]. Family-wide rules are in the [ElevenLabs README](README.md). Batch-only features are in the [Scribe v2 file](scribe_v2.md).

## How to instruct it

### Setting up the prompt

There is no system prompt. Query parameters steer the model when the WebSocket opens `wss://api.elevenlabs.io/v1/speech-to-text/realtime`. The model id is `scribe_v2_realtime` [el-api-stt-rt].

- **Language.** `language_code` and `secondary_languages` set the expected languages. The launch post says the model can follow a change of language during a session [el-api-stt-rt] [el-blog-scribe2rt].
- **Keyterms.** Up to 50 keyterms of 20 characters each, passed as query parameters. They bias the output toward names and rare terms [el-stt-keyterm].
- **Previous text.** `previous_text` goes with the first audio chunk only, and gives the model context. The guide gives three uses: the agent's last words in a conversation, a reconnection after a network fault, and a short note about the topic. It works best under 50 characters. Later chunks must not carry it, or the request fails [el-stt-commit].
- **Other options.** `no_verbatim`, `entity_detection`, `transcript_edit`, `filter_background_audio`, `include_timestamps` and `include_language_detection`. The first three are described on the capability page for this model. `filter_background_audio` and the two include options appear in the API reference [el-api-stt-rt] [el-stt-overview].

### Reasoning and effort

None. ElevenLabs describes no reasoning control for Scribe v2 Realtime.

### Output: format, length, tone

- **Events.** `session_started`, `partial_transcript` (later partials replace earlier ones), `committed_transcript` (stable text for a segment), `committed_transcript_with_timestamps` (word times and language), `committed_transcript_entities` and `edited_transcript`. The API has no separate final-transcript event [el-stt-events].
- **Length.** The pages read give no session limit. A `session_time_limit_exceeded` error exists [el-stt-events].
- **Tone.** Not applicable.

### Tools and agents

In ElevenAgents it is the default recogniser (`scribe_realtime`). The expressive-mode page says its signals, including emotional cues and prosody, time the agent's replies [el-api-agents] [el-agents-expressive].

### Coding

Browser code needs a single-use token (made on the server, valid 15 minutes). The microphone can feed the SDK directly. Server code can send chunks from a file or stream [el-stt-client].

### Long context and retrieval

Not applicable. Each committed transcript is a segment. Manual commits clear the accumulated text and start a new segment without losing context [el-stt-commit].

### Structured output

Events are JSON. Entities have character offsets. An edited transcript arrives next to the original committed text [el-stt-events].

### Images, audio, other inputs

Audio only: PCM at 8, 16, 22.05, 24, 44.1 or 48 kHz (16-bit little-endian), or mu-law at 8 kHz. The guide recommends 16 kHz, mono only, and chunks of 0.1 to 1 second. Smaller chunks lower latency and raise overhead. Processing starts after the first 2 seconds of audio [el-stt-commit].

**Turn detection.** This is a recogniser, so it has no speech output and no voice subsection. The settings below decide where one user turn ends.

- **Commit strategy.** `manual` is the default. The client commits when it chooses, ideally at silence or at a turn boundary, and the guide suggests every 20 to 30 seconds to help latency. The model commits by itself after about 36 seconds of audio. Several commits in a quick row can lower quality. `vad` commits when silence passes a threshold. The guide recommends `vad` for microphone input [el-stt-commit].
- **VAD settings.** `vad_silence_threshold_secs`, `vad_threshold`, `min_speech_duration_ms` and `min_silence_duration_ms`. The guide's example values are 1.5 s, 0.4, 100 ms and 100 ms. It gives no defaults [el-stt-commit] [el-api-stt-rt].
- **Keeping a quiet line open.** `keepalive_interval_ms` (500 to 10,000) makes the server send a keepalive partial transcript. The client must keep sending audio (silent frames are fine). The server closes the connection after 15 seconds with no client messages, and this limit cannot be changed [el-stt-commit].
- **Errors to handle.** `commit_throttled`, `rate_limited`, `queue_overflow`, `resource_exhausted`, `session_time_limit_exceeded`, `chunk_size_exceeded` and `insufficient_audio_activity`, among others [el-stt-events].

### Sampling and API parameters

`enable_logging` (default true; false is Zero Retention Mode for Enterprise). The realtime concurrency limits are 6 (Free), 9, 15, 30, 45 and 45 (Scale and Business) [el-api-stt-rt] [el-models].

### Migrating from the previous generation

There is no earlier realtime Scribe model. Before it, ElevenAgents used a different recogniser: the `elevenlabs` provider value is deprecated, and the default provider changed to `scribe_realtime` in the changelog entry of 2026-06-08 [el-changelog-0608] [el-api-agents].

## What the system card reports

ElevenLabs publishes no system card for Scribe v2 Realtime in the pages read. The launch post lists the same enterprise controls as for Scribe v2 [el-blog-scribe2rt].

## Behaviour observed in practice

- **Word error rate (M).** Artificial Analysis streaming index 3.59% (2.84% on AA-AgentTalk, 2.27% on VoxPopuli, 6.43% on Earnings22). Six of 38 streaming entries in the page data have a lower index. This library counted that rank [aa-stt-stream].
- **Latency (M).** A median of 0.134 s to the first partial transcript and 0.141 s to the final transcript after speech ends [aa-stt-stream].
- **Price (M).** US$6.5 per 1,000 minutes, equal to the list rate of US$0.39 per hour [aa-stt-stream] [el-pricing-api].
- **Maker claims.** 93.5% accuracy on 30 European and Asian languages (FLEURS), and better results than other models on 500 hard samples with noise. No method is given [el-blog-scribe2rt].

## Benchmarks

Independent: the Artificial Analysis streaming word error rate and latency figures above [aa-stt-stream]. Maker: 150 ms latency and the accuracy claims above [el-models] [el-blog-scribe2rt].

## Open questions

- The maximum session length.
- Default values of the VAD settings.
- Whether the docs' 150 ms and the measured 0.134 s describe the same event.
- Accuracy on telephone audio at 8 kHz.
