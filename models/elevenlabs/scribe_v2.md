# Scribe v2

Scribe v2 is the batch transcription model of the Scribe class, generation 2. It turns audio and video files into text in 90+ languages, with word timestamps, speaker labels, audio-event tags, keyterm prompting, entity detection and transcript editing. ElevenLabs made it for long and complex recordings. The launch post and Artificial Analysis date it 2026-01-09 (the changelog entry is dated 2026-01-12), and it replaced Scribe v1, whose removal the changelog set for 2026-07-09 [el-blog-scribe2] [el-changelog-scribe-v2] [aa-stt-board] [el-changelog-0608]. Family-wide rules are in the [ElevenLabs README](README.md).

## How to instruct it

### Setting up the prompt

Scribe v2 has no system prompt. Request fields steer it on `POST /v1/speech-to-text`, where `model_id` is the only required field [el-api-stt].

- **Language.** `language_code` (ISO 639-1 or 639-3) can improve results when the language is known. Without it, the model predicts the language. One file can hold several languages, and the model detects each one [el-api-stt] [el-blog-scribe2].
- **Keyterms.** `keyterms` biases the output toward names, product words and rare terms. The model still uses context to decide whether a term is there. A request can hold up to 1,000 keyterms of under 50 characters and at most five words each. Some characters are not allowed. More than 100 keyterms bring a minimum billed duration of 20 seconds. The launch post named 100 terms, so the docs are newer [el-stt-keyterm] [el-api-stt] [el-blog-scribe2].
- **Cleaner text.** `no_verbatim` removes fillers, false starts and non-speech sounds. The batch API reference says only Scribe v2 supports it. The capability page, the models page and the changelog entry of 2026-09-11 say it also works on Scribe v2 Medical, and the realtime API reference lists it for Scribe v2 Realtime [el-api-stt] [el-stt-overview] [el-models] [el-changelog-scribe-med] [el-api-stt-rt].
- **Entities.** `entity_detection` returns detected entities with positions. The value can be `all`, a category (`pii`, `phi`, `pci`, `other`, `offensive_language`) or single types. `entity_redaction` removes them from the text, with a choice of placeholder style [el-api-stt] [el-stt-overview].
- **Transcript editing.** `transcript_edit` takes a natural-language instruction of up to 2,000 characters. The edited text comes back in `edited_transcript` next to the unchanged original. The feature is experimental. It cannot be combined with entity detection, entity redaction or multichannel. The transcript-editing guide says the dedicated parameters (keyterms, `no_verbatim`) are cheaper and more predictable, and keeps editing for changes they do not cover [el-api-stt] [el-stt-overview] [el-stt-edit].
- **Speakers.** `diarize` labels speakers, up to 32. `num_speakers` sets an upper bound. `diarization_threshold` tunes how readily speakers merge, and works only when `diarize` is on and `num_speakers` is unset. `detect_speaker_roles` returns `agent` and `customer` labels. `use_speaker_library` matches known speakers [el-api-stt].
- **Events and timing.** `tag_audio_events` marks sounds such as laughter. `timestamps_granularity` is `word` or `character` [el-api-stt] [el-stt-overview].
- **Channels.** `use_multi_channel` transcribes each channel on its own, up to five. Each channel is billed for the full duration. `multichannel_output_style` is `separate` or `combined` [el-api-stt] [el-stt-overview].

### Reasoning and effort

None. ElevenLabs describes no reasoning control for Scribe v2.

### Output: format, length, tone

- **Format.** A JSON transcript. Items are `word`, `spacing` (not for languages without spaces) or `audio_event`. `additional_formats` exports other file types [el-stt-overview] [el-api-stt].
- **Length.** Up to 10 hours of audio in standard mode. File size is up to 3 GB on the capability page and under 5 GB on the API reference. The minimum is 100 ms of audio [el-stt-overview] [el-api-stt].
- **Tone.** Not applicable. `transcript_edit` can restyle the text [el-api-stt].

### Tools and agents

Not applicable to the model. In ElevenAgents the speech recognition defaults to `scribe_realtime`, not to this batch model [el-api-agents].

### Coding

The SDKs call `speech_to_text.convert` with `model_id="scribe_v2"`. A webhook mode sends the result later: set `webhook` to true and, if needed, `webhook_id` and `webhook_metadata` (JSON of at most 16 KB). The request can name a `source_url` instead of a file [el-api-stt].

### Long context and retrieval

A file over 8 minutes is split into up to four parts and transcribed in parallel. Concurrency is the smaller of 4 and the duration in seconds divided by 480, rounded up. Plan limits for concurrent transcriptions: 8 (Free), 12, 20, 40, 60 and 60 (Scale and Business). Requests over the limit wait in a queue [el-stt-overview] [el-models].

### Structured output

The response is structured JSON. Entities, speaker ids and edited transcripts have their own fields [el-api-stt].

### Images, audio, other inputs

Audio and video files. Audio: AAC, AIFF, OGG, MP3, Opus, WAV, FLAC, M4A, WebM. Video: MP4, AVI, MKV, MOV, WMV, FLV, WebM, MPEG, 3GPP. `file_format=pcm_s16le_16` (16 kHz mono PCM) gives lower latency than an encoded file [el-stt-overview] [el-api-stt].

### Sampling and API parameters

`temperature` (0.0 to 2.0; if omitted, the model's own value, usually 0) and `seed` (0 to 2,147,483,647, best effort). `enable_logging=false` selects Zero Retention Mode for Enterprise. Scribe v2 is eligible; a Business Associate Agreement is for Enterprise customers [el-api-stt] [el-zrm] [el-stt-overview].

### Migrating from the previous generation

The previous generation is Scribe v1. The launch post lists these gains: better handling of long audio, pauses, tone changes and long silences; keyterm prompting; entity detection; and several languages in one file. The changelog names `scribe_v2` and `scribe_v2_realtime` as the replacements [el-blog-scribe2] [el-changelog-0608].

## What the system card reports

ElevenLabs publishes no system card for Scribe v2 in the pages read. The launch post lists enterprise controls: SOC 2, ISO 27001, PCI DSS level 1, HIPAA and GDPR compliance, EU and India data residency and Zero Retention Mode [el-blog-scribe2].

## Behaviour observed in practice

- **Word error rate (M).** Artificial Analysis gives an AA-WER v2 index of 2.18% (non-streaming). By dataset: 1.51% on AA-AgentTalk, 1.74% on VoxPopuli-Cleaned and 3.95% on Earnings22-Cleaned. In the page data read, three entries have a lower index (StepAudio 3 ASR, Fun-Realtime-ASR-preview and MAI-Transcribe-2). This library counted that rank from the page data [aa-stt-board].
- **Speed (M).** A median speed factor of 83.2: 83 seconds of audio per second of processing [aa-stt-board].
- **Price (M).** US$3.67 per 1,000 minutes, equal to the list rate [aa-stt-board].
- **Maker claims.** "Over 98%" accuracy on the pricing page, and the lowest word error rate on industry benchmarks in the launch post. Neither gives a method [el-pricing-api] [el-blog-scribe2].
- **Maker language bands.** Word error rate of 5% or less in 36 languages, 5 to 10% in 21, 10 to 20% in 18 and above 25% up to 50% in 19 [el-stt-overview].

## Benchmarks

Independent: AA-WER v2 index 2.18%, with its three parts, and a speed factor of 83.2 [aa-stt-board]. Maker: the language bands above and the claims above.

## Open questions

- The file size limit (3 GB or under 5 GB) and the multichannel limit (10 hours of combined audio, or 1 hour) [el-stt-overview] [el-api-stt].
- The entity count: 65 types on the models page and 56 categories in the launch post [el-models] [el-blog-scribe2].
- Whether the note in the batch API reference that only `scribe_v2` supports `no_verbatim` is out of date. Three other maker pages say Scribe v2 Medical supports it.
- Independent word error rates on noisy phone audio.
