# Inworld Realtime TTS-2

Inworld Realtime TTS-2 is the current generation of the Inworld Realtime TTS class. It takes natural-language steering instructions in square brackets, or one request-level instruction, so a user can direct emotion, articulation, pitch, pace and vocal style, and it plays non-verbal sounds. Inworld released it on 2026-05-05. The previous generation, TTS 1.5, has no steering and has no file here, and the cheaper Realtime TTS-2 Flash model plays non-verbal tags only. Family-wide rules are in the [Inworld README](README.md).

## How to instruct it

### Setting up the prompt

- **No system prompt.** The input is text with optional markup. The model id is `inworld-tts-2`; a request names a `voiceId` or designs a voice in the request [iw-unary] [iw-design].
- **Steering is the directing control.** Natural-language instructions in square brackets, or one request-level `instruction` field. Steering works only on this model. The sister model `inworld-tts-2-flash` ignores instruction tags and the `instruction` field and still plays non-verbal tags such as `[laugh]` [iw-steering].
- **Instructions must be in English**, even when the text to speak is in another language [iw-steering].
- **Delivery mode.** `deliveryMode` takes STABLE, BALANCED (the default) or CREATIVE. It replaces `temperature`, which this model does not accept. STABLE gives predictable speech that matches the input. CREATIVE gives more variation and a wider emotional range [iw-audio].
- **The default delivery is the sample's.** The guide says the model closely reproduces the voice sample, so a calm, flat clone speaks calmly and flatly whatever the text says. A professional clone trains on more audio and keeps a wider expressive range. Steering is for moments where delivery should change [iw-guide].

### Reasoning and effort

None.

### Output: format, length, tone

- **Formats.** See the card. WAV, PCM and LINEAR16 differ in their headers: for HTTP streaming, WAV carries a header in the first chunk only; over the WebSocket, WAV repeats the header at the first chunk of each flush; LINEAR16 carries one in every streamed chunk [iw-audio].
- **Length.** See the card for limits per endpoint. Request limits and billed characters count UTF-16 code units, so many emoji count as two [iw-ws].
- **Tone.** Set by the voice, `deliveryMode`, steering instructions, punctuation and capitalisation [iw-steering] [iw-guide].

### Tools and agents

Not applicable. The Inworld MCP server and CLI expose TTS operations to coding agents; the model has no tool use [iw-intro].

### Coding

Inworld publishes Python and Node.js SDKs, a CLI and an OpenAI-compatible endpoint. The OpenAI SDKs work once the base URL, key, model and voice point at Inworld [iw-release].

### Long context and retrieval

- Long text goes to the async endpoint (preview), which takes up to 100,000 characters in one job, or to streaming requests of up to 4,000 characters [iw-unary].
- The steering rule helps long text. A long input is split internally, and each part inherits the instruction in force [iw-steering].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. A voice clone takes an audio sample. The guide says delivery in the sample sets the clone's default energy, pace and warmth [iw-guide] [iw-clone].

### Voice: turn-taking, interruption and speech style

Inworld Realtime TTS-2 is not a conversation model. It has no turn detection and no barge-in. A client stops its own playback. Inworld's example repository has a guide on barge-in over the WebSocket [iw-ws].

**How to direct delivery.**

- **Syntax.** A bracketed instruction goes before the text it affects [iw-steering]. Example written for this library, not taken from the maker and not run against the model: `[say quietly with a tremor in the voice] I did not think you would come back.`
- **Persistence.** Inworld's rule: an instruction applies from where it appears until another instruction or `[reset]` changes it. A sentence end, a paragraph break, a long input, a `<break/>` pause and a non-verbal tag do not end it [iw-steering].
- **`[reset]`.** Ends the instruction for the rest of the text. It is never spoken. It returns the voice to its own character, not to a flat read. In a run of adjacent tags, the last instruction wins [iw-steering].
- **Request field.** The `instruction` field sets one instruction for the whole request, on the unary and streaming endpoints. An inline tag replaces it from the tag onward, and it does not come back. The WebSocket API has no such field; tags stay in force for text sent later on the same context [iw-steering].
- **Free-form direction.** The guide says a full description of mood, physical manner and intent gives the most precise performance. Its examples are written as director's notes, such as speaking as if barely holding back rage, or slow and hushed with every word weighted by grief [iw-steering].
- **Single-property instructions.** Seven groups: articulation, intonation, volume, pitch, range, speed and vocal style (whisper, sing, nasal quality) [iw-steering].
- **Non-verbal sounds.** `[laugh]`, `[breathe]`, `[clear throat]`, `[sigh]`, `[cough]` and `[yawn]` are the most reliable of a longer list of recognised sounds. A bracket that names a recognised sound makes the sound once. Any other bracket is read as an instruction. `[shout]`, `[scream]`, `[sing]`, `[hum]` and `[mumble]` are instructions and persist [iw-steering].
- **Emphasis.** Capital letters stress a word, and capitals inside a word stress a syllable. Single asterisks around a word also work. Double asterisks are read aloud [iw-steering] [iw-guide].
- **Advice from the maker.** Inworld advises instructions in English, with no capitals or punctuation inside an instruction. It prefers a fuller instruction to one bare word, because a bare tag such as sad gives the model one dimension. It advises against conflicting directions in one tag, and an instruction that matches the text, because a sad instruction on joyful words degrades output. It advises a new instruction only where delivery changes, because tagging every sentence gives less continuity and can make delivery uneven [iw-steering] [iw-guide].
- **Strength and limits.** Inworld gives no figure for adherence. A mismatch between instruction and text, and conflicting instructions, are named failure sources. A tag sent to an older model may be read aloud [iw-steering].
- **For LLM-written text.** In its realtime guide Inworld advises at most one steering tag per turn, placed first, used only when the user's emotional register shifts or a style is requested, with no tag as the default. It lists non-verbal tags the LLM may use and says at most one per turn [iw-natural].

**Voice design and cloning.**

- **Design.** A description (age, gender, accent, tone, pitch, pace, timbre) plus a script gives up to three previews. A structured profile can be edited attribute by attribute (dialect, gender, age, emotion, tone, pitch, volume, speed, clarity, fluency, personality, texture, environment). Ad-hoc design (preview) generates speech from `voiceDesign.designPrompt` without saving a voice. It is not available on the WebSocket or OpenAI-compatible endpoints. The same description does not guarantee the same voice twice [iw-design].
- **Cloning.** Instant clones need as little as 3 seconds of audio. A voice gives the best likeness in the language it was cloned in. Cross-lingual use needs the `language` field and, for the most consistent results, a localised voice [iw-audio] [iw-lang].

**Multi-speaker dialogue and long-form consistency.** The pages read describe no multi-speaker request. Each request or WebSocket context uses one voice. `synthesisContext` carries the text of earlier requests so short phrases are read in context. Inworld advises the last few turns only, because long context can outweigh the text. The model's conditioning on the audio of earlier turns is stated for the Realtime API only [iw-guide] [iw-audio].

**Pronunciation and text normalisation.**

- **Inline IPA.** One word per pair of slashes, standard English IPA symbols only [iw-pron].
- **Verbatim tags.** `<verbatim>` spells a code character by character. It needs text normalisation on, is English-oriented and is most reliable on this model [iw-verbatim].
- **Normalisation.** `applyTextNormalization` is ON, OFF or unset. It expands phone numbers, dates, times, emails, money and symbols, adds slight latency and is language-specific, not locale-specific [iw-guide].
- **Pauses.** SSML `<break time="1s" />`, up to 20 per request, up to 10 seconds each. A break never changes delivery [iw-pause].

**Turn-taking.** Not applicable to a synthesis model. Inworld's Realtime API handles speech-to-speech turns and uses this model for speech [iw-natural].

### Sampling and API parameters

- `deliveryMode`, `talkingSpeed` (0.5 to 1.5), `language`, `applyTextNormalization`, `instruction`, `synthesisContext`, `audioConfig` and timestamp options [iw-audio] [iw-guide] [iw-steering].
- `temperature` is not supported on this model [iw-audio].

### Migrating from the previous generation

From Inworld TTS 1.5 (`inworld-tts-1.5-max` and `-mini`), which Inworld lists as deprecated and not recommended for new projects [iw-models] [iw-release] [iw-audio]:

- Steering is new. Instruction tags on 1.5 may be read aloud.
- `deliveryMode` replaces `temperature`.
- Languages grow from 15 to 200+ in two tiers.
- On 2026-08-06 Inworld changed steering: a tag now persists until changed or `[reset]`, a `<break/>` no longer clears it, and the `instruction` field and `[reset]` were added. Text that relied on an instruction wearing off needs a `[reset]`.
- `inworld-tts-1` and `inworld-tts-1-max` were discontinued on 2026-06-15 and are routed to newer models.
