# Cartesia Sonic 3.6

Cartesia Sonic 3.6 is the current generation of the Cartesia Sonic speech synthesis class. It reads emotion from the transcript by itself and accepts inline emotion tags, `[laughter]` and speed and volume controls. Cartesia made it generally available on 2026-08-27 as an update to Sonic 3.5. It is a tag-directed model with a fixed emotion vocabulary, not an instruction-following model. Family-wide rules are in the [Cartesia README](README.md).

## How to instruct it

### Setting up the prompt

- **The text is the prompt.** There is no system prompt. Cartesia's 3.6 notes say the model follows the transcript faithfully and voices confirmation codes and heteronyms without preprocessing [cart-sonic36].
- **Model ids.** `sonic-3.6` points at the latest stable snapshot. A dated snapshot (`sonic-3.6-2026-08-27`) never changes. `sonic-preview` is a beta model that changes without notice. Cartesia advises a dated snapshot for production and for teams that run their own evaluations before updates [cart-sonic36].
- **Controls.** Emotion, speed and volume go in `generation_config` on each request or as inline tags. `generation_config` is scoped to one request. There is no account-wide setting [cart-emotion].
- **Tags.** The SSML page lists five: `speed`, `volume`, `emotion`, `break` and `spell` [cart-ssml].
- **Prompting for an LLM.** The prompting page gives a starter system prompt for voice agents that tells the LLM to write plain prose with terminal punctuation, normal capitals, spell tags for codes and no markdown [cart-prompting].

### Reasoning and effort

None.

### Output: format, length, tone

- **Formats.** See the card. Only the Bytes endpoint returns wav or mp3. SSE and WebSocket return raw audio [cart-format].
- **Language.** `language` or `locale`, never both. A locale such as `en-GB` sets the language and region. `accent` (multilingual voices only) sets how the voice sounds, apart from locale. `normalization` sets the reading convention for numbers and dates [cart-chlog26].
- **Tone.** Set by the voice, the text and the controls above [cart-emotion].

### Tools and agents

Not applicable. Cartesia offers Managed Agents that run speech-to-text (Ink), an LLM and Sonic. They are a separate product [cart-chlog26].

### Coding

Cartesia publishes client libraries (Python, TypeScript and others), an MCP server and a starter system prompt for coding agents. The pages read give no further coding guidance [cart-prompting].

### Long context and retrieval

Long text is sent as continuations on one context. See the voice section for buffering rules [cart-buffer] [cart-contexts].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. A voice clone takes an audio clip: 10 seconds is enough to start, and up to 60 seconds helps keep the accent on Sonic 3.6 and newer. Files must be 16 MB or smaller [cart-ivc].

### Voice: turn-taking, interruption and speech style

**How to direct delivery.**

- **Default behaviour.** With no control, Sonic reads the emotional subtext of the transcript. Cartesia's 3.6 notes say the model varies pacing and intonation to the emotional context without tags, and that pause length follows the sentence [cart-sonic36].
- **Emotion (beta).** Two routes. The first is the request field `generation_config.emotion`. The second is an inline tag, `<emotion value="angry"/>`, placed before the text it affects. The maker calls both beta and says emotion tags work for English only. The model treats them as push toward more emotion and not as exact settings [cart-emotion] [cart-ssml].
- **Vocabulary.** A fixed list of 58 values. Six are the primary ones with the most training data and the best results: neutral, calm, angry, content, sad and scared. The rest include happy, excited, enthusiastic, triumphant, surprised, curious, sarcastic, ironic, dejected, melancholic, anxious, panicked, proud, confident, skeptical and determined. A value outside the list is unsupported, and the maker gives no guarantee for it [cart-emotion].
- **Matching rule.** The tag only works when the emotion fits the words. The guide's own example of a sad tag on an excited sentence is "unlikely to work well" [cart-emotion].
- **Mid-text shifts.** The SSML page calls emotion control highly experimental, most of all when the emotion changes inside one generation. It advises one generation context per emotion, and voices tagged Emotive in the playground, because other voices may not respond reliably [cart-ssml].
- **Illustration, written for this library and not taken from the maker.** `<emotion value="sad"/> I kept your coat. <emotion value="calm"/> It is in the hall.` This shows the tag syntax with a plausible match of words and emotion. It is not a sample from the guide. It was not run against the model.
- **Speed and volume.** `generation_config.speed` runs from 0.6 to 1.5 and `volume` from 0.5 to 2.0, or the tags `<speed ratio="0.8"/>` and `<volume ratio="1.5"/>`. The maker treats both as guidance and not as strict multipliers. Small changes are hard to hear in short samples. It suggests 0.7 and not 0.9 to hear a slowdown. Professional voice clones take their pacing from the source recordings and do not accept speed changes. When text streams token by token, a decimal value must arrive whole, or the tag is read aloud [cart-emotion] [cart-ssml] [cart-buffer].
- **Non-verbal sound.** `[laughter]` makes the model laugh. The pages read list no other non-verbal tag [cart-emotion].
- **Written disfluencies.** On 3.6 the model gives fillers such as uh, um and hmm a natural thinking pace when they are written in standard form with commas. The maker advises sparing use, because the model never adds them itself [cart-prompting].
- **Pauses.** Punctuation first. A `<break time="500ms"/>` tag gives a fixed silence and splits the generation, so it can sound less natural. Several breaks in a row can cause hallucination [cart-prompting] [cart-ssml].
- **Emphasis.** The prompting page says capital letters change how a word is read, not how loud it sounds, and advises against capitals for emphasis [cart-prompting].

**Voice choice, design and cloning.**

- **Voices.** 500+ built-in voices. Cartesia advises stable, realistic voices for agents and voices tagged Emotive for characters. The emotion guide names eight voices with the best emotional response [cart-voices] [cart-emotion].
- **Instant clone.** Takes the mood of the clip. The guide says a cheerful recording gives a voice that sounds cheerful everywhere, and advises natural speech over announcer-style delivery. Each clone is built from one language; accents add languages [cart-ivc].
- **Professional clone.** Trained on 30+ minutes from one speaker. It keeps rare accents and character voices. A clone made on an older model works on 3.6 [cart-sonic36] [cart-voices].
- **Voice design from a description.** The pages read describe none for Sonic.

**Multi-speaker dialogue and long-form consistency.**

- **One voice per context.** Inputs on a context keep every field the same except the transcript and a few flags. A second speaker needs a second context. Several contexts can run on one connection and cost the same as separate requests [cart-contexts].
- **Continuations.** Continuations keep prosody and voice across chunks. Cartesia advises them for LLM-streamed text. Set `continue` true for each input that a later one follows, and false at the end [cart-prompting] [cart-contexts].
- **Buffering.** `max_buffer_delay_ms` runs from 0 to 5000 and defaults to 3000. A value above 0 gives managed buffering. A value of 0 means the client sends whole sentences. The guide warns against sentence chunks together with the default delay, because the server then waits up to 3 seconds for more text [cart-buffer].

**Pronunciation and normalisation.**

- **Normalisation.** The `normalization` field takes `auto`, `off` or a locale code. The normalizer covers dates, times, phone numbers, currency, units and numbers. Date ranges, fractions and equations are not normalised and need to be written out [cart-norm].
- **Dictionaries.** A pronunciation dictionary replaces words with IPA-like text or a sounds-like respelling. Dictionaries are supported on sonic-3 models and later [cart-pron] [cart-bytes].
- **Spelling.** `<spell>` tags read codes character by character [cart-prompting].
- **Written form.** The guide says conventional written forms and normal capitals give the best pacing, and that heavy pre-processing hurts [cart-prompting].

**Turn-taking.** Not applicable to a synthesis model. Cartesia's separate speech-to-text model Ink and its Managed Agents handle turns [cart-chlog26].

### Sampling and API parameters

- `generation_config` with `speed`, `volume` and `emotion`; `language` or `locale`; `accent`; `normalization`; `pronunciation_dict_id`; `max_buffer_delay_ms`; `context_id` and `continue` on WebSocket; `output_format` [cart-bytes] [cart-chlog26] [cart-buffer].
- The pages read list no temperature or seed.

### Migrating from the previous generation

From Sonic 3.5 [cart-chlog26] [cart-sonic36]:

- The maker says 3.6 is fully backwards compatible. Existing voice IDs, request shape and prompts work. Customers on `sonic-3.5` repoint traffic by hand.
- Changes: two new languages (Odia and Urdu), Hindi in Latin script, in-transcript disfluencies, English heteronyms, and native letter names for spelled codes in all languages.
- Instant clones keep up to 60 seconds of audio on 3.6, against 10 seconds before.
- New optional TTS API fields in the August 2026 changelog: `locale`, `accent` and `normalization`. The same entry adds API version 2026-08-14, which cleans up multilingual voice support and drops deprecated fields.
- The maker reports that listeners preferred 3.6 to 3.5 by nearly two to one on English transcripts. This is a maker result.

## What the system card reports

Cartesia publishes no system card in the pages read. Its terms prohibit cloning a person's voice without consent, including public figures. Zero data retention for agent calls (transcripts, recordings and logs) is offered to Enterprise customers [cart-site] [cart-chlog26].

## Behaviour observed in practice

- **Rank (M).** Artificial Analysis gives a quality Elo of 1278.08 for Sonic 3.6, 1190.35 for Sonic 3.5 and 1060.41 for Sonic 3 [aa-tts-board].
- **Throughput (M).** Median generation speed is about 110 characters a second for Sonic 3.6 and about 119 for Sonic 3.5 in the same data [aa-tts-board].
- No practitioner report was read for 3.6.

## Benchmarks

Independent: Artificial Analysis quality Elo 1278.08 [aa-tts-board]. Maker: nearly two to one listener preference over Sonic 3.5 on English transcripts, with no sample size given [cart-chlog26].
