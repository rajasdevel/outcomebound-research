# MiniMax M3

MiniMax M3 is the current generation of MiniMax's M class (generation 3), released on 2026-06-01. It is a native
multimodal mixture-of-experts model (about 428B parameters, 23B active) that takes text, image and video, runs to 1M
tokens of context through a sparse-attention design, and is aimed at coding, long-running agent work and multimodal
tasks. Its weights are open under a community licence that grants non-commercial use and attaches conditions to
commercial use (an attribution notice, and MiniMax's written authorization above US$20 million in yearly revenue). It
replaced
[MiniMax M2.7](MiniMax-M2.7.md), whose thinking could not be switched off; M3's can. Rules that hold across MiniMax
models are in the [MiniMax README](README.md); this file says what is specific to M3.

## How to instruct it

MiniMax publishes no prompting guide for M3. What it does publish is an agent post (written for M2), a tool-use guide
for M3, API references and a launch post; the [README](README.md#prompting-guides) summarises them. This file adds
what is specific to M3 and labels each claim as what MiniMax says (L), what was measured (M) or an observation (A).

### Setting up the prompt

- **System prompt and role.** The `system` field works on both protocols. MiniMax names no default system prompt for
  M3 (its M2.7 card names one) and gives no role-prompt advice. Recommended sampling is temperature 1.0 and top_p 0.95
  (L). [minimax-m3-hf-readme, minimax-anthropic-api]
- **Scaffold-independent prompts.** For M2, MiniMax says it trained across variations of tools, system prompt, user
  prompt, environment and tool output so behaviour holds in unfamiliar scaffolds (L); it makes the same kind of claim for
  M3 only through its benchmarks, most of which ran in Claude Code. [minimax-agent-generalization, minimax-m3-blog]
- **Collaboration style.** MiniMax trained and evaluated M3 against an interactive user simulator (requirement
  elaboration, solution discussion, correction, task switching) so that the model collaborates instead of only executing
  (L). MiniMax publishes no measurement of how often M3 asks a clarifying question. [minimax-m3-blog]
- **Structure, examples, long-document placement.** MiniMax gives no preference between XML tags and Markdown, no few-shot
  guidance, and no placement advice. The one placement rule it states is for caching: the cache matches prefixes in the
  order tool list, system prompt, user messages, so static or repeated content goes first and per-user dynamic content
  last. [minimax-prompt-caching]
- **Instruction files.** MiniMax's M2.1 post claimed support for Claude.md, agent.md, cursor rules, Skill.md and slash
  commands; no such statement was found for M3. [minimax-m21-news]

### Reasoning and effort

- **The control is a toggle, not a level.** `thinking` takes `adaptive` or `disabled`; the Hugging Face card names three
  modes: enabled (always reason), adaptive (the model decides when more reasoning helps) and disabled (minimum latency).
  M3 has no effort field: on the Responses endpoint setting an effort turns thinking on without tuning depth (L).
  [minimax-m3-hf-readme, minimax-responses-ref]
- **The default depends on the endpoint.** Omit `thinking` and M3 does not think on the Anthropic-compatible and Responses
  endpoints, and does think (adaptive) on the OpenAI Chat Completions endpoint (L). Send `{"type": "adaptive"}` to be
  explicit. [minimax-anthropic-api, minimax-openai-api]
- **What MiniMax says each mode is for.** Thinking on for complex reasoning, agent tasks and long-horizon collaboration;
  off for latency-sensitive uses such as conversation and code completion; both modes cost the same (L).
  [minimax-m3-blog]
- **Continuity.** M3 uses interleaved thinking: it reasons before each tool call. The key rule in MiniMax's tool guide is
  to return the whole assistant message every turn, thinking included, or the chain of reasoning breaks. [minimax-m3-function-call]
- **Budgets.** Thinking tokens count toward `max_tokens`; a limit that is too small returns no text. The recommended
  `max_completion_tokens` is 131072 and the maximum 524288. [minimax-chat-openai-ref]
- **Prompts that ask for reasoning.** MiniMax does not address adding "think step by step" to M3; the toggle is its
  documented control.
- **Independent view.** Artificial Analysis lists M3 as a reasoning model but does not state which mode it ran. [aa-minimax-m3]

### Output: format, length, tone

MiniMax documents no verbosity, formatting or tone control for M3, and no prefill. `stop_sequences` is ignored on the
Anthropic-compatible endpoint. On the OpenAI endpoint thinking arrives inside `content` in `<think>` tags unless
`reasoning_split` is true; with it, thinking comes back separately. Artificial Analysis's index run used about 117M output
tokens, against about 209M for GLM-5.3 at max on the same index (M). [minimax-anthropic-api,
minimax-openai-api, aa-minimax-m3, aa-glm-5-3]

### Tools and agents

- **Definitions and choice.** `tools` and `tool_choice` are supported on both protocols; function calls come back as
  `tool_use` blocks or `tool_calls`. MiniMax states no tool-count limit and no parallel-call rule. [minimax-anthropic-api,
  minimax-m3-function-call]
- **Persistence and long-horizon work.** MiniMax reports M3 running about 12 hours on a paper reproduction (18 commits,
  23 figures), about 24 hours on a Hopper FP8 kernel task (147 benchmark submissions and 1,959 tool calls, utilisation
  from 7.6% to 71.3%, a 9.4 times speed-up) and 12 hours on PostTrainBench (0.37); it says most other models stopped
  improving within 30 submissions while M3's best came at submission 145 (L, MiniMax's own runs and wording).
  [minimax-m3-blog]
- **Computer use and harness.** M3 can operate a desktop; OSWorld-Verified 70.06% at 200 steps (68.70% at 100) in the launch post's method note, with
  relative 0-to-1000 coordinates on 1920 by 1080 screenshots, and 75.2 in the Hugging Face card's benchmark image; MiniMax does not reconcile the two (L). MiniMax Code, MiniMax's own agent, is built on OpenCode and
  Pi and adds an agent-team mode with a producer-and-verifier loop (L). [minimax-m3-blog]
- **Context management.** Return all blocks; use the caching rules; for the successor model MiniMax recommends compacting at
  512K for everyday work (see the [README](README.md#prompting-guides)). The Anthropic endpoint ignores `context_management`
  and `mcp_servers`. [minimax-anthropic-api]

### Coding

- **Measured by MiniMax (all in its own harnesses, thinking mode not stated).** SWE-Bench Verified 80.5 (Claude Code, mean of
  4 runs); SWE-Bench Pro 59.0, published before Scale's V2 split (Claude Code, aligned with the official logic); Terminal-Bench 2.1 66.0 (Terminus 2, 8 CPU and 16 GB sandbox, 2 h
  timeout, 128K output); SWE-fficiency 34.8; KernelBench Hard 28.8; MCP Atlas 74.2 (L). MiniMax overrode the default
  system prompt for SWE-Bench Verified runs, and added anti-cheating monitoring to NL2Repo. [minimax-m3-blog]
- **Measured independently.** Artificial Analysis: Terminal-Bench 2.1 65.2 (agreeing with MiniMax's 66.0) but
  Terminal-Bench 4.0 only 2.0; the newer benchmark nearly defeats M3, as it did M2.7 (0.0) (M). M3 has no row on Scale's
  SWE-Bench Pro V2 page, the tbench.ai board, Artificial Analysis's Coding Agent Index or METR's page. [aa-minimax-m3,
  scale-swe-pro-v2, tbench-4]
- **Special-casing.** No MiniMax or independent finding on test special-casing or reward hacking was found.

### Long context and retrieval

- **Limits.** 1M tokens of context; MiniMax's M3 page says the API guarantees at least 512K. OpenRouter lists 1,048,576
  tokens of context and 512,000 of output. MiniMax's reference allows output up to 524,288 tokens (131,072 recommended). Above 512K input tokens the price doubles (US$0.60 in, US$2.40 out, US$0.12 cached). [minimax-m3-page,
  minimax-pricing, openrouter-models]
- **Design.** MiniMax Sparse Attention cuts per-token compute at 1M tokens to a twentieth of the previous generation's, with
  prefill more than 9 times and decoding more than 15 times faster (L, vendor figures). [minimax-m3-blog]
- **Quality at length.** Artificial Analysis's AA-LCR (long-context reasoning) is 83.0%, against 80.0% or less for the other
  Z.ai and MiniMax models in this library (M). MiniMax's own LOCA-Bench run at 256K scored 49.3 (L). [aa-minimax-m3,
  minimax-m3-hf-readme]
- **Caching.** Automatic for requests of at least 512 tokens, or explicit with `cache_control` on the Anthropic endpoint; cached
  input US$0.06 per million tokens. [minimax-prompt-caching, minimax-explicit-cache]

### Structured output

No JSON mode, response-format field or strict-tool setting appears in the references MiniMax publishes for M3, and the
parameters it lists as ignored do not cover one. Function-calling schemas (`input_schema` or `parameters`) are the
documented route to structured arguments. OpenRouter's parameter list shows `response_format` and `structured_outputs`
for M3, which describes that host, not MiniMax's API (A). [minimax-anthropic-api, minimax-chat-openai-ref, openrouter-models]

### Images, audio, other inputs

Image and video input, text output. Images: JPEG, PNG, GIF, WEBP up to 10 MB; video: MP4, AVI, MOV, MKV up to 50 MB inline or
512 MB through the Files API; frame rate 0.2 to 5 per second; body up to 64 MB; `detail` low, default or high. Audio input is
unsupported. MiniMax's evaluation notes: Video-MME 84.6 at 512 frames (1 frame a second), OmniDocBench with long edge up to 3584
pixels, MMMU-Pro on the final-line format (Artificial Analysis: 78.6). [minimax-anthropic-api, minimax-openai-api,
minimax-m3-blog, aa-minimax-m3]

### Sampling and API parameters

Temperature 0 to 2, recommended 1.0; top_p default 0.95; `top_k` and `stop_sequences` ignored on the Anthropic endpoint;
penalties and `logit_bias` ignored on the OpenAI endpoint; `n` is 1; `service_tier: priority` costs 1.5 times. MiniMax's video
evaluations used temperature 1.0 and top_p 0.95. [minimax-anthropic-api, minimax-openai-api, minimax-m3-blog]

### Migrating from the previous generation

From M2.7:

- **Thinking is no longer always on.** On the Anthropic endpoint a request that omits `thinking` now runs without
  reasoning; a prompt tuned on M2.7 that relied on thinking needs `thinking: {"type": "adaptive"}`. On the OpenAI endpoint
  the default is on. [minimax-anthropic-api, minimax-openai-api]
- **New inputs and size.** Image and video input; 1M context against 204,800; maximum output 524,288 against a 204,800 bound.
- **API limits.** 200 requests and 10M tokens a minute, against 500 and 20M for M2.7. top_p default 0.95 against 0.9. [minimax-rate-limits]
- **Price.** The same US$0.30 in and US$1.20 out up to 512K input tokens; M3 shows a "permanent 50% off" label on its list
  price and doubles above 512K. [minimax-pricing]
- **Licence.** M2.7's weights carry a non-commercial licence; M3's allow commercial use with a "Built with MiniMax M3" notice
  and a one-time notice to MiniMax, or written authorization above US$20 million in yearly revenue. [minimax-license]
- **Results.** Artificial Analysis: Intelligence Index 22.8 to 29.2, Terminal-Bench 4.0 0.0 to 2.0, IFBench 75.7 to 82.9, AA-LCR
  78.3 to 83.0, hallucination rate 35.6% to 18.4% (M). [aa-minimax-m2-7, aa-minimax-m3]
- **Advice about removing old prompt text.** None is published.

## Behaviour observed in practice

- **Independent run (M, Artificial Analysis).** Intelligence Index 29.2; AA-Omniscience hallucination rate 18.4% with 16.7%
  accuracy; IFBench 82.9; GPQA Diamond 92.9; Humanity's Last Exam 39.0; SciCode 47.1; CritPt 3.7; US$0.30 in and US$1.20 out;
  about US$538 to run the whole index (about US$0.51 a task), about 665 seconds a task, about 75 output tokens a second
  and 2.2 seconds to the first token. [aa-minimax-m3]
- **Token use (A, reported AA figures on an older index version).** A June 2026 practitioner post gave about 24k output tokens a
  task for M3 against 43k for GLM-5.2 (earlier version, so not comparable with today's numbers). [willison-glm52]
- **Self-hosting maturity (L).** MiniMax labels its own SGLang recipe experimental, on a development image, and says the weights
  must be held in full (about 444 GB as MXFP8). [minimax-m3-local-deploy]
- **Benchmark versions disagree.** MiniMax's Terminal-Bench 2.1 score (66.0) and Artificial Analysis's Terminal-Bench 4.0 score (2.0)
  differ widely; no reliability data for thinking-off runs was found.

## Open questions

- Which thinking mode MiniMax's and Artificial Analysis's M3 numbers were run in.
- Whether M3 follows policy files and long instruction sets as it follows short ones: no instruction-following benchmark of M3 by
  a third party was found.
- Test special-casing, refusal and prompt-injection behaviour: unmeasured in public.
- Whether the endpoint-dependent thinking default is deliberate.
- Whether the "guaranteed minimum of 512K" tokens means the API serves less than 1M under load.
