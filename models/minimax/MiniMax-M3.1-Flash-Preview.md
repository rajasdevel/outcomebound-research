# MiniMax M3.1 Flash Preview

MiniMax M3.1 Flash Preview is a preview language model in MiniMax's M family (class MiniMax M Flash, generation 3.1), which
press pages date to 2026-09-27. MiniMax's docs call it the latest M-series model for agentic reasoning, tool use, coding and
long-context work, with a 1M-token context, image and video input, and a thinking depth set by an effort field; thinking
cannot be turned off. It is offered only through the M Plan subscription and MiniMax Code, not as pay-as-you-go API, and
MiniMax publishes no benchmark, price, weights or model card for it. It follows [MiniMax M3](MiniMax-M3.md), whose thinking
can be switched off. Rules that hold across MiniMax models are in the [MiniMax README](README.md); this file says what is
specific to this model.

## How to instruct it

MiniMax publishes no prompting guide for this model. What exists: the text-generation page (thinking depth), the API
references, a product page built from a preview guide that MiniMax says it supplied, and tool-setup pages for Claude Code and
Codex. Labels: L is what MiniMax says, M a measurement, A a press or third-party observation.

### Setting up the prompt

- **What the product page says to supply.** For coding, the repository, reproduction steps and acceptance criteria; for research,
  source data and dates; for visual analysis, the original images or video. It adds that case outcomes are examples, not
  guarantees (L). [minimax-m31-page]
- **Four documented cases.** Performance diagnosis of a web app using browser profiling and flame charts, with data preserved and a
  before-and-after report (one documented case with three runs on 8,000 records); three-statement and DCF financial workbooks that
  separate historical data, assumptions and formula-driven estimates; image-difference analysis; an interactive fluid simulation
  (L). [minimax-m31-page]
- **Sampling and system prompt.** Temperature 0 to 2 (1 recommended) and top_p 0.95 by default, as for M3; MiniMax names no system
  prompt. Structure, examples and long-document placement: no guidance. [minimax-anthropic-api, minimax-openai-api]

### Reasoning and effort

- **The control.** `effort` takes `low`, `medium`, `high`, `xhigh` or `max`; omitted, it defaults to `max`. The field is
  `output_config.effort` on the Anthropic-compatible endpoint, `reasoning_effort` on Chat Completions and `reasoning.effort` on
  Responses. Higher levels think more thoroughly and use more output tokens at higher latency (L). [minimax-text-generation]
- **Thinking cannot be disabled.** `thinking: {"type": "disabled"}` or an effort of `none` returns HTTP 400 ("requires adaptive
  thinking", error 2013); MiniMax's advice for cutting latency and tokens is a lower effort. The page for the model recommends `max` as the default and
  asks callers to set effort explicitly (L). [minimax-text-generation, minimax-anthropic-api, minimax-m31-page]
- **What each level is for.** MiniMax states no per-level guidance and publishes no measurement of the levels, and none exists
  from Artificial Analysis. A MiniMax comparison of context windows (below) is the only effort-adjacent data.
- **Visibility.** Thinking comes back as a `thinking` block (Anthropic), in `reasoning_content` (Chat Completions) or as a reasoning
  item (Responses). The product page says to read `reasoning_content` only when present, because it can be absent, and to update
  integrations that relied on `reasoning_details` or inline `<think>` text. MiniMax asks for thinking blocks to be returned
  unchanged in later turns. [minimax-m31-page,
  minimax-openai-api, minimax-m3-tool-guide]
- **Budgets.** Thinking tokens count toward `max_tokens`; MiniMax notes that a limit too small for reasoning and answer can end
  the reply with no text.
  [minimax-text-generation]

### Output: format, length, tone

No verbosity, formatting or prefill controls are documented. `stop_sequences` is ignored on the Anthropic-compatible endpoint. The
product page quotes about 150 output tokens a second and says actual speed depends on load and lengths; it is not an end-to-end
latency guarantee (L). [minimax-anthropic-api, minimax-m31-page]

### Tools and agents

Tools and tool choice follow the family rules (MiniMax asks for the whole assistant message to be returned each turn; see
the [README](README.md#prompting-guides)). The M Plan bundles two MCP tools, `web_search` and `understand_image`, and works with MiniMax
Code and with Claude Code, Codex, Cursor, OpenCode, Hermes Agent and OpenClaw through a Subscription Key. MiniMax's Codex and Claude
Code pages set the client's auto-compaction window to 512K (524,288 tokens) and say 1M is for tasks that must keep extensive code or
documents in context. The model catalog in MiniMax's Codex guide marks the model as supporting parallel tool calls and lists
text and image input; no tool-count limit is stated. [minimax-m-plan, minimax-llms-txt, minimax-m-plan-codex,
minimax-m-plan-claude-code]

### Coding

MiniMax publishes no benchmark for the model. Its case descriptions stress evidence from tests and measurements over plausible
code. Press pages note that MiniMax released no benchmark, price or model card at launch. No result exists on Scale, tbench.ai,
Artificial Analysis or METR. [minimax-m31-page, datanorth-m31, startupfortune-m31]

### Long context and retrieval

1M tokens of context. MiniMax compares a 512K and a 1M client window on ProgramBench (200 tasks): similar average performance, 111.42M
against 136.76M total tokens a task (18.5% fewer), and about 19.9% lower estimated cost at 512K (L, MiniMax's own run, effort not
stated). Prompt caching is listed as supported; the family caching rules apply. [minimax-m-plan-codex, minimax-m31-page]

### Structured output

No JSON mode or strict-tool setting is documented, as for the rest of the family. [minimax-chat-openai-ref]

### Images, audio, other inputs

Text, image and video input; text output; no native image or video output. Limits follow the family table (images up to 10 MB, video
up to 50 MB inline or 512 MB through the Files API). The product page says image and video work in a tool-enabled environment uses code
and image-processing tools for tasks such as finding image differences, structuring charts and analysing video shots. [minimax-anthropic-api,
minimax-m31-page]

### Sampling and API parameters

As for M3: temperature 0 to 2, top_p 0.95, `top_k` and `stop_sequences` ignored on the Anthropic endpoint, penalties ignored on the OpenAI
endpoint, `service_tier` available. `reasoning_split: false` is not supported (thinking is always returned separately). [minimax-anthropic-api,
minimax-openai-api]

### Migrating from the previous generation

From M3 (the product page's comparison): reasoning is always on instead of optional; effort levels exist where M3 has none; the reasoning
text arrives in a separate field that may be missing, where M3 may return it inline in `<think>` tags depending on configuration;
the context window (1M), the inputs (text, image, video) and caching match. Steps MiniMax lists: remove any `thinking.type=disabled` or
`effort=none` (both return an error), review the effort setting, update parsers that expect `reasoning_details` or inline `<think>` text,
keep thinking blocks, and reserve output budget. MiniMax also says to confirm current API behaviour before changing a production
integration. Access changes too: M3 is pay-as-you-go; this model is M Plan only for now. [minimax-m31-page, minimax-text-generation]

## What the system card reports

MiniMax publishes no model card, system card or safety report for this model. Press pages say the launch carried no benchmark, price or
technical documentation. The product page states architecture figures from its supplied guide (428B total and about 23B active
parameters, sparse attention, a native visual encoder), which are the same totals as M3's but are not on an API reference or model card.
Nothing is published on refusals, over-refusal, sycophancy, deception, reward hacking, prompt injection, agentic safety or cyber and biology
evaluations. [datanorth-m31, startupfortune-m31, minimax-m31-page]

## Behaviour observed in practice

No independent or practitioner evaluation was found. Press pages say a model appearing under another name on OpenRouter at zero price
before launch was fingerprinted by developers as the same model; MiniMax does not confirm that (A). Its own docs say the model is offered
only through M Plan and MiniMax Code, so outside harnesses use a Subscription Key in tools such as Claude Code. [startupfortune-m31,
minimax-m-plan]

## Benchmarks

None. Not on Scale's SWE-Bench Pro V2 page, the tbench.ai Terminal-Bench 4.0 board, Artificial Analysis (no page; 404 on 2026-10-03) or METR's
page, and MiniMax publishes no scores. The only quantitative statement from MiniMax is the ProgramBench window comparison under Long
context. [scale-swe-pro-v2, tbench-4, aa-coding-agent, metr-time-horizons]

## Open questions

- Benchmarks, a price and a model card, and whether MiniMax will release weights.
- What each effort level buys; whether `max` as the default is the right setting for cost.
- Whether the preview becomes the 3.1 generation of the M class or stays a separate Flash line.
- Whether a pay-as-you-go API will follow, and at what price.
- Release date: only press pages give it.
