# Grok Voice Think Fast 2.0

Grok Voice Think Fast 2.0 is SpaceXAI's speech-to-speech model. It takes audio or text and gives back speech and text over a WebSocket Realtime API that follows the shape of the OpenAI Realtime API. The announcement is dated 2026-07-29. The alias `grok-voice-latest` moved to it on 2026-08-05. It replaced Grok Voice Think Fast 1.0 (announced 2026-04-23), which the docs no longer list as a choice. The model reasons while it speaks. Family-wide rules for the maker are in the [xAI README](README.md) [xai-announce-2] [xai-release-notes] [xai-s2s].

## How to instruct it

### Setting up the prompt

`instructions` on `session.update` is the system prompt. xAI's prompting guide says it controls what the agent says and not how the voice sounds. It advises leaving out rules about audio quality, phonetic pronunciation, speaking rate, background sounds or emotion switching in the voice, or rewriting them as rules about the words the agent writes [xai-s2s-prompting].

The guide gives one recommended shape: second person ("You are...") in Markdown, with these `##` sections in this order [xai-s2s-prompting]:

1. Role & Persona
2. Objective
3. Conversation Flow
4. Guardrails & Escalation
5. Voice & Communication Style

A section named `## CRITICAL INSTRUCTIONS` may follow for hard rules, in capitals with `ALWAYS` and `NEVER`. The guide says the model treats it as top priority, so it must stay short. Other advice in the guide:

- Short bullets are preferred to long paragraphs. Examples help, because the model follows sample phrases closely.
- Only tools that exist in the tool list are to be named. A mismatch gives bad replies.
- Business facts go in the prompt word for word, with the full website address. The agent is told to answer only from approved facts and to say it does not know otherwise.
- The first spoken line has its own field and is not part of the prompt.
- An explicit rule pins the language if it drifts. A variety rule is the fix if replies repeat.
- Rules such as escalation are written as plain English, not as symbols.
- The guide pairs a transfer tool with the exact line to say while it runs, and says whether a tool needs confirmation first.

For 2.0, xAI says to write a much shorter prompt than for earlier models. It suggests asking Grok to generalise an existing prompt, and to remove the workaround rules that were added to patch older models [xai-s2s].

### Reasoning and effort

`reasoning.effort` takes `high` (default) or `none`. High effort is for multi-step instructions, nuanced tone and unclear questions. `none` turns reasoning off [xai-s2s]. The model reasons in parallel with speech, and xAI says it uses fewer reasoning tokens than 1.0, so tool calls start earlier, often before the end of the first sentence [xai-announce-2].

### Output: format, length, tone

The guide's sample style section asks for spoken words only (no Markdown, lists, emoji or stage directions), one or two short sentences per turn unless the caller wants more, a calm tone, and a short check-in question when the caller is silent or has interrupted. It also gives these rules [xai-s2s-prompting]:

- The guide's rule for numbers and codes is to read them one character at a time, separated by hyphens (for example 4-1-5-5-5-1-2-3-4), to repeat the exact sequence, and then to ask for confirmation.
- When the input is empty, garbled or cut off, ask a short question and do not guess.

`audio.output.speed` runs from 0.7 to 1.5 (default 1.0). `replace` maps a phrase to a spoken substitute before synthesis. It changes the audio and not the transcript [xai-s2s]. A per-response `instructions` field on `response.create` overrides the session prompt for one reply [xai-s2s].

### Tools and agents

Tool types are `file_search`, `web_search`, `x_search`, `mcp` and `function`. Parallel tool calls are supported. xAI's guide advises a short preamble before each tool call ("I'm checking that now") to hide latency. It says to call read-only tools without asking and to confirm before changes such as refunds or bookings [xai-s2s] [xai-s2s-prompting].

One practical rule: when a tool is called during speech, the server sends all the audio first and the function call with `response.done`. If the client sends the result and `response.create` at once, the next reply starts while the old audio still plays. The guide advises to send the result, wait until the audio of the turn has finished playing, and then send `response.create`, with a visual thinking cue meanwhile [xai-s2s].

A stronger text model can act as the thinker. The guide's "rephrase supervisor" pattern tells the realtime model to open with a short remark, give the gist in two sentences or fewer, and format numbers and dates for speech [xai-s2s-prompting].

### Coding

xAI gives no coding guidance for this model.

### Long context and retrieval

The pages state no context size. By default a connection loses its history when the socket closes. With `resumption.enabled` set to true the server caches the turns under a conversation id. A reconnect with `?conversation_id=` replays them [xai-s2s].

### Structured output

xAI documents no structured-output setting for the voice model.

### Images, audio, other inputs

Input is audio or text. Codecs are PCM (8000 to 48000 Hz), G.711 mu-law and A-law, and Opus. Audio can travel as base64 JSON or as raw binary frames [xai-s2s]. `audio.input.transcription.language_hint` biases transcription to a language (for Spanish and Portuguese a regional code is required). `keyterms` takes up to 100 terms of at most 50 characters for names and jargon. Both can change mid-session [xai-s2s].

### Voice: turn-taking, interruption and speech style

**Turn detection.** `turn_detection.type` is `server_vad` or `null`. With `server_vad` the server finds the end of the user turn and replies. With `null` the client sends text turns, or commits and clears the audio buffer itself. `idle_timeout_ms` makes the server speak first when the user stays silent for that time after a reply. The timer re-arms after each reply and fires again and again until the user speaks. xAI documents no VAD threshold or silence setting for this model [xai-s2s] [xai-rest-voice].

**Interruption.** In VAD mode, barge-in is automatic. xAI's list of best practices says to enable `server_vad` for natural barge-in. In manual mode, `response.cancel` stops a reply. `conversation.item.truncate` cuts an assistant audio item at a given time so the transcript matches what the user heard. A scripted `force_message` line (for example a recording notice) can be marked `interruptible: false`. The server then drops caller audio until it finishes [xai-s2s] [xai-rest-voice].

**Latency habits.** The best-practice list says to open the WebSocket and start the microphone at the same time and to buffer the early audio. It says not to wait for the socket to open. It advises chunks of about 100 ms. It advises 24 kHz PCM both ways to avoid resampling. It advises to play audio deltas as they arrive. It advises to reconnect with exponential back-off while audio keeps buffering [xai-s2s].

**Voices.** The built-in voices share one roster with text-to-speech. The default is `eve`. All voices can speak every supported language. A custom voice, cloned from a short clip, works like a built-in one [xai-s2s] [xai-tts].

**Delivery.** For browsers and phones, mint a short-lived client secret on the server (`POST /v1/realtime/client_secrets`, at most 3,600 seconds, default 600) so the API key stays off the client. SIP routing connects phone calls to a session and adds DTMF events, which direct WebSocket sessions do not emit [xai-rest-voice] [xai-sip].

### Sampling and API parameters

None of the session parameters is a sampling control. xAI documents `instructions`, `reasoning.effort`, `voice`, `tools`, `turn_detection`, `resumption`, audio settings, `audio.output.speed`, transcription hints and `replace` [xai-s2s].

### Migrating from the previous generation

xAI's announcement says 2.0 improves reasoning, transcription accuracy and conversation over 1.0. It reports a time to first audio of 0.70 seconds against 1.25 seconds and about 0.4 times the reasoning tokens. It says reinforcement learning made the model speak in shorter sentences, ask one question at a time and avoid filler [xai-announce-2]. Independent figures agree with the direction. Artificial Analysis measured conversational dynamics at 95.1% for 2.0 and 77.8% for 1.0. Its interruption-handling part moved from 21.5% to 97.0%, and its turn-taking part from 95.0% to 90.8% [aa-s2s]. The docs advise pinning a versioned name in production, because `grok-voice-latest` follows the newest model. The docs also say that prompt fixes needed for GPT models are not needed, and that rules added only to patch the previous model can go [xai-s2s].

The API follows the OpenAI Realtime API. The base URL and key are the main changes. Differences: the transcription event is `conversation.item.input_audio_transcription.updated` and carries the cumulative transcript, `conversation.item.retrieve` is not supported, and `output_audio_buffer` events exist for WebRTC and SIP only. SpaceXAI adds `force_message`, `resumption` and `replace` [xai-s2s].

## What the system card reports

xAI has published no model card for the voice models in the sources read. The announcement says nothing about safety tests. The prompting guide makes a safety path mandatory for agents that may meet a person in crisis: respond with empathy, point to emergency services or a crisis line, and transfer to a human [xai-s2s-prompting].

## Behaviour observed in practice

Artificial Analysis measured the model on its Speech to Speech page (read 2026-10-03), listed as Grok Voice Think Fast 2.0 High [aa-s2s]:

- Speech reasoning (Big Bench Audio): 97.2%.
- Conversational dynamics: 95.1%. The parts are pause handling 97.8, turn-taking 90.8, interruption handling 97.0 and backchannel handling 94.9.
- Agentic performance (tau-Voice): 56.5%. The parts are airline 56.0, retail 49.7 and telecom 63.7.
- Time to first audio: 0.70 seconds on average.
- Arena preference Elo: 1011. Task success rate: 94.6%, as the page labels it.

The announcement quotes an Artificial Analysis index of 82.9. The page read on 2026-10-03 shows 81.3 in its table and 82.9 in its embedded data, so this file records no index value [xai-announce-2] [aa-s2s]. No practitioner report was found.
