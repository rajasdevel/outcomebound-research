# Grok Voice 3.0

Grok Voice 3.0 (`grok-voice-3.0`) is SpaceXAI's current speech-to-speech model, generation 3.0 of the Grok Voice class. It takes audio or text and gives back speech and text over the same WebSocket Realtime API as the model before it, which follows the shape of the OpenAI Realtime API. The release notes and the announcement date it 2026-10-14. On that day the alias `grok-voice-latest` moved to it and [Grok Voice 2.0](grok-voice-think-fast-2.0.md) became deprecated. xAI says the endpoint, session parameters, events and price did not change. Family-wide rules are in the [xAI README](README.md) [xai-release-notes] [xai-s2s] [xai-announce-3].

## How to instruct it

### Setting up the prompt

`instructions` on `session.update` is the system prompt. xAI's prompting guide says it controls the words the agent says, not the sound of the voice. Rules about audio quality, phonetic pronunciation, speaking rate, background sound or emotion changes in the voice are to be left out, or rewritten as rules about the words [xai-s2s-prompting].

The guide recommends one shape and says that prompts in this shape stay closest to the training distribution. Write in the second person ("You are..."), in Markdown, with these `##` sections in this order: Role & Persona, Objective, Conversation Flow, Guardrails & Escalation, and Voice & Communication Style. A `## CRITICAL INSTRUCTIONS` section can follow for hard rules. The model treats it as the highest priority, so it must stay short [xai-s2s-prompting]. Other points from the guide:

- Prefer short bullets to long paragraphs. Give sample phrases, because the model follows them closely. Small changes of wording can change behaviour a lot.
- Name only the tools that are in the tool list. A mismatch gives bad replies.
- Put business facts and the full website address into the prompt word for word. Tell the agent to answer only from approved facts and to say that it does not know otherwise.
- The first spoken line is a separate field. Do not script it in Conversation Flow.
- Write rules as plain English, not as symbols. Capitals (`ALWAYS`, `NEVER`, `EVERY`) give emphasis.

For 3.0, the guide's migration section says the model is "significantly more capable", so the prompt should be much shorter. It suggests asking Grok to generalise an existing prompt, and removing rules that were added only to patch the previous model or GPT models [xai-s2s].

### Reasoning and effort

`reasoning.effort` takes `high` (the default) or `none`. The guide says `high` is for multi-step instructions, nuanced tone and unclear questions. `none` turns reasoning off [xai-s2s]. xAI publishes no figure for the reasoning tokens of 3.0.

### Output: format, length, tone

The guide's sample style section asks for short, natural sentences and a calm tone. Its rule for numbers and codes is to say each character apart, with hyphens, to repeat the exact sequence and then to ask for confirmation. When the input is empty, garbled or cut off, the agent asks a short question and does not guess. If replies repeat, the guide adds a variety rule. If the language drifts, it adds a language lock [xai-s2s-prompting].

`audio.output.speed` runs from 0.7 to 1.5 (default 1.0). `replace` maps a phrase to a spoken substitute before synthesis. It changes the audio and not the transcript. Matching ignores case, needs whole words, and the longest match wins. An `instructions` field on `response.create` overrides the session prompt for one reply [xai-s2s].

### Tools and agents

Tool types are `file_search`, `web_search`, `x_search`, `mcp` and `function`. The server runs web search, X search, collections search and MCP tools itself. The client runs function tools. When the model makes several function calls, send every result and then one `response.create`. A `response.create` sent early makes the model answer without all the results [xai-s2s].

When a tool is called during speech, the server sends all the audio first and the function call with `response.done`. The guide says to send the result, wait until the audio of the turn has played, and then send `response.create`. Otherwise the next reply overlaps the old audio [xai-s2s].

The prompting guide advises a short spoken preamble before a tool call ("I'm checking that now") to hide latency. It says to call read-only tools without asking and to confirm before a tool that changes something, such as a refund or a booking. For a stronger text model that acts as the thinker, its "rephrase supervisor" pattern keeps the spoken reply to two sentences or fewer [xai-s2s-prompting].

### Coding

xAI gives no coding guidance for this model.

### Long context and retrieval

The pages state no context size. By default a connection loses its history when the socket closes. With `resumption.enabled` set to true, the server caches the turns under a conversation id, and a reconnect with `?conversation_id=` replays them. Both connections must opt in. The cache is dropped after 30 minutes of inactivity [xai-s2s].

### Structured output

xAI documents no structured-output setting for the voice model.

### Images, audio, other inputs

Input is audio or text. Codecs are PCM (8000 to 48000 Hz, default 24000), G.711 mu-law and A-law at 8000 Hz, and Opus at 24000 Hz. Audio can travel as base64 JSON or as raw binary frames. `audio.input.transcription.language_hint` biases transcription to one language (Spanish and Portuguese need a regional code), and `audio.input.transcription.keyterms` takes up to 100 terms of at most 50 characters. Both can change during a session [xai-s2s].

### Voice: turn-taking, interruption and speech style

**Turn detection.** `turn_detection.type` is `server_vad` or `null`. With `server_vad`, the server finds the end of the user turn and replies. With `null`, the client commits and clears the audio buffer itself. `idle_timeout_ms` makes the server speak when the user stays silent for that time after a reply. The timer starts again after each reply [xai-s2s].

**Interruption.** In VAD mode, barge-in is automatic, and the best-practice list says to enable `server_vad` for natural barge-in. A scripted `force_message` line, such as a recording notice, is spoken word for word with no model involved. When it is marked `interruptible: false`, the server drops caller audio until its playback ends [xai-s2s].

**Latency habits.** The guide says to open the WebSocket and start the microphone at the same time, and to buffer the early audio. It advises chunks of about 100 ms, 24 kHz PCM both ways, playback of each audio delta as it arrives, and reconnection with exponential back-off [xai-s2s].

**Voices.** One voice roster serves speech-to-speech and text-to-speech. The default is `eve`. A custom voice cloned from a short clip works as a built-in voice does [xai-s2s].

**Speech style.** The prompt shapes the words, not the sound (see above). For phone calls, SIP routing connects a call to a session [xai-s2s].

### Sampling and API parameters

None of the session parameters is a sampling control. The session takes `instructions`, `reasoning.effort`, `voice`, `tools`, `turn_detection`, `resumption`, the audio settings, `audio.output.speed`, the transcription hints and `replace` [xai-s2s].

### Migrating from the previous generation

xAI says the API is unchanged: 3.0 uses the same endpoint, session parameters and events as 2.0, at the same price. A session that uses `grok-voice-latest` already runs on 3.0. A client pinned to `grok-voice-2.0` sets `model` to `grok-voice-3.0`. The docs advise a versioned name in production, because the alias follows the newest model [xai-release-notes] [xai-s2s]. The guide's prompt advice for 3.0 is to shorten the prompt and remove workaround rules. It names no other change. On Artificial Analysis, time to first audio rose from 0.70 seconds for 2.0 to 0.81 seconds for 3.0, and tau-Voice rose from 56.5% to 71.6% [aa-s2s].

## What the system card reports

xAI has published no model card for the voice models in the sources read. The announcement gives no safety tests. The prompting guide's reference example tells the agent to respond with empathy when a caller mentions self-harm, abuse or a medical emergency, to point to emergency services or a crisis line, and to transfer to a human [xai-s2s-prompting] [xai-announce-3].

## Behaviour observed in practice

Artificial Analysis measured the model on its Speech to Speech page (read 2026-10-31) [aa-s2s]:

- Speech to Speech Index: 86.9, second behind Phonic 1 (High) at 87.1.
- Speech reasoning (Big Bench Audio): 98.5%.
- Conversational dynamics: 97.0%. The parts are pause handling 98.5, turn-taking 100, interruption handling 96.5 and backchannel handling 92.9.
- Agentic performance (tau-Voice): 71.6% over three trials. The parts are airline 69.3, retail 66.1 and telecom 79.5.
- Time to first audio: 0.81 seconds on average. Cost per task on its Big Bench Audio run: about US$0.025.

The page holds several arena Elo figures for this model on different boards, so this file records none. No practitioner report was found.

## Benchmarks

Independent: the Artificial Analysis results above [aa-s2s]. Maker: the announcement cites Artificial Analysis data of 2026-10-13 (index 86.9 in first place, Big Bench Audio 98.5%, arena Elo 1070, task success 94.8%, Full Duplex Bench 97.0%, tau-Voice 71.6%). It also reports 74% accuracy on ServiceNow's EVA-Bench and calls the model the best on accuracy and customer experience together. This file did not read EVA-Bench itself [xai-announce-3]. The announcement says Grok Voice 3.0 runs in Tesla vehicles and in Starlink call centres. These are the maker's own deployment claims [xai-announce-3].
