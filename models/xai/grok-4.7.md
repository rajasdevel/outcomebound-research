# Grok 4.7

Grok 4.7 (`grok-4.7`, released 2026-09-21) is SpaceXAI's newest Grok model (the maker calls it its frontier model) and the current generation of the Grok class. It is a reasoning model with text and image input and text output, built by the maker for coding, agentic tasks and knowledge work. It replaced Grok 4.6 at the same list price and context window, on a larger base model with a longer reinforcement-learning run weighted toward multi-hour tasks [xai-47-news] [xai-docs-47-overview]. Rules that hold for every Grok model are in [the xAI README](README.md#family-wide-behaviour); this file gives what is specific to 4.7.

## How to instruct it

xAI publishes no prompting guide for Grok 4.7 (see [the guides section of the README](README.md#prompting-guides)). What follows is what the maker's API documentation, its model card and its release post say, with Artificial Analysis and Cursor measurements where they exist.

### Setting up the prompt

- **Where the system prompt goes.** The docs' examples send a `system` message in the Responses `input` array; `instructions` is an alternative field that cannot be combined with `previous_response_id`, because a continued response reuses the earlier system prompt [xai-docs-gen] [xai-docs-respref].
- **Message order.** The models page says chat models accept `system`, `user` and `assistant` messages in any order, with no role-order rule [xai-docs-models].
- **Length and style.** No page tells how literally 4.7 follows instructions. The only length advice is for Grok Build instruction files: they load in full, and short, specific instructions are followed more reliably than long ones [grok-f1]. The 2025 advice to write a thorough system prompt was written for `grok-code-fast-1` and has not been restated for 4.x [grok-f15]. Cursor says Grok 4.6 follows detailed instructions more reliably than 4.5 and that 4.7 builds on it with stronger self-verification; neither claim is backed by a published instruction-following score [cursor-grok-46] [cursor-grok-47]. Artificial Analysis published an instruction-following score (IFBench, 81%) for Grok 4.3 in April 2026; none was found for 4.6 or 4.7 [grok-f9].
- **Structure.** No source recommends XML tags or Markdown for 4.7. The 2025 guide recommended either to mark sections of context [grok-f16]. The Grok Build harness prompt itself uses XML-style tags for its sections [xai-build-prompt].
- **Order of material.** For caching, the docs say to put static content first: the system prompt, few-shot examples and reference documents, then the conversation [xai-docs-cache-best]. No page says where a long document should sit for best answer quality.
- **Honesty and over-refusal.** The card says xAI's system prompts steer the model toward honesty and truth-seeking while avoiding over-refusal on benign or hypothetical discussion; it does not publish those prompts for the API [xai-47-card].
- **Harness knowledge.** The maker trained 4.7 to understand the Grok Bot harness natively, which it credits for better conversational and general knowledge work [xai-47-news].

### Reasoning and effort

- **Control.** `reasoning.effort` on the Responses API (`reasoning_effort` on Chat Completions) takes `low`, `medium`, `high` (default) or `xhigh`. Reasoning cannot be disabled [grok-f10] [xai-docs-47].
- **What xAI says each level is for.** `low`: latency-sensitive agentic use and simple tool calling. `medium`: complex data analysis and long-context reasoning. `high`: very hard problems, multi-step logic, competition-style tasks. `xhigh`: maximum depth where answer quality matters more than response time [grok-f10].
- **What the levels cost and gain.** On Cursor's own CursorBench 4.0 table (run by Cursor, L), Grok 4.7 scores 33.1% at low (about $1.58 and 40 steps per task), 41.6% at medium ($3.49, 60 steps), 43.9% at high ($4.69, 71 steps) and 46.3% at xhigh ($6.01, 88 steps). For comparison Grok 4.6 scores 33.4, 36.1, 40.4 and 41.4 at the same four levels. Cursor's Grok 4.7 page describes a wider gap between levels than on 4.6, with more thinking time going to harder tasks [cursor-bench-board] [cursor-grok-47].
- **Token volume.** Artificial Analysis (M) measured about 81k output tokens per Intelligence Index task at xhigh, against 36k for Grok 4.6 at high and 38k at xhigh, about 7.1 minutes per task, and 240M output tokens for the whole index, which it calls very verbose against a median of 81M [aa-grok-47] [aa-grok-47-model]. Reasoning tokens are billed at the output price and count toward rate limits [xai-docs-cache-usage] [xai-docs-rates].
- **Visibility.** The docs say 4.7 exposes summarised reasoning that streams next to the answer (Responses events `response.reasoning_summary_text.delta`; xAI SDK `reasoning_content`), and that the Responses API always returns `reasoning.encrypted_content` for 4.7, whether or not `include` asks for it; passing the reasoning items back unchanged keeps reasoning and cache hits across turns when the client holds history. The reasoning page adds that this default, unlike an explicit `include`, does not stop SpaceXAI from storing the thinking trace on its servers; whether the response itself is stored is still set by `store` [grok-f10] [xai-docs-47-overview].
- **What fails.** `presencePenalty`, `frequencyPenalty` and `stop` return an error on reasoning models [grok-f10]. A Microsoft Foundry integration page on xAI's site says to encourage step-by-step reasoning when needed; no core 4.7 page says that, and the model reasons on every request [grok-f11].

### Output: format, length, tone

- No parameter for verbosity or response length is documented for 4.7. The cap is `max_output_tokens`, which counts visible tokens only and defaults to 128,000; reasoning and function-call tokens sit outside it [xai-docs-respref].
- `stop` sequences are rejected, so a response ends when the model finishes or hits the cap [grok-f10].
- Prefill of the assistant turn is not documented.
- The Grok Build system prompt shows the style xAI asks of its own agent: lead with the answer, plain words, complete sentences, no invented labels or acronyms, and a final message that stands alone for a reader who has not seen the tool calls [xai-build-prompt]. Nothing says the API model has that style by default.

### Tools and agents

- **Function calling.** Up to 350 tools per request; each needs a name and a JSON Schema `parameters` object whose root is an object (or `anyOf`/`oneOf` of objects, otherwise the request fails with 400); a description is optional but the docs say a clear one helps the model choose. Arguments always conform to the schema (strict is implicit). `tool_choice` accepts `auto`, `required`, `none` or a named function. Parallel calls are on by default and can be turned off with `parallel_tool_calls: false`. With streaming, a function call arrives whole in one chunk [xai-docs-fc].
- **Server-side tools** (web search with up to five allowed or excluded domains, X search, code execution in a sandbox, collections search, image generation, remote MCP) run on the maker's servers. When a request mixes them with client-defined functions, server tools run automatically and the request pauses when the model calls a client function; `max_turns` limits only the server-side turns inside one request and resets after each client-side call [xai-docs-tools-adv] [xai-docs-websearch] [xai-docs-codeexec].
- **Long-running work.** To keep agentic state across turns either store the conversation (`previous_response_id`) or pass back the encrypted reasoning and tool outputs. The docs recommend context compaction for long agent loops, especially tool-heavy ones: `POST /v1/responses/compact` returns an opaque item that replaces the earlier turns; it must be passed back whole and is not parsed or pruned [xai-docs-47-overview] [xai-docs-compaction].
- **What the maker claims.** The release post says 4.7 keeps going for longer on hard tasks and checks its own results more closely; the card credits its CursorBench 4.0 gain to more attention to edge cases, more persistence and better self-checking [xai-47-news] [xai-47-card].
- **In Grok Build.** The harness has plan mode (edit tools limited to the plan file until approval; the page notes that the shell is not gated, so bash can still write files), permission modes (ask, auto, always-approve), and subagents of three built-in types: general-purpose, explore (read-only) and plan [xai-build-plan] [xai-build-perms] [xai-build-subagents]. In Cursor, Grok 4.7 has all of Cursor's agent tools [cursor-grok-47].

### Coding

- The card's coding results are in [the benchmarks section](#benchmarks). The maker built 4.7 for long-horizon work: it reports CursorBench 4.0 at 46.3% (xhigh) and 43.9% (high), DeepSWE v1.1 at 71.0% (high, mini-SWE-agent harness, run by Datacurve), Terminal-Bench 4.0 at 38.0% (xhigh, Grok Build, run by Harbor), SWE-Marathon v1.1 at 46.0% (high) and FrontierSWE V2 at 29.0% (xhigh) [xai-47-card].
- Artificial Analysis rates Grok 4.7 with Grok Build at 56 on its Coding Agent Index (xhigh), up 9 points from Grok 4.6 (xhigh), and fourth among models in their native harnesses (M) [aa-grok-47].
- Absolute terminal scores depend on the harness: Terminal-Bench 4.0 is 38.0% on the card, 37.6% in the announcement and 33% in Artificial Analysis's index; the card itself says scores stay sensitive to the agent harness [xai-47-card] [xai-47-news] [aa-grok-47].
- 4.7 had supplemental training on anonymised Cursor workflow data. The card's coding rows use several harnesses: Grok Build for Terminal-Bench 4.0 and the engineering and cyber tests, mini-SWE-agent for DeepSWE, Proximal's Proximus for FrontierSWE, each model's native harness for SWE-Marathon; the card does not name the harness behind its CursorBench figures [xai-47-card].
- Project instructions: Grok Build reads `AGENTS.md` and compatible files (see README); Cursor reads `.cursor/rules` and `AGENTS.md` [grok-f1] [cursor-harness-doc].

### Long context and retrieval

- **Limits.** 500k tokens of context [xai-docs-47]. In Cursor the standard window is 256k, with a 500k long-context tier billed at double the standard rates above 256k input tokens [cursor-grok-47].
- **Pricing.** A request whose prompt reaches 200k tokens is billed at $4 input, $1 cached and $12 output per Mtok for every token in it, against $2, $0.50 and $6 below [xai-docs-47].
- **Quality at length.** The maker says 4.7 manages longer context better. Artificial Analysis measured AA-LCR (long-context reasoning) 3.7 points lower than Grok 4.6 (high) while most other index items were level or higher (M) [xai-47-news] [aa-grok-47].
- **Caching and compaction.** The overview page recommends a `prompt_cache_key` and context compaction for long loops, and the caching page says history must stay append-only [xai-docs-47-overview] [grok-f17].
- **Retrieval tools.** Collections search (RAG over uploaded files) is billed at $2.50 per 1k calls; files and collections storage and downloads are billed separately [xai-docs-pricing].

### Structured output

- `response_format` with `type: "json_schema"` constrains output to a schema; `json_object` returns any valid JSON; `text` is the default. Tool arguments are always schema-conformant. Structured outputs can be combined with server-side and function tools on Grok 4 family models [xai-docs-so] [xai-docs-47].
- Supported: string, number, integer, boolean, null, object, array, enum, const, `anyOf`, `oneOf` (treated as `anyOf`), `allOf` with one subschema, and non-circular `$ref`/`$defs`. Enforced string formats: `date`, `time`, `date-time`, `email`, `uuid`, `ipv4`, `ipv6`, `uri`. Guaranteed limits: `minLength` and `maxLength` up to 2,048, `minItems` and `maxItems` up to 256, `minProperties` and `maxProperties` up to 64. `additionalProperties` defaults to false. Regular expressions are a subset of ECMAScript with implicit anchoring and no backreferences, lookaround or word boundaries [xai-docs-so].
- Rejected with 400: empty `enum` or `anyOf`, boolean property schemas, `minContains`/`maxContains`, `items` as an array. Accepted but not guaranteed: `not`, `if/then/else`, multi-subschema `allOf`, other formats and over-limit constraints; the docs advise validating when strict conformance matters [xai-docs-so].
- The docs do not describe what the model does when it declines a request under a schema.

### Images, audio, other inputs

- Text and image in, text out. Image files: JPEG or PNG, up to 20 MiB each, no stated count limit, as a public URL or a base64 data URL, in any order with text. The docs advise against server-side storage of request history (`store: false`) when sending images, because such requests may fail. The page's examples pass `detail: "high"` without explaining the setting, and image token cost is not described [xai-docs-img] [xai-docs-models].
- Web search can let the model inspect images it finds (`enable_image_understanding`, which adds a `view_image` tool billed in tokens) [xai-docs-websearch] [xai-docs-pricing].
- Audio and video input are not offered by this model; speech and image or video generation are separate models and APIs [xai-docs-models].

### Sampling and API parameters

- `temperature` runs 0 to 2 and `top_p` 0 to 1 (the reference advises changing one, not both); the Responses API also offers `top_k` and `min_p`. The docs state no defaults and do not say whether reasoning mode changes their effect [xai-docs-respref]. The code-execution page suggests temperature 0.0 to 0.3 for calculations [xai-docs-codeexec].
- Errors on reasoning models: `presencePenalty`, `frequencyPenalty`, `stop`. Not supported: `logprobs` and `top_logprobs` (silently ignored from the 4.20 models on), `logit_bias`, `truncation` [grok-f10] [xai-docs-chatref] [xai-docs-respref].
- Other: `seed` (best effort), `n` (billed per choice), `service_tier` (`default`, `priority` or `fast`; the Chat Completions reference says `fast` and `priority` are interchangeable, meaning the model's fast deployment where one is configured and otherwise higher scheduling priority; `priority` is billed at 2x), `safety_identifier` (a stable, hashed end-user id, so a violation is attributed to that user and not to the API key) [xai-docs-chatref] [xai-docs-pricing] [xai-docs-security].

### Migrating from the previous generation

From Grok 4.6 to 4.7, per the sources read:

- **API shape is the same**: same endpoints, effort levels, context, list prices and rate limits. The model id is `grok-4.7` [xai-docs-47] [xai-docs-46].
- **New in 4.7:** the Responses API returns encrypted reasoning on every response, and summarised reasoning is exposed; the docs describe both for 4.7 only. Both 4.7 and 4.6 are served on the US regional endpoint [grok-f10] [xai-docs-regions].
- **Token use more than doubled** at the top level (81k against 38k per index task), so budgets, timeouts and spend set for 4.6 may need revisiting; effort levels are more separated, so `low` and `medium` may behave more differently from `high` than they did [aa-grok-47] [cursor-grok-47].
- **Quality changes measured by others (M):** Intelligence Index 46 against 44; AA-Briefcase 1657 Elo against 1546 for Grok 4.6 (high) as listed in the announcement; Terminal-Bench 4.0 up 4.5 points; AA-LCR down 3.7 points; AA-Omniscience hallucination 29% against 34% [aa-grok-47] [xai-47-news].
- **Safety changes:** the release post describes an entirely new safeguard stack [xai-47-news]; in the card, standard jailbreak compliance 0.01% against 0.04%; self-harm prompt compliance 1.05% against 0.84% (a higher failure rate, as the card says); dual-use biology scores equal or lower [xai-47-card].
- **Knowledge cutoff:** pretraining June 2026 (with supplemental data to August 2026), against January 2026 for 4.6; the docs give May 2026 for 4.7 [xai-47-card] [xai-docs-47-overview].
- **Availability:** Grok 4.6 remains on the API with no retirement notice; Cursor recommends 4.7 over it and Artificial Analysis labels 4.6 deprecated [cursor-grok-46] [aa-grok-46-model].

## What the system card reports

The card (2026-09-21) lists Grok 4.7 as text and image in, text out; available through the API, Grok Build, Cursor (all plans), Office add-ins and model gateways, with consumer apps to follow. Pretraining cutoff June 2026; supplemental data to August 2026; supplemental training on anonymised Cursor workflow data [xai-47-card].

**Capabilities (maker-reported, mostly third-party-run, L).** Coding: see Benchmarks. Knowledge work: Harvey Legal Agent Benchmark 19.6% at xhigh (Vals AI, Valkyrie harness, internet off) against 15.8% for Grok 4.6 and 6.7% to 11.3% for the Fable models listed. Engineering: EEBench 66.0% at xhigh (Atopile), below GPT-6 Astra (69.3%) and above Opus 5 (61.6%); CADGenBench 44.4% at high (Mecado). Medical: HealthBench Professional 56.7% at xhigh, with Grok 4.6 (high) as grader and tasks rejected by safety filters scored zero. Biology agents: LatchBio capability suite 44.5% at xhigh.

**Cyber.** Small capability gains over 4.6, in defence and vulnerability mitigation as much as in red-team use. Capability tests run without production safeguards: CyberGym 80.3% (high; 4.6 79.7%, GPT-5.6 Sol 83.6%), CVE-Bench 36.6% (xhigh) and 37.7% (high) against 39.8% for 4.6, CathedralBench hard subset 29% against 25%. The maker gave an unrestricted configuration to outside evaluators, who corroborated its results. HackerBench v0.3 with safeguards on: harmful or dual-use compliance 4.02% (xhigh) and 3.31% (high), against 5.93% for 4.6 (high), 7.8% for 4.5 and 35.7% for GPT-5.6 Sol (max). Benign-task refusal is 0.00% at xhigh and 0.31% at high, and 0.0% for the three other rows (read from the chart's bar order, which the card text does not restate). HackerBench is the maker's own suite [xai-47-card].

**Biology and chemistry.** Scores stay below xAI's framework thresholds; there is no dual-use capability increase over 4.6 and several measures fall, which the card attributes to safer training environments and data selection, not to extra refusal training. VCT 63.0% (4.6: 67.4%); Biosecurity VCT 41.5% (47.8%); WMDP-Bio 88.1%, Chem 84.9%, Cyber 88.1%; LAB-Bench practical 76.8% (80.7%); ProtocolQA open-ended 70.4% (79.6%); BixBench 88.4% (93.8%). Refusals: BioUseBench severity-5 refusal 91.4% (90.7%); BioSecBench refusal 62.4% (45.6%; higher is better, per the announcement) against 25.5% and 31.8% for the two peers run by LatchBio [xai-47-card].

**Jailbreaks and refusals (lower is better).** Standard jailbreaks 0.01% compliance, StrongREJECT 2.0% (4.6: 3.9%), long-horizon and Crescendo-style 0.65% (1.0%). General refusals set in six languages: 1.10% compliance (0.93%). Child safety 0.0%. Bio refusal recall 100%, chem 99.9%, FORTRESS radiological and nuclear 97.9%. Self-harm: 1.05% compliance (0.84%), counting a refusal without redirecting to help as a failure [xai-47-card].

**Behaviours.** MASK-Rectified dishonesty 0.00% (4.6: 1.90%), on a set derived from the public MASK benchmark with grading changed so that obvious role-play is not counted as lying; sycophancy on confidently stated wrong answers 0.03% (0.04%), an internal test [xai-47-card].

**Safeguards and limits that can stop a request.** Layered: safety fine-tuning, system prompts, and on some surfaces runtime input and topical filters (CSAM, self-harm, biological and chemical weapons paths, cyber). The pricing page says a request judged to break the usage guidelines is still charged, and one caught before generation on the Responses API costs $0.05 [xai-47-card] [xai-docs-pricing]. xAI says it gives selected cyber-defence partners invite-only access to red-team capabilities [xai-47-news]. The card does not report prompt-injection, reward-hacking, special-casing or sandbagging results for 4.7.

## Open questions

- Maximum output length: the docs say no limit and default the cap to 128,000 visible tokens.
- How well 4.7 follows long or highly specified system prompts: no independent measurement found.
- Whether summarised reasoning is stable enough to display to users: only the docs' example exists.
- Knowledge cutoff: the docs say May 2026, the card says June 2026 (data to August 2026).
- The Terminal-Bench 4.0 public leaderboard could not be read, so the card's harness-specific figures lack an independent check of the board itself.
- No source compares Fast and standard output quality.
