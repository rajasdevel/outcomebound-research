# Grok Build 0.1

Grok Build 0.1 (`grok-build-0.1`) is SpaceXAI's coding model, trained for agentic software work: web development, debugging and MCP support, as the API announcement puts it. It is the only generation of the Grok Build class and the successor to `grok-code-fast-1`, whose slug and two other aliases now route to it. It reached the API in public beta on 2026-05-29 at $1 input and $2 output per Mtok with a 256k context; the announcement called it the model behind the Grok Build agent. xAI's models page now names Grok 4.7 for code and chat, and the Grok 4.7 card names 4.7 as the agent's default model [xai-build01-news] [xai-docs-build01] [xai-docs-models] [xai-47-card]. Shared Grok API rules are in [the xAI README](README.md#family-wide-behaviour).

## How to instruct it

xAI publishes no prompting guide for this model. The only coding-model guide is the archived one for `grok-code-fast-1` (November 2025 copy), whose slug now routes here; nothing says it was revised for Build 0.1 [grok-f15] [grok-migration-may15].

### Setting up the prompt

- The archived guide's advice for building agents on the API: give a detailed system prompt covering the task, expectations and edge cases; mark sections of context with XML tags or Markdown headings with definitions; give specific context (file paths, the code at issue) and explicit goals; avoid vague or irrelevant context [grok-f15] [grok-f16].
- The announcement says the model performs best inside an agentic harness and names Grok Build, Cursor, Hermes Agent, OpenClaw, Kilo Code and OpenCode as examples; Cursor's own price list and model docs do not list `grok-build-0.1` [xai-build01-news] [cursor-pricing].
- In Grok Build, project instructions load from `AGENTS.md`, `CLAUDE.md` and rule files; short, specific instructions are followed more reliably than long ones [grok-f1].

### Reasoning and effort

- The model page lists "Reasoning: Yes" but no effort levels or default; whether `reasoning_effort` is accepted is not stated [xai-docs-build01]. The reasoning page's table covers only Grok 4.5, 4.6, 4.7 and the 4.20 multi-agent model [grok-f10].
- The archived guide says the predecessor reasoned with interleaved tool calling during thinking, sent summarised thinking through an OpenAI-compatible interface, and exposed its trace as `reasoning_content` only in streaming mode [grok-f15].
- For reasoning models in general the API rejects `presencePenalty`, `frequencyPenalty` and `stop`; whether that list applies unchanged here is not stated for this model [grok-f10].

### Output: format, length, tone

- No output controls are documented for this model. The announcement claims 100 or more tokens per second at launch (maker claim); Artificial Analysis measured 68.6 tokens per second for the June 2026 snapshot (M) [xai-build01-news] [aa-build-0616].

### Tools and agents

- Function calling and structured outputs are supported [xai-docs-build01]. The archived guide asks for native tool calling and warns that XML-formatted tool calls may hurt performance [grok-f15].
- The announcement says it is also fast and economical for general agentic and tool-calling use outside coding [xai-build01-news].
- Caching matters for tool loops: the archived guide says cache hits drive the predecessor's speed and advises against changing prompt history; the current caching pages say the same [grok-f15] [grok-f17].

### Coding

- No benchmark appears in the announcement, on the model page, or in a model card. Artificial Analysis lists "Grok Build 0.1 0616", a June 2026 snapshot, at 27 on its Intelligence Index (M), and marks it deprecated because newer releases exist [aa-build-0616].
- The 2026 cards for Grok 4.6 and 4.7 say their safety results also apply to Grok Build; the sentence names the agent and does not mention Build 0.1 [xai-47-card].

### Long context and retrieval

- 256,000 tokens; prompts reaching 200k tokens are billed at the doubled rate ($2 input, $0.40 cached, $4 output) for all tokens in the request [xai-docs-build01].
- Not available on the US regional endpoint; model regions `us-east-1` and `us-west-2` [xai-docs-build01] [xai-docs-regions].

### Structured output

- The model page lists structured outputs as supported; the schema rules on the structured-outputs page apply to the Grok 4 family and are written against `grok-4.7` examples [xai-docs-build01] [xai-docs-so].

### Images, audio, other inputs

- Text and image input, text output [xai-docs-build01]. No image guidance specific to this model.

### Sampling and API parameters

- Rate limits at tier 0: 37 requests per second and 10M tokens per minute [xai-docs-rates].
- Batch API: not supported [xai-docs-build01].
- Aliases `grok-code-fast-1`, `grok-code-fast` and `grok-code-fast-1-0825` resolve to this model; since 2026-05-15 requests to the old slug reach it [xai-docs-build01] [grok-migration-may15].

### Migrating from the previous generation

- From `grok-code-fast-1`: the slug redirects automatically, so existing calls now reach Build 0.1 without any code change, at $1 and $2 per Mtok [grok-migration-may15] [xai-docs-build01]. The old model's price and behaviour are not what a redirected caller now gets; the docs say Build 0.1 delivers significantly improved agentic coding and web development [grok-migration-may15].
- xAI's own recommendation for code is now Grok 4.7 [xai-docs-models].

## What the system card reports

xAI publishes no model card for `grok-build-0.1`. The card for its predecessor, `grok-code-fast-1` (2025-08-26), described: a fixed system-prompt prefix stating the safety policy, inserted in every evaluation and production deployment, with training on an instruction order in which the safety policy outranks the rest of the system prompt and the system prompt outranks user messages; model-based input filters for biological and chemical weapons queries and child sexual exploitation; an answer rate of 0.00 on its harmful-request set, with user or system jailbreaks added; an AgentHarm answer rate of 17.0 and an AgentDojo hijacking attack success rate of 26.9 with the mitigation, and a MASK dishonesty rate of 71.9, which xAI said it did not consider a serious concern for a coding model. Whether any of that holds for Build 0.1 is not stated [xai-codefast-card].

- Practitioner reports (A): none with measurements found.

## Open questions

- Reasoning effort levels, default and whether the setting is accepted.
- Whether the card for `grok-code-fast-1` carries over; base model, size and knowledge cutoff are not disclosed.
- Status: the API post says public beta, the release notes say early access, and the model page no longer says either; the card marks it preview as a judgement.
- Whether the live slug equals the June snapshot Artificial Analysis measured.
- Whether it will be retired: no notice found.
- The May 15 migration page is not consistent with itself: its general notice says retired slugs redirect to `grok-4.3`, while its table and the model page route `grok-code-fast-1` to `grok-build-0.1`.
