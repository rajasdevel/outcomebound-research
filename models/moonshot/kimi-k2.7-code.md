# Kimi K2.7 Code

Kimi K2.7 Code is a coding-focused model that Moonshot AI built on its general K2.6 model: a one-trillion-parameter mixture-of-experts model (32B active per token) with a 256K-token window that reads text, images and video, always thinks, and is released with open weights under a modified MIT licence. It belongs to the class Kimi K Code, generation 2.7, and appeared in June 2026 (the weights were first uploaded on 2026-06-11). It targets long-horizon coding and, according to Moonshot, follows instructions more reliably over long contexts than K2.6 while using about 30% fewer thinking tokens. A faster id, `kimi-k2.7-code-highspeed`, serves the same weights at twice the price. What Moonshot's models share (API, fixed parameters, preserved reasoning, vision rules, safety evidence) is on the [Moonshot page](README.md); this file says what is specific to K2.7 Code.

## How to instruct it

Moonshot publishes a quickstart for K2.7 Code and shared pages on thinking models, structured output and vision; the general prompt guide applies to every Kimi model. The [prompting-guides section of the maker page](README.md#prompting-guides) summarises them. Moonshot gives no K2.7-specific prompting advice beyond what is below.

### Setting up the prompt

- **System prompt.** Moonshot's examples use a one-line system message; its general guide advises details, a role, delimiters, written steps, examples and reference text [kimi-prompt-guide]. The model card calls Kimi Code CLI the framework the model works best in [open-weight-g13].
- **Instruction following.** Moonshot's quickstart says K2.7 Code follows instructions more reliably in long contexts than K2.6, citing unnamed external benchmark evaluations that it says also show about 30% less over-thinking and a 10% gain on agentic tasks; no instruction-following score is published [kimi-k27-quickstart] (class L). The cautions Moonshot gives for K3 (acting beyond the request) are not stated for this model.
- **Document placement.** No guidance.
- **Reasoning history.** The system relies on earlier reasoning being kept in the conversation (next section) [kimi-model-params].

### Reasoning and effort

- **No control.** Thinking is always on and cannot be disabled; the API has no `reasoning_effort` field for this model. The `thinking` field may be left out; if sent, only `{"type": "enabled", "keep": "all"}` is accepted, and `disabled` returns an error [kimi-model-params] [kimi-thinking-models].
- **Preserved thinking.** Always on: the `reasoning_content` of every earlier assistant message must stay in the history as returned. When migrating from K2.6, Moonshot says historical reasoning must now be passed back [kimi-model-params].
- **Token use.** Moonshot says thinking tokens fall about 30% against K2.6 [open-weight-g13]. Artificial Analysis counted 30k output tokens per task for the model, 19k of them reasoning, against 48k and 32k for K3 [aa-cmp-k27code-m3] [aa-cmp-k3-m3]. One practitioner's nine-task coding test measured 272 reasoning tokens per task, the second lowest of the nine reasoning models it compared (class A, easy tasks) [datallm-k27-review].
- **Limits.** Moonshot says to set `max_tokens` to at least 16,000 for multi-step tool use, because reasoning and answer share the limit, and to stream [kimi-thinking-models].
- **Step-by-step prompting.** No guidance for this model.

### Output: format, length, tone

- **Length and verbosity.** No verbosity setting. The default output limit is not stated; output can reach the 262,144-token window minus the prompt [kimi-troubleshooting].
- **Prefill.** Partial mode continues a supplied prefix; with thinking on, the previous `reasoning_content` goes back with it, and a small `max_tokens` can end the output inside the reasoning [kimi-partial-mode].
- **Style.** Moonshot publishes nothing on tone or formatting defaults for this model.

### Tools and agents

- **Choice.** `tool_choice` supports `auto` and `none`; `required` is rejected (only K3 supports it), and forcing a named function is incompatible with thinking [kimi-model-params] [kimi-tool-choice].
- **Multi-step calls.** The model shares K2 Thinking's design of interleaved thinking with multi-step tool calls; Moonshot's rules are to keep all reasoning from the current task in the context, not to set `temperature`, and to stream [open-weight-g13] [kimi-thinking-models].
- **Repeated calls.** Moonshot's pages on repeated tool calls apply: check the message layout and add reminders after repeated identical calls (details in the [K3 file](kimi-k3.md#tools-and-agents)).
- **Maker results.** MCP Atlas 76.0 (K2.6 69.4, GPT-5.5 79.4, Claude Opus 4.8 81.3) and MCP Mark Verified 81.1 (72.8, 92.9, 76.4), both with a 100-call or 100-step budget and 32k tokens per step, over three runs; in-house Kimi Claw 24/7 Bench 46.9 (42.9, 52.8, 50.4) in the OpenClaw harness [kimi-k27-code-hf].
- **Dynamic tool loading.** Not available; it works on K3 only [kimi-dynamic-tools].
- **Images and video in tool results.** Moonshot's quickstart example has a tool return video content blocks (a clip cut from a local file) that the model then reads, so tool results can carry visual input on Chat Completions [kimi-k27-quickstart].

### Coding

- **Maker table.** In Kimi Code CLI with thinking on, temperature 1.0, top-p 0.95 and a 262,144-token window: Kimi Code Bench v2 (in-house) 62.0 against 50.9 for K2.6, 69.0 for GPT-5.5 and 67.4 for Claude Opus 4.8; ProgramBench 53.6 against 48.3, 69.1 and 63.8; MLS Bench Lite 35.1 against 26.7, 35.5 and 42.8. The competing models ran in Codex and Claude Code at xhigh effort (max for Opus on MLS Bench Lite) [kimi-k27-code-hf] (class L). In the maker's own table K2.7 Code trails GPT-5.5 on all six rows and Claude Opus 4.8 on five of the six.
- **Independent.** Artificial Analysis scores the model 26 on its Intelligence Index and 1% on Terminal-Bench 4.0, against 44 and 13% for K3 [aa-cmp-k3-m3]. Scale's SWE-Bench Pro V2 has no K2.7 Code row [scale-swe-pro-v2].
- **Harness notes.** Moonshot's Claude Code guide uses K2.7 Code for the haiku slot next to K3 for the others [kimi-claude-code]. The faster id does about 180 tokens a second, up to 260 on short contexts, and Moonshot says capacity for it is limited and speed can fluctuate [kimi-k27-quickstart].
- **Observed.** One practitioner ran nine coding tasks with hidden tests and scored 9 of 9, as did nine of the other 12 models tried, so correctness on easy tasks does not separate models (class A) [datallm-k27-review].

### Long context and retrieval

- **Limits.** 262,144 tokens of context; output up to the window minus the prompt [kimi-pricing] [kimi-troubleshooting].
- **Quality.** Moonshot claims better instruction following in long contexts without a long-context score. Artificial Analysis's long-context reasoning test gives 79% (AA-LCR v1.1), against 89% for K3 [aa-cmp-k27code-m3] [aa-cmp-k3-m3].
- **Caching.** Automatic; cached input is $0.19 against $0.95 for a miss. The caching guide's rules (stable material first, nothing that changes in the prefix, entries refreshed by use) are written around K3, and its FAQ says separately billed cache writes apply to K3 only, not to K2.7 Code [kimi-pricing] [kimi-context-caching].

### Structured output

Moonshot describes K2.7 Code as having the most stable structured-output support of its models: nested objects, arrays, `anyOf`, `oneOf`, `$ref` and `additionalProperties: true` all work, and it follows the schema reasonably whether `strict` is true, false or omitted; Moonshot still advises `strict: true`. Parse only `content`, not `reasoning_content` [kimi-response-format].

### Images, audio, other inputs

Images and video are accepted. Moonshot lists images as png, jpeg, webp and gif and video as mp4, mpeg, mov, avi, flv, mpg, webm, wmv and 3gpp on the quickstart (its shared vision guide lists more image types). Content must be an array of parts; public image URLs are not supported, so use base64 or an uploaded file id; very large video must be uploaded. Moonshot advises images up to 4K and video up to full HD. The model card says video chat is experimental and works only on Moonshot's official API. The request body may not exceed 100 MB. No audio [kimi-k27-quickstart] [kimi-vision] [open-weight-g13].

### Sampling and API parameters

`temperature` is fixed at 1.0, `top_p` at 0.95, `n` at 1 and both penalties at 0; other values return an error. The model card says non-thinking ("instant") mode is not supported [kimi-model-params] [open-weight-g13].

### Migrating from the previous generation

- **From K2.6.** Same architecture and deployment method as K2.5 and K2.6, so self-hosted runtimes carry over [open-weight-g13]. On the API, the `thinking` field becomes optional and may only be `enabled` with `keep` set to `all`; thinking can no longer be switched off; earlier `reasoning_content` must be passed back; `temperature` stays fixed (K2.6 used 0.6 without thinking). Moonshot's table shows gains on its tests (Kimi Code Bench v2 50.9 to 62.0, ProgramBench 48.3 to 53.6, MCP Atlas 69.4 to 76.0), and cached input costs $0.19 against $0.16 [kimi-k27-code-hf] [kimi-model-params] [kimi-pricing].
- **To K3.** Replace the model id, delete the `thinking` field, use `reasoning_effort`, and keep sending complete assistant messages; K3 accepts `tool_choice: required`, takes 1M tokens, costs about three to four times as much per token and runs at less than half the output speed, 36 tokens a second against 95 (see the [K3 file](kimi-k3.md#migrating-from-the-previous-generation)) [kimi-model-params] [aa-k27-code].

## What the system card reports

Moonshot publishes no system card or technical report for K2.7 Code. The Hugging Face model card has a six-row benchmark table against K2.6, GPT-5.5 and Claude Opus 4.8, the run settings, and deployment notes [kimi-k27-code-hf].

The card contains no safety evaluation: nothing on refusals or over-refusal, reward hacking, sycophancy, deception, prompt-injection resistance, or biology and cyber policies, and no named safeguards. No independent safety assessment of K2.7 Code was found; the UK AISI and CAISI cyber assessment covers K3, not this model [uk-aisi-caisi-k3].

## Behaviour observed in practice

- **Speed and cost (class M).** Artificial Analysis: 95 output tokens a second, 3.05 s to the first token, about 27 s to the first answer token; $0.54 per index task and $993 for the run; 122M output tokens across the index [aa-k27-code] [aa-cmp-k27code-m3].
- **Factual calibration (class M).** AA-Omniscience, which penalises wrong answers, scored -10 on a scale from -100 to 100, against 20 for K3 [aa-cmp-k27code-m3] [aa-cmp-k3-m3].
- **Easy coding tasks (class A).** 9 of 9 on a nine-task execution-checked set, 10.4 s a task, about $1.34 per thousand tasks at OpenRouter's listed prices; the same review notes that thinking and the fixed sampling values cannot be changed [datallm-k27-review].
- **Position against K3 (class M).** Far behind on Artificial Analysis's index (26 against 44) and Terminal-Bench 4.0 (1% against 13%) [aa-cmp-k3-m3].
