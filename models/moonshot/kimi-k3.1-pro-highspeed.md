## How to instruct it

### Setting up the prompt

The [standard variant](kimi-k3.1-pro.md#setting-up-the-prompt) gives the common prompt setup. Use the Highspeed API id. L [models].

### Reasoning and effort

The same three effort levels and default apply; thinking stays on. See the [standard variant](kimi-k3.1-pro.md#reasoning-and-effort). L [parameters].

### Output: format, length, tone

The [standard variant](kimi-k3.1-pro.md#output-format-length-tone) describes streaming and partial output. No distinct Highspeed verbosity control was verified. L [quickstart].

### Tools and agents

The [standard variant](kimi-k3.1-pro.md#tools-and-agents) gives the shared parameter constraints and continuation requirements. L [parameters].

### Coding

No independent Highspeed coding result was verified. The standard endpoint's benchmark scores are not copied here.

### Long context and retrieval

The K3-series context limit applies. Vercel's route lists the shared context and maximum output; a direct Moonshot output ceiling was not established. L [parameters] [gateway-highspeed].

### Structured output

See the [standard variant](kimi-k3.1-pro.md#structured-output) for the documented schema interface. Separate Highspeed schema reliability was not measured.

### Images, audio, other inputs

The shared quickstart documents image and video requests. It establishes no audio interface. L [quickstart].

### Sampling and API parameters

Moonshot explicitly applies K3's parameter constraints to Highspeed. See the [standard variant](kimi-k3.1-pro.md#sampling-and-api-parameters). L [parameters].

### Migrating from the previous generation

Select `kimi-k3.1-pro-highspeed` and retain the same API constraints. Route prices differ; Vercel lists the same cache-read rate as standard, with higher input, output and cache-write rates. L [models] [gateway-highspeed].
