# Kimi K2.6

Kimi K2.6 is Moonshot AI's general model of the K2 line before K3: a one-trillion-parameter mixture-of-experts model (32B active per token) with a 256K-token window that reads text, images and video, thinks by default, and has open weights under a modified MIT licence. It belongs to the class Kimi K, generation 2.6, and appeared in April 2026. Moonshot describes it as built for long-horizon coding, coding-driven design and long-running agent work, and it replaced K2.5. K2.7 Code was later built on it, and K3 is the current model of the class. What the Kimi models share (API, fixed parameters, vision rules, safety evidence) is on the [Moonshot page](README.md); this file says what is specific to K2.6.

## How to instruct it

Moonshot publishes a K2.6 quickstart, a thinking-model guide that covers K2.6, K2.7 Code and K3, a model-parameter reference and a general prompt guide. It publishes no prompt-writing advice written for K2.6 alone. The [prompting-guides section of the maker page](README.md#prompting-guides) lists the guides; this section says what applies to K2.6.

### Setting up the prompt

- **System prompt.** Moonshot's K2.6 examples use a one-line system message ("You are Kimi."). The general guide advises giving details, a role, delimiters such as XML tags or triple quotes, written steps, examples and reference text [kimi-k26-quickstart] [kimi-prompt-guide] (class L). The model card calls Kimi Code CLI the framework K2.6 works best in [kimi-k26-hf].
- **Instruction following.** Moonshot's quickstart says K2.6 follows instructions and corrects itself much better than earlier versions, with no score attached. Its blog lists partner remarks of the same kind (class L, quoted by the maker, so read as marketing evidence) [kimi-k26-quickstart] [kimi-k26-blog].
- **Document placement.** No guidance.
- **Reasoning history.** K2.6 does not keep earlier-turn reasoning unless asked (next section) [kimi-thinking-models].

### Reasoning and effort

- **The control.** K2.6 is a toggle, not an effort scale. The `thinking` field takes `{"type": "enabled"}` (the default) or `{"type": "disabled"}`, which gives the "instant" mode. The OpenAI SDK has no such field, so it goes in `extra_body`. K2.6 has no `reasoning_effort` field [kimi-model-params] [kimi-thinking-models].
- **Preserved thinking.** `thinking.keep` is `null` by default, which ignores `reasoning_content` from earlier turns (shorter context, lower cost). `"all"` keeps it. Moonshot recommends `keep: "all"` together with `type: "enabled"` and says the card's preserve-thinking mode improves coding-agent work. Kept reasoning stays in the window and is billed [kimi-thinking-models] [kimi-k26-hf].
- **Within one task.** For multi-step tool use Moonshot says to send back all reasoning from the current task, set `max_tokens` to at least 16,000, stream, and leave `temperature` alone [kimi-thinking-models].
- **Token use.** Artificial Analysis counted 180M output tokens across its index run, which it calls very verbose against a median of 140M [aa-k26].
- **Step-by-step prompting.** No guidance for K2.6.

### Output: format, length, tone

- **Length and verbosity.** No verbosity setting. Reasoning and answer share `max_tokens`. The card's example limits run from 4,096 to 8,192 tokens for plain chat and up to 98,304 for reasoning benchmarks [kimi-k26-hf].
- **Style.** Moonshot publishes nothing on tone or formatting defaults for K2.6.
- **Prefill.** Partial mode is a family feature (see the [K2.7 Code file](kimi-k2.7-code.md#output-format-length-tone)); Moonshot gives no K2.6 note.

### Tools and agents

- **Choice.** `tool_choice` supports `auto` and `none`; `required` returns an error (only K3 supports it) [kimi-model-params].
- **Multi-step calls.** The card says K2.6 shares K2 Thinking's design of interleaved thinking with multi-step tool calls [kimi-k26-hf].
- **Agent swarm.** Moonshot says K2.6 can scale to 300 sub-agents running 4,000 coordinated steps, and that its hosted "Agent Swarm" and "Claw Groups" features are products on top of the model, with the latter a research preview. These are Moonshot product features, not API parameters [kimi-k26-hf] [kimi-k26-blog].
- **Multimodal tool results.** The quickstart's example has a tool return video content blocks that the model then reads, so tool results can carry visual input [kimi-k26-quickstart].
- **Long-horizon work.** Moonshot's blog describes runs of 12 to 13 hours with over 1,000 to over 4,000 tool calls and a five-day autonomous operations agent; these are maker-published case studies, unverified by others (class A in effect) [kimi-k26-blog].
- **Context management in its tests.** BrowseComp used a discard-all strategy; HLE with tools and WideSearch kept only the latest round of tool messages once the window passed a threshold; DeepSearchQA used no management and counted overflow as failure [kimi-k26-hf].

### Coding

- **Maker table.** Thinking on, averaged over 10 runs: SWE-Bench Pro 58.6 (GPT-5.4 57.7, Claude Opus 4.6 53.4, Gemini 3.1 Pro 54.2, K2.5 50.7), SWE-Bench Verified 80.2, SWE-Bench Multilingual 76.7, Terminal-Bench 2.0 66.7 in the Terminus-2 framework (K2.5 50.8), LiveCodeBench v6 89.6. The SWE-Bench rows use Moonshot's own scaffold with six tools. Rows marked with an asterisk for competitors were re-run by Moonshot [kimi-k26-hf] (class L).
- **Independent.** No independent coding-agent result was found: Scale's SWE-Bench Pro V2 table has no K2.6 row [scale-swe-pro-v2].
- **Harness notes.** Moonshot names Kimi Code CLI as the best-fit harness. Its Vendor Verifier checks third-party hosts of its models [kimi-k26-hf] [kimi-vendor-verifier].
- **Benchmark settings.** Moonshot's benchmarking guide lists K2.6 settings: temperature 1.0, top-p 0.95, 256k tokens for coding, 96k for vision and reasoning, 300 steps for agent tasks [kimi-benchmark-guide].

### Long context and retrieval

- **Limits.** 262,144 tokens of context; output up to the window minus the prompt [kimi-pricing].
- **Quality.** Moonshot publishes no long-context retrieval score for K2.6.
- **Caching.** Automatic; cached input is $0.16 against $0.95 for a miss. The caching guide is written around K3 and says separately billed cache writes apply to K3 only (see the [Moonshot page](README.md)) [kimi-pricing].

### Structured output

Moonshot's response-format guide is shared by the family and has no K2.6 note; see the [K2.7 Code file](kimi-k2.7-code.md#structured-output) for the schema rules Moonshot gives. Parse only `content`, not `reasoning_content`.

### Images, audio, other inputs

Images and video are accepted. Content must be an array of parts; public image URLs are not supported, so send base64 or an uploaded file id. Moonshot's model card says video chat is experimental and works only on its official API. The vision encoder is MoonViT with 400M parameters. No audio [kimi-k26-quickstart] [kimi-k26-hf].

### Sampling and API parameters

- `temperature` is fixed: 1.0 in thinking mode and 0.6 in instant mode. `top_p` is fixed at 0.95, `n` at 1, both penalties at 0. Other values return an error [kimi-model-params].
- For self-hosted copies the card recommends temperature 1.0 for thinking and 0.6 for instant, top-p 0.95, and `chat_template_kwargs` (`thinking`, `preserve_thinking`) in place of the API's `thinking` field. Its benchmark footnote says top-p 1.0 was used for the reported scores, which differs from the 0.95 it recommends [kimi-k26-hf].

### Migrating from the previous generation

- **From K2.5.** K2.5 was retired from the API on 2026-08-31 (K2.6 has the same architecture and deployment method, so self-hosted setups carry over). Moonshot's table shows gains on its tests: SWE-Bench Pro 50.7 to 58.6, Terminal-Bench 2.0 50.8 to 66.7, Toolathlon 27.8 to 50.0, MCPMark 29.5 to 55.9, HLE with tools 50.2 to 54.0 [kimi-k26-hf] [kimi-models].
- **To K2.7 Code.** Thinking becomes always on and may only be `enabled` with `keep` set to `all`; historical `reasoning_content` must be passed back; temperature stays 1.0 (K2.6 used 0.6 without thinking). See the [K2.7 Code file](kimi-k2.7-code.md).
- **To K3.** Replace the model id, delete the `thinking` field, use `reasoning_effort` if the default (max) is too slow, and send complete assistant messages back as returned. Thinking can no longer be turned off; `tool_choice: required` works; the window is 1M tokens [kimi-model-params]. See the [K3 file](kimi-k3.md).

## What the system card reports

Moonshot publishes no system card for K2.6. The Hugging Face model card has the benchmark table, settings, deployment notes and licence; the tech blog repeats the table with demonstrations. Neither reports refusals or over-refusal, reward hacking, sycophancy, deception, prompt-injection resistance, or biology and cyber policies. The blog says K2.6 shows "enhanced safety awareness during extended research tasks" without a measurement [kimi-k26-hf] [kimi-k26-blog]. No independent safety assessment of K2.6 was found; the UK AISI and CAISI cyber assessment covers K3.

## Behaviour observed in practice

- **Speed, cost and verbosity (class M).** Artificial Analysis: about 68 output tokens a second, slower than its median of 71; $0.80 per index task; 180M output tokens across the index [aa-k26].
- **Maker case studies (class L, unverified by others).** Long autonomous runs and swarm demonstrations are in Moonshot's blog; no independent replication was found [kimi-k26-blog].
- **Hosted copies.** Moonshot says scores differ between its API and other providers' copies of its models and points to the Vendor Verifier [kimi-k26-hf] [kimi-vendor-verifier].
