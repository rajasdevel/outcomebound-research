# DeepSeek V4-Pro (0813)

DeepSeek V4-Pro (0813) is the generally available release of the larger model in DeepSeek's fourth generation: a text-only mixture-of-experts model (1.6T parameters, 49B active per token) with a 1M-token window and MIT-licensed weights. It belongs to the class DeepSeek Pro, generation 4. It replaced the V4-Pro Preview of 2026-04-24 under the same API id, `deepseek-v4-pro`. DeepSeek's later V4.1-Flash is cheaper and, by DeepSeek's account, ahead of it in tests, and DeepSeek's own pages disagree about whether V4-Pro stays in service (see the [maker page](README.md#models-and-lineage)). Everything the two current DeepSeek models share (API, thinking rules, sampling, tool-call rules, safety evidence) is on the [DeepSeek page](README.md); this file says what is specific to V4-Pro.

## How to instruct it

DeepSeek publishes no prompt-writing guide for V4-Pro; the [prompting-guides section of the maker page](README.md#prompting-guides) lists what exists. This section reports what the API documentation, the model card, the technical report on the Preview and outside evaluators say, and marks where nothing is published.

### Setting up the prompt

- **System prompt.** The API takes a normal `system` message, and system messages may also appear later in a conversation on the Chat Completions format [deepseek-chat-api]. In the model's own prompt format the system text sits at the start of the sequence, tool definitions are added to it as a schema block, and for the max effort mode DeepSeek puts an extra instruction in front of it (below) [open-weight-f16] [hf-v41-encoding]. DeepSeek gives no advice on roles, personas, XML tags, Markdown or example placement for V4-Pro; its report publishes its math-evaluation templates (see the reasoning section) but no general prompt guidance.
- **How literally it follows instructions.** DeepSeek's survey of its own developers (85 people who used the Preview for agentic coding) found 52% ready to make it their main coding model and 39% leaning that way; respondents rated it satisfactory on most tasks but reported small errors, misreadings of vague prompts and occasional over-thinking [open-weight-f16] (class L, maker-run). Its report on Chinese office tasks says the model sometimes overlooks specific formatting constraints and trails Claude Opus 4.6 slightly on instruction following there [open-weight-f16].
- **Many simultaneous instructions.** An independent keyword-inclusion test (Arize, May 2026, V4 Pro before the 0813 release) saw the model start dropping named instructions near 750 at once and ignore nearly half at 2,000, the weakest of the frontier models in that test [measured-g10] (class M, one benchmark).
- **Long documents.** DeepSeek gives no placement rule. Its caching guide implies keeping stable material (system text, reference documents) at the front and varying text at the end, because only whole stored prefixes hit the cache [deepseek-context-caching].
- **Self-hosting.** No Jinja chat template ships with the weights; the repository's `encoding` folder is the reference [hf-v4-pro-0813].

### Reasoning and effort

- **The control.** Thinking is on by default at high effort. On Chat Completions `reasoning_effort` takes `low`, `high` or `max`; `none`, or `thinking: {type: disabled}`, turns thinking off (the Anthropic format sets the level with `output_config.effort`, the Responses format with `reasoning.effort`). Aliases map as minimal to low, medium and xhigh to high, ultra to max [deepseek-thinking-mode]. The reasoning arrives as `reasoning_content`.
- **What each level is for.** DeepSeek's change log says low suits simple tasks, high suits everyday agent work and max suits more complex scenarios [deepseek-changelog]. In the Preview report the three modes (non-think, high, max) were trained as separate specialists with different length penalties, and evaluated with context windows of 8K, 128K and 384K tokens; the max mode beat high on the hardest tasks [open-weight-f16].
- **Max effort and the system prompt.** For max, DeepSeek's own formatting adds an instruction at the head of the system prompt that asks for absolute maximum effort, comprehensive decomposition to the root cause, stress-testing against edge cases and adversarial scenarios, and a written record of every step, alternative and rejected hypothesis [open-weight-f16]. The API documentation does not say how it renders max effort, and the report gives no advice on writing a similar line by hand.
- **Output budget.** The API default for `max_tokens` is 64K with thinking and 128K with thinking at max; for local runs DeepSeek recommends a 384K output limit at high and max [deepseek-chat-api] [hf-v4-pro-0813]. DeepSeek raises the default limit when thinking is on, which indicates that reasoning counts against it, so a low limit can end a reply inside the reasoning.
- **Budgets and visibility.** The Anthropic format ignores `thinking.budget_tokens`; only the effort level is honoured [deepseek-anthropic-api]. The reasoning is returned as raw text; the Responses format generates no reasoning summary [deepseek-responses].
- **Interleaved thinking.** When a request carries tools, the V4 series keeps all earlier reasoning in the context across tool results and across new user messages; without tools it drops reasoning from earlier turns [open-weight-f16]. The report recommends non-thinking mode for agent frameworks that simulate tools through user messages, because those never enter the tool path.
- **Step-by-step prompting.** DeepSeek gives no instruction on this for V4-Pro. Its own math evaluations used a prompt asking for step-by-step reasoning with the final answer in a box, and a longer proof-oriented prompt for the max setting [open-weight-f16].

### Output: format, length, tone

- **Length and verbosity.** There is no verbosity control: the Responses format accepts `text.verbosity` and ignores it [deepseek-responses]. Output length is bounded by `max_tokens` and by `stop` sequences (up to 16).
- **Style, as the maker reports it.** On long Chinese professional documents the Preview model wrote developed narratives rather than bare bullet lists, followed formal numbering conventions, and added supplementary analysis and self-checks that were not asked for; it was less able to compress long input into short summaries, and its slide layouts were weak [open-weight-f16] (class L, human-rated against Opus 4.6, Preview).
- **Prefill.** Assistant-prefix completion exists in beta: end the message list with an assistant message that has `prefix: true`, and use the base URL `https://api.deepseek.com/beta`; DeepSeek's example starts a code fence and stops on the closing fence. A `reasoning_content` field on that last message carries thinking text in the same feature [deepseek-chat-api].
- **Stopping.** The finish reasons include `length` (output cut at `max_tokens` or the window) and `content_filter` (content withheld by DeepSeek's filters) [deepseek-chat-api].

### Tools and agents

- **Definitions.** Tools are function definitions with a JSON Schema. Chat Completions accepts only `function` tools; the Responses format also accepts one custom tool, `apply_patch`, for Codex, and ignores built-in tool types such as web search or computer use. Names allow letters, digits, underscore and dash, up to 128 characters [deepseek-chat-api] [deepseek-responses].
- **Reasoning must travel with the history.** With tools present, every earlier turn's `reasoning_content` goes back in the request, including turns that made no call; omission returns 400 [deepseek-thinking-mode]. Two coding clients hit this error in April and May 2026 (class A) [opencode-issue] [cursor-forum].
- **Choice and parallelism.** `tool_choice` supports `none`, `auto`, `required` and a named function, but the last two are rejected in thinking mode [deepseek-chat-api]. The Responses format always allows parallel calls; the Anthropic format ignores `disable_parallel_tool_use` [deepseek-responses] [deepseek-anthropic-api].
- **Strict schemas.** In beta, `strict: true` on every function makes the output follow the schema; it works with and without thinking (details under structured output) [deepseek-tool-calls].
- **Markup and escaping.** The V4 series writes tool calls in an XML-style block with a typed `string` attribute per parameter, which DeepSeek says reduced escaping failures [open-weight-f16].
- **Long-horizon work.** DeepSeek's pages give no persistence or context-management prompts. For its search benchmark (BrowseComp) the report reuses V3.2's discard-all context-management strategy, and it describes reasoning persistence only for tool calls [open-weight-f16].
- **Breadth of tools.** DeepSeek states the Preview did well on two benchmarks that use many tools and MCP servers (MCPAtlas and Toolathlon), which it takes as evidence the model does not only work in DeepSeek's own harness [open-weight-f16].
- **Computer use.** Not offered: the model takes no images.

### Coding

- **What the maker reports.** On an internal set of 30 research-and-development tasks, kept from about 200 collected from more than 50 engineers (PyTorch, CUDA, Rust, C++), the Preview in max mode passed 67% against 47% for Claude Sonnet 4.5, 70% for Opus 4.5, 73% for Opus 4.5 with thinking and 80% for Opus 4.6 with thinking [open-weight-f16] (class L, internal). For the 0813 release it reports Terminal-Bench 2.1 87.9, DeepSWE 62.7 and NL2Repo 61.5, run in DeepSeek Harness in minimal mode at max effort with temperature 1.0 and top-p 0.95 [hf-v4-pro-0813].
- **Harnesses.** DeepSeek's integration pages configure Claude Code (names that start `claude-opus` map to this model; its page sets effort to max and an auto-compact window of 786,432 tokens, and points the opus slot at V4.1-Flash unless changed) and Codex (through the Responses format, with a script that lists V4-Pro as option 2) [deepseek-claude-code] [deepseek-codex]. DeepSeek publishes no per-harness table for V4-Pro; its harness comparison, in the [V4.1-Flash file](deepseek-flash.md#tools-and-agents), covers V4.1-Flash only.
- **Observed.** No independent agentic-coding run of 0813 was found beyond Artificial Analysis's Terminal-Bench 4.0 component (14%, against the maker's own 12.4) [aa-cmp-pro-k3] [hf-v41-flash]. NIST's CAISI measured the earlier Preview at 74% on SWE-Bench Verified, below Opus 4.6 (79%) and GPT-5.5 (81%) [nist-caisi-v4-pro].

### Long context and retrieval

- **Limits.** 1M tokens of context; up to 384K tokens of output [deepseek-pricing]. The architecture combines compressed sparse attention and heavily compressed attention; DeepSeek says at 1M tokens the Pro model needs 27% of V3.2's per-token compute and 10% of its KV cache [open-weight-f16].
- **Retrieval quality.** In DeepSeek's tests of the Preview, retrieval stayed stable inside 128K tokens and degraded visibly beyond that; DeepSeek compares its 1M-token results with other models as follows: MRCR at 1M scored 83.5 against 76.3 for Gemini 3.1 Pro and 92.9 for Claude Opus 4.6; CorpusQA at 1M scored 62.0 against 53.8 and 71.7 [open-weight-f16] (class L). Artificial Analysis's long-context reasoning test gave 80% (AA-LCR v1.1) [aa-cmp-pro-k3]. The base model scored 51.5 on LongBench-V2, higher than V4.1-Flash's base model (45.2) [hf-v41-flash].
- **Caching.** Prefix caching is automatic. The cache-hit price is about 3% of the miss price ($0.044 against $1.32 at peak), and the `usage` object reports hit and miss tokens [deepseek-pricing] [deepseek-context-caching]. Passing a `user_id` isolates one end user's cache from others [deepseek-rate-limit].
- **Rate limit.** 500 concurrent requests per account for this model, a fifth of the Flash limit [deepseek-rate-limit].

### Structured output

- **JSON mode.** `response_format: {type: json_object}` guarantees valid JSON when the prompt itself asks for JSON and shows an example. Without that, the model may stream whitespace until the token limit; `max_tokens` has to be large enough to avoid a truncated document, and DeepSeek notes empty responses can still occur [deepseek-json] [deepseek-chat-api]. There is no schema-constrained response format; schemas apply to tool calls only.
- **Strict tool schemas (beta).** Needs the `/beta` base URL, `strict: true` on every function, every object property listed as required and `additionalProperties: false`. Supported types are object, string, number, integer, boolean, array, enum and anyOf, with `$ref` and `$def` for reuse. Strings take `pattern` and a `format` of email, hostname, ipv4, ipv6 or uuid but no length limits; numbers take const, default, minimum, maximum, exclusive bounds and multipleOf; arrays take no `minItems` or `maxItems` [deepseek-tool-calls].

### Images, audio, other inputs

DeepSeek lists vision as not supported for `deepseek-v4-pro`; the documentation does not say what an image request returns, and images are accepted only by `deepseek-flash` [deepseek-pricing] [deepseek-vision]. No audio or video input is documented.

### Sampling and API parameters

- In thinking mode `temperature`, `presence_penalty` and `frequency_penalty` are accepted and ignored, and `top_p` is raised to at least 0.95 [deepseek-thinking-mode].
- Without thinking, `temperature` runs 0 to 2 (default 1) and `top_p` is fixed at 1.0 [deepseek-chat-api].
- For self-hosting DeepSeek recommends temperature 1.0, with top-p 0.95 for agentic use and 1.0 otherwise; it ran the 0813 code-agent benchmarks at temperature 1.0 and top-p 0.95 [hf-v4-pro-0813].
- `logprobs` with up to 20 alternatives is available. Streaming usage appears on the last chunk [deepseek-chat-api].

### Migrating from the previous generation

- **From the Preview (same id).** The 0813 model is built on the Preview's structure with a DSpark speculative-decoding module attached; the API id did not change. DeepSeek's own table shows large gains: DeepSWE 12.8 to 62.7, Terminal-Bench 2.1 72.1 to 87.9, NL2Repo 38.5 to 61.5, CyberGym 52.7 to 83.3, Toolathlon-Verified 55.9 to 74.1, HLE without and with tools 37.7 and 48.2 to 42.7 and 60.0 [hf-v4-pro-0813]. Findings from the Preview period (the CAISI, FAR.AI and Arize studies) therefore describe an earlier model, and this file marks them so. Prices changed too: the Preview was listed at $1.74 input, $0.0145 cached and $3.48 output per million tokens in NIST's table, against $1.32, $0.044 and $3.96 at peak now [nist-caisi-v4-pro] [deepseek-pricing].
- **Effort.** The Preview exposed non-think, high and max modes; the API since 2026-08-13 takes `low`, `high` and `max` plus `none` [deepseek-changelog].
- **From V3.2 (the earlier `deepseek-chat` and `deepseek-reasoner`).** Those names were retired after 2026-07-24. Reasoning is now kept across user messages whenever tools are present (V3.2 dropped it at each new user message), and the tool-call markup is new for anyone who builds prompts by hand [open-weight-f16].
- **To V4.1-Flash.** The two models differ in vision, per-token price, concurrency limit, the effort scale in the weights and the DSML tag spelling (V4 writes the tag names without a space; V4.1 adds one) [hf-v41-encoding]. See the [V4.1-Flash file](deepseek-flash.md#migrating-from-the-previous-generation).

## What the system card reports

DeepSeek publishes no system card for V4-Pro. The model card on Hugging Face has a benchmark table, run settings and deployment notes; the [V4 technical report](https://arxiv.org/html/2606.19348v1) describes the Preview. Neither contains a safety evaluation, so there is nothing to report on refusals, over-refusal, reward hacking, sycophancy, deception, prompt-injection resistance or biology and cyber policies [open-weight-f16] [hf-v4-pro-0813].

What the report does measure (all maker-run, Preview, max mode unless stated): knowledge and reasoning benchmarks, long-context retrieval, agent benchmarks, Chinese writing win rates against Gemini 3.1 Pro (62.7% to 34.1% on functional writing; 60.0% in instruction following and 77.5% in writing quality on creative writing), a 30-task white-collar comparison against Opus 4.6 with a 63% non-loss rate, and a developer survey. The only cyber-related figure the maker gives is a capability score: CyberGym 83.3 for the 0813 model [hf-v4-pro-0813].

No safeguards, classifiers or deployment restrictions are named. The API returns `content_filter` as a finish reason when content is withheld, and a `user_id` field exists to help DeepSeek's safety review [deepseek-chat-api]. For evidence on safety, see the next section.

## Behaviour observed in practice

- **Safety under attack (class M).** FAR.AI, in May 2026 against the then-current V4-Pro (the Preview), found that direct harmful requests (chemical, biological, radiological, nuclear, cyber and terrorism-related) were blocked in every domain it tried, and that three jailbreaks then succeeded in 99.6% to 100% of attempts: a public jailbreak first shared for V3.2, reused without change (about 15 minutes of attacker effort, user prompt only), a false-authority framing (about 45 minutes, needs the system message) and a response-prefill attack (about 150 minutes, needs prefill access). FAR.AI says the jailbroken model kept nearly its full baseline usefulness on biology, chemistry and coding tasks. The write-up does not define a block, give sample sizes or say which effort setting was used; and it predates 0813 [far-ai-v4-pro].
- **Capability against the frontier (class M).** NIST's CAISI (2026-05-01, Preview, cloud-served at max): SWE-Bench Verified 74, PortBench 44, CTF-Archive-Diamond 32, ARC-AGI-2 semi-private 46, GPQA-Diamond 90, math contests 96 to 97, and an estimated Elo of 800 against 999 for Opus 4.6 and 1,260 for GPT-5.5. CAISI judged it about eight months behind the frontier, and noted that it scored better on benchmarks that DeepSeek's report itself uses than on CAISI's non-public ones [nist-caisi-v4-pro].
- **Speed and cost (class M).** Artificial Analysis measured 110 output tokens a second, 1.71 s to the first token and about 20 s to the first answer token at max effort; 55k output tokens per Intelligence Index task, of which 38k were reasoning; $0.67 per task and $1,122 for the full index run [aa-pro] [aa-cmp-pro-k3].
- **Factual calibration (class M).** On AA-Omniscience, which subtracts a penalty for wrong answers, the 0813 model scored 1 on a scale from -100 to 100 (V4.1-Flash scored -5) [aa-cmp-pro-k3].
- **Client breakage (class A).** Users of two third-party coding clients reported HTTP 400 errors in multi-turn tool use because the client did not send `reasoning_content` back [opencode-issue] [cursor-forum].
- **Status of the id (class L).** The id may be served by V4-Pro-0813 or may route to V4.1-Flash: the news post of 2026-09-10 and the change log of the same date conflict. [deepseek-news-260910] [deepseek-changelog]
