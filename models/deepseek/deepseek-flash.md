# DeepSeek V4.1-Flash

DeepSeek V4.1-Flash is a multimodal mixture-of-experts model: a 552B-parameter backbone that uses 8B parameters per token while reading a prompt and 16B while writing, a 1M-token window, image input, text output and MIT-licensed weights. It is the current model of the class DeepSeek Flash, generation 4.1, released 2026-09-10 as `deepseek-flash`. It replaced V4-Flash and the experimental V4-Flash-Vision-Exp, which DeepSeek calls retired, and DeepSeek's release post says tests by several parties put it ahead of the larger V4-Pro on performance, cost, speed and total runtime. It is built for agent work that sends long inputs. Everything the two current DeepSeek models share (API, thinking rules, sampling, tool-call rules, safety evidence) is on the [DeepSeek page](README.md); this file says what is specific to V4.1-Flash.

## How to instruct it

DeepSeek publishes no prompt-writing guide for V4.1-Flash; the [prompting-guides section of the maker page](README.md#prompting-guides) lists what exists. This section reports the API documentation, the model card and prompt-format reference, the technical report and outside evaluators, and says where nothing is published. DeepSeek's text about V4.1-Flash gives no prompting advice of its own beyond what is below.

### Setting up the prompt

- **System prompt and message roles.** `system`, `user`, `assistant` and `tool` roles work on Chat Completions, and system messages may appear in the middle of a conversation; the V4.1 prompt format has a dedicated token for them and treats one like a user message when it adds the assistant header [deepseek-chat-api] [hf-v41-encoding]. The vision guide allows images only in user messages (and, on the Responses format, in developer messages and tool outputs); an image in a system or assistant message returns 400. The Chat Completions reference also lists image parts in `tool` messages, which the vision guide does not mention [deepseek-vision] [deepseek-responses] [deepseek-chat-api].
- **Prompt format changes from V4.** For anyone who builds prompts or serves the weights, V4.1 changed three things: the tool-call block is renamed from `tool_calls` to `calls` and every DSML tag name now follows a space after the DSML token, the effort line is numeric, and mid-conversation system messages exist [hf-v41-encoding].
- **Where the effort line goes.** The reference encoder writes `Reasoning Effort: <number> (range 1-100, ...)` once, at the start of the conversation and only in thinking mode [hf-v41-encoding]. The V4.1 report says the effort level was trained as a line prepended to the system prompt [deepseek-v41-paper].
- **Instruction following.** DeepSeek publishes no instruction-following study for V4.1-Flash. For the older V4-Pro Preview, its developers reported misread vague prompts, and an outside test saw instructions dropped past about 750 at once [measured-g10]; neither was run on this model.
- **Examples, structure, document placement.** No DeepSeek source gives advice on XML tags, Markdown, examples or document order for V4.1-Flash. The caching guide implies placing stable text first [deepseek-context-caching].
- **Mixed text and images.** The model reads images interleaved with text in one turn, in the order given; DeepSeek's report evaluates visual agent tasks in a harness with a 512k-token context [hf-v41-encoding] [hf-v41-flash].

### Reasoning and effort

- **The control.** Thinking is on by default at high effort. `reasoning_effort` takes `low`, `high` or `max`; `none`, or `thinking: {type: disabled}`, turns thinking off. The weights accept an integer from 1 to 100; the API presets are low = 50, high = 75 and max = 100, and values in between exist only when self-hosting [deepseek-thinking-mode] [deepseek-v41-paper].
- **What the effort setting buys (DeepSeek's measurements).** Raising the effort from 25 to 100 lifted the average score on eight reasoning benchmarks from 67.1 to 76.3, DeepSWE v1.1 from 66.0 to 74.2 and Terminal-Bench 2.1 from 82.4 to 90.6, for about 2.5 times the output tokens. Accuracy rose on every one of the eight reasoning benchmarks, and response length grew two- to threefold (for example 4.6k to 11.4k tokens on AIME 2026 and 29.1k to 86.1k on MathArena Apex 2025). Most of the gain arrives early: settings between 60 and 80 reach most of the accuracy of 100 with less than half its tokens, while moving from there to 100 makes agent runs 1.6 to 1.8 times longer for a small further gain. DeepSeek concludes that max suits the hardest tasks and that a middle setting balances cost and accuracy well for routine agent work [deepseek-v41-paper] (class L).
- **Scaffold interaction.** In the appendix, output length rises with effort in every scaffold, but accuracy does not rise at every step. On DeepSWE v1.1, Claude Code's curve is the flattest and adds few tokens, while DeepSeek Harness (minimal) starts lowest and gains most at the highest token cost; on Terminal-Bench 2.1 the three scaffolds tested sit close together, and DeepSeek reads this as the scaffold mattering at least as much as the effort setting once a task is close to its ceiling [deepseek-v41-paper].
- **Budgets and visibility.** The Anthropic format ignores `thinking.budget_tokens`; only the effort level counts. Reasoning is returned as raw text in `reasoning_content`, and the Responses format creates no reasoning summary [deepseek-anthropic-api] [deepseek-responses].
- **Token output.** Default `max_tokens` is 64K with thinking, 128K at max; for self-hosting DeepSeek recommends an output limit of at least 256K [deepseek-chat-api] [hf-v41-flash]. Artificial Analysis counted 89k output tokens per task for this model (63k of them reasoning) against 55k for V4-Pro and 48k for Kimi K3 [aa-cmp-flash-k3] [aa-cmp-pro-k3].
- **Interleaved thinking.** As on V4-Pro, a request with tools keeps all earlier reasoning in the context; a request without tools drops it, and the reference encoder's `drop_thinking` option does the same when self-hosting [hf-v41-encoding].
- **Step-by-step prompting.** DeepSeek gives no instruction on this for V4.1-Flash.

### Output: format, length, tone

- **Verbosity.** No verbosity setting: the Responses format accepts `text.verbosity` without effect [deepseek-responses].
- **Prefill.** Assistant-prefix completion works in beta on the `/beta` base URL, with `stop` sequences to cut the continuation [deepseek-chat-api].
- **Formatting defaults.** DeepSeek publishes none.
- **Stopping.** `finish_reason` is `length` when `max_tokens` ends the output [deepseek-chat-api].

### Tools and agents

- **Definitions and rules.** Function tools, `reasoning_content` that must travel with the history whenever tools are present, strict schemas in beta, parallel calls, and the thinking-mode limits on `tool_choice` are described on the [maker page](README.md#family-wide-behaviour) and in the [tool-calls guide](https://api-docs.deepseek.com/guides/tool_calls); they are the same for this model [deepseek-tool-calls] [deepseek-thinking-mode].
- **Image results from tools.** On the Responses format, a tool's output may itself contain an image, which the model reads; this is new relative to V4-Pro, which has no vision [deepseek-responses].
- **Trained across harnesses.** DeepSeek reports reinforcement-learning runs that trained jointly across several versions of Claude Code, and across OpenCode, Pi and DeepSeek Harness in standard and PTC modes, and says it merged checkpoints from runs on different scaffolds. The harness is MIT-licensed on GitHub. Its three modes are minimal (one bash tool), standard (26 function tools including web search and fetch) and PTC (a `run_code` tool that runs TypeScript programs over 24 underlying tools) [deepseek-v41-paper] [deepseek-harness-repo].
- **Multi-agent work.** With DeepSeek Harness in its Agent Team mode (a lead agent that spawns persistent teammates), ProgramBench Almost@1 rose to 30.04% at 8 hours against 20.39% for a single agent, and FrontierSWE v2 Mean@5 to 32.90% at 20 hours against 28.20% [deepseek-v41-paper] (class L, preliminary).
- **Long-horizon limits.** DeepSeek gives no persistence prompts. Its evaluations cap agents at 500 steps and run at a 1M-token context [hf-v41-flash].
- **Injected instructions.** A study that ran DeepSeek Harness with V4-Flash (V4.1-Flash's predecessor on the same API alias) as the backend placed instructions in 16 content channels over 14,560 runs: a rule-based judge counted full attack success in 5.6% and partial compliance in 2.0%, and an LLM judge 5.3% and 7.3%. The highest rates for single conditions were 25.5% for hidden Unicode in file mode and 16.0% for the skills channel in file mode (rule-based judge), and 17.0% for fake-completion text in text mode (LLM judge); 68.4% of runs ended in an explicit refusal (rule-based judge), and the authors recommend controls between untrusted content and sensitive actions [ipi-dsh-paper] (class M, other model version).
- **Computer use.** DeepSeek publishes no computer-use result for this model. It does report visual agent tasks (below).

### Coding

- **Harness spread (DeepSeek's table).** At max effort the same weights score differently by scaffold. DeepSWE v1.1: mini-SWE 74.2, DeepSeek Harness minimal 72.6, standard 70.5, PTC 67.6, Claude Code 69.8, Pi 66.2, Codex 65.6, OpenCode 65.5. Terminal-Bench 2.1: DeepSeek Harness minimal 90.6, mini-SWE 90.3, Claude Code 88.0, Pi 86.1, standard and PTC 85.8, OpenCode 85.0, Codex 84.1 [hf-v41-flash] (class L; DeepSWE ran each task 8 times, Terminal-Bench 3 times, no network access for Terminal-Bench). The simplest harnesses (one bash tool) scored highest.
- **Mini-SWE's rules.** DeepSeek's port of mini-swe-agent has a single bash tool, requires a tool call on every turn and ends on a submission marker [deepseek-v41-paper].
- **Claude Code and Codex.** DeepSeek's Claude Code page sets effort to max, an auto-compact window of 786,432 tokens, the 1M-context suffix for the main, opus and sonnet slots, and no suffix for haiku and subagents. Its Codex script offers this model as option 1 and declares image input [deepseek-claude-code] [deepseek-codex].
- **Independent.** Artificial Analysis measures 27% on Terminal-Bench 4.0 against DeepSeek's own 31.2; the leaders in DeepSeek's table score 51.8 (Claude Opus 5) and 39.9 (GPT-5.6 Sol) [aa-cmp-flash-k3] [hf-v41-flash]. Enclave's vendor-run hacking benchmark had the model compromise all 11 vulnerable targets (cost $4.65, 266.2M of 268.3M input tokens cached) while four fixed controls stayed secure; six runs used the planned weakness and five used extra routes the vulnerable builds allowed [enclave-flash] (class M, vendor-run). A practitioner site relaying hands-on tests (class A) reported code that looked right and failed on inspection [mindstudio-flash].

### Long context and retrieval

- **Limits.** 1M tokens of context, up to 384K output [deepseek-pricing].
- **Design.** Cross-layer KV reuse in compressed sparse attention 2 and FP4 KV caching cut the global KV cache to 890 bytes per token (about a quarter of V4-Flash's), and the causal encoder-decoder layout means only 8B parameters are active per token while reading a prompt; decode compute stays nearly flat as context grows from 4K to 1M tokens (a 25% increase) [deepseek-v41-paper].
- **Retrieval quality.** DeepSeek published no MRCR or CorpusQA result for this model. The base model scored 45.2 on LongBench-V2, level with V4-Flash's base (44.7) and below V4-Pro's base (51.5) [hf-v41-flash]. Artificial Analysis's long-context reasoning test gave 84% (AA-LCR v1.1), above V4-Pro's 80% [aa-cmp-flash-k3] [aa-cmp-pro-k3].
- **Stated risks.** DeepSeek says two new mechanisms can degrade the model in untested boundary cases: selection errors in the sparse attention and approximate state rebuilding after a cache resumes. It names sparse retrieval over long contexts and cache-resumption boundaries as the next things to stress-test [deepseek-v41-paper].
- **Caching.** Automatic prefix caching; a cache hit costs about 2% of a miss ($0.006 against $0.30 at peak) [deepseek-pricing] [deepseek-context-caching].
- **Rate limit.** 2,500 concurrent requests per account [deepseek-rate-limit].

### Structured output

Same as V4-Pro. JSON mode (`response_format: {type: json_object}`) needs a prompt that asks for JSON and shows an example, a `max_tokens` that leaves room, and tolerance for occasional empty replies. Strict tool schemas (beta, `/beta` base URL) work with and without thinking and accept object, string, number, integer, boolean, array, enum and anyOf. There is no response format that takes a JSON Schema [deepseek-json] [deepseek-tool-calls]. The [V4-Pro file](deepseek-v4-pro.md#structured-output) lists the supported keywords.

### Images, audio, other inputs

- **Formats and routes.** JPEG, PNG, GIF and WebP, detected from file content. Three routes: a base64 data URL, an http(s) link (URL up to 8,192 characters, file up to 32 MiB, download within 60 seconds) or a Files API id (up to 64 MiB) [deepseek-vision].
- **Detail and cost.** `detail: low` downsizes to 512 by 512; `high`, `original` and `auto` keep the original. Before inference an image is scaled up if below about 544 by 544 and scaled down to about 1300 by 1300 pixels in total area otherwise, so one image costs at most 1,024 tokens whatever its size [deepseek-vision].
- **Limits.** 48 MiB request body; 600 images per request; at most 64 MiB of images inline (200 MiB with Files API ids); at most 8,192 pixels a side, falling to 4,096 when a request has 15 or more images [deepseek-vision].
- **Quality.** The base model scored MMMU-Pro 56.5, CVBench 77.9, DocVQA 95.6 and RefCOCO 86.0; the instruct model scored 78.9 on Chartography, 89.6 on BabyVision and 49.0 on ZeroBench-main with tools, below Claude Opus 5 on all three (84.0, 94.1 and 52.0) and above Kimi K3 on all three (68.1, 85.7 and 41.0) in DeepSeek's table [hf-v41-flash]. DeepSeek's report says a measurable gap to the leading closed models remains in vision [deepseek-v41-paper].
- **Training.** The vision encoder (DeepSeek-ViT) was trained on images from 544 by 544 to 1344 by 1344 pixels and downsamples each 3 by 3 block, cutting visual tokens ninefold [deepseek-v41-paper].
- **Audio and video.** Not supported or documented.

### Sampling and API parameters

Same rules as on V4-Pro: in thinking mode `temperature` and the penalties are ignored and `top_p` has a floor of 0.95; without thinking `temperature` runs 0 to 2 and `top_p` is fixed at 1.0. For self-hosting DeepSeek recommends temperature 1.0, top-p 0.95 or 1.0, and `max_tokens` of at least 256K; every published run used temperature 1.0 and top-p 0.95 [hf-v41-flash] [deepseek-thinking-mode].

### Migrating from the previous generation

- **Ids.** `deepseek-flash` is the id to use. `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp` still work and are served by this model at its price; `deepseek-chat` and `deepseek-reasoner` were retired after 2026-07-24 [deepseek-pricing] [deepseek-changelog]. The id carries no version, so the model behind it moves with each Flash release.
- **Quality shifts from V4-Flash (0731) in DeepSeek's tables.** DeepSWE 54.4 to 74.2, Terminal-Bench 2.1 82.7 to 90.6, Terminal-Bench 4.0 7.0 to 31.2, CyberGym 76.7 to 88.1, AutomationBench 37.7 to 54.8, HLE with tools 51.5 to 63.9; HLE without tools on the text-only subset 37.8 to 39.1 (V4.1-Flash scores 36.8 on the full set, which V4-Flash has no published score for) [hf-v41-flash]. On the base models, MATH rose from 57.4 to 61.1 while MGSM fell from 85.7 to 80.2 [hf-v41-flash].
- **Vision.** Images are native; the experimental vision variant is retired. Images work only in user messages [deepseek-vision].
- **Effort and prompts.** The effort scale in the weights is now numeric; prompt builders must use the new DSML spelling [hf-v41-encoding].
- **Price.** Lower than V4-Flash's: $0.30 input, $1.20 output and $0.006 cached at peak, half that off-peak [deepseek-pricing] [deepseek-news-260910].
- **Behaviour to retest.** Token use per task rose (about 250M output tokens across Artificial Analysis's index run) and the thinking-with-tools rules are unchanged [aa-flash].

## What the system card reports

DeepSeek publishes no system card for V4.1-Flash. The [V4.1 technical report](https://arxiv.org/html/2609.19969) covers architecture, training, evaluation and limitations, and has no safety, alignment, refusal, jailbreak or prompt-injection evaluation and no biology or cyber policy [deepseek-v41-paper].

What it measures (maker-run, max effort unless stated): reasoning, coding and agent benchmarks, the effort sweep, scaffold robustness, multimodal tests, a multi-agent experiment, and base-model scores. It claims parity with closed frontier models on most benchmarks and that the model can complete over 95% of real-world tasks, and says that this parity does not imply the same strength on hard reasoning and edge cases. Its own table shows the gaps: Humanity's Last Exam without tools 36.8 against 56.3 for Claude Opus 5, ProgramBench 20.3 against 37.0, Terminal-Bench 4.0 31.2 against 51.8 [hf-v41-flash].

Dual-use capability: the report publishes CyberGym 88.1, SEC-Bench Pro 62.8 and ExploitGym 15.3 and asks the community to apply the cyber capability responsibly, for defensive work [deepseek-v41-paper]. No refusal behaviour, classifier or usage restriction is described; the API can return `content_filter` as a finish reason [deepseek-chat-api].

Safety evidence therefore comes from outside: see the next section and the [maker page](README.md#family-wide-behaviour).

## Behaviour observed in practice

- **Speed and cost (class M).** Artificial Analysis: 211 output tokens a second, 1.09 s to the first token, about 10.6 s to the first answer token and 13 s end to end at max effort; $0.27 per Intelligence Index task and $477 for the run, against $2.00 and $3,658 for Kimi K3 [aa-cmp-flash-k3].
- **Factual calibration (class M).** AA-Omniscience, which subtracts a penalty for wrong answers, scored -5 on a scale from -100 to 100, against 1 for V4-Pro and 20 for Kimi K3 [aa-cmp-flash-k3] [aa-cmp-pro-k3].
- **Offensive-security task (class M, vendor-run).** Enclave's benchmark: 11 of 11 vulnerable targets compromised, four controls intact, with the caveat that five runs used extra routes the benchmark had left open [enclave-flash].
- **Injection resistance (class M, predecessor model).** About 5% to 6% full attack success under a rule-based judge in a 14,560-run study of DeepSeek Harness with V4-Flash [ipi-dsh-paper].
- **Maker's own caution (class L).** The report says near-parity on benchmarks does not mean frontier-level strength on difficult reasoning and edge cases [deepseek-v41-paper].

## Open questions

- Whether the maker will publish a system card or a safety evaluation, and how V4.1-Flash behaves under adversarial and injected prompts (the only injection study found used its predecessor).
- Whether the sparse-attention and cache-resumption risks that DeepSeek names show up in long, resumed agent sessions.
- Independent agentic-coding results on SWE-Bench Pro or the METR time horizon; Artificial Analysis's coding-agent index showed no DeepSeek entry.
- Whether a V4.1-Pro will change the Flash price, id or position (see the [maker page](README.md#open-questions)).
