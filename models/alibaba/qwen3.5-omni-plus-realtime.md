# Qwen3.5-Omni-Plus-Realtime

Qwen3.5-Omni-Plus-Realtime is the larger realtime tier of the 3.5 generation of Alibaba's Qwen Omni line. It takes streaming audio, images or video and text. It gives back speech and text over WebSocket, WebRTC or AOQ. The 3.5 omni release came in Plus and Flash tiers. The Flash tier is in the card [Qwen3.5-Omni-Flash](qwen3.5-omni-flash.md), which covers its HTTP and realtime endpoints. The 3.8 generation is [Qwen3.8-Omni-Flash-Realtime](qwen3.8-omni-flash-realtime.md). This file says what differs from it. Family-wide rules are in the [Alibaba README](README.md) [qwencloud-page-35plus-rt] [qwencloud-s2s-models].

## How to instruct it

### Setting up the prompt

The `instructions` field of `session.update` is the system message. It sets the role and the goal. The guide's example is a hotel customer-service agent with the rule to give no unconfirmed information [qwencloud-rt-guide]. The technical report says the training data uses the ChatML format and that a third training stage, interaction-aligned reinforcement learning, targets three faults in long chats: unplanned language switches, an unstable persona and weaker instruction following over long contexts [arxiv-qwen3-5-omni]. Alibaba gives no other prompt-writing advice for this model.

### Reasoning and effort

The model has no thinking mode and no effort control. Alibaba's table of speech models shows no thinking support for any realtime omni model [qwencloud-s2s-models].

### Output: format, length, tone

`modalities` takes `["text"]` or `["text", "audio"]`. For this model the billing counts only the audio when speech is on. The page says the output text is not charged then [qwencloud-page-35plus-rt] [qwencloud-rt-guide]. The page lists the text-only output at US$12.4 per million tokens and the speech output at US$62 [qwencloud-page-35plus-rt]. Alibaba gives no length or tone advice.

### Tools and agents

The Plus realtime model supports function calling through `session.tools` and web search through `enable_search` (the `agent` strategy). The two cannot run at the same time [qwencloud-rt-guide] [qwencloud-client-events]. It does not list MCP servers. The 3.8 model does. On the maker's own tool-use test (OmniGAIA), the report scores the Plus model at 57.2 and the Flash model at 33.9 [arxiv-qwen3-5-omni].

### Coding

Alibaba publishes no coding guidance for this model. The report says the model can write code from spoken and visual instructions. It gives no score for that ability [arxiv-qwen3-5-omni].

### Long context and retrieval

The model page gives a 262K context, with up to 196K input and 65K output [qwencloud-page-35plus-rt]. Each response reads the retained history again, so input tokens add up turn by turn. The session keeps 100 audio turns or 600 seconds of audio, and 50 video turns or 240 seconds of video [qwencloud-rt-guide]. The report claims over 10 hours of audio and over 400 seconds of 720p video for the model family [arxiv-qwen3-5-omni].

### Structured output

The model page lists structured outputs as a feature. The realtime guide has no rules for it [qwencloud-page-35plus-rt].

### Images, audio, other inputs

Input audio is PCM, 16-bit, mono, 16 kHz by default. Output audio is PCM, 24 kHz by default. The session can set 8, 16, 24 or 48 kHz, or a WAV container, for each direction before audio starts. Image frames go in as JPG at about one per second over WebSocket. Over WebRTC they travel on the video track. Speech recognition covers 113 languages and dialects, and speech output covers 36 [qwencloud-rt-guide] [qwencloud-client-events]. The report gives these maker results for the Plus model: DailyOmni 84.6 and VideoMME with audio 83.7 on audio-visual tests [arxiv-qwen3-5-omni].

### Voice: turn-taking, interruption and speech style

**Turn detection.** `server_vad` is the default. The guide recommends `semantic_vad` for the Qwen3.5 realtime models. Its example uses `threshold` 0.5 and `silence_duration_ms` 800. The ranges are -1.0 to 1.0 and 200 to 6000 ms. The guide's comment says to raise the threshold in noisy places and lower it in quiet ones. A lower silence value gives faster replies but may fire on short pauses [qwencloud-rt-guide] [qwencloud-client-events].

**Silence prompts.** `idle_timeout_ms` (5000 to 30000 ms, `server_vad` mode only) makes the model speak first after the user stays silent past the limit. The timer starts when the last reply audio finishes playing [qwencloud-client-events].

**Interruption.** Alibaba calls the feature semantic interruption. The model tries to tell a real attempt to take the floor from a backchannel or background noise. The server sends `input_audio_buffer.speech_started` when the user starts to speak. The client must clear its own playback buffer over WebSocket. The guide advises headphones, because echo can trigger an interruption [qwencloud-rt-guide]. Artificial Analysis has no conversational-dynamics run for this model, so no independent number supports the claim [aa-s2s].

**Voice and style.** The model has 55 preset voices: 47 multilingual and 8 dialectal. The default is `Tina`. The model also takes cloned voices. The guide says the model obeys spoken commands that change volume, speed and emotion, for example "speak faster", "louder" or "in a happy tone" [qwencloud-rt-guide]. The report describes the same control and adds that the speech generator takes a prompt that holds a text description of the target voice [arxiv-qwen3-5-omni].

**Session handling.** One WebSocket session lasts up to 120 minutes. The report gives a first-packet latency of 435 ms for audio input and 651 ms for video input on the Plus model. The set-up was internal and used one concurrent request [arxiv-qwen3-5-omni]. Artificial Analysis measured 2.64 seconds to first audio on its own set [aa-s2s]. The two figures measure different things.

### Sampling and API parameters

`temperature` and `top_p` exclude each other. The rate limit on the model page is 100K tokens and 60 requests per minute [qwencloud-page-35plus-rt] [qwencloud-client-events].

### Migrating from the previous generation

The 3.5 realtime models replaced `qwen3-omni-flash-realtime`. That older model keeps only 8 dialogue turns, has no function calling and no web search, and has no semantic VAD [qwencloud-rt-guide] [qwencloud-s2s-models]. The newer 3.8 model drops `idle_timeout_ms` and adds MCP, multichannel audio and video aggregation [qwencloud-client-events].

## What the system card reports

Alibaba has published no system card for this model. The technical report has no safety or refusal section. It reports tests of capability only [arxiv-qwen3-5-omni].

## Behaviour observed in practice

Artificial Analysis measured the model on its Speech to Speech page (read 2026-10-03). It scored 98.7% on speech reasoning and took 2.64 seconds on average to the first audio. Its arena preference Elo was 859, and its task success rate was 62.0% [aa-s2s]. The page lists no conversational-dynamics or tau-voice result for the model. No practitioner report was found.

## Benchmarks

Independent: the three Artificial Analysis results above [aa-s2s]. Maker: the technical report claims the best results of its set on 215 audio and audio-visual subtasks. Alibaba ran those tests itself [arxiv-qwen3-5-omni].

## Open questions

- Whether the model is full-duplex in the sense of the Artificial Analysis test. No run exists.
- Why Artificial Analysis lists lower audio prices than the QwenCloud page.
- Whether Alibaba will retire this tier when it replaces the 3.5 generation.
