# Qwen3.6-27B

Qwen3.6-27B is a dense, 27-billion-parameter vision-language model from Alibaba, released as open weights under Apache-2.0
on 2026-04-22 and hosted on QwenCloud. It sits in the Qwen open-weights class at generation 3.6. Alibaba aims it at agentic
coding, repository-level reasoning and front-end work, and it takes text, images and video. It replaced Qwen3.5-27B, and
Qwen3.8-27B (2026-08-14) followed it [hf-qwen3-6-27b] [qwencloud-page-36-27b] [qwencloud-changelog]. Family-wide rules are
in the [Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

Alibaba gives no guidance on writing a system prompt, on roles, on XML or Markdown structure, on examples or on where to place
long documents for this model. The README summarises QwenCloud's general prompt-design page [qwencloud-prompting]. The model
card and the chat template give the mechanics that do exist. The template puts a system message first and raises an error if a
system message appears later, or if a system message holds an image or a video. With tools, it adds the tool definitions
and the tool-call format to the system turn. The model card says it does not officially support the `/think` and `/nothink`
switches of Qwen3 [hf-qwen3-6-27b] [hf-qwen3-6-27b-template]. For benchmarking, the card suggests asking for step-by-step
reasoning with a boxed final answer on maths problems, and a JSON `answer` field holding only the choice letter on
multiple-choice questions [hf-qwen3-6-27b].

### Reasoning and effort

- **Thinking is on by default.** The model writes a `<think>` block before its answer. To switch it off, set
  `enable_thinking` to false: in the template's `chat_template_kwargs` for a self-hosted server, or as a top-level
  `enable_thinking` on QwenCloud. The template then adds an empty think block [hf-qwen3-6-27b] [hf-qwen3-6-27b-template].
- **No effort levels.** The template has no effort sentence, and QwenCloud documents `reasoning_effort` for the Qwen3.8 models
  only [hf-qwen3-6-27b-template] [qwencloud-api-chat]. `thinking_budget` applies on QwenCloud, whose table gives a budget
  of 80k [qwencloud-thinking] [qwencloud-models].
- **Preserved thinking.** By default only the thinking of the latest user turn stays in the history. The card says Qwen3.6
  was trained to use thinking traces from earlier messages and gives the `preserve_thinking` option (in
  `chat_template_kwargs`, or as a top-level setting on QwenCloud). Alibaba says it helps agent work, can lower total token use
  and improves key-value cache reuse. It is off unless set [hf-qwen3-6-27b] [hf-qwen3-6-27b-template].
- **Length.** The card advises at least 128K of context so that thinking keeps working, and an output of 32,768 tokens for most
  queries, or 81,920 for competition-level maths and code [hf-qwen3-6-27b].

### Output: format, length, tone

The card gives no formatting or tone guidance. It suggests `presence_penalty` between 0 and 2 to curb endless repetition, and
warns that a higher value can cause language mixing and a small loss of quality [hf-qwen3-6-27b]. The hosted output limit is
65K, and OpenRouter lists 81,920 tokens [qwencloud-page-36-27b] [openrouter-models].

### Tools and agents

The card says the model is strong at tool calling and points to Qwen-Agent (with MCP configuration) and Qwen Code. The card's
server commands add a tool-call parser: `qwen3_coder` for SGLang and vLLM, with the `qwen3` reasoning parser. The template
wraps a call as a `<tool_call>` block holding a `<function=name>` element with `<parameter=name>` elements, and wraps results
as `<tool_response>` blocks in a user turn. With preserved thinking, the reasoning of earlier assistant turns goes back into
the prompt [hf-qwen3-6-27b] [hf-qwen3-6-27b-template]. On QwenCloud function calling is supported and built-in tools are not
[qwencloud-changelog] [qwencloud-models]. In thinking mode `tool_choice` accepts `auto` or `none` only
[qwencloud-fn-calling]. No guidance on subagents or context management is published.

### Coding

Alibaba's card reports, as maker runs: SWE-bench Verified 77.2, SWE-bench Pro 53.5 (on a re-run set with corrected tasks, so
not the Scale V2 set), SWE-bench Multilingual 71.3, Terminal-Bench 2.0 59.3, SkillsBench 48.2, NL2Repo 36.2 and QwenWebBench 1487.
The footnotes give an internal scaffold with bash and file-edit tools (temperature 1.0, top_p 0.95, 200K context) for the
SWE-bench runs; Harbor with Terminus-2, a 3-hour timeout and 32 CPUs for Terminal-Bench; OpenCode on 78 tasks for SkillsBench;
and Claude Code with at most 900 turns for NL2Repo [hf-qwen3-6-27b]. For precise coding such as web development the card
suggests temperature 0.6 [hf-qwen3-6-27b]. Independent runs: Artificial Analysis measured Terminal-Bench 2.1 at 60.7% and
Terminal-Bench 4.0 at 0%; Epoch AI measured SciCode 37% [aa-qwen3-6-27b] [epoch-qwen3-6-27b].

### Long context and retrieval

The native context is 262,144 tokens, extensible to about 1,010,000 with YaRN at factor 4.0. Every common engine applies static
YaRN, which can lower quality on short inputs, so the card advises setting it only when long inputs are needed and choosing a
factor near the typical length (2.0 for about 524,288 tokens) [hf-qwen3-6-27b]. Artificial Analysis's long-context reasoning
test (AA-LCR) gave 77.3 [aa-qwen3-6-27b]. The hosted model has a 260K maximum input and rate limits of 1M tokens and 600
requests per minute; the page shows no cache price [qwencloud-page-36-27b].

### Structured output

QwenCloud's guide lists the Qwen3.6 open-source series for JSON Object mode in non-thinking mode only. In thinking mode the
setting raises no error, but the JSON may not be valid, and the guide suggests a second pass by a cheap model to repair it. The
model is not on the JSON Schema list [qwencloud-structured]. For a self-hosted server the model card documents no structured
output setting.

### Images, audio, other inputs

Text, image and video in; text out. The card gives image and video examples through an OpenAI-compatible server. The default
video sampling is 2 frames per second. Setting `longest_edge` in the video preprocessor to 469,762,048 allows hour-long video
at about 224k video tokens. The card's vision results include MMMU 82.9, AndroidWorld 70.3 and VideoMME 87.7 (maker runs). On
vLLM a `--language-model-only` flag skips the vision encoder to free memory for cache [hf-qwen3-6-27b] [vllm-recipe-36-27b].

### Sampling and API parameters

Alibaba's card gives three sets of values. Thinking mode for general tasks: temperature 1.0, top_p 0.95, top_k 20, min_p 0,
presence_penalty 0, repetition_penalty 1. Thinking mode for precise coding: temperature 0.6 with the other values unchanged.
Non-thinking mode: temperature 0.7, top_p 0.80, top_k 20, presence_penalty 1.5. It adds that support for sampling parameters
varies by engine [hf-qwen3-6-27b]. On QwenCloud, the API reference gives a default `presence_penalty` of 1.5 for Qwen3.6 in
non-thinking mode, and a temperature range from 0 up to but not including 2 [qwencloud-api-chat]. The vLLM recipe adds
`--reasoning-parser qwen3`, `--tool-call-parser qwen3_coder`, optional multi-token prediction and prefix caching, and notes that
prefix caching with the model's linear-attention layers is experimental [vllm-recipe-36-27b].

### Migrating from the previous generation

The previous model is Qwen3.5-27B. QwenCloud says the 3.6 model improves agentic coding and STEM reasoning, and spatial
intelligence, object localisation and detection in vision [qwencloud-page-36-27b]. Alibaba's card compares the two: SWE-bench
Verified 77.2 against 75.0, SWE-bench Pro 53.5 against 51.2, Terminal-Bench 2.0 59.3 against 41.6, SkillsBench 48.2 against
27.2 and NL2Repo 36.2 against 27.3 (maker runs) [hf-qwen3-6-27b]. The new item is `preserve_thinking`. Alibaba's own
numbers put the 27B above Qwen3.5-397B-A17B on the same coding table (for example Terminal-Bench 2.0 59.3 against 52.5)
[hf-qwen3-6-27b].

## What the system card reports

Alibaba has published no system card for Qwen3.6-27B. The Hugging Face page is a model card with benchmarks and settings, and
it holds no safety, refusal, alignment or reward-hacking findings. QwenCloud moderates requests to the hosted model, as the
README says; a self-hosted copy has no such filter [hf-qwen3-6-27b].

## Behaviour observed in practice

- **Index, verbosity and speed (M).** Artificial Analysis (index v4.3.2): 21, with 160M output tokens against a median of 82M
  for open models of its size class, 55.8 output tokens per second, and US$0.62 per index task. The page marks the model as
  superseded by Qwen3.8 27B [aa-qwen3-6-27b].
- **Knowledge reliability (M).** Artificial Analysis: accuracy 19.6% and a hallucination rate of 49.3% on its knowledge test
  [aa-qwen3-6-27b].
- **Capability index (M).** Epoch AI: 146, rank 70 of 253 on 2026-10-03; GPQA Diamond 86%, OTIS Mock AIME 91%, FrontierMath
  Tiers 1-3 35% [epoch-qwen3-6-27b].
- **Local use (A).** On the day of release, one practitioner ran a 4-bit community quantisation (Q4_K_M, 16.8 GB) in
  llama.cpp's server with a 65,536-token context and measured about 25 output tokens per second on two SVG-drawing tasks
  (4,444 and 6,575 tokens). He judged the first result very good for a local model of that size. The post gives no
  hardware [willison-36-27b].
- **Agreement between sources (M).** GPQA Diamond reads 87.8 (maker), 84.2 (Artificial Analysis) and 86 (Epoch AI)
  [hf-qwen3-6-27b] [aa-qwen3-6-27b] [epoch-qwen3-6-27b].

## Benchmarks

Independent: Artificial Analysis index 21; Terminal-Bench 4.0 0%; Terminal-Bench 2.1 60.7%; GPQA Diamond 84.2; Humanity's Last
Exam 23.1; SciCode 42.8; IFBench 67.6; AA-LCR 77.3 [aa-qwen3-6-27b]. Epoch AI: capability index 146; FrontierMath Tiers 1-3 35%;

[aa-coding-agents]. Maker runs, each with its scaffold and settings, are in the card.

## Open questions

- Whether Q4 and lower quantisations keep the maker's coding scores; no independent test of this model was found.
- Alibaba's blog post for the release renders by script and was not read, so any detail only it holds is missing.
- Whether Ollama, LM Studio and Jan carry the model in a form that applies the thinking settings correctly.
