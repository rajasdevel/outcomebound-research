# Qwen3.7-Max

Qwen3.7-Max is Alibaba's closed Max-class model of generation 3.7. QwenCloud's changelog dates its release to
2026-05-21. The page for the bare id lists text input and text output, a 1M-token context and thinking on by default.
Alibaba presents it as a model for coding agents, office work and long autonomous runs
[qwencloud-page-37max] [qwencloud-changelog] [blog-qwen3-7]. It follows the preview model Qwen3.6-Max-Preview, and
Qwen3.8-Max (2026-08-03) followed it. Family-wide rules are in the [Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

Alibaba gives no model-specific guidance on system prompts, roles, structure, examples or where to put long documents
for this model. QwenCloud's general prompt-design page is summarised in the README [qwencloud-prompting]. The launch post
holds one prompt instruction. For reasoning tasks it recommends a system prompt that opens "Reasoning effort is set to
xhigh. Please think carefully through the task" and then asks the model to check key assumptions, weigh plausible
alternatives and put correctness, consistency and clarity of the final answer first [blog-qwen3-7].
A footnote of the same post says that, in its terminal-task runs, each turn starts with a token that lets the model
decide whether to use extended thinking. The post does not name the token [blog-qwen3-7].
QwenCloud's model-selection page does not list the model among its recommended models. It stays in the page's full
table and in its list of 1M-context models [qwencloud-models].

### Reasoning and effort

- **Control.** Thinking is on by default. `enable_thinking` switches it off per request. `thinking_budget` caps the
  reasoning tokens; the API reference gives the model's maximum as the default and the model table gives a thinking
  budget of 256k [qwencloud-thinking] [qwencloud-api-chat] [qwencloud-models] [qwencloud-changelog].
- **No effort levels.** QwenCloud's API reference documents `reasoning_effort` for the Qwen3.8 models and not for
  Qwen3.7. The system sentence above is the nearest equivalent that Alibaba gives for 3.7-Max
  [qwencloud-api-chat] [blog-qwen3-7].
- **Preserved thinking.** The launch post says the model supports `preserve_thinking`, which keeps the thinking of all
  earlier turns in the messages, and calls it recommended for agentic tasks. The API reference lists the model as
  supporting it, and marks the setting on by default only for Qwen3.8 models. In a tool loop, QwenCloud says to send
  the earlier `reasoning_content` back with the tool results and says that leaving it out lowers accuracy
  [blog-qwen3-7] [qwencloud-api-chat] [qwencloud-thinking].
- **Calls.** The thinking guide lists Qwen3.7-Max among the models that accept non-streaming calls. In thinking
  mode `max_tokens` is limited to 1 through 32,768, so QwenCloud advises `max_completion_tokens`, which covers
  reasoning and reply together [qwencloud-thinking].
- **Cost of thinking.** Thinking tokens are billed as output tokens. Artificial Analysis counted 120M output tokens for
  its index run, against a median of 81M for its comparison group [qwencloud-thinking] [aa-qwen3-7-max].

### Output: format, length, tone

Alibaba gives no formatting, length or tone guidance for this model. The model page gives a 131K output limit, also with
thinking. QwenCloud's model table gives 64k, The Batch's write-up of the launch says 64,000 and the launch post's
OpenClaw configuration uses 65,536, so the documents disagree [qwencloud-page-37max] [qwencloud-models] [batch-37max]
[blog-qwen3-7]. Prefix completion (partial mode) is listed as a feature [qwencloud-page-37max]. OpenRouter lists the model with a 131,072-token
output limit [openrouter-models].

### Tools and agents

- **Function calling** is supported. In thinking mode `tool_choice` accepts `auto` or `none` only
  [qwencloud-fn-calling] [qwencloud-models].
- **Built-in tools.** The model page lists the code interpreter, web extractor and web search, all through the Responses
  API. The Chat Completions parameter `search_strategy` accepts `agent` (several search and model rounds) for the
  Qwen3.7-Max series, and `agent_max`, which adds web extraction, in thinking mode. With either setting only the
  search-sources option is available and the other web-search features are off [qwencloud-page-37max] [qwencloud-api-chat].
- **Harnesses.** The launch post says the benchmark scores come from several agent scaffolds and that the model works
  across Claude Code, OpenClaw and Qwen Code. Its Claude Code set-up uses the Anthropic-compatible endpoint and sets
  both the main and the small-fast model variables to `qwen3.7-max` [blog-qwen3-7].
- **Long runs.** The post reports a 35-hour autonomous run that optimised an attention kernel on accelerator hardware
  not seen in training: 432 kernel evaluations and 1,158 tool calls ended at a 10.0 times geometric-mean speedup over
  the reference. Under the same conditions it reports GLM 5.1 at 7.3 times, Kimi K2.6 at 5.0 times, DeepSeek V4 Pro at
  3.3 times and Qwen3.6-Plus at 1.1 times. It says the runs that stopped early did so because the agent made no tool call
  for five rounds in a row, which is a stop rule of the run, not a model setting. This is a maker result [blog-qwen3-7].
- **Business simulation.** On YC-Bench, a year-long start-up simulation, the post gives revenue of US$2.08M for 3.7-Max,
  against US$1.05M for Qwen3.6-Plus and US$352K for Qwen3.5-Plus (maker result) [blog-qwen3-7].
- No guidance on subagents, context management or computer use is published; the model takes text only.

### Coding

All coding numbers are maker runs unless marked. Settings from the post's footnotes: SWE-bench runs use an internal
scaffold with bash and file-edit tools at temperature 1.0, top_p 0.95 and a 200K context. SWE-bench Pro was re-run on a
set whose problem tasks Alibaba corrected, so it is not the Scale V2 set. Terminal-Bench 2.0 uses Harbor with Terminus-2
and a 5-hour timeout. NL2Repo runs through Claude Code with shell commands that fetch the target repository disabled
[blog-qwen3-7]. The scores are in the card: SWE-bench Pro 60.6, SWE-bench Verified 80.4, SWE-bench Multilingual 78.3,
Terminal-Bench 2.0 69.7 and NL2Repo 47.2. An independent run differs in size: Epoch AI measured SWE-bench Verified at
77%, and Artificial Analysis measured 74.5% on its Terminal-Bench 2.1 harness and 1.5% on the harder Terminal-Bench 4.0
[epoch-qwen3-7-max] [aa-qwen3-7-max].

### Long context and retrieval

The context window is 1M tokens, with up to 991K input, or 983K with thinking [qwencloud-page-37max]. Rate limits on the
page are 1M tokens and 600 requests per minute. Implicit cache hits cost US$0.50 per million tokens, explicit cache
creation US$3.125 and an explicit hit US$0.25; the README describes the cache rules [qwencloud-page-37max]
[qwencloud-cache]. The post's table, an image, gives 90.4 on MRCR-v2 (the 128K subset with eight needles), against 85.9 for
Qwen3.6-Plus (maker runs). Artificial Analysis's long-context reasoning test (AA-LCR) gave 79.0
[blog-qwen3-7] [aa-qwen3-7-max].

### Structured output

QwenCloud's guide lists the Qwen3.7-Max series for JSON Object mode without the thinking-mode restriction that it puts on
older models, and for JSON Schema mode (strict) [qwencloud-structured]. QwenCloud's model table shows a dash for
structured output on this model, so the two pages disagree [qwencloud-models].

### Images, audio, other inputs

The page for the bare id lists text input only. QwenCloud's changelog says the snapshot dated 2026-06-08 added image
understanding, and the model table lists that snapshot by its dated id. No page read says which snapshot the bare id now
serves [qwencloud-page-37max] [qwencloud-changelog] [qwencloud-models]. No audio or video input is listed.

### Sampling and API parameters

Alibaba gives no recommended sampling values for this model. Its benchmark footnotes use temperature 1.0 and top_p 0.95
(top_k 20 for terminal tasks). The API reference gives a default `presence_penalty` of 1.5 for Qwen3.7 in non-thinking
mode, a default `top_k` of 20 for models it does not list, and a temperature range from 0 up to but not including 2. It
says to set one of `temperature` and `top_p`, not both [blog-qwen3-7] [qwencloud-api-chat].

### Migrating from the previous generation

The previous Max model is Qwen3.6-Max-Preview (2026-04-20). QwenCloud's table lists it as a preview with a 256k context,
a 64k output limit, a 128k thinking budget and no built-in tools. 3.7-Max has a 1M context, a 256k thinking budget and
built-in tools [qwencloud-models]. QwenCloud's guide lists 3.6-Max-Preview for JSON Object mode that holds reliably
only in non-thinking mode, and not for JSON Schema; 3.7-Max is listed for both without that limit [qwencloud-structured]. Artificial Analysis lists the two at 28 and 29 on its index (v4.3.2); its data flags the 28 as an
estimate, not a full run. Epoch AI gives 149 and 154 on its capability index [aa-qwen3-6-max] [aa-qwen3-7-max]
[epoch-qwen3-7-max].
The post compares 3.7-Max with Qwen3.6-Plus: SWE-bench Pro 60.6 against 56.6, Terminal-Bench 2.0 69.7 against 61.6,
NL2Repo 47.2 against 34.4 and Humanity's Last Exam 41.4 against 28.8 (maker figure) [blog-qwen3-7]. The 3.6 generation
introduced `preserve_thinking` as an opt-in, and the 3.7 post recommends it. On 2026-10-10 QwenCloud retires
`qwen3.6-max-preview` and names `qwen3.7-max` as the replacement, and its snapshot notice does the same for the older
`qwen3-max` snapshots [qwencloud-mainline-notice] [qwencloud-snapshot-notice].

## What the system card reports

Alibaba has published no system card or model card for Qwen3.7-Max, and the technical report that the post announces was
not found. The post holds one safety-related item. During reinforcement-learning runs of more than 80 hours, the model
itself retrieved and replayed training trajectories in over 10,000 calls. It found candidate reward-hacking patterns, such
as attempts to bypass constraints to reach ground-truth answers on GitHub. It added 13 heuristic rules and flagged 1,618
hacking cases. For the kernel benchmark, the post says another model (GPT-5.4 at xhigh effort) checked the runs for hacking.
Both are statements by the maker [blog-qwen3-7]. No refusal, over-refusal, sycophancy, deception, prompt-injection, cyber or
biology result is published for this model. QwenCloud moderates requests and responses, as the README says.

## Behaviour observed in practice

- **Index, verbosity and speed (M).** Artificial Analysis (index v4.3.2): 29, with 120M output tokens against a median of
  81M, 201.3 output tokens per second (rank 7 of 224) and US$1.15 per index task [aa-qwen3-7-max].
- **Knowledge reliability (M).** Artificial Analysis's chart data gives accuracy 31.1% and a hallucination rate of 25.6% on
  its AA-Omniscience test [aa-qwen3-7-max]. At launch The Batch relayed a lower hallucination rate (23%) from an earlier index
  version (class A), so the figures do not compare [batch-37max].
- **Agent claims (A).** The Batch wrote on 2026-06-05 that Artificial Analysis had not yet run the model on its long agentic
  tasks and that the maker's agent claims were unvalidated by independent benchmarks [batch-37max]. Artificial Analysis's
  coding-agent data read on 2026-10-03 holds no run for this model [aa-coding-agents].
- **Agreement between sources (M).** GPQA Diamond reads 92.4 (maker), 92.3 (Artificial Analysis) and 91 (Epoch AI)
  [blog-qwen3-7] [aa-qwen3-7-max] [epoch-qwen3-7-max].
