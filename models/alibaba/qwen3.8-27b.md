# Qwen3.8-27B

Qwen3.8-27B is a dense, 27-billion-parameter vision-language model from Alibaba, released as open weights under
Apache-2.0 on 2026-08-14 (hosted on QwenCloud from 2026-08-19). It sits in the Qwen open-weights class at
generation 3.8, is meant for coding, office-style work and agent loops that must fit on one machine, and builds
on Qwen3.6-27B [hf-qwen3-8-27b] [qwencloud-page-27b]. It takes text, images and video, thinks by default and can
be run without thinking. Family-wide rules are in the [Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

Alibaba gives no model-specific guidance on system prompts, roles, structure, examples or document placement for the
27B. The card's "Best Practices" covers sampling, output length, long-context and long-video settings only
[hf-qwen3-8-27b], and QwenCloud's general prompt-design page is summarised in the README [qwencloud-prompting]. The
chat template requires the system message first, writes tool calls as XML-like blocks and, for effort, adds a
sentence to the system turn when the level is `xhigh` or `low` and nothing for `medium` [hf-27b-template].
A study of five unnamed models found fully compliant replies falling to zero by 80 simultaneous instructions; it
is not shown to include this model [arxiv-2607-19257].

### Reasoning and effort

- **Control.** Thinking is on by default and is switched off per request with `enable_thinking` false
  (`chat_template_kwargs` on a self-hosted server, top level on QwenCloud). Depth is `reasoning_effort`: `xhigh`
  (default, for complex tasks), `medium` (balance of accuracy and speed), `low` (speed and cost)
  [hf-qwen3-8-27b] [qwencloud-thinking]. On QwenCloud the levels stand for reasoning budgets of 4,096, 16,384 and
  262,144 tokens, cannot be combined with `thinking_budget`, and `none` turns thinking off [qwencloud-api-chat].
- **History.** `preserve_thinking` is on by default and keeps thinking from every earlier message; setting it false
  keeps only the latest user turn's thinking. Alibaba says it improves decision consistency and cache reuse, which
  matters for agent loops [hf-qwen3-8-27b].
- **Warning on low effort.** The card says that in multi-turn agent work lower effort may not shorten the
  task; faster turns can bring insufficient analysis, more failures and retries, and so more total time and
  tokens [hf-qwen3-8-27b]. An independent test on one codebase task agrees: `low` had a median latency of 95 s and the
  lowest quality score (7.79), `medium` 75.5 s and 8.18, `xhigh` 143.1 s and 8.61, and `medium` finished in fewer agent
  rounds than `low` on two thirds of the questions; run-to-run noise was about 0.18 points, so the `medium` to
  `xhigh` gap is near the noise [kodesage-27b].
- **Runaway thinking.** Users in the card's discussion thread report long thinking at the `xhigh` default (about 60,000
  thinking tokens per turn in one report, and a first token after about 40 seconds under Claude Code in another);
  one user traced slow turns to a bug in their own Jinja template that broke cache reuse and forced a 70k-token
  prefill each turn; workarounds named are `medium` or `low` effort, turning `preserve_thinking` off and fixing the
  template. These are anecdotes with unknown setups, and Alibaba did not reply in the thread [hf-discussion-97].
- **Budgets.** Where an engine takes separate limits, the card suggests 262,144 reasoning tokens and 131,072 reply
  tokens. On QwenCloud the model page lists 262K reasoning, 983K input with thinking and 131K output, and the
  thinking guide lists the model as a hybrid open model with thinking on by default [qwencloud-page-27b]
  [qwencloud-thinking]. Artificial Analysis measured 200M output tokens at `xhigh` against a median of 82M, and
  110M at `medium` [aa-qwen3-8-27b] [aa-qwen3-8-27b-medium].

### Output: format, length, tone

No formatting, verbosity or tone guidance is published. The card says a raised presence penalty (0 to 2) can curb
endless repetition, with a risk of language mixing; the non-thinking mode's recommended presence penalty is 1.5
[hf-qwen3-8-27b]. Output limit on QwenCloud 131K [qwencloud-page-27b]. QwenCloud's thinking guide lists the hosted
27B as a hybrid model with thinking on by default; it names only the 2.4T among the Qwen3.8 models that require
streaming, and advises streaming in general [qwencloud-thinking].

### Tools and agents

The card claims better handling of environment feedback and more reliable multi-step completion
[hf-qwen3-8-27b]. A self-hosted server needs the `qwen3` reasoning parser and the `qwen3_coder` tool-call parser
[sglang-qwen38]. On QwenCloud the model has function calling and the code interpreter, image search, PDF parsing and
web tools listed on its page; the loop rules (send `reasoning_content` back with tool results, `tool_choice`
limits in thinking mode) are in the README [qwencloud-page-27b]. In thinking mode `tool_choice` accepts only `auto`
or `none` [qwencloud-fn-calling], and the `agent` web-search strategy is not available for this model on Chat
Completions, only through the Responses API [qwencloud-search]. A study of multi-turn agents on other open models
found 4-bit quantisation amplified tool-name failures up to 2.5 times while aggregate scores looked unchanged
[arxiv-2607-27275]. Computer use: the card reports OSWorld-Verified 84.3, WebArena-Verified 64.8 and AndroidWorld
81.9 (maker-run, harness not stated) [hf-qwen3-8-27b].

### Coding

Maker-run: SWE-bench Pro 61.7 on a refined set (temperature 1.0, top_p 0.95, 256K context, not the Scale V2 set),
Terminal-Bench 2.1 73.0 (Terminus, no timeout stated), DeepSWE 1.1 42.2, NL2Repo-Bench 42.3, LiveCodeBench v6 90.3,
and the in-house QwenSWEBench 79.0 [hf-qwen3-8-27b]. An independent run of Terminal-Bench 2.1 on the full-precision
weights at `xhigh` passed 63 of 89 tasks (70.8%, 95% interval 61 to 79%) with a 3-hour timeout and 98k tokens of
context reserved, about 2 points under the vendor figure [quesma-27b-quants]. The same run found the 4-bit
`Q4_K_M` file equal at 63 of 89 and the 2-bit `UD-Q2_K_XL` file at 57 of 89, with overlapping intervals, and the
2-bit file wrote about a quarter more tokens on the tasks both solved. These counts were read from the post's
chart data and are single runs [quesma-27b-quants].

### Long context and retrieval

Native 262,144 tokens; YaRN with a factor of 4.0 reaches 1,000,000. The card warns that all common engines apply
static YaRN, which may hurt short inputs, so enable it only when needed and pick a factor near the typical length
(2.0 for about 524,288 tokens) [hf-qwen3-8-27b]. Hosted, the model page shows a 1M window with 991K input
[qwencloud-page-27b]. Local setups usually run far less context: the independent quantisation test reserved 98k and
noted that a 4-bit file fits a 24 GB card with room for about 64k tokens [quesma-27b-quants]. No retrieval
benchmark is published on the card.

### Structured output

QwenCloud's page lists structured outputs for the model, and its guide lists the open Qwen3.8 series for JSON Object
mode without the non-thinking restriction it puts on older models; its JSON Schema (strict) list names only Max,
Flash and the 3.7 models, so JSON Object mode is the documented route [qwencloud-page-27b] [qwencloud-structured].

### Images, audio, other inputs

Images and video go in as `image_url` and `video_url` content parts. Default video sampling is 2 frames per second;
on vLLM it can be changed through `mm_processor_kwargs`; setting `longest_edge` to 469,762,048 in the video
preprocessor config allows hour-long video (about 224k tokens) [hf-qwen3-8-27b]. Vision results (maker-run) include
MathVision 90.0 without and 94.6 with code interpreter (CI), CharXiv RQ 83.7 and 90.2, OmniDocBench 1.5 91.1,
RealWorldQA 85.9, ERQA 65.5 [hf-qwen3-8-27b]. No audio input.

### Sampling and API parameters

Thinking mode: temperature 1.0, top_p 0.95, top_k 20, min_p 0, presence_penalty 0, repetition_penalty 1. Non-thinking
mode: temperature 0.7, top_p 0.80, top_k 20, min_p 0, presence_penalty 1.5. Engines differ in which they honour
[hf-qwen3-8-27b]. In the card's discussion thread, one user traced slow turns to a fault in their own chat template that broke cache
reuse (anecdote) [hf-discussion-97].

### Migrating from the previous generation

From Qwen3.6-27B (the model page says 3.8 builds on it): on the card's own table Terminal-Bench 2.1 rises from
63.4 to 73.0, SWE-bench Pro from 53.5 to 61.7, DeepSWE 1.1 from 13.3 to 42.2, IFBench from 69.1 to 79.5, OSWorld-
Verified from 63.9 to 84.3 [hf-qwen3-8-27b]. An independent test found `medium` effort about 32% faster than
Qwen3.6-27B on one task, at a similar or slightly higher quality score [kodesage-27b]. Behaviour that shifts:
effort levels now exist; `preserve_thinking` is on by default (it was opt-in in 3.6); the thinking temperature is
1.0 where 3.6's precise-coding setting was 0.6 [qwen-f6] [qwen-f23].

## What the system card reports

Alibaba has published no system card for the 27B. The card holds benchmarks and best practices; it names no safety
evaluation and no refusal, sycophancy, deception, injection or cyber and biology measurement [hf-qwen3-8-27b]. The
weights are Apache-2.0, and third-party derivatives with refusal behaviour removed exist; they say nothing about
the original [mindstudio-obliterated]. The card's discussion thread read concerns thinking length only and holds no safety finding [hf-discussion-97].

## Behaviour observed in practice

- **Index and verbosity (M).** Artificial Analysis v4.3.2: 34 at `xhigh` (first of 142 open-weights models of
  similar size on its page), 200M output tokens against a median of 82M, 45.5 output tokens per second, 3.82 s to first token; 28 at
  `medium` with 110M tokens [aa-qwen3-8-27b] [aa-qwen3-8-27b-medium].
- **Quantisation (M).** On the 27B, a 4-bit file matched full precision on Terminal-Bench 2.1 and IFBench, and on
  GPQA Diamond the 2-bit file was slightly lower; 1-bit files performed near chance on GPQA Diamond. IFBench was
  unchanged down to 2-bit [quesma-27b-quants].
- **Local runs (A).** A reviewer ran it on one A100 80 GB under vLLM; `medium` finished agent tasks in fewer rounds
  than `low` [kodesage-27b].
- **Long thinking (A).** See "Runaway thinking" above [hf-discussion-97].
