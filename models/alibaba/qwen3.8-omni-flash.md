# Qwen3.8-Omni-Flash

Qwen3.8-Omni-Flash is Alibaba's hosted omni-modal model: text, image, audio and video in, text out, with a 1M-token
context. It is the 3.8 generation of the Qwen Omni class, built on the Flash-Next architecture and aimed at
agents that analyse meetings, long videos and mixed media; it succeeds the Qwen3.5-Omni models, which could also
speak [qwencloud-changelog] [aliyun-omni]. QwenCloud's changelog dates it 2026-09-18. It cannot produce audio. Family-wide rules are in the [Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

Alibaba gives no guidance on system prompts or roles for Omni-Flash. QwenCloud's omni-model page points it at
audio and video analysis, meeting summaries and subtitles, and its audio and video understanding guide (written for
the Qwen-Omni models) gives prompt advice by use: a short prompt of under 50 words for quick review or segmenting
recordings up to 60 minutes, and a supplied structured prompt for detailed analysis of short clips (up to 2 to 4
minutes), which asks for a timed storyline, a list of on-screen text with timestamps and a speaker-labelled
transcript [qwencloud-omni-models] [qwencloud-av-understanding]. QwenCloud's accuracy overview advises putting the
main question at the start or end of the prompt for vision and omni models [qwencloud-accuracy]. The caching guide's
general advice (text before images when one question covers many images, image first when many questions cover
one image) applies to media placement [qwencloud-cache]. Launch write-ups list meeting minutes with speaker
attribution, video localisation and long-video question answering as uses (class A) [digitalapplied-omni].

### Reasoning and effort

Thinking is on by default. QwenCloud's API reference documents `reasoning_effort` for this model with the levels
`low`, `medium` and `xhigh` and the default `xhigh`; it maps `minimal` to `low`, `high` and `max` to `xhigh`, and
`none` to thinking off, and says not to combine it with `thinking_budget` [qwencloud-api-chat]. Model Studio's
thinking page names `reasoning_effort` for this model alone among the Qwen3.8 and 3.7 pages, and `preserve_thinking`
is on by default for it [aliyun-thinking] [qwencloud-api-chat]. The model page lists 262K maximum reasoning tokens,
983,616 input tokens with thinking (991,808 without) and 131,072 output tokens [qwencloud-page-omni] [aliyun-omni].
QwenCloud notes thinking tokens are billed as output and that thinking-mode requests on long prompts risk timeouts
[qwencloud-thinking].

### Output: format, length, tone

Text only; the example on the model page sets `modalities` to text and says not to request audio
[qwencloud-page-omni]. For speech, QwenCloud points to a separate real-time model (`qwen3.8-omni-flash-realtime`,
released 2026-09-21, over WebSocket, WebRTC and AOQ) or to Qwen3.5-Omni for spoken replies [qwencloud-changelog]
[qwencloud-omni-models]. No formatting or tone guidance is published.

### Tools and agents

Custom function calling and web search are supported through Chat Completions and Responses; QwenCloud's page lists
`web_search` as the built-in Responses tool, and the `agent` search strategy is available for this model
[aliyun-omni] [qwencloud-omni-models] [qwencloud-search]. QwenCloud's audio and video guide requires streaming for
all Qwen-Omni requests [qwencloud-av-understanding]. The changelog and model page recommend the companion
Qwen-MM-Plugins so agent frameworks can use the model's multimodal abilities; write-ups say the plugins target
Claude Code, Codex, Gemini CLI and Qwen Code, and that the Qwen-Live Harness repository for real-time use returned
not-found when one outlet checked on launch day (class A) [qwencloud-changelog] [digitalapplied-omni]
[orcarouter-omni]. The vendor-reported "agentic understanding" mode cut tokens per query on a video benchmark from
145,736 to 79,117 (about 45.7% fewer) while raising accuracy from 63.4 to 67.8, per a secondary write-up; the scores
measure the model together with its harness [digitalapplied-omni].

### Coding

Alibaba lists coding among the agent tasks the model is built for, but its material centres on multimedia work. No
coding benchmark was found [qwencloud-changelog].

### Long context and retrieval

1M context with 991,808 maximum input tokens [aliyun-omni]. Model Studio's vision page gives videos up to 2 hours
for this model; launch write-ups also cite up to an hour of continuous audio-video per call [aliyun-vision]
[orcarouter-omni]. Audio is counted at 7 tokens per second (about 25,200 tokens an hour) according to a secondary
write-up citing Model Studio; QwenCloud's page does not state it [digitalapplied-omni]. Implicit and session caching
are available; implicit cache hits cost US$0.016 per million tokens [qwencloud-page-omni] [aliyun-omni]
[qwencloud-cache].

### Structured output

QwenCloud's page lists structured outputs. Its guide lists this model for JSON Object mode in non-thinking mode only
(in thinking mode the setting is accepted but may not take effect) and not for JSON Schema mode, and multimodal inputs
fall back to JSON Object mode in any case [qwencloud-page-omni] [qwencloud-structured].

### Images, audio, other inputs

Audio input covers 113 languages and dialects; two- and four-channel spatial audio is accepted by setting
`use_multichannel`; video and images are accepted alongside text [aliyun-omni]. Regions: Beijing, Singapore, Hong
Kong, Tokyo, Frankfurt and Virginia [aliyun-omni]. The audio and video guide recommends lower `max_pixels` (230,400)
for quick, cheap review and 921,600 to 2,073,600 for detailed work [qwencloud-av-understanding]. Vendor-reported
figures, all as relayed: WildClawBench-MM 71.0 (Qwen3.5-Omni-Plus 34.5, Gemini 3.8 Flash 58.9), OmniVideoBench 63.4
in a static setting and 67.8 in agent mode (Gemini 3.8 Flash 65.2 static), AgenticVBench 36.8 (Qwen3.5-Omni-Plus 14.5,
Gemini 3.8 Flash 45.0), and a FLEURS speech-recognition error of 9.3 against 7.2 for the predecessor, a small
regression [digitalapplied-omni] [orcarouter-omni].

### Sampling and API parameters

QwenCloud's API reference gives this model's defaults: temperature 0.6, top_p 0.95 and presence_penalty 0 in thinking
mode, and 0.7, 0.8 and 1.5 without thinking [qwencloud-api-chat]. Rate limits: 2M tokens and 30K requests per minute
[qwencloud-page-omni].

### Migrating from the previous generation

From Qwen3.5-Omni-Plus: output is text only where the predecessor could speak, and the 3.8 model adds effort levels
[qwencloud-omni-models] [qwencloud-api-chat]. Alibaba reports an average gain of more than 25% over 29 evaluations or
more than 26% over 30 (write-ups differ), and an estimated cost per hour more than 98% lower for audio input and 93%
lower for audio-video, both against the predecessor; the estimate prices a two-minute clip times 30, with video at
720p and one frame per second [technode-omni] [runtimewire-omni] [digitalapplied-omni] [orcarouter-omni]. The price
comparison is Qwen to Qwen, not against other labs.

## What the system card reports

Alibaba has published no system card or model card for Omni-Flash; a write-up of 2026-09-18 notes that no model card was
available [digitalapplied-omni]. No refusal, sycophancy, deception, injection or cyber and biology finding exists for
the model. QwenCloud moderates all requests and responses [qwencloud-security].

## Behaviour observed in practice

No independent evaluation was found: Artificial Analysis has no page for the model, and write-ups state that
independent testing has not validated the vendor's comparisons [orcarouter-omni] [runtimewire-omni]. One write-up
warns that the speaker-labelling gain may reflect pipeline engineering and not the model alone [orcarouter-omni].

## Benchmarks

Independent: none. Scale SWE-Bench Pro V2 and METR list no entry, and Artificial Analysis has no page for it
[scale-swe-pro-v2] [metr-horizons]. Vendor-reported figures are in the card; they are relayed by write-ups, not read
from a maker table.
