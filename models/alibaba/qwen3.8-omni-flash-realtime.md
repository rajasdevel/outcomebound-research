# Qwen3.8-Omni-Flash-Realtime

Qwen3.8-Omni-Flash-Realtime is the realtime audio and video model of Alibaba's Qwen Omni line, generation 3.8. It takes streaming audio, images or video and text. It gives back speech and text. Alibaba calls it full-duplex and aims it at smart devices, robotics and interactive agents. QwenCloud's changelog dates it 2026-09-21. It follows `qwen3.5-omni-plus-realtime` and `qwen3.5-omni-flash-realtime`. The text-only `qwen3.8-omni-flash` is a different model for file analysis ([qwen3.8-omni-flash](qwen3.8-omni-flash.md)). Family-wide rules are in the [Alibaba README](README.md) [qwencloud-changelog] [qwencloud-page-38rt].

## How to instruct it

### Setting up the prompt

The `instructions` field of `session.update` is the system message. It sets the role and the goal of the model. The guide shows one example: a customer-service agent for a hotel, with a rule to give no unconfirmed information [qwencloud-rt-guide] [qwencloud-client-events]. Alibaba gives no prompt-writing advice for this model beyond that example. The detailed advice that Alibaba publishes for speech prompts is in the guide for the separate Qwen-Audio models. See [Qwen-Audio-3.1-Realtime-Plus](qwen-audio-3.1-realtime-plus.md).

The client sends `session.update` first, after the connection opens. For this model the `session` object is required. The server checks the values and returns the full configuration. It leaves out the MCP credentials [qwencloud-client-events]. The audio format, the channel layout and the video setting must be set before the first audio segment. They cannot change after audio input starts [qwencloud-client-events].

### Reasoning and effort

The model has no thinking mode and no effort control. QwenCloud's table of speech models shows no thinking support for it. Its text-output sibling `qwen3.8-omni-flash` has `reasoning_effort` [qwencloud-s2s-models].

### Output: format, length, tone

`modalities` takes `["text"]` or `["text", "audio"]`. The default is both. The guide gives no length or tone advice for this model [qwencloud-client-events].

Billing differs between the pages. The model page says output text is not charged when audio is on. The realtime guide says this model bills the output audio and its text, each at the output rate. Alibaba states the opposite for the Qwen3.5 realtime models. The pages do not settle which one is right, so a budget based on either rule is uncertain [qwencloud-page-38rt] [qwencloud-rt-guide].

### Tools and agents

The model supports function calling through `session.tools`. The client returns the result with `conversation.item.create`, then sends `response.create`. It also supports MCP servers. The server must be a public HTTPS Streamable HTTP service. Approval of each call is on by default. A response that needs a tool comes only after tool discovery finishes [qwencloud-rt-guide] [qwencloud-client-events].

The MCP limits are: 8 servers, 128 tools, 30 seconds for tool discovery, 60 seconds for an approval, 30 seconds for a tool run and 256 tool calls in total [qwencloud-interaction-flow]. Web search is available through `enable_search`. It cannot run at the same time as tools or MCP [qwencloud-client-events] [qwencloud-rt-guide]. MCP calls cost nothing extra; the model tokens are billed as usual [qwencloud-rt-guide].

### Coding

Alibaba publishes no coding guidance or score for this model.

### Long context and retrieval

The session accepts at most 196,608 input tokens in total. Input tokens add up with each turn, because the model reads the retained history again on every response. The model keeps 100 audio turns or 600 seconds of audio, and 50 video turns or 240 seconds of video. It drops the oldest first [qwencloud-rt-guide]. A multi-turn call can therefore cost more than the audio length suggests. Context cache is listed as a feature on the model page [qwencloud-page-38rt].

### Structured output

The model page lists structured outputs as a feature. The realtime guide gives no rules for it [qwencloud-page-38rt].

### Images, audio, other inputs

- **Audio.** Input is PCM, 16-bit, 16 kHz. The model page's example plays the output at 24 kHz. The client-events page offers a WAV container and 8, 16, 24 or 48 kHz, but it scopes these options to the Qwen3.5 realtime models [qwencloud-client-events] [qwencloud-page-38rt].
- **Multichannel.** Over WebSocket the model takes 1, 2 or 4 channels. The format must be PCM, 16 kHz, s16le and interleaved. The channel layout is `raw_mic_array` for 2 channels and `foa_ambix` for 4. Two or four channels count twice as many input audio tokens [qwencloud-client-events] [qwencloud-rt-guide].
- **Images and video.** Over WebSocket, the client sends JPG frames with `input_image_buffer.append`. At least one audio append must come first. The rules are: one image per second, up to 1080p (480p or 720p is recommended), at most 256 KB after Base64 encoding. Over WebRTC the frames travel on the video track [qwencloud-client-events] [qwencloud-rt-guide].
- **Video aggregation.** `session.video.input.representation_compact` is `none` by default. `normal` cuts the video tokens to one quarter. It must be set before the first audio segment [qwencloud-rt-guide] [qwencloud-client-events].
- **Languages.** The guide gives 113 languages and dialects for recognition and 36 for speech. The model page says over 60 and over 30 [qwencloud-rt-guide] [qwencloud-page-38rt].

### Voice: turn-taking, interruption and speech style

**Protocols.** WebSocket suits server-side work. WebRTC suits browsers and low-latency voice, with echo cancellation and noise reduction built in. AOQ suits native mobile apps. The guide says WebRTC is available by allowlist only. A raw WebSocket has no echo cancellation, so the client must handle echo [qwencloud-rt-guide] [qwencloud-rt-overview]. The WebSocket endpoint is `wss://maas.qwencloudapi.com/api-ws/v1/realtime`, with the model name in the `model` query parameter [qwencloud-rt-guide].

**Turn detection.** There are three modes [qwencloud-client-events] [qwencloud-rt-guide]:

- `server_vad` (default) finds the end of speech from acoustic features.
- `semantic_vad` judges whether the speech is meaningful. It filters backchannels and background noise. The client-events page says this model supports it. A code comment in the guide recommends it for this model and the Qwen3.5 realtime models.
- `turn_detection: null` is manual mode. The client sends `input_audio_buffer.commit` and then `response.create`. WebRTC does not support manual mode.

Two settings tune the VAD. `threshold` runs from -1.0 to 1.0 and defaults to 0.5. The guide's own comment says to raise it in noisy places and lower it in quiet ones. `silence_duration_ms` runs from 200 to 6000 and defaults to 800. A lower value gives faster replies but may fire on short pauses. `idle_timeout_ms` (5000 to 30000 ms, `server_vad` only) belongs to the Qwen3.5 realtime models. This model does not list it.

**Interruption.** In VAD mode, the start of user speech produces `input_audio_buffer.speech_started`. The session configuration that the server returns shows `interrupt_response: true` by default [qwencloud-server-events]. Over WebSocket, the example code stops its player at that event. Over WebRTC the platform plays the audio track itself. `response.cancel` stops a response by hand and returns an error if none is running. The guide advises headphones, because echo from the speaker can trigger an interruption [qwencloud-rt-guide] [qwencloud-client-events].

**Voice and style.** The default voice is `Tina`. The guide names `session.audio.output.voice` for new integrations. It takes precedence over the older `session.voice`. The guide names `longanlingxin`, a warm and empathetic voice, among the voices for this model. The pages disagree on voice cloning for this model: the model-selection text lists it, and the client-events page limits cloned voices to the Qwen3.5 realtime models [qwencloud-rt-guide] [qwencloud-client-events]. Alibaba states that the Qwen3.5 realtime models take spoken commands to change volume, speed and emotion, for example "speak faster". It does not say the same for this model [qwencloud-rt-guide].

**Session handling.** One WebSocket session lasts at most 120 minutes. The connection then closes. A client that needs a longer call must reconnect and carry its own context. Alibaba documents no resume feature [qwencloud-rt-guide].

### Sampling and API parameters

`temperature` (range 0 up to but not including 2) and `top_p` exclude each other. The API reference gives model-dependent defaults for `top_k`, `max_tokens` and `seed`. The rate limit is 2M tokens and 60 requests per minute [qwencloud-client-events] [qwencloud-page-38rt].

### Migrating from the previous generation

The previous generation of this class is the Qwen3.5 realtime pair. The 3.8 model adds multichannel input, video aggregation, MCP with approvals, and the voice `longanlingxin`. It has a 196,608-token input limit. The 3.5 models use a 262K context with 196K input. The 3.5 models also offer `idle_timeout_ms`, voice cloning that the pages confirm for them, and a 55-voice list [qwencloud-rt-guide] [qwencloud-client-events] [qwencloud-page-35plus-rt]. Audio is priced much lower than for the 3.5 Plus model: US$0.93 against US$16.5 per million input audio tokens [qwencloud-page-38rt].
