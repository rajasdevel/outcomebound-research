# Qwen3.6-Plus

Qwen3.6-Plus is Alibaba's closed, hosted model of the Qwen Plus class, generation 3.6. It launched on QwenCloud and
Alibaba Cloud Model Studio on 2026-04-02. It takes text, images and video, has a 1M-token context and thinks by default
[qwencloud-changelog] [blog-qwen3-6-plus] [aliyun-thinking]. Alibaba says it improves agentic coding (front-end work and repository-level
tasks) and multimodal perception over Qwen3.5-Plus, and that it answers community feedback on that model
[blog-qwen3-6-plus]. It replaced Qwen3.5-Plus, and Qwen3.7-Plus (2026-06-01) followed it. Family-wide rules are in the
[Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

Alibaba gives no model-specific guidance on system prompts, roles, structure, examples or placement of long documents.
The README summarises QwenCloud's general prompt-design page [qwencloud-prompting]. QwenCloud's model-selection page does
not list the model among its recommended models; it stays in the full table [qwencloud-models]. The launch post names the
1M context window as the default for this model [blog-qwen3-6-plus].

### Reasoning and effort

- **Control.** Alibaba Cloud Model Studio's thinking guide lists the model as hybrid with thinking on by default
  [aliyun-thinking]. `enable_thinking` switches thinking per request and `thinking_budget` caps the reasoning tokens;
  QwenCloud's model table gives a thinking budget of 80k. Thinking tokens are billed as output
  [qwencloud-thinking] [qwencloud-models].
- **Preserved thinking starts here.** The launch post presents `preserve_thinking` as a new API setting of this release.
  It keeps the thinking of all earlier turns in the messages and is recommended for agentic tasks. It is off by default. By
  default only the thinking of the latest user turn is kept, which the post calls interleaved thinking. Alibaba says
  preserving earlier thinking helps decision consistency and in many cases lowers total token use. QwenCloud's API reference
  lists the model as supporting it [blog-qwen3-6-plus] [qwencloud-api-chat].
- **Tool loops.** QwenCloud says to send the earlier `reasoning_content` back with the tool results, and that leaving it out
  lowers accuracy [qwencloud-thinking].
- **No effort levels.** `reasoning_effort` is documented for the Qwen3.8 models only [qwencloud-api-chat].
- **Calls.** The thinking guide lists Qwen3.6 Plus among the models that accept non-streaming calls [qwencloud-thinking].

### Output: format, length, tone

No formatting, length or tone guidance exists for this model. The output limit is 65K on the model page (also with
thinking) and 64k in QwenCloud's table. Prefix completion is listed as a feature, and OpenRouter lists 65,536 tokens [qwencloud-page-36plus] [qwencloud-models]
[openrouter-models].

### Tools and agents

Function calling is supported. In thinking mode `tool_choice` accepts `auto` or `none` only [qwencloud-fn-calling]. The model
page lists web search, the code interpreter, the web extractor and text-to-image and image-to-image search, all through the
Responses API [qwencloud-page-36plus]. The API reference's list of models for the `agent` search strategy does not name
this model [qwencloud-api-chat]. The launch post says the model works with OpenClaw, Claude Code, Qwen Code, Kilo Code,
Cline and OpenCode. Its Claude Code set-up uses the Anthropic-compatible endpoint with `qwen3.6-plus` set for both the main
and the small-fast model variables. It also says that signing in to Qwen Code with OAuth gave each user 1,000 free calls a
day at the time of the post [blog-qwen3-6-plus]. The post describes a GUI-agent use (reading a screen and choosing the next
step) without a number for it. No guidance on subagents or context management is published.

### Coding

Maker runs from the launch post, read from its figure: SWE-bench Verified 78.8, SWE-bench Pro 56.6 (on a re-run set with
corrected tasks, so not the Scale V2 set), SWE-bench Multilingual 73.8, Terminal-Bench 2.0 61.6, NL2Repo 37.9 and
QwenWebBench 1501.7. Settings from the footnotes: the SWE-bench runs use an internal scaffold with bash and file-edit tools at
temperature 1.0, top_p 0.95 and a 200K context; Terminal-Bench 2.0 uses Harbor with Terminus-2, a 3-hour timeout, 32 CPUs and
48 GB RAM; NL2Repo runs through Claude Code with at most 900 turns [blog-qwen3-6-plus]. In the Qwen3.7 launch post, a 35-hour kernel
optimisation run gave 3.6-Plus a 1.1 times speedup, against 10.0 times for 3.7-Max, and on KernelBench L3 it produced an
accelerated kernel for 48% of the problems, against 96% for 3.7-Max (maker results) [blog-qwen3-7]. No independent run exists on Scale's SWE-Bench Pro V2 or on Artificial Analysis's
coding-agent board. Artificial Analysis's Terminal-Bench 2.1 run gave 61.4%, and its chart data holds no Terminal-Bench 4.0
value for the model [aa-qwen3-6-plus] [scale-swe-pro-v2] [aa-coding-agents].

### Long context and retrieval

The context window is 1M tokens, with up to 991K input, or 983K with thinking. Rate limits on the page are 5M tokens and
15K requests per minute. The price shown is for inputs up to 256K tokens, with an explicit cache creation price of US$0.625
and an explicit hit price of US$0.05 per million tokens; the page shows no implicit-cache price and no tier for longer
inputs [qwencloud-page-36plus]. The README describes the cache rules [qwencloud-cache]. Artificial Analysis's long-context
reasoning test (AA-LCR) gave 78.3 [aa-qwen3-6-plus]. The post's text claims records in exact extraction from very long
contexts. Its table, an image, gives AA-LCR 68.3 and LongBench v2 62.0 for 3.6-Plus, against 74.0 and 64.4 for Claude Opus 4.5
in the same table (maker runs) [blog-qwen3-6-plus].

### Structured output

QwenCloud's guide lists Qwen3.6-Plus for JSON Object mode in non-thinking mode only. In thinking mode the setting raises no
error, but the JSON may not be valid. For that case the guide suggests a second pass by a cheap model to repair the
output. The model is not on the JSON Schema list [qwencloud-structured].

### Images, audio, other inputs

Text, image and video in; text out. The vision guide gives up to 256 images per request for this model, 32 by 32 pixels per
image token, and the pixel and frame-rate settings that the README describes. Qwen3.6 models also accept an `fps` value that
tells the model the spacing of frames passed as an image list. The launch post lists visual coding (a page generated from a
screenshot or design mockup), document and chart reading, and video analysis as uses. No audio input is listed
[qwencloud-vision] [blog-qwen3-6-plus].

### Sampling and API parameters

Alibaba gives no recommended sampling values for this model. The API reference names `qwen3.6-plus` with a default
`presence_penalty` of 0.5 and states no mode for it, and gives 1.5 for Qwen3.6 in non-thinking mode, so the two entries
overlap. It gives a temperature range from 0 up to but not
including 2. It says to set one of `temperature` and `top_p`, not both [qwencloud-api-chat]. The benchmark footnotes use
temperature 1.0 and top_p 0.95 for coding and temperature 0.6 for the Claw-style tests [blog-qwen3-6-plus].

### Migrating from the previous generation

The previous Plus model is Qwen3.5-Plus (QwenCloud lists snapshots dated 2026-02-15 and 2026-04-20). QwenCloud's changelog says Qwen3.6-Plus
upgrades coding, multimodal work and general reasoning, and "fixes known issues" of 3.5-Plus. Its model table gives both a 1M
context, a 64k output limit and an 80k thinking budget [qwencloud-changelog] [qwencloud-models]. The new item is
`preserve_thinking`, which is opt-in. The launch post compares 3.6-Plus with the open Qwen3.5-397B-A17B and does not show
3.5-Plus: Terminal-Bench 2.0 61.6 against 52.5, SWE-bench Pro 56.6 against 50.9, SWE-bench Multilingual 73.8 against 69.3 and
NL2Repo 37.9 against 32.2 (maker figures) [blog-qwen3-6-plus]. On a year-long business simulation, the Qwen3.7 post gives
US$1.05M of revenue for 3.6-Plus against US$352K for 3.5-Plus (maker result) [blog-qwen3-7]. QwenCloud's retirement notices
read on 2026-10-03 send older models to `qwen3.7-plus` and do not list 3.6-Plus [qwencloud-snapshot-notice].

## What the system card reports

Alibaba has published no system card or model card for Qwen3.6-Plus, and the launch post has no safety section, so no
refusal, alignment, reward-hacking or injection finding is available. QwenCloud moderates requests and responses, as the
README says.

## Behaviour observed in practice

- **Index and speed (M).** Artificial Analysis lists an index of 27 (version 4.3.2, median 26 for its comparison group) and
  56.3 output tokens per second (rank 131 of 224). Its data flags the score as an estimate, not a full run, and the page shows
  no token count or cost per task [aa-qwen3-6-plus]. The same index version lists Qwen3.7-Plus at 25 from a full run. The
  estimate and the full run are not comparable, so no ordering of the two models follows.
- **Individual tests (M).** Artificial Analysis: GPQA Diamond 88.2, Humanity's Last Exam 27.8, IFBench 75.2, AA-LCR 78.3 and a
  hallucination rate of 34.6% on its knowledge test [aa-qwen3-6-plus].
- The page marks the model as superseded by Qwen3.7 Plus and keeps benchmarking only the default 10k-token workload
  [aa-qwen3-6-plus]. No practitioner report was found.

## Benchmarks

Independent: Artificial Analysis index 27 (estimated), Terminal-Bench 2.1 61.4%, GPQA Diamond 88.2, Humanity's Last Exam
27.8, IFBench 75.2, AA-LCR 78.3, MMMU-Pro 78.0 [aa-qwen3-6-plus]. No entry exists on Scale's SWE-Bench Pro V2 page, METR's
page or Artificial Analysis's coding-agent board that this file could find, and no Epoch AI page was found
[scale-swe-pro-v2] [metr-horizons] [aa-coding-agents]. Maker results, with settings, are in the card; the launch post's tables
are images and the values were read from its figure.
