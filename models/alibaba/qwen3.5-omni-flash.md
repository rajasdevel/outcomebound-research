# Qwen3.5-Omni-Flash

Qwen3.5-Omni-Flash is Alibaba's closed, hosted omnimodal model of the Qwen Omni class, generation 3.5, released on
2026-03-30 as the lower-cost, lower-latency variant beside Qwen3.5-Omni-Plus. It takes text, images, audio and video and
outputs text and speech. It has a 256K-token context and no thinking mode. It replaced Qwen3-Omni-Flash, and Qwen3.8-Omni-Flash
(2026-09-18), which outputs text only, followed it [qwencloud-page-35omni-flash] [arxiv-qwen3-5-omni] [aa-qwen3-5-omni-flash]
[qwencloud-omni-models]. Family-wide rules are in the [Alibaba README](README.md).

## How to instruct it

### Setting up the prompt

- **System message.** QwenCloud's omni guide says Qwen3-Omni-Flash and later series support a system message. Role and
  terminology instructions can go there. Its older model, Qwen-Omni-Turbo, ignores the system message when audio is output
  [qwencloud-omni-guide]. The technical report says all training data uses the ChatML format [arxiv-qwen3-5-omni].
- **Prompt by task.** QwenCloud's table pairs use cases with media length and prompt style. For fast review and content
  extraction it suggests media of up to 60 minutes and a simple prompt of at most 50 words. For standard analysis it suggests
  up to 4 minutes of video (2 minutes of audio) and, for fine-grained analysis of several speakers or complex scenes, up to
  2 minutes of video (1 minute of audio). For both of the latter it suggests a structured prompt. For fine-grained
  description of long media it says to segment the media first [qwencloud-omni-guide].
- **Structured prompt.** The suggested layout asks for sections: a time-stamped storyline in prose that blends audio and
  video, the visible text with times, and speaker profiles followed by a transcript with each speaker's state and words. It
  allows further sections [qwencloud-omni-guide].
- **Question placement.** QwenCloud's accuracy overview puts the main question at the start or end of a vision or omni prompt
  [qwencloud-accuracy].
- **Multi-turn rules.** A user message may hold text plus data of one other modality, and different modalities go in
  separate user messages. Assistant messages hold text only [qwencloud-omni-guide].
- **Image size by task.** For video, the guide suggests `max_pixels` of 230,400 for cheap review, 921,600 to 2,073,600 for
  extraction and standard analysis, and 2,073,600 for fine-grained work [qwencloud-omni-guide].

### Reasoning and effort

QwenCloud lists thinking mode for Qwen3-Omni-Flash only. The technical report calls the 3.5 series instruct models, and
Artificial Analysis lists the model as non-reasoning. No reasoning control, effort level or thinking budget exists for this
model [qwencloud-omni-models] [arxiv-qwen3-5-omni] [aa-qwen3-5-omni-flash]. The report's agent test for it ran without a
thinking prompt [arxiv-qwen3-5-omni].

### Output: format, length, tone

- **Streaming is required.** Every request to Qwen-Omni models must set `stream=True`
  [qwencloud-omni-guide].
- **Text or speech.** The `modalities` parameter takes `["text","audio"]` or `["text"]`, and speech output also needs
  `audio` with a `voice` and a `format`; only `wav` is supported. The audio arrives as Base64 fragments in the stream, which the
  client joins and decodes, or plays as they arrive [qwencloud-api-chat] [qwencloud-omni-guide].
- **Languages.** The guide lists speech output in 29 languages and 7 Chinese dialects, and input in 74 languages and 39 dialects.
  QwenCloud's speech-to-speech page says 8 output dialects and 113 input languages and dialects in total, and gives 36
  speech output languages and dialects for the realtime model. The model page says audio input in more than 60 languages
  and speech output in more than 30. The technical report gives 113 languages and dialects for recognition and 36 for
  speech synthesis. The counts differ from page to page [qwencloud-omni-guide] [qwencloud-s2s-models]
  [qwencloud-page-35omni-flash] [arxiv-qwen3-5-omni].
- **Voice.** Voice cloning from a reference sample works with this model in the non-realtime and the realtime APIs
  [qwencloud-voice-cloning].
- **Length.** The model page gives a 65K output limit [qwencloud-page-35omni-flash]. Alibaba gives no formatting or tone guidance.

### Tools and agents

- **Function calling** works over HTTP with text output. When retrieving tool information, set `stream=True`, and QwenCloud
  recommends `modalities=["text"]` so that no audio is produced during tool selection [qwencloud-fn-calling]
  [qwencloud-omni-models].
- **Web search** works through `enable_search` with `search_strategy` set to `agent`, the only value accepted. The model
  decides by itself whether to search. Web search and function calling cannot be enabled together [qwencloud-omni-guide]
  [qwencloud-omni-models] [qwencloud-s2s-models] [qwencloud-api-chat].
- **Agent results.** The report describes native tool use, web search and "audio-visual vibe coding" (code written from
  spoken and visual instructions). On its OmniGAIA tool-use test the Flash model scored 33.9 and the Plus model 57.2
  (maker run; judge DeepSeek-V3.2-Thinking). On text agent tests Flash scored 55.3 on BFCL-V4 and 78.0 on TAU2Bench
  [arxiv-qwen3-5-omni].
- No guidance on subagents, context management or computer use is published.

### Coding

No coding-agent benchmark exists for this model. The report's text table gives LiveCodeBench v6 56.6 for Flash, against 65.6
for Plus and 67.1 for the text-only Qwen3.5-Plus-Instruct (maker runs). It also describes an emergent ability to write code
from audio-visual instructions, without a score [arxiv-qwen3-5-omni].

### Long context and retrieval

The model page gives a 262K context with up to 196K of input; the report and Artificial Analysis say 256k
[qwencloud-page-35omni-flash] [arxiv-qwen3-5-omni] [aa-qwen3-5-omni-flash]. Media limits on QwenCloud: audio up to 3 hours or
2 GB, with up to 2,048 files by URL (250 as Base64). Video up to 1 hour or 2 GB, with up to 512 files by URL (250 as Base64).
An image list holds 2 to 2,048 images, and each image can be up to 20 MB [qwencloud-omni-guide]. The report and the model page claim more than 10 hours of audio
and over 400 seconds of 720p video at 1 frame per second, which differ from the guide's file limits
[arxiv-qwen3-5-omni] [qwencloud-page-35omni-flash]. Billing counts 7 tokens for each second of input audio and 12.5 for each second of output audio.
An image costs 1 token per 32 by 32 pixels, at least 24 tokens and 1,280 at most by default; `vl_high_resolution_images` raises
the top to 16,384 [qwencloud-omni-guide]. Long-text results fall behind the Plus model: AA-LCR 46.0 against 57.0 and
LongBench v2 46.4 against 59.6 (maker runs), and Artificial Analysis measured 52.0 on its AA-LCR [arxiv-qwen3-5-omni]
[aa-qwen3-5-omni-flash].

### Structured output

QwenCloud's guide names the Qwen3.5-Omni-Plus series for JSON Object mode (non-thinking) and does not name the Flash model.
The Flash model page lists structured outputs as a feature, and the guide's rule that JSON Object mode needs the word "JSON" in
a message applies wherever it is on [qwencloud-structured] [qwencloud-page-35omni-flash]. The model is not on the JSON Schema
list.

### Images, audio, other inputs

Text, image, audio and video in; text and speech out. The guide shows media as URLs or Base64 data, and a video file can carry
audio that the model also hears, billed apart from the pictures [qwencloud-omni-guide]. The report's audio-in results for Flash
include MMAU 80.4 and an average word error rate of 10.8% on the FLEURS multilingual test set (the Plus model: 6.6%;
Gemini-3-Flash in the report's table: 10.5%) [arxiv-qwen3-5-omni]. Vision results for Flash include MMMU 76.9, RealWorldQA 77.5
and VideoMME 77.0, under the Plus model's 80.1, 84.1 and 81.9. On audio-visual tests Flash scored DailyOmni 81.8 and VideoMME with
audio 79.3 (maker runs) [arxiv-qwen3-5-omni]. The report gives a theoretical first-packet latency of 235 ms for audio input and 426 ms
for video input on the Flash model at one concurrent request. It measured them in an internal vLLM set-up. It says the Flash and Plus deployments differ,
so the two are not for strict comparison [arxiv-qwen3-5-omni].

### Voice: turn-taking, interruption and speech style

This model has two endpoints. The HTTP endpoint (`qwen3.5-omni-flash`) takes a finished request and streams back text and speech. It has no turn detection and no barge-in. The realtime endpoint (`qwen3.5-omni-flash-realtime`) runs over WebSocket, WebRTC or AOQ and holds a live conversation [qwencloud-omni-guide] [qwencloud-rt-guide].

**Prompt.** The `instructions` field of the realtime `session.update` is the system message. The guide's example is a hotel customer-service agent with the rule to give no unconfirmed information. Alibaba gives no other speech-prompt advice for this model. The technical report names three faults that its last training stage targets in long chats: language switches that nobody asked for, an unstable persona and weaker instruction following over long contexts [qwencloud-rt-guide] [arxiv-qwen3-5-omni].

**Turn detection (realtime).** `server_vad` is the default. The guide recommends `semantic_vad` for the Qwen3.5 realtime models. Its example uses `threshold` 0.5 and `silence_duration_ms` 800. The ranges are -1.0 to 1.0 and 200 to 6000 ms. The guide's comment says to raise the threshold in noisy places and lower it in quiet ones. A lower silence value gives faster replies and may fire on short pauses. `idle_timeout_ms` (5000 to 30000 ms, `server_vad` mode only) makes the model speak first when the user stays silent. `turn_detection: null` selects manual mode, in which the client sends `input_audio_buffer.commit` and `response.create`. WebRTC supports the VAD modes only [qwencloud-client-events] [qwencloud-rt-guide].

**Interruption (realtime).** Alibaba calls it semantic interruption. The model tries to tell a real attempt to take the floor from a backchannel or background noise. The server sends `input_audio_buffer.speech_started` when the user starts to speak, and the client must clear its playback buffer. The guide advises headphones, because echo can trigger an interruption [qwencloud-rt-guide].

**Voice and style.** The model has 55 preset voices (47 multilingual, 8 dialectal). The default is `Tina`. Cloned voices work on both endpoints. The realtime model takes spoken commands that change volume, speed and emotion, for example "speak faster" or "in a happy tone" [qwencloud-rt-guide] [qwencloud-voice-cloning]. On the HTTP endpoint, speech output needs `modalities` with `audio`, a `voice` and the `wav` format [qwencloud-omni-guide].

**Limits.** One realtime WebSocket session lasts up to 120 minutes. The session keeps 80 audio turns or 480 seconds of audio, and 50 video turns or 120 seconds of video [qwencloud-rt-guide]. Artificial Analysis measured 0.79 seconds to first audio for the realtime Flash model. It scored 59.0% on speech reasoning, against 98.7% for the Plus realtime model [aa-s2s].

### Sampling and API parameters

Alibaba gives no recommended sampling values for this model. The API reference gives a default `presence_penalty` of 1.5 for
Qwen3.5-Omni. It gives a default `top_k` of 20 for models it does not list separately (it names 50 for Qwen3-Omni-Flash).
The temperature range runs from 0 up to but not including 2, and the reference says to set one of `temperature` and `top_p`
[qwencloud-api-chat].
Rate limits on the page are 100K tokens and 60 requests per minute [qwencloud-page-35omni-flash].

### Migrating from the previous generation

The previous model is Qwen3-Omni-Flash. The report lists five technical upgrades: hybrid-attention mixture-of-experts layers in both the
Thinker and the Talker; a 256k context; a speech generator that predicts several codebooks per frame; ARIA, which aligns text
and speech units while streaming; and wider multilingual training. It lists three new abilities: controllable captioning,
real-time interaction (semantic interruption, control of volume, speed and emotion, voice cloning) and agent behaviour
[arxiv-qwen3-5-omni]. On QwenCloud the limits grew: audio from 20 minutes to 3 hours, video from 150 seconds to 1 hour, and
from one file per request to many [qwencloud-omni-guide]. Speech output grew from 11 languages and 8 dialects to 29 languages
and 7 dialects [qwencloud-omni-guide]. Web search and voice cloning are new, and thinking mode is gone: Qwen3-Omni-Flash is a
hybrid thinking model with thinking off by default, and returns no speech while thinking [qwencloud-omni-guide]
[qwencloud-omni-models]. Billing for audio changed from 12.5 tokens per second in both directions to 7 in and 12.5 out
[qwencloud-omni-guide]. A QwenCloud notice retires several Qwen3-Omni-Flash snapshots (dated 2025-09-15 and 2025-12-01) on
2026-10-10 and names `qwen3.5-omni-plus` as the replacement [qwencloud-old-models-notice].

## What the system card reports

Alibaba has published no system card for Qwen3.5-Omni-Flash. The technical report has no safety, refusal or misuse section. It
does describe training steps that aim at behaviour. After specialist distillation, an on-policy distillation step pulls the
quality of replies to spoken queries up to the quality of replies to text queries. A third step, interaction-aligned
reinforcement learning, targets three faults that Alibaba saw in multi-turn chats: unintended switches of language, an
inconsistent persona and weaker instruction following over long contexts [arxiv-qwen3-5-omni]. The model can clone a voice
from a sample and QwenCloud moderates requests, as the README says; the pages read state no rule on cloning consent
[qwencloud-voice-cloning].

## Behaviour observed in practice

- **Index and speed (M).** Artificial Analysis lists an index of 12 (v4.3.2) and 215.6 output tokens per second (rank 3 of 75
  models in its comparison class). Its data flags the score as an estimate, not a full run [aa-qwen3-5-omni-flash].
- **Individual tests (M).** Artificial Analysis: GPQA Diamond 74.2, Humanity's Last Exam 7.6, IFBench 38.0, AA-LCR 52.0 and
  MMMU-Pro 64.7. On its knowledge test, accuracy was 14.7% and the hallucination rate 93.4%, so the model rarely declines to
  answer [aa-qwen3-5-omni-flash].
- **Agreement between sources (M).** GPQA reads 76.4 (maker) and 74.2 (Artificial Analysis), and IFBench 38.4 and 38.0
  [arxiv-qwen3-5-omni] [aa-qwen3-5-omni-flash].
- **Price (M).** Artificial Analysis lists US$0.10 input and US$0.80 output, while the QwenCloud page lists US$0.40 and US$2.20
  for text, image and video input and text output. The pages do not say why [aa-qwen3-5-omni-flash]
  [qwencloud-page-35omni-flash].
- **Speech-to-speech tests, realtime endpoint (M).** On Artificial Analysis's Speech to Speech page (read 2026-10-03) the realtime Flash model scored 59.0% on speech reasoning (Big Bench Audio), took 0.79 seconds on average to the first audio, and reached an arena preference Elo of 841 and a task success rate of 29.1%. The page lists no conversational-dynamics run for it [aa-s2s].
- No practitioner report was found.

## Benchmarks

Independent: Artificial Analysis index 12 (estimated), GPQA Diamond 74.2, Humanity's Last Exam 7.6, IFBench 38.0, AA-LCR 52.0,
MMMU-Pro 64.7 [aa-qwen3-5-omni-flash]. No Terminal-Bench 4.0 value, no Epoch AI page and no entry on Scale's SWE-Bench Pro V2
page, METR's page or Artificial Analysis's coding-agent board was found [scale-swe-pro-v2] [metr-horizons] [aa-coding-agents].
Maker results are in the card, each from a table of the technical report. The report's headline results are for the Plus model.
For Flash the report gives text, vision, audio and audio-visual tables with Gemini-3.1 Pro and Qwen3.5-Plus-Instruct beside it
[arxiv-qwen3-5-omni].

## Open questions

- Independent tests of the speech output quality and of audio understanding on the HTTP endpoint. Only the realtime endpoint has Artificial Analysis speech-to-speech results, and none covers conversational dynamics.
- Which of the audio and video limits applies: the guide's 3 hours and 1 hour, or the 10 hours and 400 seconds
  that the report and the model page claim.
- Whether JSON Object mode is supported for this model as it is for the Plus model.
- Why the price differs between QwenCloud and Artificial Analysis, and whether the cache is billed.
