# Qwen3.6-35B-A3B

Qwen3.6-35B-A3B is a mixture-of-experts vision-language model from Alibaba with 35 billion parameters in total and 3 billion
active for each token. It is open weights under Apache-2.0, released on 2026-04-16 and hosted on QwenCloud. It sits in the
Qwen open-weights class at generation 3.6 and is the small, fast sibling of Qwen3.6-27B. Alibaba aims it at agentic coding and
it takes text, images and video. It replaced Qwen3.5-35B-A3B. The 3.8 generation has no model of this size. The weights file counts 35.95 billion parameters
[hf-qwen3-6-35b-a3b] [hf-api-36-35b] [qwencloud-page-36-35b] [qwencloud-changelog]. Family-wide rules are in the
[Alibaba README](README.md), and most of what is true for [Qwen3.6-27B](qwen3.6-27b.md) holds here.

## How to instruct it

### Setting up the prompt

Alibaba gives no guidance on writing a system prompt, on roles, structure, examples or placement of long documents for this
model. The README summarises QwenCloud's general prompt-design page [qwencloud-prompting]. The chat template is the same
as the 27B's. A system message must come first and cannot hold images or videos. Tool definitions and the tool-call format
go into the system turn. The model card says the `/think` and `/nothink` switches of Qwen3 are not officially supported
[hf-qwen3-6-35b-a3b] [hf-qwen3-6-35b-a3b-template].

### Reasoning and effort

- **Thinking is on by default** and is switched off with `enable_thinking` set to false (in `chat_template_kwargs` on a
  self-hosted server, top-level on QwenCloud). `preserve_thinking` keeps the thinking of earlier turns and is off unless set.
  Alibaba says it helps agent work, can lower total token use and improves cache reuse [hf-qwen3-6-35b-a3b].
- **No effort levels.** The template has no effort sentence and QwenCloud documents `reasoning_effort` for the Qwen3.8 models
  only. `thinking_budget` applies on QwenCloud, whose table gives a budget of 80k [hf-qwen3-6-35b-a3b-template]
  [qwencloud-api-chat] [qwencloud-thinking] [qwencloud-models].
- **Length.** The card advises at least 128K of context, and an output of 32,768 tokens for most queries or 81,920 for
  competition-level problems [hf-qwen3-6-35b-a3b].
- **Observed cost of thinking.** One practitioner found far longer thinking than on Qwen3.5-35B-A3B (see below)
  [lilting-36-35b].

### Output: format, length, tone

The card gives no formatting or tone guidance. It suggests `presence_penalty` between 0 and 2 to curb endless repetition, and
warns that a higher value can cause language mixing and a small loss of quality [hf-qwen3-6-35b-a3b]. The hosted output limit
is 65K; OpenRouter lists a larger limit, 235,929 tokens [qwencloud-page-36-35b] [openrouter-models].

### Tools and agents

The card says the model is strong at tool calling and points to Qwen-Agent and Qwen Code. Its server commands add the
`qwen3_coder` tool-call parser with the `qwen3` reasoning parser. The tool-call format is the same `<tool_call>` block as for
the 27B [hf-qwen3-6-35b-a3b] [hf-qwen3-6-35b-a3b-template]. Unlike the 27B, QwenCloud's table lists built-in tools for this
model as well as function calling, and its page has a built-in-tools section [qwencloud-models] [qwencloud-page-36-35b]. In
thinking mode `tool_choice` accepts `auto` or `none` only [qwencloud-fn-calling]. The card's agent-style results are in the
Coding section.

### Coding

Maker runs from the card: SWE-bench Verified 73.4, SWE-bench Pro 49.5 (on a re-run set with corrected tasks, so not the Scale
V2 set), SWE-bench Multilingual 67.2, Terminal-Bench 2.0 51.5, SkillsBench 28.7, NL2Repo 29.4 and QwenWebBench 1397. The
footnotes give an internal scaffold with bash and file-edit tools (temperature 1.0, top_p 0.95, 200K context), Harbor with
Terminus-2 and a 3-hour timeout, OpenCode for SkillsBench and Claude Code with at most 900 turns for NL2Repo
[hf-qwen3-6-35b-a3b]. General-agent results: TAU3-Bench 67.2, MCPMark 37.0, MCP-Atlas 62.8 and WideSearch 60.1, with the
footnoted judges and user models (the TAU3 user model is gpt-5.2 at low effort) [hf-qwen3-6-35b-a3b]. For precise coding the
card suggests temperature 0.6. Artificial Analysis measured Terminal-Bench 2.1 at 44.9% and Terminal-Bench 4.0 at 0%
[aa-qwen3-6-35b-a3b].

### Long context and retrieval

The native context is 262,144 tokens, extensible to about 1,010,000 with YaRN at factor 4.0. Static YaRN can lower quality on
short inputs, so the card advises setting it only when long inputs are needed [hf-qwen3-6-35b-a3b]. Artificial Analysis's
long-context reasoning test (AA-LCR) gave 71.7 [aa-qwen3-6-35b-a3b]. The hosted model has a 260K maximum input and rate limits
of 1M tokens and 600 requests per minute; the page shows no cache price [qwencloud-page-36-35b].

### Structured output

QwenCloud's guide lists the Qwen3.6 open-source series for JSON Object mode in non-thinking mode only. In thinking mode the
setting raises no error, but the JSON may not be valid. The model is not on the JSON Schema list [qwencloud-structured].

### Images, audio, other inputs

Text, image and video in; text out. Card results include MMMU 81.7, RealWorldQA 85.3 and VideoMME 86.6 (maker runs). The video
preprocessor guidance is the same as for the 27B: 2 frames per second by default, and `longest_edge` of 469,762,048 for
hour-long video [hf-qwen3-6-35b-a3b].

### Sampling and API parameters

The card's values differ from the 27B's in one place. Thinking mode for general tasks: temperature 1.0, top_p 0.95, top_k 20,
min_p 0, **presence_penalty 1.5**, repetition_penalty 1 (the 27B card gives 0). Thinking mode for precise coding: temperature
0.6, top_p 0.95, top_k 20, presence_penalty 0. Non-thinking mode: temperature 0.7, top_p 0.80, top_k 20, presence_penalty 1.5.
Support for these parameters varies by engine [hf-qwen3-6-35b-a3b]. On QwenCloud the API reference gives a default
`presence_penalty` of 1.5 for Qwen3.6 in non-thinking mode and a temperature range from 0 up to but not including 2
[qwencloud-api-chat].

### Migrating from the previous generation

The previous model is Qwen3.5-35B-A3B. QwenCloud says the 3.6 model improves agentic coding, maths and code reasoning, and
spatial intelligence and object detection [qwencloud-page-36-35b]. The card compares the two (maker runs): SWE-bench Verified
73.4 against 70.0, SWE-bench Multilingual 67.2 against 60.3, Terminal-Bench 2.0 51.5 against 40.5, SkillsBench 28.7 against 4.4,
NL2Repo 29.4 against 20.5, QwenWebBench 1397 against 978, LiveCodeBench v6 80.4 against 74.6 and GPQA 86.0 against 84.2. Two
agent tests went the other way: TAU3-Bench 67.2 against 68.9 and Tool Decathlon 26.9 against 28.7 [hf-qwen3-6-35b-a3b]. The new
item is `preserve_thinking`.

## What the system card reports

Alibaba has published no system card for Qwen3.6-35B-A3B. The Hugging Face page is a model card with benchmarks and settings and
holds no safety, refusal, alignment or reward-hacking findings. QwenCloud moderates requests to the hosted model, as the README
says; a self-hosted copy has no such filter [hf-qwen3-6-35b-a3b]. One practitioner reports that the model refused
explicit requests but accepted literary framings (class A) [lilting-36-35b].

## Behaviour observed in practice

- **Index, verbosity and speed (M).** Artificial Analysis (index v4.3.2): 18, with 160M output tokens against a median of 82M
  for open models of its size class, 121.6 output tokens per second on Alibaba's API (rank 16 of 142), and US$0.48 per index task
  [aa-qwen3-6-35b-a3b].
- **Knowledge reliability (M).** Artificial Analysis: accuracy 18.8% and a hallucination rate of 50.5% on its knowledge test
  [aa-qwen3-6-35b-a3b].
- **Local use (A).** A test of 2026-04-21 on a 64 GB Apple M1 Max machine, using Ollama 0.20.6 and a 23 GB 4-bit
  build, measured 27.22 tokens per second against 27.24 for Qwen3.5-35B-A3B, so the same speed. With thinking on, the new model
  wrote 8,504 characters of reasoning for a small Python task against 652 for the older model, switched to English reasoning on a
  Japanese prompt, and took over 100 seconds. With thinking off the same function took 15 to 20 seconds. The author judged the
  thinking mode too slow for chat [lilting-36-35b].
- **Agreement between sources (M).** GPQA Diamond reads 86.0 (maker) and 84.1 (Artificial Analysis) [hf-qwen3-6-35b-a3b]
  [aa-qwen3-6-35b-a3b].

## Benchmarks

Independent: Artificial Analysis index 18; Terminal-Bench 4.0 0%; Terminal-Bench 2.1 44.9%; GPQA Diamond 84.1; Humanity's Last Exam
22.2; SciCode 36.6; IFBench 64.4; AA-LCR 71.7 [aa-qwen3-6-35b-a3b]. No Epoch AI page was found for this model. Scale's
SWE-Bench Pro V2 page, METR and Artificial Analysis's coding-agent board hold no entry that this file could find
[scale-swe-pro-v2] [metr-horizons] [aa-coding-agents]. Maker runs, each with its scaffold and settings, are in the card.

## Open questions

- Whether the 128K-or-more context advice and the longer thinking hold under quantisation; no independent test of this model
  was found.
- Why the card sets `presence_penalty` to 1.5 for general thinking tasks and the 27B card sets 0.
- Whether Alibaba's release blog post, which renders by script and was not read, holds more guidance.
