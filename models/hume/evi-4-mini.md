# Hume EVI 4-mini

EVI 4-mini is the current version of Hume's Empathic Voice Interface, a realtime speech-to-speech API over WebSocket. EVI measures vocal expression in the user's speech, passes it with the transcript to a language model, and speaks the reply in a synthetic voice that it shapes to the context. EVI 4-mini needs a supplemental language model of your choice and adds 11 languages. Hume's changelog dates it 2025-10-03. Hume has announced that the EVI and TTS APIs end on 2026-11-13. Maker-wide facts are in the [Hume README](README.md) [hume-overview] [hume-evi-version] [hume-changelog].

## How to instruct it

### Setting up the prompt

EVI 4-mini uses a system prompt, stored as a versioned resource in the API. If you give none, Hume applies a default prompt, which is on GitHub. With a supplemental language model, the system prompt goes to that model on every turn. Hume's prompting guide says the following [hume-prompting] [hume-language-model]:

- **What a prompt can do.** It guides language, style, format, flow and tool use. It can set an emotional tone, which affects the voice a little, for example "warm and nurturing". It cannot change the voice's accent, gender or identity, cannot set the speaking speed, and cannot give the model the date, time or user details without dynamic variables or web search. Voice is changed in the voice settings. Speed changes by a spoken request during the chat.
- **Be specific.** Clear, direct instructions with a stated limit, for example a rule to reply in fewer than three sentences of under twenty words each. Few-shot examples set tone and phrasing well.
- **Use sections.** Titled sections help. XML tags suit Anthropic models and Markdown headings suit OpenAI models.
- **Write for speech.** Tell the model that all output is spoken, to avoid text formatting, to prefer easily spoken words and to use natural interjections and discourse markers.
- **Keep it small.** Hume says the best prompts are small, stable and focused. Large reference text, per-user data, full tool schemas and long reasoning instructions add delay and cost on every turn. Inject small facts at run time with dynamic variables, web search or tools.
- **Test.** Start with 10 to 20 ideal example conversations, change one part of the prompt at a time, and test in real voice calls.

### Reasoning and effort

EVI has no reasoning setting. For hard reasoning, long prompts or tool use, Hume says a supplemental language model usually does better than its own speech-language model. EVI 4-mini requires a supplemental model [hume-prompting] [hume-evi-version].

### Output: format, length, tone

Output is audio and text. Hume's expressive prompting passes the top three vocal expressions of the user's turn (of 48) to the language model in brackets after the message. The prompt tells the model how to use them, for example to share joy, to acknowledge anger and try to calm it, or to answer sarcasm with humour. A second rule can name a mismatch between words and tone aloud [hume-prompting]. EVI delivers the prosody scores of the assistant in a separate `assistant_prosody` message [hume-evi-version].

### Tools and agents

EVI supports tool use and webhooks. With a supplemental model, the FAQ says tool use works with Anthropic, OpenAI and Google models. Model-specific features such as structured output and response prefill are not supported. Temperature works with every supplemental model; prompt caching applies to Anthropic and OpenAI models. The user can bring their own API key for the language model in the session settings [hume-faq] [hume-language-model].

### Coding

Hume gives no coding guidance.

### Long context and retrieval

Hume states no context size. The supplemental model sets it. A compact system prompt leaves more room for history. A chat can be resumed from an earlier chat group [hume-prompting] [hume-chat-ref].

### Structured output

Not supported with supplemental models, according to the FAQ [hume-faq].

### Images, audio, other inputs

Input is live audio, or text. Linear 16 PCM must be described in a `session_settings` message with the format, sample rate and channels. WebM can carry its own header, so open the WebSocket before the microphone starts. Mu-law, which Twilio streams use, is not supported and must be converted. Output is base64 WAV at 48 kHz in `audio_output` chunks. The languages are English, Japanese, Korean, Spanish, French, Portuguese, Italian, German, Russian, Hindi and Arabic [hume-audio-guide] [hume-chat-ref] [hume-evi-version].

### Voice: turn-taking, interruption and speech style

**Turn detection.** Three settings in the config's `turn_detection` [hume-turn-detection]:

- `end_of_turn_silence_ms`: 500 to 3000, default 800. A lower value is faster and may cut in on a pause. Hume's examples use 2000 for patient talk (language learning) and 500 for fast talk (scheduling).
- `speech_detection_threshold`: 0.0 to 1.0, default 0.5. A higher value suits noisy places.
- `prefix_padding_ms`: 0 to 1000, default 300. More padding keeps the start of a word.

**Interruption.** By default EVI stops at the first speech it hears. `interruption.min_interruption_ms` (50 to 2000, default 800) makes EVI keep going through short sounds. Hume suggests 1500 for resilient replies and 100 for a quick yield, and says to pair a higher value with a higher `end_of_turn_silence_ms` for a fully patient exchange. On `user_interruption` the client must stop playback and clear the queued audio, because EVI stops generating but the browser still plays what it has [hume-interruption] [hume-interruptibility].

**Interruption delay.** By default a `user_message` event comes only after enough speech for an accurate transcript, so the user may be slow to interrupt while the browser still plays a turn that EVI has finished generating. Hume says to open the socket with `verbose_transcription=true` to get interim user messages at once, and to stop playback on them. Code that reads transcripts must ignore or merge interim messages [hume-audio-guide].

**Audio handling.** EVI makes audio faster than it is spoken, so queue segments and play them in order. A sudden stop causes a click, so fade out when you stop playback [hume-audio-guide].

**Voices.** More than 100 predesigned voices, plus voices you design or clone. A voice prompt in the language you want creates a voice for another language. The config must set a voice [hume-voice] [hume-evi-version].

**Silence and length.** The inactivity timeout defaults to 120 seconds (30 to 1,800). The maximum duration defaults to 1,800 seconds and cannot go higher. Hume says to combine timeouts with event messages that give the user a notice or a check-in before the chat ends [hume-timeouts].

### Sampling and API parameters

Temperature is available for all supplemental models. Hume lists no other sampling setting on the pages read [hume-faq].

### Migrating from the previous generation

The change from EVI 3 to 4-mini is a config change: set `evi_version` to `"4-mini"`. The effects are 11 languages in place of English, a latency gain of about 100 ms per response, no quick responses, and a required supplemental model. Voices should be created again with a prompt in the target language [hume-evi-version].
