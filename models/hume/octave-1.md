# Hume Octave 1

Hume Octave 1 is a speech synthesis model of the Hume Octave class, generation 1. Hume calls it a speech-language model. It takes natural-language acting instructions and voice descriptions, so a user can direct emotion, style and pace beyond choosing a voice. Hume published it on 2025-02-26. The whole TTS API, with Octave 2, ends on 2026-11-13. Family-wide rules are in the [Hume README](README.md).

## How to instruct it

### Setting up the prompt

- **No system prompt.** The input is utterances. Each utterance holds `text`, an optional `voice`, an optional `description` (the acting instruction), `speed` and `trailing_silence` [hume-tts-overview] [hume-acting].
- **Acting instructions.** The `description` field takes natural language. The maker names five aspects it can steer: emotional tone, delivery style, performance context, speaking rate and trailing silence. Without an instruction, Octave infers delivery from the description of the base voice and from the text [hume-acting].
- **Version.** The request field `version` selects Octave 1 or 2. If the field is absent, Hume routes the request to the model it judges most suitable. The acting-instruction page states that `description` works on Octave 1 only, so a request that depends on it sets `version` to 1 [hume-acting] [hume-ws-ref].
- **Without a voice.** If a request names no voice, the `description` acts as a voice prompt that creates a new voice. The overview says to switch off instant mode for this use, because instant mode needs a named voice [hume-acting] [hume-tts-overview].

### Reasoning and effort

None. Octave is a speech-language model with no reasoning control.

### Output: format, length, tone

- **Formats.** MP3, WAV or PCM. Streamed JSON returns base64 audio with metadata. Streamed file returns raw bytes. The WebSocket takes text in pieces [hume-tts-overview] [hume-ws-ref].
- **Length.** 5,000 characters of text and 1,000 characters of description per utterance. At most 5 generations per request [hume-tts-overview].
- **Instant mode.** On by default since 2025-06-27. It sends smaller chunks of about one second and reaches first audio in about 200 ms. It needs a named voice and one generation [hume-tts-overview] [hume-changelog].
- **Tone.** Set by the `description`, the voice and the text. The maker states that Octave adapts pronunciation, pitch, tempo and emphasis to the emotional intent it finds in the words [hume-tts-overview].

### Tools and agents

Not applicable. The model has no tool use. Hume offers an MCP server that exposes its TTS tools to MCP clients such as Claude Desktop and Cursor [hume-tts-overview].

### Coding

Hume publishes SDKs for TypeScript, Python and .NET, a command-line tool, and sample code. The pages read give no coding guidance for the model [hume-tts-overview].

### Long context and retrieval

Octave 1 supports continuation. It carries the emotional and linguistic context of earlier speech into the next generation. The details are in the voice section below [hume-continuation].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. A voice clone needs an audio sample, which the user records or uploads in the Platform. The overview says about 15 seconds of audio is enough [hume-tts-overview] [hume-voice-cloning].

### Voice: turn-taking, interruption and speech style

Octave 1 is not a conversation model. It has no turn detection and no barge-in. A client that wants to stop playback stops its own player.

**How to direct delivery.**

- **Field.** `description` on each utterance. The field is per utterance, so a script changes delivery by splitting into utterances [hume-acting].
- **Length.** Hume advises at most about 100 characters. Its example is to write "frightened, rushed" and not a long sentence about a scared person who wants to leave [hume-acting].
- **Precision.** Hume advises precise emotions. It contrasts a broad word such as sad with melancholy or frustrated [hume-acting].
- **Combinations.** Hume advises pairing an emotion with a delivery style, for example an excited tone with whispering. It also lists pacing words (rushed, measured, a deliberate pause) and the audience (speaking to a child, addressing a large crowd) [hume-acting].
- **Speed is separate.** Hume advises the `speed` parameter, not words in the description, to change the rate. `speed` runs from 0.5 to 2.0 on a non-linear scale. A value of 2.0 is faster, not twice as fast. `trailing_silence` adds seconds of silence after an utterance. Both work on every model [hume-acting].
- **Pauses inside an utterance.** Hume gives `[pause]` and `[long pause]` in the text as a way to add breaks within one utterance [hume-acting].
- **Examples in the maker's guide.** A whispered "hushed" instruction on a question gives a soft, secretive read. An "urgent, panicked" instruction on a short command gives fast, tense delivery. A "calm, serene" instruction suits a meditation script, and the guide pairs it with a speed near 0.65 and four seconds of trailing silence [hume-acting].
- **Illustration, written for this library and not taken from the maker.** `description: "weary, resigned"` with the text "Fine. We will do it your way." and `speed: 0.9`. This is an illustration of the field, not a sample from the guide. It was not run against the model.
- **Strength.** Hume gives no figure for how strongly the field acts. In its own blind test against ElevenLabs with 180 raters, Octave was chosen as the better match to the given description or prompt in 57.7% of trials. The launch post does not say whether the prompts were voice descriptions or acting instructions. This is a maker result [hume-blog-octave].
- **What fails or limits.** The guide states that `description` is for Octave 1 only. The voice design guide says to avoid non-speech markup such as emojis, HTML and Markdown in the input [hume-acting] [hume-voice-design].

**Voice design and cloning.**

- **Design.** A voice prompt describes the speaker (tone, speaking style, emotion or attitude, setting and role), and a sample line gives delivery context. Octave reads both together. The Platform makes three candidates. The API returns up to five generations. A saved voice keeps the speech and the prompt that made it. The maker's examples are character prompts such as an expressive Valley Girl, a hype man and a pirate captain [hume-voice-design].
- **Version rule.** Voice design needs Octave 1. Voices designed there work in Octave 2 requests [hume-voice-design].
- **Cloning.** A clone comes from a recording or an uploaded file with consent. Availability depends on the subscription tier. The overview gives 15 seconds of audio as enough [hume-voice-cloning] [hume-tts-overview].

**Multi-speaker dialogue and long-form consistency.**

- **Chaining.** Several utterances in one request continue from the one before. A request can also continue from an earlier call through `context`, by `generation_id` or by context utterances [hume-continuation].
- **Voice carries over.** Octave keeps the voice of the previous utterance. A request names a voice only to change it. Continuation works across different voices, so a dialogue switches the `voice` field per utterance [hume-continuation].
- **Scope.** Continuation looks back one utterance only. Context utterances are reference only and add latency, because the model first has to generate the speech it continues from [hume-continuation].
- **Emotion by context.** The guide shows that the same line reads as excited or disappointed according to the line before it [hume-continuation].
- **Homographs.** Continuation also gives context for words such as bow, bass and read [hume-continuation].

**Pronunciation and text normalisation.** The pages read describe no phoneme tag and no text normalisation switch for Octave. Punctuation and context shape pronunciation [hume-continuation] [hume-voice-design].

**Turn-taking.** Not applicable to a synthesis model. Hume's separate speech-to-speech product, EVI, holds conversations and has its own files in this folder.

### Sampling and API parameters

- `version` ("1" or "2"), `instant_mode`, `num_generations`, `format`, `include_timestamp_types` (Octave 2 only) and `context` [hume-ws-ref].
- A `temperature` parameter is marked experimental in the changelog. The pages read give no range or default [hume-changelog].

### Migrating from the previous generation

There is no earlier Octave in scope. What changes in the next version [hume-tts-overview] [hume-acting] [hume-timestamps]:

- Octave 2 (preview) supports 11 languages, against 2 for Octave 1, about 100 ms model latency, and word and phoneme timestamps.
- The `description` field is documented for Octave 1 only. Octave 2 support is listed as coming soon.
- A request with `version` 2 must name a voice [hume-ws-ref].

## What the system card reports

Hume publishes no system card for Octave in the pages read. The FAQ says users own the audio they generate. A custom voice grants Hume a licence to use voice models to provide and improve its services. The Terms of Use and the prohibited use policy apply [hume-tts-overview] [hume-tts-faq].

## Behaviour observed in practice

- **Rank (M).** Artificial Analysis gives a quality Elo of 1036.11 for Octave TTS, the first version, and 1051.32 for Octave 2 on its leaderboard data [aa-tts-board].
- **Throughput (M).** The same data gives a median of about 45 characters a second for the first version [aa-tts-board].
- No practitioner report was read for this version.

## Benchmarks

Independent: Artificial Analysis quality Elo 1036.11 [aa-tts-board]. Maker: in a blind test with 180 raters against ElevenLabs, Octave was preferred in 71.6% of trials for audio quality, 51.7% for naturalness and 57.7% for matching the given description or prompt [hume-blog-octave].

## Open questions
