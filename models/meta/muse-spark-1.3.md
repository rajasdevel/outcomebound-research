# Muse Spark 1.3

Muse Spark 1.3 is Meta's closed-weight reasoning model in the Muse Spark class, generation 1.3, released on
2026-09-02. It is aimed at agentic and coding work and is served by the Meta Model API and the Muse Code terminal
agent. It replaced [Muse Spark 1.2](muse-spark-1.2.md) as the model Meta recommends. Meta says it takes fewer turns on
coding work than 1.2, is less verbose, and asks for clarification, help or confirmation more often. What holds for the whole Meta family (API
protocols, tiers, effort parameters, the safety-report digest) is on the [Meta page](README.md); this file says what
is specific to 1.3.

## How to instruct it

Meta publishes no prompting guide for Muse Spark, so this section collects what its API pages, release post and
harness documentation say that bears on a prompt. Where Meta is silent the section says so.

### Setting up the prompt

- **No guide, no stated style rules.** Nothing Meta published says whether to use XML tags or Markdown, how many
  examples to give, or where to place long documents. The 1.3 post says the model keeps detailed requirements across
  long multi-step tasks better than earlier versions, without dropping constraints or drifting from the requested
  workflow, and that it maps new messages to the right task when several tasks share one long thread
  [meta-1-3-post].
- **Trained to ask.** Meta says the model asks clarifying questions when a prompt is ambiguous, asks the user for help
  when stuck, confirms before consequential actions and judges irreversible actions better than 1.2. It also says
  the model adapts to a stated preference for frequent updates or for silent background work [meta-1-3-post]. A prompt
  that leaves a decision open may therefore draw a question instead of an action, and a preference about
  interruptions is something the post says the model responds to. No rate for any of these behaviours is published
  [note-muse-1-3].
- **Where text goes.** The Messages API `system` field takes text blocks only. Images go in user messages; the
  model does not process them in other roles [meta-api-messages, meta-api-images].
- **Cache-friendly order.** Meta's caching page says to put stable content first (system prompt, few-shot examples,
  conversation history) and the changing user message last, so the longest prefix is reused [meta-api-caching].
- **Muse Code.** The terminal agent reads `AGENTS.md`, `CLAUDE.md`, `.agents/AGENTS.md` and `.claude/CLAUDE.md`, with
  rules in the [Meta page](README.md#prompting-guides) [meta-muse-code-config].

### Reasoning and effort

- **The control.** `minimal`, `low`, `medium`, `high`, `xhigh` and `max`, passed as described on the [Meta
  page](README.md#api-surface). `none` returns HTTP 400; there is no way to switch reasoning off [meta-api-reasoning].
  Meta's reasoning page calls `low` recommended for direct-answer tasks [meta-api-reasoning].
- **What Meta recommends for agents.** The coding-agent page sets `high`, with `xhigh` and `max` for deeper analysis, a
  `reasoning.summary` of `auto`, and `include: ["reasoning.encrypted_content"]` so reasoning survives multi-turn
  tool loops [meta-api-coding]. Muse Code defaults to `high`; its `ultra` tier delegates to the provider's highest tier
  [meta-muse-code-config].
- **`max` availability.** On launch day Artificial Analysis and VentureBeat called `max` a limited preview for Meta
  partners with more safety testing pending, and LiteLLM said it was not yet available [aa-1-3-article,
  venturebeat-muse-1-3, litellm-muse-1-3]. On 2026-10-03 Meta's models and reasoning pages list it for the standard
  tier only (not the contributor tier) at the same per-token price as the other levels, the 1.3 post opens by saying
  it is available, and Artificial Analysis lists one API provider for it [meta-api-models, meta-api-reasoning,
  meta-1-3-post, aa-muse-1-3-max]. A practitioner write-up (class A) reports that it reached general availability a
  few days after launch [note-muse-1-3]. No live API call was made.
- **What `max` costs.** Meta's reasoning page says reasoning tokens make up a larger share of output at `max` and
  advises a generous output limit [meta-api-reasoning].
- **Thinking visibility.** The chain of thought is not returned. The Responses API can return a summary through
  `reasoning.summary` (`auto` about one sentence, `concise`, `detailed`), which Meta says is not guaranteed on every
  turn; Chat Completions returns a `reasoning_content` field that is emptied for outside callers
  [meta-api-reasoning].
- **Budget.** Reasoning shares the output budget. A practitioner test with a 6,000-token completion cap saw all three
  `xhigh` coding attempts spend 5,997 tokens on hidden reasoning and return no code, while two of three `high`
  attempts produced a usable patch (class A) [kingy-muse-1-3]. Meta's coding-agent page tells agent configurations
  to declare an output limit of 131,072 tokens [meta-api-coding].
- **Latency and tokens.** Artificial Analysis measured a time to first token of 32.5 s at `xhigh` and 50.8 s at `max`
  (67.0 s to the first answer token at `max`), and 140 million and 170 million output tokens to run its index against
  a median of 81 million. Per task it counted 55,000 output tokens at `xhigh`, of which 33,000 were reasoning
  [aa-muse-1-3-xhigh, aa-muse-1-3-max, aa-compare-1-3-vs-1-2, aa-compare-1-3-max-vs-medium]. Artificial Analysis says
  the gain of `max` over `xhigh` on agentic tests comes from more turns and more reasoning tokens (62% more on
  GDPval-AA v2, 28% more on tau3-Bench Banking) [aa-1-3-article].
- **Step-by-step prompting.** Meta says nothing about it; on a model that always reasons, no source recommends
  adding it.

### Output: format, length, tone

- No verbosity, length or format parameter exists in the documentation read. Meta's post says 1.3 is less verbose
  than 1.2 on coding work and has a cleaner coding style [meta-1-3-post]; Artificial Analysis, counting tokens on its
  own index, calls both the `xhigh` and `max` settings "very verbose" [aa-muse-1-3-xhigh, aa-muse-1-3-max].
- The Messages API rejects `stop_sequences`. Prefilling the assistant turn is not documented [meta-api-messages].
- Streaming shows an initial wait before visible text because reasoning runs first [meta-api-reasoning]. Meta advises
  streaming for long audio and for high effort to avoid timeouts [meta-api-video].
- Tone: Meta's behaviour claims (asking, confirming, calibrated hesitation) are the only description of default
  manner; there is no style guidance.

### Tools and agents

- **Definitions.** Function tools use JSON-schema parameters. Custom tools take freeform text and exist on the
  Responses API only. Function names match `^[a-zA-Z0-9_.-]+$` with at most one dot (two or more dots return 400).
  `call_id` is 1 to 64 characters and a mismatch returns 400. Meta says to validate arguments in application code even
  with a schema [meta-api-tools].
- **Calls.** `parallel_tool_calls` defaults to true; false limits the model to one call per turn. Only `tool_choice: "auto"` is
  supported. `strict` defaults to false, and `strict: true` needs `additionalProperties: false` and every property
  required or the request returns 400. Meta says every result of a parallel batch must be returned before the next request
  [meta-api-tools].
- **Large tool libraries.** Tools marked `defer_loading: true`, plus one `tool_search` tool, are loaded on demand; names and descriptions of
  deferred tools stay visible and only their parameter schemas are withheld. It works on the Responses API and the
  Messages adapter, cannot be combined with `json_schema` output, and Meta advises namespaces of fewer than 10
  functions each [meta-api-tool-search].
- **Reasoning continuity.** Meta recommends the Responses API (or the Messages surface through the Claude Agent SDK) so reasoning
  carries across tool turns. OpenCode with an OpenAI-compatible adapter on Chat Completions loses reasoning between
  turns; Codex with `wire_api = "responses"` replays it [meta-api-coding, meta-api-frameworks].
- **Computer use and search.** The `computer` tool and `web_search` are described on the [Meta
  page](README.md#family-wide-behaviour). Search grounding costs $2.50 per 1,000 queries on top of tokens
  [meta-api-pricing]. Its search page offers `search_context_size` (low, medium, high) and an approximate
  `user_location`, reserves the internal tool names `browser.search`, `browser.open` and `browser.find` when search is
  in the request, and says single-fact and recent-events questions are the most reliable while multi-hop research is
  less dependable [meta-api-search].
- **Long unattended runs.** Meta advises wall-clock timeouts with idle watchdogs, sandboxing, and matching completion
  events explicitly instead of trusting stream termination [meta-api-frameworks]. Muse Code does not commit or push
  unless asked [meta-muse-code-config].
- **Observed.** In one hands-on test the model passed 6 of 6 tool-workflow trials that involved pagination, retryable
  reads, timeouts and idempotency, and made only the authorised writes (class A) [kingy-muse-1-3].

### Coding

- **Maker claims.** Meta says 1.3 finishes coding work with about 20% fewer tool calls and about 25% fewer tokens than
  1.2 [meta-1-3-post]. Its scorecard (an image; the numbers below come from relays) gives 88.8 on Terminal-Bench 2.1,
  75.4 on DeepSWE v1.1 and 59.4 on SWE-Atlas Codebase QnA, all at `max` [eesel-muse-1-3, venturebeat-muse-1-3]. Meta's
  methodology says it compares 1.3 at `max` with 1.2 at `xhigh`, and reports the highest comparable value from its own
  run, the official leaderboard or the model provider's results; refusals score zero [meta-methodology-1-3].
- **Independent.** Artificial Analysis's Coding Agent Index (v1.5: DeepSWE v1.1, Terminal-Bench 4.0 and
  SWE-Atlas-QnA) in the Muse Code harness: 54 at `max` (DeepSWE 72%, Terminal-Bench 4.0 32%, SWE-Atlas 59%, $3.98 a
  task) and 48 at `xhigh` (73%, 17%, 55%, $3.47 a task) [aa-coding-muse-code]. Figures of 64 and 68 that circulated at
  launch could not be traced to a page that opens and are not used. The Terminal-Bench 4.0 run inside its
  Intelligence Index resolved 17% of tasks at `xhigh` and 33% at `max` [aa-compare-1-3-vs-1-2,
  aa-compare-1-3-max-vs-medium].
- **Tokens against Meta's claim.** On its agentic evaluations Artificial Analysis counted about 57% more input tokens
  and about 8% more output tokens per task than for 1.2, a different workload from Meta's [aa-1-3-article].
- **Harness notes.** Muse Code is the maker's harness. Meta's coding-agent page gives configurations for OpenCode,
  Codex and Claude Code, and its agent-frameworks page for the Claude Agent SDK and the Codex app-server, with the
  settings in [Tools and agents](#tools-and-agents) [meta-api-coding, meta-api-frameworks]. For Claude Code, Meta says
  to point every model alias and the subagent model at `muse-spark-1.3` so no path falls back to a model Meta does not
  serve [meta-api-coding].
  Meta's September safety post describes labelling untrusted outside input at the harness level in its own agent
  product [meta-safety-blog].
- **A caution.** One review (class A) notes that Meta's 75.4 on DeepSWE did not appear on the public DeepSWE
  leaderboard and that the model's game-building output in its own test trailed lower-ranked models
  [mindstudio-muse-1-3]. Meta's methodology explains part of the first point: it ran 1.3 itself with mini-swe-agent and
  took the other models' DeepSWE scores from the official leaderboard [meta-methodology-1-3].

### Long context and retrieval

- Context is 1,048,576 tokens and the maximum output 131,072 [meta-api-models, meta-api-coding].
- Artificial Analysis's long-context reasoning test (AA-LCR v1.1) gave 83% at both `xhigh` and `max`, against 79% for
  1.2; its launch article reported a 4-point drop from 83% to 79% on its own table, and the two do not agree
  [aa-compare-1-3-vs-1-2, aa-compare-1-3-max-vs-medium, aa-1-3-article].
- In a hands-on test of structured extraction from a contract packet of about 96,000 tokens, all four profiles tested
  (1.3 at `high` and `xhigh`, 1.2 at `xhigh` and one other vendor's model) recovered all seven controlling terms with
  exact citations in three of three trials (class A) [kingy-muse-1-3].
- Caching is automatic and prefix-based; cached input costs $0.15 per million tokens against $1.25 uncached, an 88%
  discount; `prompt_cache_retention: "24h"` asks for longer retention as a hint [meta-api-caching, meta-api-pricing].
- Meta's scorecard (relayed by two third parties; the post shows it as an image) gives MRCR v2 8-needle scores of 98.5
  (256K to 512K tokens) and 98.1 (512K to 1M) at `max`, and 97.6 and 93.1 at `xhigh`, against 66.3 and 55.5 for 1.2
  at `xhigh` [eesel-muse-1-3, note-muse-1-3]. Meta's methodology describes the test as pure retrieval from context,
  100 examples per band, scored by sequence similarity [meta-methodology-1-3].

### Structured output

- `response_format` of type `json_schema` constrains decoding; Pydantic parsing works through the OpenAI SDK's
  `beta.chat.completions.parse`. On the Messages API the schema goes in `output_config.format` [meta-api-structured,
  meta-api-messages].
- Limits: nesting depth 10; 5,000 properties in total; 120,000 characters of string content combined; 1,000 enum
  values by default; a string enum of more than 250 values is held to 15,000 characters; 200,000 nodes after `$ref`
  inlining. Recursive schemas return HTTP 400. The same limits apply to function-tool parameter schemas
  [meta-api-structured].
- Output under `response_format` is always schema-constrained, so `strict: false` behaves like `strict: true` there;
  the flag only decides whether the server also checks the schema against the strict subset [meta-api-structured].
- `strict: true` requires an object root with no `anyOf`, `oneOf` or `allOf` at the root, every property listed in
  `required`, and `additionalProperties: false` [meta-api-structured].
- It combines with tool calling, image input and search grounding, but not with `tool_search` [meta-api-structured,
  meta-api-tool-search, meta-api-search].

### Images, audio, other inputs

- **Images.** Public URLs, base64 data URLs or Files API ids; JPEG, PNG, GIF, WebP and ICO; up to 50 images and 50 MB
  inline (1 GiB by Files API). A 1280-pixel image costs about 1,300 to 1,500 tokens; the input-token endpoint gives
  exact counts. Grounding output can be a point, a box or a count on a 0 to 1000 normalised grid [meta-api-images].
- **Grounding prompts.** Meta's image page advises asking for one output shape and listing the objects, keeping the
  grounding instruction in the user message with a minimal system prompt, pairing it with structured output, pointing
  at every instance before counting, and clamping values that land slightly outside 0 to 1000; it reports that opening
  a box prompt with an expert role and an instruction not to miss objects improves recall [meta-api-images].
- **PDFs.** Text from the first 100 pages and page images from the first 50, which also count toward the 50-image
  limit. Text, JSON and JSONL files are accepted [meta-api-files].
- **Video.** MP4 by URL, base64 or Files API; an embedded audio track is processed with the frames [meta-api-video].
- **Audio.** MP3 and WAV. Meta says audio understanding in 1.3 is not fully supported and quality may be degraded,
  and recommends 1.2 for audio. For transcription set `max_tokens` to at least 4,000 and stream [meta-api-video]. Artificial
  Analysis lists text, image and video input only [aa-muse-1-3-xhigh].
- **Multimodal methodology.** Meta published a methodology note for the 1.3 benchmarks [meta-methodology-1-3].

### Sampling and API parameters

- Meta's Messages page says the model works best at its default temperature of 1.0, advises leaving sampling unset
  for most work, and says to set `temperature` or `top_p` but not both; its coding-agent page calls the defaults (both
  1.0) the recommended setting [meta-api-messages, meta-api-coding]. The Messages API holds `temperature` to 0 to 1,
  passes `top_p`, and rejects `top_k` and `stop_sequences`. OpenRouter lists `temperature`, `top_p`, `top_k` and
  `repetition_penalty` for the model [openrouter-1-3].
- Log probabilities are unsupported and return HTTP 400 [meta-api-reasoning].
- Rate limits and prices are on the card and the [Meta page](README.md#api-surface). `service_tier` on the Messages
  API takes `auto` or `standard_only` [meta-api-messages].

### Migrating from the previous generation

- **Effort.** 1.2 tops out at `xhigh`; 1.3 adds `max` on the standard tier. Muse Code's configuration
  page still names `muse-spark-1.2` as its default model and is undated [meta-muse-code-config].
- **Behaviour.** Prompts written for 1.2 that left a choice open may now meet a clarifying question or a
  confirmation request, since the 1.3 post says that behaviour was added or strengthened [meta-1-3-post].
- **Tokens and latency.** Meta claims 25% fewer tokens and 20% fewer tool calls on coding work. Artificial Analysis
  measured more input tokens and 8% more output tokens per agentic task, higher time to first token (32.5 s at
  `xhigh` against 12.0 s for 1.2) and 55,000 against 48,000 output tokens per index task [meta-1-3-post,
  aa-1-3-article, aa-compare-1-3-vs-1-2]. A hands-on test measured mean task time of 86.7 s at `high` and 99.0 s at
  `xhigh` against 36.0 s for 1.2, all through OpenRouter (class A) [kingy-muse-1-3].
- **Audio.** Meta points audio work to 1.2 [meta-api-video, meta-api-models].
- **Knowledge and hedging.** Artificial Analysis's AA-Omniscience index fell from 27 to 23 on its v4.3.2 pages; its
  launch article reports accuracy falling 3 points (45% to 42%) at `xhigh` and attributes it to a higher abstention
  rate, which also lowered the hallucination rate [aa-compare-1-3-vs-1-2, aa-1-3-article].
- **Price.** Unchanged at $1.25 input, $4.25 output and $0.15 cached per million tokens [meta-api-pricing].

## What the system card reports

Meta published no system card, safety report or evaluation report for Muse Spark 1.3. The 1.3 post says the model
resists adversarial inputs and prompt injection better than before and is better calibrated about irreversible steps in
long agent tasks, and gives no figures [meta-1-3-post]. Meta's September safety post calls 1.3 close to the state of the art on
prompt-injection robustness and describes defences it builds around its own agent product [meta-safety-blog]. A
methodology note covers how the capability benchmarks ran [meta-methodology-1-3].

The nearest measured baseline is the Muse Spark 1.1 evaluation report, written for an earlier model; its figures
are not 1.3's. The [Meta page](README.md#system-card-practice) summarises it in full. The points that
bear most on deployment:

- Before mitigation, 1.1 could not be ruled out as reaching Meta's high-risk threshold for chemical and biological
  and for cyber capability. Meta ships safeguards that refuse such requests (97.7% to 99.8% refusal on its chemical
  and biological sets), so a request in those areas may be refused, and a benign cyber request may be too (5.7% false
  refusals on cyber chat for 1.1; 16.5% on benign agentic tasks).
- Prompt injection: 0.7% attack success on AgentDojo and 0% on simple file injection for 1.1, but Meta ran these
  without system defences and advises tool allowlists and workspace isolation.
- Behaviour: deception 0.1% on DeceptionBench and 95.7 on the MASK honesty test for 1.1; sycophancy 49.2% on Meta's
  adversarial set; the model often says it suspects it is being tested (27.9% of samples), so evaluation results may
  not carry over to deployment. Meta's coding-agent risk-escalation test (SAVE-Bench) scored 1.1 at 90.7.

## Behaviour observed in practice

- Long wait for the first token and high token use at high effort (Artificial Analysis's median for its price tier is 4.02 s): time to first token of 32.5 s (`xhigh`) and 50.8 s (`max`); 140 and
  170 million output tokens to run the index; per task 55,000 output tokens at `xhigh` (class M, Artificial Analysis)
  [aa-muse-1-3-xhigh, aa-muse-1-3-max, aa-compare-1-3-vs-1-2].
- Cost per task on Artificial Analysis's index: $1.37 at `xhigh` and $1.60 at `max`; its article gives $0.55 for
  `xhigh` on a different task set (class M) [aa-muse-1-3-xhigh, aa-muse-1-3-max, aa-1-3-article].
- Budget starvation under a tight completion cap, with `xhigh` returning no visible code in three of three attempts
  (class A, one test) [kingy-muse-1-3].
- Six of six tool-workflow trials passed in one test (pagination, retries, timeouts, idempotency and an injected
  instruction to delete data, with only the authorised writes made), and a contract extraction at about 96,000 tokens
  passed three of three (class A) [kingy-muse-1-3].
- Benchmark rank and open-ended coding quality can diverge: one review found the DeepSWE score absent from the
  public board and plainer output than lower-ranked models on a game-building prompt (class A) [mindstudio-muse-1-3].
- Gateways: LiteLLM, Vercel's AI Gateway and OpenRouter list the model; OpenRouter listed it at no charge in one
  review (class A) [litellm-muse-1-3, vercel-muse-1-3, openrouter-1-3, mindstudio-muse-1-3].
- The contributor endpoint is cheaper and, per Meta's pricing page, lets Meta train on prompts and completions
  [meta-api-pricing].
