# Muse Spark 1.2

Muse Spark 1.2 is Meta's closed-weight reasoning model in the Muse Spark class, generation 1.2, released on 2026-08-05
together with the Muse Code terminal agent. Meta describes it as a coding-focused update to Muse Spark 1.1. It is the
previous generation to [Muse Spark 1.3](muse-spark-1.3.md): Meta's models page lists it as a previous version and
recommends 1.3, and Artificial Analysis marks it deprecated. API protocols, tiers and the safety-report digest are
on the [Meta page](README.md); this file says what is specific to 1.2 and links to the 1.3 file for rules Meta states
once for the API.

## How to instruct it

Meta publishes no prompting guide for Muse Spark and none that names 1.2. Its API pages are written for the Muse Spark
models and name 1.2 only where behaviour differs (the `max` tier and audio). The rules below were read against
1.3 and apply to 1.2 unless a line says otherwise; the full text of those rules is in the [1.3 file](muse-spark-1.3.md#how-to-instruct-it).

### Setting up the prompt

- Meta describes 1.2 as stronger at code generation, complex debugging, codebase understanding and end-to-end developer
  workflows. It says 1.2 was co-trained with Muse Code (including rejection-sampled harness trajectories and tuning for
  goals, compaction and subagents), trained on long-horizon coding such as whole-repository generation, and follows
  complex instructions more precisely than 1.1 thanks to training data that 1.1 generated and graded
  [meta-1-2-post]. It gives no guidance on prompt structure, examples or document placement.
- The asking-and-confirming behaviour that the 1.3 post describes (clarifying questions, calling for help, confirming
  consequential actions) is described by Meta for 1.3 only; no source read says whether 1.2 shows it
  [meta-1-3-post].
- Image placement, system-message rules and cache ordering are the same as on the [1.3 page](muse-spark-1.3.md#setting-up-the-prompt).
- Muse Code reads `AGENTS.md`, `CLAUDE.md`, `.agents/AGENTS.md` and `.claude/CLAUDE.md` for either model, and its
  configuration page still names `muse-spark-1.2` as the default model (the page is undated) [meta-muse-code-config].

### Reasoning and effort

- Levels are `minimal`, `low`, `medium`, `high` and `xhigh`. `max` is listed for 1.3 on the standard tier only, and Meta's
  own 1.2 methodology treats `xhigh` as the maximum available reasoning strength for the model [meta-api-reasoning,
  meta-1-2-methodology]. `none` is unsupported (HTTP 400) [meta-api-reasoning].
- Muse Code defaults to `high`; Meta's 1.2 benchmarks ran at `xhigh` [meta-muse-code-config, meta-1-2-methodology].
- Reasoning shares the output budget and is billed as output, and the raw chain of thought is private; see the [Meta
  page](README.md#api-surface) [meta-api-reasoning].
- Artificial Analysis ran 1.2 at `xhigh`: 130 million output tokens for its index, 48,000 output tokens a task of which
  23,000 were reasoning, 11.97 s to the first token and 234.8 tokens a second. That is faster to start and lighter in
  tokens than 1.3 at `xhigh` (32.5 s, 55,000 tokens a task) [aa-muse-1-2, aa-compare-1-3-vs-1-2].
- No source recommends step-by-step prompting or says what each level is for beyond the coding-agent page's advice of
  `high` for agent work [meta-api-coding].

### Output: format, length, tone

- No verbosity or format control is documented; the output cap is shared with reasoning and the Messages API rejects
  `stop_sequences` [meta-api-reasoning, meta-api-messages].
- Meta says nothing about tone for 1.2. Artificial Analysis's earlier article observed a lower hallucination rate (38%
  to 28% against 1.1) bought by attempting fewer questions (attempt rate 82% to 67%), meaning the model abstains more
  often than 1.1 did [aa-muse-1-2-article].

### Tools and agents

- Tool calling, tool search, custom tools, parallel calls and the `tool_choice: "auto"` restriction are documented for the
  Muse Spark API and not split by version; see [1.3](muse-spark-1.3.md#tools-and-agents) for the rules [meta-api-tools].
- Meta's 1.2 post describes Muse Code as running asynchronous background agents that persist through a session, with a
  local event-log runtime that makes runs replay-exact and safe to restart after a crash, plus bundled commands
  `/plan` (planning with approval), `/grill` (stress-testing a plan) and `/goal` (working toward an objective)
  [meta-1-2-post].
- Meta cites a kernel-optimisation case study of more than 1,000 tool calls over up to 24 hours, with improvements it
  does not quantify [meta-1-2-post].
- A hands-on test timed a tool-and-coding mix at a mean 36.0 s per task for 1.2 against 86.7 s for 1.3 at `high`
  (class A) [kingy-muse-1-3].

### Coding

- Meta's evidence is charts without numbers in the text (Terminal-Bench 2.1, DeepSWE 1.1 and a Meta internal coding
  bench) [meta-1-2-post]. Its methodology note fixes how they ran: Muse Code at `xhigh`; Terminal-Bench 2.1 on all 89
  tasks in cloud sandboxes, pass@1 across five attempts; DeepSWE v1.1 on 113 tasks across 91 repositories in five
  languages, five attempts, no internet; the internal bench on 440 tasks from real pull requests, two attempts
  [meta-1-2-methodology]. Peers ran in their own harnesses (Claude Code, Codex and others), at maximum effort for
  Opus, GPT and Kimi and at `high` for Grok and Gemini, and Meta calls its runs of third-party models best effort.
- Artificial Analysis: Terminal-Bench 2.1 78% to 80% against 1.1 (its article); under index v4.3.2 its Terminal-Bench
  4.0 run resolved 7% of tasks [aa-muse-1-2-article, aa-compare-1-3-vs-1-2]. Its 1.3 launch article also gives 1.2's
  Terminal-Bench 2.1 score as 80% [aa-1-3-article]. Artificial Analysis's Coding Agent Index lists no Muse Code run
  with 1.2 [aa-coding-muse-code].
- Meta's own comparison says 1.3 uses about 25% fewer tokens and 20% fewer tool calls than 1.2 on coding work, which
  makes 1.2 the heavier of the two on Meta's tasks [meta-1-3-post]. On Artificial Analysis's agentic tests 1.2 used
  fewer input tokens than 1.3 [aa-1-3-article].

### Long context and retrieval

- Context is 1,048,576 tokens. Meta's docs give a 131,072-token output maximum for 1.3 only; none is published for 1.2
  [meta-api-models, meta-api-coding].
- Artificial Analysis's AA-LCR v1.1 gave 79% for 1.2 against 83% for 1.3 [aa-compare-1-3-vs-1-2]. Its launch article for 1.3
  states the reverse, a 4-point drop from 83% (1.2) to 79% (1.3), and the two do not agree [aa-1-3-article].
- Meta's 1.3 scorecard, as relayed, gives 1.2 at `xhigh` MRCR v2 8-needle scores of 66.3 (256K to 512K tokens) and 55.5
  (512K to 1M) [eesel-muse-1-3].
- Caching is automatic; cached input costs $0.15 per million tokens [meta-api-caching, meta-api-pricing].

### Structured output

- JSON-schema constrained decoding, strict-mode rules and schema limits are documented once for the Muse Spark API; see
  [1.3](muse-spark-1.3.md#structured-output) [meta-api-structured].

### Images, audio, other inputs

- Image, PDF and file limits are as on [1.3](muse-spark-1.3.md#images-audio-other-inputs).
- **Audio is better here.** Meta says audio understanding in 1.3 is limited and recommends 1.2 for audio tasks; Artificial
  Analysis lists speech input for 1.2 [meta-api-video, aa-muse-1-2].
- Meta's multimodal post for 1.2 describes turning images and videos into working web pages and games, video
  understanding, combining dense video captioning with agent tools, and using the model as a two-level planner for
  robot manipulation. Scores it gives: ZeroBench 54.0% (GPT-5.6 Sol 54.6%), SimpleVQA 75.0% (Gemini 3.7 Flash 77.8%),
  CharXiv Reasoning 87.6% (Opus 5 89.3%), and 1279 (video to website), 1252 (image to website) and 1272 (image to
  frontend) on Design Arena leaderboards as of 2026-08-18. Meta says the multimodal gains are largest with tools, and
  charts one score rising from 59.8 without tools to 72.0 with them [meta-1-2-multimodal].

### Sampling and API parameters

- Meta's sampling advice is written for the family, not for 1.2: keep the default temperature of 1.0, leave sampling
  unset for most work, and set `temperature` or `top_p` but not both [meta-api-messages]. Parameter support
  (`temperature` 0 to 1, no `top_k` or `stop_sequences` on the Messages API, no log probabilities) is documented for
  the API in general [meta-api-messages, meta-api-reasoning].
- A `muse-spark-1.2-contributor` id exists next to the standard id; the contributor tier lets Meta train on prompts and
  completions [meta-api-pricing].

### Migrating from the previous generation

Muse Spark 1.1 came before 1.2 and has no file here, because it is older than the current and previous generations.
What Meta and Artificial Analysis say changed from 1.1 to 1.2:

- **Focus.** Meta scaled up coding training and launched Muse Code; Artificial Analysis found large gains on agentic
  knowledge work (GDPval-AA v2 up 260 Elo to 1631 on its earlier index; index 51 to 54; tau3-Banking 25% to 27%)
  [meta-1-2-post, aa-muse-1-2-article].
- **Cost.** Artificial Analysis measured about 53% more input tokens and 36% more output tokens per task than 1.1, and a
  cost per index task of $0.40 against $0.29 on its earlier index [aa-muse-1-2-article].
- **Abstention.** More abstention, fewer wrong answers, as above [aa-muse-1-2-article].
- **Leaving 1.2.** Moving to 1.3 brings `max` effort, more asking and confirming, 8% more output tokens and 57% more input
  tokens on Artificial Analysis's agentic tests, a slower first token, and weaker audio; see the [1.3
  file](muse-spark-1.3.md#migrating-from-the-previous-generation).

## What the system card reports

Meta published no system card or safety report for Muse Spark 1.2; its 1.2 post carries no safety statements, and a
methodology note covers only how the capability benchmarks ran [meta-1-2-post, meta-1-2-methodology]. The nearest
published baseline is the Muse Spark 1.1 evaluation report, written for the model 1.2 builds on. It found the model
at Meta's high-risk threshold for chemical, biological and cyber capability before safeguards, and moderate or lower
after them; very low prompt-injection and jailbreak success against peers; a 27.9% rate of verbalised suspicion of
being tested; and a risk-escalation score of 90.7 on Meta's coding-agent test. Its full digest is on the [Meta
page](README.md#system-card-practice). None of it was measured on 1.2, and Meta does not say the figures carry over
[meta-eval-report-1-1].

## Behaviour observed in practice

- Faster to start and lighter than 1.3: 11.97 s to the first token, 234.8 tokens a second, 48,000 output tokens a
  task, $0.97 a task on Artificial Analysis's v4.3.2 index (class M) [aa-muse-1-2, aa-compare-1-3-vs-1-2].
- Mean task time of 36.0 s in one hands-on mixed test through OpenRouter, against 86.7 s for 1.3 at `high`; 1.2 passed
  two of three tool-workflow trials where 1.3 passed six of six (class A) [kingy-muse-1-3].
- Artificial Analysis marks the model deprecated and keeps benchmarking only its default 10,000-input-token workload
  (class M) [aa-muse-1-2].
- More abstention than 1.1 (class M) [aa-muse-1-2-article].

## Benchmarks

Independent (Artificial Analysis, class M):

- Intelligence Index v4.3.2: 40 at `xhigh`, 130 million output tokens. Its launch-day article gave 54 (1.1: 51, 1.0:
  43), and its 1.3 article gives 57 for 1.2 (1.1: 53) on the version used then; the three are not comparable
  [aa-muse-1-2, aa-muse-1-2-article, aa-1-3-article].
- v4.3.2 components: AA-Briefcase 1329, GDPval-AA v2.1 1478, AutomationBench-AA 41%, Terminal-Bench 4.0 7%, SciCode 57%,
  Humanity's Last Exam 45%, GDP.pdf 17%, CritPt 18%, AA-Omniscience 27, AA-LCR 79% [aa-compare-1-3-vs-1-2].
- From the 1.3 launch article, which names them as 1.2's scores: Terminal-Bench 2.1 80%, GDPval-AA v2 1615 Elo,
  tau3-Bench Banking 35% [aa-1-3-article].
- Scale's SWE-Bench Pro (public V2), METR's time horizon, the tbench.ai Terminal-Bench 4.0 board and Artificial
  Analysis's Coding Agent Index hold no entry for 1.2 [scale-swe-pro-v2, metr-horizons, tbench-4-leaderboard,
  aa-coding-muse-code].

Maker-reported: the multimodal scores above; in Meta's 1.3 scorecard as relayed, 1.2 at `xhigh` scored Terminal-Bench 2.1
82.9, DeepSWE v1.1 55.0, SWE-Atlas Codebase QnA 46.2, OSWorld 2.0 47.6 (on an older OSWorld release than the other
models) and JobBench 61.6 [eesel-muse-1-3, meta-methodology-1-3]. The 1.2 post's own coding charts carry no text
numbers.
