# Muse Wonder

Muse Wonder is the first generation (1.0) of Meta's Muse Wonder class, a closed model that Meta calls its most capable
model for complex software engineering and long-horizon agent work. Meta released it on 2026-10-12 together with a
higher-capability variant, [Muse Wonder Full](muse-wonder-full-1.0.md), which only Muse Code subscribers can use. It
does not replace Muse Spark: Meta's docs keep [Muse Spark 1.3](muse-spark-1.3.md) for high-volume, latency-sensitive
and cost-sensitive work, and say that the two take the same requests on the same endpoints. Meta's models page calls
Muse Wonder a preview. L [meta-wonder-post] [meta-api-models]

## How to instruct it

What is the same for every Muse model on Meta's API (protocols, the Messages-API limits, tool and caching rules) is in
the [maker README](README.md#api-surface). This file says what differs for Muse Wonder.

### Setting up the prompt

Meta publishes no prompting guide for Muse Wonder. Its docs make it the default model for long-running agent work: the
coding-agent, agent-framework and computer-use guides run the main loop on `muse-wonder-1.0` and send subagents and
lightweight tasks to `muse-spark-1.3`. The computer-use guide gives a sample system prompt, passed as `instructions` on
the Responses API, that limits batching to actions that need no new screenshot and tells the model to finish only when
the screen shows the goal done. L [meta-api-coding] [meta-api-frameworks] [meta-api-computer-use]

The launch post describes two trained behaviours, which Meta names Active Memory (carrying context about the user
across conversations and retrieving it when it becomes relevant) and Active Focus (trying other approaches, working
through blockers, asking for clarification when needed and checking in before important actions). The post gives no
rate for either behaviour. L [meta-wonder-post]

### Reasoning and effort

The control is `reasoning_effort` (Chat Completions) or `reasoning.effort` (Responses), with the levels `minimal`,
`low`, `medium`, `high`, `xhigh` and `max`. `none` returns HTTP 400. When the parameter is omitted the model picks a
level. `max` goes beyond `xhigh`, bills at the same per-token price, and gives a larger share of output to reasoning
tokens, so Meta advises a generous output limit. Meta suggests `max` on Muse Wonder for the hardest problems, such as a
concurrency bug or a large migration. `max` on `muse-wonder-1.0` does not select Muse Wonder Full. L [meta-api-reasoning]

The coding-agent page calls `high` a strong default for Codex and lists `xhigh` and `max` as deeper options. L
[meta-api-coding]

### Output: format, length, tone

Reasoning tokens count toward `max_tokens` or `max_output_tokens` and are billed as output; a budget that is too small
can cut the visible answer. A Responses run that reaches `max_output_tokens` returns HTTP 200 with `status:
"incomplete"`. No Meta page read gives an output limit for this model; OpenRouter lists 943,718 tokens for its route
(class A). L [meta-api-reasoning] [meta-api-computer-use]; A [openrouter-models]

### Tools and agents

Meta's model page says Muse Wonder plans long tasks, delegates to sub-agents, calls tools in parallel and recovers
from errors; these are the maker's claims. Its agent-framework page documents the Claude Agent SDK over the Messages
surface with Muse Wonder as the main model. The tool rules of the family (only `auto` for `tool_choice` on Chat
Completions and Responses, `strict` off by default, `defer_loading` with tool search) are in the
[maker README](README.md#api-surface). L [meta-wonder-page] [meta-api-frameworks]

### Coding

The coding-agent page gives copy-paste configurations for OpenCode, Codex and Claude Code. For Codex it sets
`muse-wonder-1.0`, a 1,048,576-token window, automatic compaction at 900,000 tokens and the Responses API, which carries
reasoning across turns. For Claude Code it sets `muse-wonder-1.0` for the main loop and the `opus` alias, and
`muse-spark-1.3` for the `sonnet` and `haiku` aliases and for subagents; it also sets `ENABLE_TOOL_SEARCH=true`, because
Claude Code turns MCP tool search off for hosts that are not Anthropic's. L [meta-api-coding]

Muse Code offers Muse Wonder on pay-as-you-go and on every subscription plan. Its effort tiers run from `none` to
`ultra` with `high` as default; `ultra` maps to the highest level that a provider supports, and the Meta provider does
not accept `none`. The configuration page still names `muse-spark-1.2` as Muse Code's default model. L
[meta-muse-code-config] [meta-muse-code-subscriptions]

### Long context and retrieval

The context window is 1,048,576 tokens, with no long-context price premium. Meta's MemoryBench (64K to 100K-token
conversations, internal) is the only long-conversation figure Meta gives (85.6, maker). For computer use, `truncation:
"auto"`, where enabled, trims older screenshots to stay inside the window. L [meta-api-models] [meta-api-pricing]
[meta-wonder-page] [meta-api-computer-use]

### Structured output

Meta's models page lists structured output among Muse Wonder's capabilities. The family's `json_schema` rules are in
the [Muse Spark 1.3 file](muse-spark-1.3.md#structured-output); no page read gives limits that differ for Muse Wonder.
L [meta-api-models]

### Images, audio, other inputs

Input is text, image, video, audio and PDF; output is text. Meta's audio warning for Muse Spark 1.3 is not repeated for
Muse Wonder. Computer use runs on the Responses API only, through the `computer` tool, and Meta's guide makes Muse
Wonder its default model for it. Meta's model card names visual and spatial reasoning, especially 3D tasks, as a known
limitation. L [meta-api-models] [meta-api-computer-use] [meta-wonder-card]

### Sampling and API parameters

No page read gives sampling advice that differs from the family rule (defaults of 1.0 for `temperature` and `top_p`,
best left unset); see the [maker README](README.md#api-surface). Rate limits are 3,000 requests and 4,000,000 tokens a
minute per team. L [meta-api-coding] [meta-api-pricing]

### Migrating from the previous generation

Muse Wonder has no earlier generation. Meta says that moving a workload from Muse Spark to Muse Wonder is a change of
model id. Three differences matter when a harness switches: the price is about three times Muse Spark 1.3's input
price and almost five times its output price; there is no `-contributor` id; and `max` effort is available, as it is on
Muse Spark 1.3. L [meta-api-models] [meta-api-pricing] [meta-api-reasoning]

## What the system card reports

Meta's model card (dated 2026-10-12, with a correction on 2026-10-23) covers both variants. Its risk results are for
Muse Wonder Full, and Meta says this is why the assessment covers every model in the family. The results are in the
[Muse Wonder Full file](muse-wonder-full-1.0.md#what-the-system-card-reports). In short: without mitigations Meta does
not rule out the high-risk threshold for chemical and biological risk, and rates cyber and loss of control as moderate
or lower; with mitigations all domains are moderate or lower. The card recommends deploying the model inside a larger
system with guardrails, and human confirmation before irreversible actions in agent use. The launch post says a full
report with more safety evaluations will follow. L [meta-wonder-card] [meta-wonder-post]

## Behaviour observed in practice

- **Verbosity and cost.** Artificial Analysis measured 110 million output tokens to run its index at `max` (median 70
  million) and $6.95 per index task, at 143 output tokens a second. M [aa-wonder]
- **As a coding agent.** In Muse Code at `max`, Artificial Analysis measured $8.05 and 24.5 minutes per task, against
  $3.91 and 23.3 minutes for Muse Spark 1.3 at `max`. M [aa-coding-muse-code]

No practitioner report was read for this file.

## Benchmarks

Independent:

- Artificial Analysis Intelligence Index v5.0: 43 at `max`. Terminal-Bench 4.0 inside that index: 52.0%. M [aa-wonder]
- Artificial Analysis Coding Agent Index v2.0, in Muse Code at `max`: 52 (FrontierCode v1.1 46%, Terminal-Bench 4.0
  48%, SWE-Atlas-QnA-AA 62%). Muse Wonder Full scores 59 and Muse Spark 1.3 46 on the same index. M
  [aa-coding-muse-code]
- SWE-Bench Pro (Scale, public V2) with mini-swe-agent at `xhigh`: 96.73 on the Full tab (rank 6) and 90.2 on the HARD
  tab (rank 5). M [scale-swe-pro-v2]
- METR: no entry. The tbench.ai 4.0 board data has no Muse Wonder row. M [metr-horizons] [tbench-4-leaderboard]

The maker's (Meta's table at `max`, against Claude Fable 5.1, GPT-6 Astra and Claude Opus 5.5 run at `max`): DeepSWE
v1.1 78.8 (Datacurve's run, per Meta), SWE-Marathon 53.1, OSWorld V2.1 72.6 partial and 34.3 binary, ProgramBench 50.0,
MemoryBench 85.6, Personal Superintelligence Index 54.3, and an Artificial Analysis index of 52 that Meta's card
describes as v4.3. Meta says that some competitor runs are its own best effort and may not be tuned for those models.
L [meta-wonder-page] [meta-wonder-card]
