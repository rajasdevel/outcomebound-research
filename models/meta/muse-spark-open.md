# Muse Spark Open

Muse Spark Open is the open-weight release of Meta's Muse Spark, published on 2026-10-15: a sparse mixture-of-experts
model with 816 billion parameters (42 billion active per token), text, image, video and audio input, and a
1,048,576-token context. Meta builds it for coding and agent work. It is a class of its own here (Muse Spark Open),
because Meta does not give it a Muse Spark version number and does not serve it on its own API. It does not replace a
model; [Muse Glimmer 30B](muse-glimmer-30b.md) stays Meta's small open model. L [meta-spark-open-post]
[meta-spark-open-docs] [meta-api-models]

## How to instruct it

Meta publishes a prompting guide and a recommended-settings page for this model. They assume an OpenAI-compatible
server (SGLang or vLLM started with the `muse` reasoning and tool-call parsers, or a hosted provider). The API rules of
the hosted Muse Spark models in the [maker README](README.md#api-surface) do not apply here. L
[meta-spark-open-prompting] [meta-spark-open-settings]

### Setting up the prompt

- **Roles.** `system` (or `developer`), `user`, `assistant` and `tool`. The chat template does not replace its own
  system block with yours. It renders, in order: a default line that names the model a helpful AI assistant, a
  knowledge cutoff of 2026-01-04 and the current date; then your system prompt; then the tool definitions; then the
  reasoning strength, unless your prompt sets one; then the list of recipients the model can address. Pass
  `current_date` in `chat_template_kwargs` to set the date. L [meta-spark-open-prompting]
- **Order matters.** Meta says the model gives more attention to the start of the system prompt, so put the rules that
  must always hold first. Its sample structure is role, objective, priority rules in order, a scope check, a decision
  procedure, tools, the exact output shape and a completion rule. Do not describe tools in the prompt; pass them in
  `tools`. L [meta-spark-open-prompting]
- **Recipients.** The model addresses each message to `self` (reasoning), `commentary` (progress shown while it works),
  a tool name, or `user` (the final answer). L [meta-spark-open-prompting]

### Reasoning and effort

Reasoning cannot be turned off. `reasoning_effort` takes `low`, `medium`, `high` or `xhigh` (the default), which the
template turns into a numeric strength of 8, 32, 256 or 512. Any other value, `none` and `max` included, is rejected.
A line such as `Reasoning strength: 256.` in the system prompt fixes the strength for every request and overrides
`reasoning_effort`; it takes the number, not the level name. Meta suggests `low` for classification, extraction and short
tool loops, `medium` for general agent work, `high` for multi-step reasoning and hard debugging, and `xhigh` where depth
matters more than latency. A server with the `muse` parser returns the reasoning in its own field. L
[meta-spark-open-prompting] [meta-spark-open-settings] [meta-spark-open-card]

### Output: format, length, tone

- **Stop tokens.** A finished turn ends with `<|eot|>`; a message inside a continuing turn (reasoning, commentary, or a
  tool call followed by another) ends with `<|eom|>`. Stop only on `<|eot|>` and the end-of-text token: stopping on
  `<|eom|>` cuts the model off before its tool call or answer. `eos_token_id` is 200001 and 200008. L
  [meta-spark-open-settings]
- **Streaming.** Meta advises `stream: true` for reasoning work, because long traces at high strength can hit client
  or proxy timeouts. L [meta-spark-open-settings]
- **Chain of thought.** The model card advises not to show raw chain of thought in user-facing products and to check
  any reasoning summary. L [meta-spark-open-card]

### Tools and agents

Pass tools in the OpenAI function-calling format; run each `tool_calls` entry and return a `tool` message with the
call's `id`, then loop until no calls remain. The model can ask for several calls in one turn; answer each before the
next request. The template renders calls in an XML-like format and wraps results in `<tool_output>`, carrying only the
function name, so return results in call order when several calls use one tool. If you render prompts yourself, pass
each call's arguments as a dictionary, not a JSON string. Parser flags: SGLang `--reasoning-parser muse
--tool-call-parser muse`; vLLM the same plus `--enable-auto-tool-choice`; TensorRT-LLM `musespark` for both. L
[meta-spark-open-prompting] [meta-spark-open-settings]

The model card recommends system-level guardrails, protection of internal assistant messages from user manipulation,
and human confirmation for irreversible actions in agent use. L [meta-spark-open-card]

### Coding

Meta's launch post describes on-device runs in Muse Code on two Mac Studios with M5 Ultra: real iOS changes to an
open-source Mastodon client and an end-to-end video-editing task (maker's account). Meta's model card recommends `high`
or `xhigh` for coding and agent tasks. L [meta-spark-open-post] [meta-spark-open-card]

### Long context and retrieval

Of 62 decoder layers, 46 use sliding-window attention over the last 2,048 tokens and 16 use full attention, so only 16
layers keep a key-value cache for the whole context. Meta advises setting the server's maximum context length
(`--context-length` in SGLang, `--max-model-len` in vLLM) to what the work needs, not the full window. L
[meta-spark-open-settings]

### Structured output

Meta's pages give no structured-output or JSON-schema interface for this model. The prompting guide's sample system
prompt asks for an exact JSON shape in prose. L [meta-spark-open-prompting]

### Images, audio, other inputs

Send `image_url`, `video_url` and `audio_url` content parts in a `user` message; the model reads parts in the order
sent. For video, Meta advises clips longer than a few seconds at 448 pixels or more on the short side; on very short or
low-resolution clips the model can say that it cannot view the video. A 1.8-billion-parameter perception encoder handles
vision. L [meta-spark-open-prompting] [meta-spark-open-card]

### Sampling and API parameters

Meta recommends `temperature` 1.0, `top_p` 1.0, `top_k` disabled and `do_sample` true; its card results were measured at
these values with `xhigh`. Hardware: BF16 weights are about 1.65 TB and serve on eight B300 GPUs (Meta budgets about 2 TB
of VRAM); NVFP4 weights are about 537 GB and serve on one 4-GPU Blackwell node, though the model card says NVFP4 needs at
least 700 GB of VRAM. Two Mac Studios with M5 Ultra and MLX also run it, per Meta. L [meta-spark-open-settings]
[meta-spark-open-docs] [meta-spark-open-get] [meta-spark-open-card]

### Migrating from the previous generation

There is no earlier open Muse Spark. From hosted Muse Spark 1.3, the differences that break a request are: no `minimal`
or `max` effort and a default of `xhigh`; no Responses or Messages surface from Meta (a self-hosted or provider server
instead); a fixed knowledge cutoff in the system block; and stop-token handling that is the caller's job when the
template is rendered by hand. L [meta-spark-open-prompting] [meta-spark-open-settings]

## What the system card reports

The Hugging Face model card has a safety and preparedness section; the launch post says a full evaluation report will
follow. Meta says the model got extra safety post-training because open weights carry their own considerations and the
model may run as a standalone model without system guardrails, and that it met its framework's release thresholds. L
[meta-spark-open-post] [meta-spark-open-card]

- **Cyber misuse**, with adaptive attackers and no system safeguards: 99.2% of jailbreaks refused on Meta's internal set
  and 94.8% across PolyGuard (cyber subset), RedCode and CyberBench 2024; Meta gives 75.5% and 70.2% for Kimi K3 in the
  same setup.
- **Chemical and biological**: over 98% refused on SecureBio's BioTIER and over 99% on Meta's single-turn chemistry set;
  over 97% (biology) and 98% (chemistry) on new internal multi-turn agent sets.
- **Loss of control**: MASK honesty 98.1%; 0% misbehaviour on agentic misalignment.
- **Adversarial refusal**: StrongREJECT v2 attack success 0.5 against 62.9 to 86.4 for the open-weight models in Meta's
  table; FORTRESS adversarial risk 5.8 and over-refusal 17.4, the highest over-refusal score in that table (lower is
  better for both).
- **Scope.** Meta says the results describe the released checkpoint only, and that fine-tuning or other changes can
  weaken safety.

The licence (Muse Model License, dated 2026-10-15) allows use, change, distillation and resale, and has four
conditions: keep the licence and usage policy with copies; show "Built with Muse Spark Open" in each product (or its
documentation, website or settings menu); a licensee that offers models to third parties as a service, and whose gross
revenue with its affiliates passes 20 million US dollars in any 12-month period, must notify Meta and sign a separate
agreement before it offers the model in that service (internal use and features of its own non-service products are
excepted); and follow a usage policy that, among other things, bans military and weapons uses and the
operation of critical infrastructure, and says the model is not intended for people under 18. This is a summary, not
legal advice. L [meta-spark-open-license]

## Behaviour observed in practice

- **Speed and verbosity.** Artificial Analysis measured 139 output tokens a second and 91 million output tokens to run
  its index (median 99 million for open models of its size), at $2.02 per index task. M [aa-spark-open]
- **Terminal work is weak on new tasks.** Artificial Analysis measured 76.4% on Terminal-Bench 2.1 but 8.1% on
  Terminal-Bench 4.0; in Muse Code it scored 6% on Terminal-Bench 4.0. M [aa-spark-open] [aa-coding-muse-code]
- **Hallucination.** Artificial Analysis gives an AA-Omniscience hallucination rate of 28.0%. M [aa-spark-open]

No practitioner report was read for this file.
