# GPT-Live 1.1

GPT-Live 1.1 (`gpt-live-1.1`) is OpenAI's full-duplex voice model for multilingual conversations. It succeeds [GPT-Live 1](gpt-live-1.md) in the GPT Live class. OpenAI started the ChatGPT Voice rollout on 2026-10-15 and listed the API release on 2026-11-19. The API announcement confirms ChatGPT Plus and Pro access, and the ChatGPT notes say voice choices can vary by region and account [openai-live-changelog] [openai-live-release] [openai-chatgpt-notes].

## How to instruct it

### Setting up the prompt

Set the assistant's role and speaking style in `session.instructions`, which accepts up to 16,384 tokens. OpenAI's template keeps three headings: `Backchannel policy`, `Interruption policy`, and `Delegation policy`. Under delegation, list the backend capabilities and give specific conditions for a handoff. For example, delegate a request to change a reservation, but ask for a missing identifier before sending an ambiguous request. Keep the tool procedures and business rules in the backend [openai-live-prompting] [openai-live-sessions] [openai-live-delegation].

### Reasoning and effort

The voice model hands off reasoning. In Responses delegation, choose the backend model and set `reasoning.effort` according to the values that model supports. Client delegation lets the application choose and run its own backend [openai-live-model] [openai-live-delegation].

### Output: format, length, tone

Describe the desired pace, tone, and response length in the conversation prompt. Use `session.thinking.append` for concise facts the model can use silently and `session.commentary.append` for content it can paraphrase aloud. Use `session.instructions.append` for instructions during the call. For wording that must be exact, OpenAI recommends verified playback controlled by the application [openai-live-prompting] [openai-live-sessions].

### Tools and agents

Set `delegation.type` to `responses` for OpenAI-managed backend calls, or to `client` for application-managed work. Client mode is the default. The application checks permissions and confirmations and keeps task state. Wait for a verified backend result before speaking as if a requested action succeeded [openai-live-delegation] [openai-live-sessions] [openai-live-prompting].

### Coding

Coding and other tool work can run in a backend agent while GPT-Live handles the conversation [openai-live-model] [openai-live-delegation].

### Long context and retrieval

The shared Live guide documents a default context of 128,000 tokens, including audio. At more than 90% use, the session starts a replacement engine with the original instructions and up to 8,192 tokens of conversation history, which can include a summary. Keep facts that the application needs outside the voice context [openai-live-sessions].

### Structured output

The Live model page lists streaming and function calling. Use the delegated backend's text settings and tools for structured results [openai-live-model] [openai-live-delegation].

### Images, audio, other inputs

The model takes audio and text and returns audio and text through Live, with WebRTC, WebSocket, and SIP transports. The model page lists Live support and excludes the Realtime, Responses, and standalone audio endpoints. WebSocket uses one fixed audio format for both directions. WebRTC uses a media track for audio. Input and output transcript fragments have approximate timestamps and no event that marks a completed conversational turn [openai-live-model] [openai-live-start] [openai-live-websockets] [openai-live-sessions].

### Voice: turn-taking, interruption and speech style

- Set `audio.output.voice` when you create the session. The default is `marin`. The Live guide lists presets labeled English, Portuguese, Spanish, German, French, Hindi, Japanese, and Korean. It also permits authorized custom voices. Try the chosen voice and prompt in the languages and accents the application needs. Start a new session to change the voice [openai-live-sessions] [openai-live-prompting] [openai-custom-voices].
- The model can listen while it speaks. Set when to give short listening cues and when to yield. Handle any change to pending backend work in the application's task logic [openai-live-model] [openai-live-prompting] [openai-live-delegation].
- The November changelog documents standby for GPT-Live 1 and 1.1 on WebRTC. At creation, set `session.wake_policy.type` to `speech`. Set `session.idle_timeout_s` to a whole number from 5 to 60 to pause after that many seconds without an input or output transcript. If you omit it, inference stays active after the first wake until the session ends. Keep the microphone track active so speech can resume the same session and restore its history. The first reply to a short utterance after standby can take longer. The optional wake VAD threshold is 0–1 and defaults to 0.5. This threshold applies to wake-up [openai-live-changelog] [openai-live-sessions] [openai-live-reference].
- Voice time accrues per second at US$0.05/min active and US$0.02/min in WebRTC standby. Muting the microphone leaves active inference running. Backend model and tool use is billed separately [openai-live-pricing] [openai-live-cost].

### Sampling and API parameters

Choose the Live model, voice, and delegation mode when you create the session. You can update supported Responses settings in a running session that already uses Responses delegation. The guides list no voice sampling controls. The model page lists separate concurrent-session limits for each of the two GPT-Live models, applied across inference regions. Check your organization's limit for the applicable count [openai-live-model] [openai-live-sessions] [openai-live-reference].

### Migrating from the previous generation

Use `gpt-live-1.1` in the existing Live configuration. Express handoff rules in plain language. The previous model's prompt guide uses the `<|SpawnThinking|>` marker in these rules. Both versions use the same context append events [openai-live-changelog] [openai-live-prompting] [openai-live-sessions].

## What the system card reports

The Deployment Safety Hub page covers the earlier GPT-Live 1 and GPT-Live 1 mini. A system card for GPT-Live 1.1 was not found [openai-live-safety].

## Behaviour observed in practice

OpenAI reports better multilingual pronunciation, more consistent accents, and more accurate transcription. These are maker claims. The sources checked give no independent measure of those changes for this version [openai-live-changelog] [openai-live-model] [aa-speech-to-speech].

## Benchmarks

No GPT-Live 1.1 scores were found in the Artificial Analysis speech leaderboard or Arena, the Scale AudioMultiChallenge audio board, or the τ-voice and Full-Duplex-Bench-v2 papers. The Artificial Analysis leaderboard has entries for GPT-Live 1. The coding and task-horizon benchmarks in the card format apply to backend work and do not measure this voice frontend [aa-speech-to-speech] [aa-speech-arena] [scale-audiomc] [tau-voice] [full-duplex-bench].

## Open questions

- OpenAI's documents read give no complete language list, model output-token cap, exact session duration limit, or measured latency figure for this release [openai-live-model] [openai-live-sessions] [openai-live-release].
- The Live conversation guide names built-in voices, such as `calandria` and `pearl`, that the TypeScript reference enum does not list. The enum alone does not establish which choices an account can use [openai-live-sessions] [openai-live-reference].
- The TypeScript reference mentions SIP under `idle_timeout_s`. The changelog, model page, sessions guide, and cost guide describe the standby feature or rate for WebRTC. SIP availability and standby pricing remain unverified [openai-live-reference] [openai-live-changelog] [openai-live-model] [openai-live-sessions] [openai-live-cost].
