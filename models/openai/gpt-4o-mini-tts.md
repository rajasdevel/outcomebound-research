# GPT-4o mini TTS

GPT-4o mini TTS is OpenAI's speech synthesis model that takes written instructions for delivery. It reads the input text aloud in a built-in or custom voice, and an `instructions` string tells it how to speak: accent, emotion, intonation, impressions, pace, tone and whispering. OpenAI launched it on 2025-03-20 and described it as the first of its text-to-speech models that you can tell how to say a line. OpenAI announced on 2026-10-01 that it removes the model on 2027-01-06 and names GPT-Realtime-2.1 Mini as the replacement. Family-wide rules are in the [OpenAI README](README.md).

## How to instruct it

### Setting up the prompt

The request has three inputs and two options: `model`, `input` (the text to speak), `voice`, and optionally `instructions` and `response_format`. There is no system prompt and no tag syntax. The `instructions` string is free text [o-guide-tts] [o-ref-speech].

```json
{
  "model": "gpt-4o-mini-tts",
  "voice": "marin",
  "input": "Your table is ready. Please follow me.",
  "instructions": "Speak like a calm, friendly host. Keep a steady pace and smile as you talk.",
  "response_format": "wav"
}
```

- **What OpenAI says the string can control.** Accent, emotional range, intonation, impressions, speed of speech, tone and whispering [o-guide-tts]. The launch post gave the example of an instruction to talk like a sympathetic customer service agent [o-blog-2025-03].
- **The maker's own examples.** OpenAI's demo site, OpenAI.fm, ships 29 preset styles, and its source repository is public under the MIT licence. Each preset pairs a voice, a sample text and an instructions string. Most presets lay out the string as short labelled lines. By our count of the labels in the source file, Tone appears in all 29 presets, Pronunciation in 21, Emotion in 15, Voice in 13, Pacing in 9, Delivery in 8, Pauses and Punctuation in 6 each, and Phrasing in 5. The Calm preset uses the layout Voice Affect, Tone, Pacing, Emotion, Pronunciation and Pauses. The preset names include Calm, Dramatic, Fitness Instructor, Medieval Knight, Bedtime Story, Robot, Auctioneer, Pirate and Noir Detective [o-fm-repo].

A prompt in the demo's layout, written as our own example:

```text
Voice Affect: Warm, unhurried, a little amused.
Tone: Friendly and informal, like a neighbour with good news.
Pacing: Easy and steady; slower on names and numbers.
Emotion: Quiet delight at good news, and sympathy when the news is bad.
Pronunciation: Clear consonants; say product names slowly.
Pauses: A short pause before each new idea.
```

- **Length.** The API reference sets a maximum of 4,096 characters for `instructions`, the same as for `input`. The demo site cuts both the text and the instructions at 1,000 characters. That is the demo's own limit and not the API's [o-ref-speech] [o-fm-repo].
- **Where it does not work.** The `instructions` field has no effect on `tts-1` and `tts-1-hd` [o-ref-speech].
- **Disclosure.** OpenAI's usage policies require a clear notice to end users that the voice is AI-generated [o-guide-tts].

### Reasoning and effort

None. There is no reasoning control for the model [o-model].

### Output: format, length, tone

- **Formats.** `mp3` (default), `opus`, `aac`, `flac`, `wav` and `pcm`. PCM is raw 24 kHz, 16-bit, little-endian. OpenAI advises `wav` or `pcm` for the fastest response [o-guide-tts].
- **Speed.** A separate `speed` parameter takes 0.25 to 4.0 (default 1.0). The pages read do not say how it interacts with a pace written into `instructions` [o-ref-speech].
- **Streaming.** The endpoint streams with chunked transfer. `stream_format` is `audio` or `sse`, and `sse` does not work on `tts-1` or `tts-1-hd` [o-guide-tts] [o-ref-speech].
- **Length of one request.** Up to 4,096 characters by the API reference. The model page says 2,000 input tokens [o-ref-speech] [o-model].

### Tools and agents

Not a tool-calling model. OpenAI's Agents SDK voice pipeline chains speech-to-text, an agent and text-to-speech. OpenAI's voice agents guide says to use the chained path when you want to inspect or change text between stages [o-blog-2025-03] [o-voice-agents].

### Coding

The endpoint is `POST /v1/audio/speech`. OpenAI shows examples for an SDK (JavaScript, Python, Go, Java, C# or Ruby), curl and the CLI. A custom voice is passed as an object, for example a `voice` with an `id` [o-ref-speech] [o-custom-voices].

### Long context and retrieval

The input is capped at 4,096 characters. Longer text needs several requests. OpenAI publishes no guidance on how to split it or on keeping a voice steady across requests [o-ref-speech].

### Structured output

Not supported [o-model].

### Images, audio, other inputs

Text only. A custom voice comes from a consent recording and a matching audio sample, as described below [o-custom-voices].

### Voice: turn-taking, interruption and speech style

The model is not a conversation model. It has no turn detection and no barge-in. Turn-taking does not apply. The client stops playback.

**How to direct delivery.** The `instructions` string holds plain language. OpenAI's guide names seven things it can control. The demo presets show the pattern of short labelled lines (see above). OpenAI gives no list of supported tags or styles, no scale for strength, and no statement of what the model ignores [o-guide-tts] [o-fm-repo].

**How strongly it works.** Evidence is mixed and dates matter.

- Several users in one thread (Class A, January to February 2026) report that from mid-January 2026 the model gave flat delivery for instructions that had worked before. They traced it to the change of the default snapshot. OpenAI's changelog says the `gpt-4o-mini-tts` name moved to the 2025-12-15 snapshot on 2026-01-13, and that the previous snapshot stays available under its dated id [o-community] [o-changelog].
- The same users say the 2025-03-20 snapshot followed style instructions better and had more audio artefacts, and the 2025-12-15 snapshot sounded cleaner. OpenAI's December 2025 note reports about 35 percent lower word error rate for the new snapshot on Common Voice and FLEURS, a more natural voice and better results with custom voices. It tells developers to move to the new snapshot and re-run their test cases [o-community] [o-blog-2025-12].
- A vendor paper with human raters placed the model in the top five of three of its seven text-to-speech dimensions, tied for second in acoustic quality. It did not rank the model first in any dimension, and it does not say which snapshot it used [hume-rwveq].
- Both snapshots are on the removal list [o-depr].

**Voices.** 13 built-in voices, optimised for English, with `marin` and `cedar` recommended. Older `tts-1` models have 9 [o-guide-tts].

**Custom voices.** Not a text description: OpenAI's reference says voices made from a text prompt work only in Live. A custom voice needs a consent recording of a fixed phrase, in one of the listed languages, and a sample of 30 seconds or less in a common audio format. At most 20 voices per organisation. The feature is limited to eligible customers [o-ref-speech] [o-custom-voices].

**Multi-speaker dialogue.** Not supported in one request. One request takes one `voice`, so a dialogue needs one request per speaker and a join of the audio (inferred from the request shape) [o-ref-speech].

**Long-form consistency.** No guidance. The 4,096-character cap forces chunks, and no source here says how well the voice stays the same across chunks [o-ref-speech].

**Pronunciation and text normalisation.** No phoneme tag, lexicon or normalisation switch is documented. The demo presets often carry a Pronunciation line in the instructions, for example to stress certain words [o-fm-repo].

**Non-verbal sounds.** No tag syntax. The guide lists whispering and impressions as controllable. It does not say whether laughs or breaths can be requested [o-guide-tts].

**The named replacement.** OpenAI's deprecations page says to migrate to `gpt-realtime-2.1-mini` before 2027-01-06 and points to the Realtime guide. That model is a speech-to-speech model. It is not a drop-in synthesis endpoint. The Realtime guide shows one way to get fixed speech: send a response with an empty `input` array and an instruction to say exact text. Its audio output costs US$20 per Mtok, against US$12 here. See the [GPT-Realtime-2.1 Mini file](gpt-realtime-2.1-mini.md) for the model [o-depr] [o-realtime-conv] [o-pricing].

### Sampling and API parameters

The reference lists `model`, `input`, `voice`, `instructions`, `response_format`, `speed` and `stream_format`. It lists no temperature or seed [o-ref-speech].

### Migrating from the previous generation

The earlier speech models are `tts-1` and `tts-1-hd` (2023-11-06). They take no `instructions`, have 9 voices and no SSE streaming, and cost US$15 and US$30 per 1M characters. Moving to this model adds the `instructions` string and the 13-voice set [o-guide-tts] [o-pricing] [o-ref-speech]. Within this model, moving from the 2025-03-20 snapshot to 2025-12-15 changed how strongly instructions act, by user reports, so test with the same prompts [o-community] [o-blog-2025-12]. All of these ids go on 2027-01-06 [o-depr].

## What the system card reports

OpenAI published no system card or model card for this model in the pages read. The launch post says the text-to-speech models are limited to artificial, preset voices that OpenAI monitors to make sure they match the presets. The December 2025 post says custom voices are for eligible customers, and the guide requires disclosure that the voice is AI-generated [o-blog-2025-03] [o-blog-2025-12] [o-guide-tts].

## Behaviour observed in practice

- **Flat delivery after the default snapshot moved (A).** Several users reported the same effect and the same fix, which is to pin the dated 2025-03-20 id [o-community].
- **Acoustic quality (M, vendor paper).** 3.34 on a five-point scale, tied for second of 31 configurations [hume-rwveq].
- **No arena score (M).** Artificial Analysis has a page for the model and shows no Elo [aa-4o].

## Benchmarks

No independent arena score exists. A vendor paper gives 3.34 for acoustic quality [hume-rwveq]. OpenAI's own figure is a drop of about 35 percent in word error rate for the 2025-12-15 snapshot against the earlier one [o-blog-2025-12].

## Open questions

- Which snapshot the vendor paper tested.
- Whether `speed` or an instruction about pace wins when both are set.
- Whether OpenAI will give a direct synthesis endpoint for the replacement, or expects the Realtime route.
- Whether the dated 2025-03-20 id stays available until the removal date. The deprecations page lists it with the same date.
- Which voice count is right: 11 in the first paragraph of the guide and 13 in its list and in the reference.
