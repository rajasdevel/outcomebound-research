# GPT-Realtime-Whisper

GPT-Realtime-Whisper (`gpt-realtime-whisper`) is OpenAI's first streaming speech-to-text model for realtime transcription. OpenAI released it on 2026-05-07 with GPT-Realtime-2 and GPT-Realtime-Translate. It is generation 1 of the realtime transcription class here (the grouping is this library's), and GPT-Live-Transcribe followed it on 2026-07-28. OpenAI now says that existing integrations may keep using it, and that it is not the recommended start for a new one. It costs $0.017 per minute of audio [openai-changelog] [openai-guide-transcription] [openai-model-gpt-realtime-whisper]. The [OpenAI README](README.md) holds the API guide for all voice models.

## How to instruct it

### Setting up the prompt

- The model has no system prompt. The model page says it is designed for realtime use where developers tune latency and accuracy [openai-model-gpt-realtime-whisper].
- The API reference says `prompt` is not supported for `gpt-realtime-whisper` in GA Realtime sessions. OpenAI's transcription guide names the `prompt`, `keywords` and `languages` context fields for GPT-Live-Transcribe and GPT-Transcribe only [openai-ref-client-secrets] [openai-guide-transcription].
- The API reference says turn detection must be `null` for `gpt-realtime-whisper` sessions, and that VAD is not supported [openai-ref-client-secrets] [openai-guide-vad].

### Reasoning and effort

No reasoning control. The model page says developers can tune latency and accuracy. The setting is `audio.input.transcription.delay`, from `minimal` to `xhigh`; a higher value can improve accuracy and adds latency. The API reference says this setting is supported only with `gpt-realtime-whisper` in GA Realtime sessions, although the realtime transcription guide also sets it for GPT-Live-Transcribe [openai-ref-client-secrets] [openai-guide-transcription-rt].

### Output: format, length, tone

Output is text: transcript deltas as audio arrives and a completion event for each committed turn. The client sends `input_audio_buffer.commit` at the end of each turn [openai-guide-vad] [openai-guide-transcription-rt].

### Tools and agents

Not applicable. The model page lists streaming only. OpenAI's translation API reference uses this model in its example of a source-language transcription model for a translation session [openai-model-gpt-realtime-whisper] [openai-ref-translation-events].

### Coding

Not applicable.

### Long context and retrieval

The model page lists a 16,000-token window and 2,000 output tokens. Microsoft Foundry lists 32,000 and 4,096 [openai-model-gpt-realtime-whisper] [ms-foundry-models].

### Structured output

Not applicable.

### Images, audio, other inputs

Audio and text in, text out [openai-model-gpt-realtime-whisper].

### Sampling and API parameters

- Rate limits count minutes of audio per minute: 100 at tier 1 up to 1,300 at tier 5 [openai-model-gpt-realtime-whisper].
- Data: US and EU data residency for the realtime transcription endpoint [openai-guide-your-data].

### Migrating from the previous generation

This is the first generation. To move to GPT-Live-Transcribe, OpenAI's guide gives the same session flow, with `languages`, `keywords` and `prompt` as added context and no detected-language output [openai-guide-transcription-rt].

## Behaviour observed in practice

- **Independent measurement (M).** Artificial Analysis's streaming benchmark gives an AA-WER Streaming Index of 4.89% for final transcripts (AA-AgentTalk 3.85%, VoxPopuli 2.94%, Earnings22 8.90%), 0.69 s to the final transcript after speech ends, and 0.21 s to the first partial. The delay setting is not stated. GPT-Live-Transcribe scores 3.92%, 0.81 s and 0.26 s on the same page [aa-stt-streaming].
- **Cloud (L).** Microsoft Foundry lists it, dated 2026-05-06 [ms-foundry-models].
- **Practitioner reports (A).** None gathered.
