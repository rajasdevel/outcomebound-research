# gpt-oss-120b

gpt-oss-120b is the larger of the two open-weight reasoning models OpenAI released on 2025-08-05 under the
Apache 2.0 licence and its gpt-oss usage policy. It is a mixture-of-experts text model with 116.8 billion
parameters (5.1 billion active per token) whose MXFP4 weights fit one 80 GB GPU. OpenAI built it for
production, general-purpose and high-reasoning use, with configurable reasoning effort, full chain of
thought, tool use and structured output; it is the open counterpart to the o-series, which it approaches
on OpenAI's own tests, and it has no successor yet. The maker README says what holds across OpenAI models;
this file covers what is specific to the open weights, which are used through a runtime that applies the
harmony format.

## How to instruct it

### Setting up the prompt

- **The format is required.** The model was trained on OpenAI's harmony response format and does not work
  correctly without it. A hosted API or a runtime such as Ollama or vLLM applies it; the Hugging Face chat
  template applies it when the template is used; code that calls generation directly has to render it, for
  example with OpenAI's `openai-harmony` package [hf-gpt-oss-120b] [openai-harmony].
- **Roles and precedence.** Five roles: system, developer, user, assistant and tool, in decreasing order of
  authority for resolving conflicting instructions. The system message carries a fixed identity line
  (`You are ChatGPT, a large language model trained by OpenAI.`), the knowledge cutoff (2024-06 in OpenAI's
  example), the current date, the reasoning level, the valid channels and any built-in tools. OpenAI says the
  identity line should stay as it is and a different identity belongs in the developer message. The developer message holds what other models call the system
  prompt, under a heading of Instructions, then function tools under Tools and response formats under
  Response Formats [openai-harmony]. In the Hugging Face template the first system or developer message
  in the conversation becomes the developer message [hf-gpt-oss-120b].
- **Guardrails.** OpenAI's tests found the model weaker than OpenAI o4-mini at holding a system or developer
  instruction against a user who tries to override it: system-prompt extraction defence 0.832 against 0.993,
  prompt-injection hijacking 0.780 against 0.917, protecting a phrase named in a developer message 0.909
  against 0.912 and in a system message 0.912 against 0.937; password protection was the exception, where the
  120b matched or beat o4-mini (1.000 against 0.947 in a developer message). The card says a developer may be
  less able to stop a jailbreak with the system message here than OpenAI can with o4-mini, and that
  fine-tuning is a route to more robustness [arxiv-gpt-oss].
- **Examples and structure.** OpenAI's harmony guide gives no advice on examples or tags. Instruction text goes
  in the developer message as plain text.
- **Provider-supplied developer messages.** The card notes that inference providers can add a developer message
  to every user prompt; if mishandled that can circumvent guardrails, which is why OpenAI trained the model to
  rank system over developer over user instructions [arxiv-gpt-oss].

### Reasoning and effort

- **Control.** The level is set with `Reasoning: low`, `Reasoning: medium` or `Reasoning: high` in the system
  message. The default is medium. Raising the level lengthens the chain of thought on average. OpenAI reports smooth test-time
  scaling with roughly log-linear returns, and recommends choosing the size and level that balance accuracy
  against latency and cost [openai-harmony] [arxiv-gpt-oss].
- **What the card measures** (120b, low, medium, high): AIME 2025 without tools 50.4, 80.0, 92.5; GPQA Diamond
  without tools 67.1, 73.1, 80.1; Humanity's Last Exam without tools 5.2, 8.6, 14.9; MMLU 85.9, 88.0, 90.0;
  Codeforces Elo without tools 1595, 2205, 2463 [arxiv-gpt-oss].
- **Artificial Analysis** scores the model 10.2 on its Intelligence Index at low and 11.6 at high
  [aa-model-gpt-oss-120b].
- **Chain of thought.** It is returned in the `analysis` channel in the model's raw form. OpenAI says it should
  not be shown to end users, because it does not meet the safety standard of final answers, can contain
  hallucinated or policy-violating text, and can reveal information the implementer did not intend to
  expose, such as rules in the instructions. OpenAI applied no direct optimisation pressure to it so that
  developers can monitor it [openai-harmony] [arxiv-gpt-oss] [openai-gpt-oss-raw-cot].
- **Handling it in later turns.** OpenAI's guide says earlier `analysis` messages are dropped after a turn
  that ended in the `final` channel, while after a tool call the `analysis` messages back to the previous
  `final` message are kept until a new `final` message is issued, since the model calls tools from inside
  its reasoning [openai-gpt-oss-raw-cot].
- **API conventions.** In Chat Completions OpenAI points to the OpenRouter convention (a `reasoning` field on the
  message and deltas); in Responses it adds a `reasoning_text` content type and delta events, and the
  reasoning summary can be returned separately from the raw text [openai-gpt-oss-raw-cot].
- **What not to do.** No source read advises against step-by-step prompting for this model; the reasoning level
  is the documented control.

### Output: format, length, tone

- Answers for the user go in the `final` channel; the model may also write a preamble in `commentary` that is
  meant to be shown, such as an action plan before several tool calls [openai-harmony].
- `<|return|>` is a stop token when generating; OpenAI says it becomes `<|end|>` when the reply is stored in
  history [openai-harmony].
- OpenAI gives no verbosity control or formatting advice. The card says the models have a personality similar
  to ChatGPT's because they used similar post-training [arxiv-gpt-oss]. Artificial Analysis counted 84 million
  output tokens on its Index run [aa-model-gpt-oss-120b].

### Tools and agents

- **Three kinds of tool.** A browsing tool (search, open, find) and a Python tool (a stateful notebook; the
  Hugging Face template states a 120-second timeout), both declared in the system message; and developer functions declared in the developer
  message in a TypeScript-like syntax inside a `functions` namespace, with comments for descriptions. The model
  calls a function in the `commentary` channel with a recipient of `functions.<name>` and `<|constrain|>json`,
  then stops with `<|call|>`; the application answers with a tool-role message [openai-harmony]
  [hf-gpt-oss-120b].
- **Cases the card measures** (120b, low, medium, high): Tau-Bench Retail 49.4, 62.0, 67.8; Tau-Bench Airline
  42.6, 48.6, 49.2; Codeforces Elo with a terminal tool 1653, 2365, 2622 [arxiv-gpt-oss].
- **Reasoning between tool calls.** OpenAI's guides say the previous reasoning goes back to the model during
  a run of tool calls until it gives a final answer [openai-gpt-oss-raw-cot] [openai-gpt-oss-vllm].
- **Runtime behaviour.** vLLM serves function calling through both Responses and Chat Completions; OpenAI's
  Hugging Face template renders only the first tool call of an assistant message [openai-gpt-oss-vllm]
  [hf-gpt-oss-120b].
- **Agent use.** An independent study ran the model in a mini-SWE-agent harness with a 150-step budget and found
  a weak standalone agent; see Coding.

### Coding

- OpenAI's card, pass@1 with its default system prompt: SWE-bench Verified 47.9 (low), 52.6 (medium), 62.4
  (high); Aider Polyglot 24.0, 34.2, 44.4 [arxiv-gpt-oss].
- Independent: a Carnegie Mellon study of critic models steering a coding agent ran gpt-oss-120b at medium
  reasoning in the mini-SWE-agent scaffold and measured 20.4% resolved on SWE-bench Verified with no critic and
  34.8% with a small trained critic. The scaffold, not only the model, sets the number: OpenAI's own figure at
  medium reasoning is 52.6 [cmu-steer-dont-solve] [arxiv-gpt-oss].
- Artificial Analysis shows 0% for Terminal-Bench 4.0 inside its Intelligence Index [aa-model-gpt-oss-120b].
  There is no entry on Scale's SWE-Bench Pro V2 or on METR's current time-horizon results file.

### Long context and retrieval

- 131,072-token context, reached by extending the dense layers with YaRN; attention alternates between a banded
  window of 128 tokens and fully dense layers [arxiv-gpt-oss]. Hosts differ: Amazon Bedrock lists 128,000
  tokens and Groq the full 131K [aws-gpt-oss-params] [groq-gpt-oss-120b]. The maker does not publish a maximum
  output length.
- Artificial Analysis's AA-LCR long-context reasoning: 52.0% at high, against 80.7% to 84.0% for OpenAI's GPT-6
  and GPT-5.6 models at max on the same test [aa-model-gpt-oss-120b].
- OpenAI gives no placement advice. Caching depends on the host.

### Structured output

- The card says the models support Structured Outputs. In harmony, a response format is a JSON schema placed
  after a Response Formats heading at the end of the developer message. OpenAI says that alone steers the model
  and does not guarantee adherence; a guarantee needs a grammar enforced during sampling [openai-harmony]
  [arxiv-gpt-oss].
- Hosts add their own support for schemas; the feature depends on the host.

### Images, audio, other inputs

- Text in, text out. No image, audio or video input [hf-gpt-oss-120b].

### Sampling and API parameters

- The maker publishes no sampling recommendation; its vLLM example samples at temperature 1 [openai-gpt-oss-vllm].
  Hosted-API parameters are the host's: Amazon Bedrock accepts `max_completion_tokens`, `temperature` and
  `top_p` in Chat Completions and returns reasoning in tags for InvokeModel [aws-gpt-oss-params].
- Reasoning level is set in the system message (or the template's `reasoning_effort` argument), not by a
  separate model parameter.
- The model identifiers are `openai/gpt-oss-120b` (Hugging Face), `openai.gpt-oss-120b-1:0` (Bedrock) and
  `gpt-oss-120b` (Foundry preview, which needs a Foundry project) [aws-gpt-oss-params] [ms-foundry-models].

### Migrating from the previous generation

There is no earlier open-weight model in this class. For a prompt moving from an OpenAI hosted reasoning model,
the sources above imply:

- The instruction text moves into a harmony developer message, and the level into the system message.
- Reasoning goes back to the model during tool calls and is dropped after a final answer.
- The card measures a weaker instruction hierarchy, lower factual recall (SimpleQA accuracy 16.8% against 23.4%
  for o4-mini, hallucination rate 78.2% against 75.0%) and the window is 131,072 tokens [arxiv-gpt-oss].
- The card says a system message is a weaker jailbreak defence here than on o4-mini [arxiv-gpt-oss].

## What the system card reports

OpenAI published a model card, not a system card, because the models will be used inside many systems it does
not control; it says developers need their own safeguards [arxiv-gpt-oss].

- **Preparedness.** The default model does not reach High capability in biology and chemistry, cybersecurity or
  AI self-improvement. OpenAI also fine-tuned an adversarial version for biology and for cyber, simulating a
  well-resourced attacker, and its Safety Advisory Group concluded even that did not reach High. Outside experts
  (METR, SecureBio and an independent researcher) reviewed the method; of 22 recommendations OpenAI acted on
  11, including 9 of 12 marked high urgency. OpenAI also compared against other open models and found that
  releasing it does not significantly advance open biology capability.
- **Refusals and over-refusal.** On OpenAI's standard disallowed-content tests the model is within 1 to 2
  points of o4-mini; on the harder production-style set it scores above o4-mini on most categories (for
  example sexual/minors 0.967 against 0.862), but below it on illicit/violent (0.817 against 0.845).
- **Jailbreaks.** On a StrongReject test the model scores 0.979 to 0.993 across four categories, at about parity
  with o4-mini.
- **Hallucination and bias.** SimpleQA accuracy 0.168 with a hallucination rate of 0.782; PersonQA accuracy
  0.298 and hallucination rate 0.491, both worse than o4-mini; OpenAI says browsing reduces this. BBQ is at
  about parity with o4-mini.
- **Instruction hierarchy.** Weaker than o4-mini (numbers under Setting up the prompt).
- **Chain of thought.** No direct optimisation pressure on it, and it may contain hallucinated content that
  should not be shown to users.
- **Health.** HealthBench 53.0, 55.9, 57.6 (low, medium, high); HealthBench Hard 22.8, 26.9, 30.0; OpenAI says
  120b nearly matches o3 at high and that the model is not for diagnosis or treatment.
- **Safeguards.** None are built into the weights beyond training. Pre-training filtered CBRN content, and
  post-training used deliberative alignment and the instruction hierarchy.

## Behaviour observed in practice

- **Independent measurement (M).** Artificial Analysis rates it 12 on its Intelligence Index at high, a
  hallucination rate of 90.8% on AA-Omniscience and 160 output tokens a second; its providers page lists
  speeds up to about 1,700 tokens a second (Cerebras) and the lowest blended price at $0.04 per million tokens
  (CoreWeave) [aa-model-gpt-oss-120b] [aa-providers-gpt-oss-120b].
- **Agent studies (M).** In Carnegie Mellon's critic study (above), a small trained critic raised the 120b's
  resolved rate from 20.4% to 34.8%, while an untrained critic of the same size lowered it to 16.8%; the
  authors report that the untrained critic mostly told the agent to run tests and pulled it off its own
  review [cmu-steer-dont-solve].
- **Hosting (L).** Groq lists $0.15 in, $0.075 cached input and $0.60 out per million tokens; Amazon Bedrock and
  Microsoft Foundry (preview) serve it [groq-gpt-oss-120b] [aws-gpt-oss-params] [ms-foundry-models].
- **Practitioner reports (A).** None first-hand were gathered.
