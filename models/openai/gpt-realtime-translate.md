# GPT-Realtime-Translate

GPT-Realtime-Translate (`gpt-realtime-translate`) is OpenAI's streaming speech-to-speech translation model. OpenAI released it on 2026-05-07 with GPT-Realtime-2 and GPT-Realtime-Whisper. It is generation 1 of the GPT Realtime Translate class. It acts as an interpreter and not as an assistant: it takes a live audio stream, and it returns translated audio and transcript deltas while the speaker is still talking. OpenAI prices it by audio duration, $0.034 per minute [openai-changelog] [openai-model-gpt-realtime-translate] [openai-guide-translation]. The [OpenAI README](README.md) holds the API guide for all voice models.

## How to instruct it

### Setting up the prompt

- The guides read show no system-prompt or instructions field. A session has a source audio stream, a target language in `audio.output.language`, an optional source-language transcription model in `audio.input.transcription.model`, and optional noise reduction (`near_field` or `far_field`). `session.update` can change these three after creation. The session `type` and `model` are fixed [openai-ref-translation-events] [openai-guide-translation].
- To get an assistant that answers questions, calls tools and keeps a conversation, OpenAI says to use `gpt-realtime-2.1` in a standard Realtime session instead [openai-guide-translation].
- For translation that runs inside a GPT-Live conversation, OpenAI's GPT-Live prompting guide gives a translation-only prompt, which treats each user utterance as material to render and never to answer [openai-guide-live-prompting].

### Reasoning and effort

No reasoning control exists [openai-model-gpt-realtime-translate].

### Output: format, length, tone

- Output is translated audio, a stream of `session.output_audio.delta` events (play them as PCM 16-bit), and `session.output_transcript.delta` events with target text. Source text arrives as `session.input_transcript.delta` when you configure input transcription [openai-guide-translation].
- OpenAI's guide says to show both source and target transcripts when useful, and to give controls for original audio, translated audio, subtitles, mute and volume.

### Tools and agents

The model does not call tools and has no `response.create`. The model page lists streaming only. One session serves one target language, so OpenAI says to create one session for each output language [openai-guide-translation] [openai-model-gpt-realtime-translate].

### Coding

Not applicable.

### Long context and retrieval

The model page lists a 16,000-token window and 2,000 output tokens. Microsoft Foundry lists 32,000 and 4,096 [openai-model-gpt-realtime-translate] [ms-foundry-models].

### Structured output

Not applicable.

### Images, audio, other inputs

- Audio in only. Audio and text out [openai-model-gpt-realtime-translate].
- A WebSocket takes base64 PCM 16-bit audio at 24 kHz. WebRTC takes a media track [openai-guide-translation].

### Voice: turn-taking, interruption and speech style

- **No turns.** The session streams continuously from the incoming audio. The guide says to keep appending audio, including silence between phrases. There is no turn detection setting, and `response.create` is not used. [openai-guide-translation]
- **Rate limits [as-of 2026-10-09].** Limits count minutes of audio per minute: 200 at Build, 650 at Launch and 850 at Grow. Actual organization limits can differ. L ([model page](https://developers.openai.com/api/docs/models/gpt-realtime-translate#rate-limits), read 2026-10-09).
- **Transport.** WebRTC for a browser that captures or plays audio. A WebSocket for a server that already holds raw audio, such as Twilio Media Streams or SIP media. The endpoint is `/v1/realtime/translations`, not `/v1/realtime`. A browser session uses a short-lived client secret [openai-guide-translation].
- **Closing.** OpenAI's guide says to send `session.close` and keep reading until `session.closed`. The service then flushes pending input and emits the remaining translated audio and transcript. Closing the socket at once can drop output that is still draining. `session.close` works for translation sessions only [openai-guide-translation].
- **Architecture advice.** For one speaker and many listeners (livestreams, lectures, calls), run one session for each target language. For two-way calls, keep each participant's audio on its own track and run one session for each direction. For rooms, sessions equal active speakers times distinct target languages [openai-guide-translation].
- **Testing advice.** OpenAI lists language-pair quality, names, numbers, dates, currency and phone numbers, domain terms, code-switching, accents, fast and overlapping speech, first translated audio, end-of-utterance latency, subtitle timing, voice consistency and reconnect behaviour. It says to build a golden set for exact names and domain terms and to review failures by hand [openai-guide-translation].
- **Voices.** The pages read name no voice choice for the output [openai-guide-translation].
- **Languages.** OpenAI's launch announcement, as relayed in its Developer Community thread, gives more than 70 input languages and 13 output languages [community-realtime-2].

### Sampling and API parameters

- Price: $0.034 per minute of audio. No token price [openai-pricing] [openai-model-gpt-realtime-translate].
- Data: the endpoint supports US and EU data residency [openai-guide-your-data].

### Migrating from the previous generation

This is the first generation. OpenAI's text-based way to translate a finished recording is `whisper-1` through the audio translations endpoint, into English only [openai-guide-speech-to-text].
