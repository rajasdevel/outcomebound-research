# GPT-6.2 Sol

GPT-6.2 Sol is OpenAI's GPT Sol model for everyday coding and agent workflows at lower token prices than Astra. It follows
[GPT-6.1 Sol](gpt-6.1-sol.md) in the Sol class. OpenAI announced API, ChatGPT Work
and Codex availability on 2026-11-17. [launch, api-changelog, system-card, model-page, previous-model-page]

## How to instruct it

### Setting up the prompt

OpenAI offers the GPT-6.2 prompt examples as starting points for Sol. State the goal, which assumptions it can make, when to ask, and how to verify completion. The guide draws its detailed behavior observations from Astra.
For Responses, put reusable guidance in the first `developer` item in `input`. Top-level
`instructions` go after `input` and are suitable for guidance specific to the current request.
The [OpenAI README](README.md) covers the shared API conventions. [gpt62-guide]

### Reasoning and effort

Set `reasoning.effort` in Responses or `reasoning_effort` in Chat Completions. OpenAI recommends
`medium` for a first integration and `low` for a caller moving from `none` or `minimal`.
Use higher effort when task-specific evaluations justify the extra time and tokens.
Reasoning tokens count against the output budget. Responses can return an opt-in reasoning
summary. Raw reasoning is private. [gpt62-guide, reasoning-guide, aa-model]

### Output: format, length, tone

Specify the deliverable and the level of detail. The launch describes Sol as writing clear prose for everyday work. The guide gives family prompt patterns for audience, wording and format. [launch, gpt62-guide]

### Tools and agents

Use Responses for tool calls. The model page lists search, image generation, a code interpreter,
hosted shell, patching, skills, computer use and MCP. OpenAI's Multi-agent beta lets a root
agent coordinate bounded work with subagents in separate contexts. Enable it with
`multi_agent.enabled` on Responses. Keep related changes with dependencies in order and
state how concurrent work is allowed to use shared state. For discounted background runs,
set `background: true` and choose `2h` or `8h` in `background_options.completion_window`.
These windows require Standard processing, no streaming and a separate Batch/Background
rate pool. [model-page, gpt62-guide, multi-agent-guide, background-guide]

### Coding

Give the model the code conventions, the behavior that must stay stable and the checks that
demonstrate completion. OpenAI advises giving explicit criteria for verification and telling
the model to report any obstacle that prevents it from finishing. [gpt62-guide, launch, system-card]

### Long context and retrieval

The API lists 1,050,000 context tokens, at most 922,000 input tokens and 128,000 output tokens.
The model's knowledge cutoff is 2026-06-01. Use source files in a stable prompt prefix when
they will be reused. Above 272,000 input tokens, long-context rates apply to the whole request.
Editing earlier content can remove preserved reasoning. Append guidance and use a
`configuration_update` item for a mid-conversation effort or output-format change.
With eligible Zero Data Retention use, replay the previous output items in order, including
encrypted reasoning items. [model-page, api-pricing, gpt62-guide, reasoning-guide]

### Structured output

The model supports Structured Outputs. Use `text.format` in Responses or
`response_format` with `json_schema` in Chat Completions. The API supports a subset
of JSON Schema. Handle refusal and incomplete status separately from a valid schema result.
[model-page, structured-output-guide]

### Images, audio, other inputs

The API accepts text and images and returns text. Audio and video inputs are unavailable.
Image generation is a tool in Responses. [model-page]

### Sampling and API parameters

Omit `temperature`, `top_p` and `top_logprobs`. Omit `logprobs` in Chat Completions,
and remove `message.output_text.logprobs` from the Responses `include` array. Both endpoints
reject `none`. [model-page, gpt62-guide, reasoning-guide]

### Migrating from the previous generation

Set the model id to `gpt-6.2-sol`. Check the position of developer instructions, the
rules for preserving reasoning items and any Flex requests. Use Responses for tool calls.
OpenAI's current pricing table lists the same Standard token rates for Sol and GPT-6.1 Sol. [api-pricing] [gpt62-guide]

## What the system card reports

OpenAI rates both released models Critical for Cybersecurity and High for Biological and Chemical
capabilities under its Preparedness Framework. Astra meets the High threshold for AI
Self-Improvement. Sol falls below that threshold. OpenAI reports tighter safeguards for
higher-risk assistance, updates to refusal behavior and expanded monitoring. The card
distinguishes model-level tests from the safeguards that deployments add. [system-card]

In simulated workplace tasks, OpenAI reports high-severity improper actions in 0.71% versus 1.32%
of scored trials for this model and its predecessor, respectively. In its held-out prompt
injection benchmark environments, it reports 99.76% resistance to final attacks,
averaged across the tested efforts. OpenAI also reports more omissions of known obstacles in
its model-only evaluations for the new models. It says the Codex developer prompt reduced
those omissions in its tests. OpenAI reports that Sol showed fewer signs of evaluation awareness than GPT-6 Astra and GPT-6.1 Sol in replayed internal Codex sessions. [system-card]

## Behaviour observed in practice

Artificial Analysis measured 10.1 minutes at max and 3.6 minutes at medium
per Intelligence Index task on OpenAI's API. This is the evaluator's suite and provider setup.
[M, aa-model] Independent field observations outside the cited evaluations remain open.

## Benchmarks

Artificial Analysis reports 57 at `max` and 53 at `medium` on its Intelligence Index
v5.0.1. Its separate Terminal-Bench 4.0 evaluation reports 60.1% at `max` in
mini-swe-agent, averaged across three repeats per task. The Coding Agent Index publishes
Codex results with the model and effort attached. In its chart data, `shortLabel` identifies
the run and `indexScore` gives the score as a fraction. The page labels the current suite v2.1
and names Terminal-Bench 4.1, while the data attached to these rows labels the component
Terminal-Bench v4 without the minor version. [M, aa-model, aa-tbench-4-0, aa-coding-agents]

In OpenAI's internal GDPval v2 evaluation of professional workflows, this model scored
5.3 percentage points above GPT-6.1 Sol. The launch prose gives the difference.
[L, launch]
