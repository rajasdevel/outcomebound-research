# GPT-Realtime-2.1

GPT-Realtime-2.1 (`gpt-realtime-2.1`) is OpenAI's current speech-to-speech model in the Realtime API. OpenAI released it on 2026-07-06, with GPT-Realtime-2.1 Mini. It is generation 2.1 of the GPT Realtime class. It takes text, audio and image in and gives text and audio out, with a 128,000-token window and configurable reasoning effort. OpenAI calls it an update to GPT-Realtime-2 with better alphanumeric recognition, silence and noise handling, and interruption behaviour, at the same price [openai-changelog] [openai-model-gpt-realtime-2.1]. OpenAI's Realtime getting-started guide now names this model in its examples [openai-guide-realtime]. The [OpenAI README](README.md) holds the Realtime API guide, and the [GPT-Realtime-2 file](gpt-realtime-2.md) holds OpenAI's prompting guide in full.

## How to instruct it

### Setting up the prompt

- OpenAI's prompting guide, "Using realtime models", still names GPT-Realtime-2 and the earlier GPT-Realtime-1.5, and not 2.1, on 2026-10-03. The model page calls 2.1 an update to 2, so the guide is the starting point and OpenAI has published no 2.1-specific prompt advice [openai-guide-voice-prompting] [openai-model-gpt-realtime-2.1].
- The guide's rules, in short: start with a minimal prompt and add instructions for failures found in evaluation; use short labelled sections; write trigger, action and exception rules in place of broad ones; limit always, never, only and must; keep the prompt and the tool list in step; test small wording changes. The GPT-Realtime-2 file has the whole list.
- A stored prompt with variables is available through `session.prompt`, and direct session fields override it [openai-guide-conversations].
- OpenAI's launch thread says to choose 2.1 for the strongest realtime reasoning, tool use, instruction following and voice-agent behaviour, and 2.1 Mini for a faster, cheaper option [community-realtime-21].

### Reasoning and effort

- **Levels.** `minimal`, `low`, `medium`, `high`, `xhigh`. The default is `low`, according to an OpenAI staff reply. The API reference does not state it [community-default-reasoning] [openai-ref-client-secrets].
- **Guide.** The guide says to use the lowest level that gives enough intelligence and to start at `low`. Higher levels cost latency and output tokens [openai-guide-voice-prompting] [openai-model-gpt-realtime-2.1].
- **What is measured.** Artificial Analysis: Big Bench Audio 86.8% at Minimal and 95.8% at High; tau-Voice 38.0% and 45.7%; time to first audio 0.97 s and 1.21 s; Speech to Speech Index 70.3 and 73.9 [aa-speech-to-speech].
- **Compared with 2.** At High effort 2.1 scores higher on tau-Voice (45.7% against 39.8%) and level on the index (73.9 against 73.6). It scores a little lower on Big Bench Audio (95.8% against 96.6%) and takes a little longer to first audio (1.21 s against 1.14 s) [aa-speech-to-speech].

### Output: format, length, tone

- The guide's length and preamble advice applies: give a size for each task type, use one short preamble sentence only when work is visible to the user, and skip it for direct answers and unclear audio. The GPT-Realtime-2 file lists the details.
- The model can emit `commentary` and `final_answer` phases in one turn. The `phase` value in `response.done` tells them apart [openai-guide-voice-prompting].
- The `speed` setting runs from 0.25 to 1.5 as a playback multiplier [openai-ref-client-secrets].

### Tools and agents

- Function calling and remote MCP tools work as for GPT-Realtime-2: functions in `session.tools` or `response.tools`; a `function_call_output` item and `response.create` to return a result; `mcp` tools run by the Realtime API, with approval items and a follow-up `response.create` [openai-guide-conversations] [openai-guide-mcp].
- Built-in MCP connectors by `connector_id` are deprecated for models released after 2026-09-01. OpenAI's example uses an older model for connectors [openai-guide-mcp].
- OpenAI's guide says tool behaviour depends on the prompt as well as the tool spec. Define when to act, ask, confirm, retry and escalate, and keep read-only lookups apart from writes [openai-guide-voice-prompting].
- OpenAI's Live guide suggests that a Realtime model can serve as a detector next to GPT-Live, for example for voicemail detection, with a structured function result [openai-guide-live-migration].

### Coding

OpenAI gives no coding guidance for this model.

### Long context and retrieval

- 128,000-token window and 32,000-token maximum output. OpenAI's guide puts 128,000 tokens at about 1 to 2 hours of dense raw audio [openai-model-gpt-realtime-2.1] [openai-guide-voice-prompting].
- Cached audio input costs $0.40 per million tokens against $32. OpenAI says it cut p95 latency by at least 25% across its Realtime voice models through improved caching, with this release [openai-model-gpt-realtime-2.1] [community-realtime-21].
- Truncation, retention ratio and cache advice are those of the Realtime API; see the README and the GPT-Realtime-2 file.

### Structured output

The model page lists function calling and prompt caching only. The pages read describe no schema mechanism other than a function's JSON-schema parameters [openai-model-gpt-realtime-2.1].

### Images, audio, other inputs

- Text, audio and image in; text and audio out. An image goes in as an `input_image` content part [openai-guide-conversations].
- Audio formats: PCM 16-bit mono at 24 kHz, G.711 mu-law, G.711 A-law [openai-ref-client-secrets].

### Voice: turn-taking, interruption and speech style

- **Turn detection.** The settings are those of the Realtime API: `server_vad` (threshold, prefix padding, silence duration, idle timeout) and `semantic_vad` (eagerness low, medium, high or auto, with waits of at most 8 s, 4 s and 2 s), plus `create_response`, `interrupt_response`, noise reduction and `null` for push-to-talk. OpenAI's session example for this model sets `semantic_vad` [openai-guide-conversations] [openai-guide-vad].
- **What 2.1 changes.** OpenAI names three: alphanumeric recognition, silence and noise handling, and interruption behaviour. It gives no figure for any of them [openai-model-gpt-realtime-2.1].
- **Silence.** The guide's method for a voice that should stay quiet is a no-op `wait_for_user` tool and a rule that forbids filler. OpenAI says 2.1 handles silence and noise better, and does not say whether the tool is still needed [openai-guide-voice-prompting].
- **Entities and language.** The guide's rules apply: collect one value at a time, read digits back one by one, spell emails, and set a language policy that ignores accent. The GPT-Realtime-2 file has the rules.
- **Voices.** Ten built-in voices; marin and cedar are the recommended pair. Custom voices need approval [openai-guide-conversations] [openai-guide-custom-voices].
- **Problems seen with generation 2 (A).** In May 2026 developers reported 5 to 20 seconds of silence between an acknowledgment and the next step, and replies that stopped mid-sentence. OpenAI Support traced the silence to a client library (LiveKit Agents 1.5.10) that played only the first of two audio messages in a response; the reporter of the early stops traced them to false-positive content filtering. The same two-message responses can occur with 2.1 [community-realtime-2-pauses].

### Sampling and API parameters

- No `temperature` in the GA interface [openai-blog-realtime-api].
- **Rate limits [as-of 2026-10-09].** Build lists 400 requests and 200,000 tokens per minute; Grow lists 20,000 requests and 15 million tokens per minute. The page also lists Launch. Actual organization limits can differ. L ([model page](https://developers.openai.com/api/docs/models/gpt-realtime-2.1#rate-limits), read 2026-10-09).
- Sessions last at most 60 minutes [openai-guide-conversations].
- The Realtime endpoint is the only endpoint. Chat Completions, Responses, Batch and the other endpoints are not supported [openai-model-gpt-realtime-2.1].

### Migrating from the previous generation

- From GPT-Realtime-2: change the model id. Price, window, effort levels and knowledge cutoff (2024-09-30) are the same. OpenAI lists three behaviour improvements and no breaking change [openai-model-gpt-realtime-2.1]. A forum user who compared the two model pages on the release day found the same cutoff, price and window and no large difference (A) [community-realtime-21].
- From GPT-Realtime-1.5 or the older `gpt-realtime`: OpenAI's deprecation page names GPT-Realtime-2.1 as the replacement for `gpt-realtime` and `gpt-4o-realtime`, which shut down on 2027-01-20. The guide has seven migration steps [openai-deprecations] [openai-guide-voice-prompting].
- From the text-to-speech models `tts-1`, `tts-1-hd` and the `gpt-4o-mini-tts` snapshots (shutdown 2027-01-06): OpenAI names GPT-Realtime-2.1 Mini, and not this model, as the replacement [openai-deprecations].
- To move to a delegated, full-duplex design, see the [GPT-Live-1 file](gpt-live-1.md).

## Behaviour observed in practice

- **Independent measurement (M).** Artificial Analysis lists 2.1 at High with a Speech to Speech Index of 73.9, and at Minimal with 70.3. Its Arena preference Elo is 928.1 (rank 15 on the page), a little under GPT-Realtime-2's 931.66, and well under GPT-Live-1's 1,048 to 1,053 [aa-speech-to-speech]. Scale's AudioMultiChallenge has no entry for 2.1 [scale-audiomc].
- **Maker comparison (L).** In OpenAI's own GPT-Live launch comparison, 2.1 completes 45.7% of Tau3 tasks on the first attempt against 83.6% for GPT-Live-1 with an Astra backend, and has a 1.41 s turn-taking latency against 0.798 s [community-live-1].
- **Cloud (L).** Microsoft Foundry lists 2.1 and 2.1 Mini, dated 2026-07-07, and calls 2.1 an incremental update with better silence and noise handling. It shows 32,000 and 4,096 tokens where OpenAI shows 128,000 and 32,000 [ms-foundry-models].
- **Practitioner reports (A).** None first-hand about 2.1 were gathered.

## Open questions

- Whether 2.1 changed the false-positive content filtering outside English that a developer reported for generation 2.
- Whether the `wait_for_user` tool is still needed, given the better silence handling.
- The default reasoning effort. A staff reply says `low`; the API reference is silent [community-default-reasoning].
- The supported languages, and why Foundry shows a smaller token window than OpenAI.
