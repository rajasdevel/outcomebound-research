# GPT-Live-Transcribe

GPT-Live-Transcribe (`gpt-live-transcribe`) is OpenAI's streaming speech-to-text model for live audio. It returns transcript deltas as speech arrives and a final transcript when the application commits each audio turn. OpenAI released it on 2026-07-28 with GPT-Transcribe, and it is now the model that OpenAI's realtime-transcription guide recommends. It is generation 2 of the realtime transcription class here, after GPT-Realtime-Whisper (the class grouping is this library's, not OpenAI's). It costs $0.017 per minute of audio [openai-changelog] [openai-guide-transcription-rt] [openai-model-gpt-live-transcribe]. The [OpenAI README](README.md) holds the API guide for all voice models.

## How to instruct it

### Setting up the prompt

The model has no system prompt. Three kinds of context improve results for domain terms, mixed languages and code-switching [openai-guide-transcription] [openai-guide-transcription-rt]:

- `prompt`: open text that describes the recording, for example the subject or the place. OpenAI says not to restate the transcription task.
- `keywords`: literal terms that may occur, such as product names, medications and acronyms. They are hints and not required output. A keyword takes one line and may not contain `<`, `>`, a carriage return or a line feed.
- `languages`: the expected input languages. Formats are ISO 639-1 codes (`en`), selected ISO 639-3 codes (`yue`, `cmn`) and regional `zh` codes (`zh-cn`, `zh-tw`, `zh-hk`). This model uses `languages`, not the singular `language`, and the two must not be sent together. The API rejects unsupported codes, a keyword with a forbidden character and a prompt over the length limit.

A `session.update` event changes the transcription settings during a session. The session type is `transcription`.

### Reasoning and effort

No reasoning control. The tuning setting is `audio.input.transcription.delay`, with values `minimal`, `low`, `medium`, `high` and `xhigh`. Lower delay gives earlier partial text. A higher delay gives the model more audio context and can lower the word error rate. OpenAI gives no millisecond figure per level and says to benchmark with representative audio [openai-guide-transcription-rt]. The API reference, read the same day, says `delay` is supported only with `gpt-realtime-whisper` in GA Realtime sessions, so the guide and the reference disagree for this model [openai-ref-client-secrets].

### Output: format, length, tone

- Output is text: transcript deltas, then a completion event for each committed item. The order of completion events across turns is not guaranteed, so match them by `item_id` [openai-guide-transcription-rt].
- The model returns no word-level timestamps, no speaker labels and no confidence scores. It returns no detected-language prediction either. OpenAI points to a file transcription model or an application fallback for these [openai-guide-transcription-rt].

### Long context and retrieval

The model page states no window. Microsoft's Foundry listing shows 32,000 input and 4,096 output tokens [ms-foundry-models].

Not applicable.

### Images, audio, other inputs

Audio and text in, text out. A session takes streamed audio chunks. The guide example uses 24 kHz PCM [openai-guide-transcription-rt] [openai-model-gpt-live-transcribe].

### Sampling and API parameters

- Rate limits: tier 1, 500 requests and 60,000 tokens a minute; tier 5, 10,000 requests and 780,000 tokens [openai-model-gpt-live-transcribe].
- Data: the realtime transcription endpoint supports US and EU data residency [openai-guide-your-data].
- Production checklist from OpenAI: pick latency and accuracy targets before tuning; test real audio, each target language, numbers, dates, currency, emails, product names and domain terms; count empty, truncated and delayed transcripts apart from word error rate; plan how the interface revises partial text; keep a fallback for timestamps, speaker labels and confidence [openai-guide-transcription-rt].

### Migrating from the previous generation

- From GPT-Realtime-Whisper: OpenAI says existing integrations may keep it, and that it is not the recommended start for a new integration. Both models require turn detection to be omitted or null, so the client-commit flow is the same [openai-guide-transcription] [openai-guide-vad].
- From `whisper-1`, `gpt-4o-transcribe`, `gpt-4o-mini-transcribe` or `gpt-4o-transcribe-diarize`, which OpenAI removes on 2027-02-26: it names `gpt-live-transcribe` or `gpt-transcribe` as the replacement [openai-deprecations]. Speaker labels and word timestamps are not available in this model.

## Behaviour observed in practice

- **Independent measurement (M).** Artificial Analysis's streaming benchmark gives an AA-WER Streaming Index of 3.92% for final transcripts (datasets AA-AgentTalk 2.81%, VoxPopuli 2.60%, Earnings22 7.45%), 0.81 s to the final transcript after speech ends, and 0.26 s to the first partial. The page does not say which delay setting it used [aa-stt-streaming]. The same page lists GPT-Realtime-Whisper at 4.89%, 0.69 s and 0.21 s. The non-streaming page has no row for this model [aa-stt-non-streaming].
- **Cloud (L).** Microsoft Foundry lists it, dated 2026-07-29, as the current recommended model for realtime transcription [ms-foundry-models].
- **Practitioner reports (A).** None gathered.
