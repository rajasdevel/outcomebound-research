# StepAudio 3 Realtime (preview)

StepAudio 3 Realtime is StepFun's full-duplex voice model for real-time conversation. It takes streaming audio or text and gives back speech and text over a WebSocket Realtime API. StepFun names three abilities: reading acoustic cues (tone, emotion and ambient sound), managing turns with natural interruption and backchannels, and thinking while speaking. A voice agent layer can call tools while the talk goes on. The API name is `stepaudio-3-realtime-preview`. It is free for a limited time. StepFun says it will retire the preview name when a paid version arrives. A trade report dates the release 2026-09-15, and the technical report was submitted on 2026-09-12. It follows [StepAudio 2.5 Realtime](stepaudio-2.5-realtime.md). Maker-wide facts are in the [StepFun README](README.md) [step-model-page-3] [step-paper-3] [runtimewire-step].

## How to instruct it

### Setting up the prompt

`instructions` on `session.update` is the system message. StepFun's API reference says to use it for the content and format of replies (for example "be very concise" or "be friendly") and for audio behaviour (for example "speak quickly" or "inject emotion into your voice"). It adds that the model is not guaranteed to follow the instructions [step-realtime-api]. This differs from the advice of some other makers, who say a prompt controls the words and not the sound. StepFun publishes no longer prompting guide for the realtime models.

You can change any session field at any time except `voice`. The voice cannot change once the model has made audio [step-realtime-api].

### Reasoning and effort

StepFun describes adaptive reasoning. The model answers simple questions fast and reasons more on complex tasks. It hides the extra time by thinking while it speaks. The documented API has no switch or effort level. The server streams the reasoning text as `response.thinking.delta` and `response.thinking.done` events [step-model-page-3] [step-realtime-api].

### Output: format, length, tone

Output is audio plus its text. The API fixes `modalities` to text and audio. `volume_ratio` (default 1) sets output volume [step-realtime-api]. The model page names tone and emotion as inputs it understands and gives no tone controls beyond the prompt.

### Tools and agents

`session.tools` takes function tools with a name (letters, digits, underscore and hyphen, under 64 characters), a description and a JSON-schema parameter list. The model page says a voice agent calls tools or runs back-end tasks once the intent is clear, that the conversation continues while a task runs, and that the result is woven back in. It also lists built-in `web_search` and `retrieval` tools for the Realtime API [step-model-page-3] [step-realtime-api]. The technical report calls this an asynchronous tool layer that does not break the flow of the dialogue [step-paper-3]. StepFun's report gives a tau-Voice result of 56.0% macro task success. Artificial Analysis lists no tau-Voice result for the model [step-paper-3] [aa-s2s].

### Coding

StepFun gives no coding guidance for this model.

### Long context and retrieval

StepFun states no context size or session limit. The Realtime API keeps the conversation history for you. The client can add or delete items with `conversation.item.create` and `conversation.item.delete`; it cannot add assistant audio items [step-realtime-api] [step-model-page-3].

### Structured output

StepFun documents no structured-output setting for the realtime model.

### Images, audio, other inputs

Input is audio or text. The Realtime API lists `pcm16` for input and output. It does not state the sample rate for this model. The page for the 2.5 model gives 24 kHz mono. Real-time conversation supports Chinese and English only [step-realtime-api] [step-audio-models].

### Voice: turn-taking, interruption and speech style

**Turn detection.** Server VAD is off by default. To turn it on, set `turn_detection.type` to `server_vad`. Three settings tune it [step-realtime-api]:

- `prefix_padding_ms` (default 500) is the audio kept from before the start of speech.
- `silence_duration_ms` (default 100) is the silence after which the user is taken to be done. The default is short.
- `energy_awakeness_threshold` (0 to 5000, default 2500) is the energy level above which the user is taken to have started speaking.

Without VAD, the client sends `input_audio_buffer.commit` and `response.create` itself.

**Interruption.** StepFun says the user and the model can speak at the same time, that the model stops promptly when really interrupted, and that it keeps a coherent talk through pauses and casual backchannels. With VAD on, the server sends `input_audio_buffer.speech_started`, "typically used for interruption scenarios". `response.cancel` stops a response and returns an error if none is running [step-model-page-3] [step-realtime-api].

**Voices.** The seven system voices are `soft-spoken-gentleman`, `magnetic-voiced-male`, `vibrant-youth`, `lively-girl`, `livelybreezy-female`, `elegantgentle-female` and `zixinnansheng`. Cloned voices work after you clone them with the StepAudio 2.5 TTS model. StepFun says the voice is set before the model speaks. Any other value gives a 400 error [step-realtime-api].

**Latency.** StepFun gives no latency figure. Artificial Analysis measured an average of 8.83 seconds to first audio on its Big Bench Audio set. This is the slowest value among the models on its page that have one. StepFun's docs say the board results use internal parameter settings that the API does not yet expose and that actual API behaviour may differ [aa-s2s] [step-realtime-api].

### Sampling and API parameters

The reference documents no sampling parameter. Authentication is a bearer token. The endpoint is `wss://api.stepfun.ai/v1/realtime`, with the model in the `model` query parameter. The pricing page sets rate limits for the Open Platform API by tier of cumulative top-up, from 5 concurrent requests at tier V0 to 130 at tier V4. It does not say whether the tiers apply to the Realtime API [step-realtime-api] [step-pricing].

### Migrating from the previous generation

The 3 model adds full-duplex dialogue, think-while-speaking and the voice agent layer. The 2.5 model is billed by token ($1.50 input, $10.00 output per million) and the 3 preview is free for now. The seven voices and the audio format are the same on the pages read. The model name in the URL changes from `stepaudio-2.5-realtime` to `stepaudio-3-realtime-preview` [step-model-page-3] [step-pricing] [step-25-realtime].

## Behaviour observed in practice

Artificial Analysis measured the model on its Speech to Speech page (read 2026-10-03) [aa-s2s]:

- Speech reasoning (Big Bench Audio): 99.7%. The table shows 100% rounded.
- Conversational dynamics (a subset of Full Duplex Bench v1 and v1.5): 98.9%. The parts are pause handling 100, turn-taking 99.2, interruption handling 98.5 and backchannel handling 98.0.
- Time to first audio: 8.83 seconds on average.

A trade report calls the contrast the main finding: top scores for reasoning and conversation handling, and a slow first response. The model lacks the results needed for the index of the page, which needs agentic, arena and task scores [runtimewire-step] [aa-s2s]. No practitioner test was read.

## Benchmarks

Independent: the Artificial Analysis results above. Maker (technical report, StepFun's own runs): StepAudioChat in reasoning mode 73.0 macro average, MMSU 90.6, Artificial Analysis's Full-Duplex-Bench 98.9 overall, and tau-Voice 56.0% macro task success [step-paper-3].

## Open questions

- The price of the paid version and the name of the production model.
- Why the first response took 8.83 seconds, and whether the API setting changes it.
- Whether the model speaks languages beyond Chinese and English. StepFun labels other languages as in preview for its speech synthesis and recognition models, and Chinese and English only for realtime.
