# Moshi (Moshiko and Moshika)

Moshi is Kyutai's open full-duplex speech-to-speech model. It listens and speaks at the same time. It has about 7 billion parameters in its main transformer and is built on Kyutai's own text model, Helium. Kyutai published two builds in September 2024: Moshiko (a male synthetic voice) and Moshika (a female one). The weights are under CC-BY 4.0. Kyutai calls it the first real-time full-duplex spoken language model. It is the first model of the class Moshi. MoshiRAG is the second. Family-wide rules are in the [Kyutai README](README.md) [kyutai-card-moshiko] [kyutai-gh-moshi] [kyutai-moshi-paper].

## How to instruct it

### Setting up the prompt

The released builds take no system prompt, no persona text and no voice prompt. The model card and the README describe no such input. The model card says the model suits casual conversation, basic facts and advice, and role play. It says the model has limited ability for complex tasks and cannot use tools [kyutai-card-moshiko]. Kyutai trained the model in four phases: pre-training on 7 million hours of mostly English audio, post-training on simulated multi-stream data, fine-tuning for full duplex on the Fisher phone-call corpus (2,000 hours), and instruction fine-tuning on synthetic scripts that include safety refusals [kyutai-moshi-paper]. A prompt-controlled variant that is built on the Moshi weights exists from another maker. See [PersonaPlex](../other/personaplex-7b-v1.md).

### Reasoning and effort

The model has no reasoning mode and no effort control. It predicts text tokens (an inner monologue) just before each audio frame. This improves the language of the speech. It is not a thinking step that a user can set [kyutai-moshi-paper].

### Output: format, length, tone

Output is a stream of audio, plus the text of what the model says. The model speaks in one fixed voice per build. Each build is fine-tuned on one synthetic voice. The card says the model is trained to produce one voice only, to avoid impersonation. The paper tests that the model keeps its own voice and does not copy the user's voice: in 98.7% of segments the voice stayed closer to its own. No setting controls length, tone or style [kyutai-gh-moshi] [kyutai-card-moshiko] [kyutai-moshi-paper].

### Tools and agents

The model card says the model cannot access tools [kyutai-card-moshiko]. Kyutai's later model [MoshiRAG](moshirag.md) adds retrieval of facts by a separate back end.

### Coding

Kyutai gives no coding guidance. The model card says it is not meant for complex tasks.

### Long context and retrieval

The paper gives the temporal transformer a context of 3,000 steps, about 4 minutes, and says the model follows conversations across 5 minutes. It states no token limit for the released builds. The model has no retrieval [kyutai-moshi-paper].

### Structured output

Not applicable. The model produces speech and its transcript.

### Images, audio, other inputs

The model takes audio only, at 24 kHz mono. The Mimi codec turns each 80 ms frame into 8 codebook tokens (12.5 frames per second, about 1.1 kbit/s). The model is trained for English [kyutai-card-moshiko] [kyutai-moshi-paper]. The README says the web client does echo cancellation and the command-line clients do not. It recommends the web interface because the echo cancellation helps model quality [kyutai-gh-moshi].

### Voice: turn-taking, interruption and speech style

Moshi has no turn detection, no voice activity detector and no barge-in setting. The model gets the user's audio and its own audio as two parallel streams. It decides at each 80 ms step whether to speak. The paper says this lets it model interruptions, overlapping speech and backchannels without explicit turns. It reports that overlap is 10 to 20% of spoken time in natural conversation, citing earlier work [kyutai-moshi-paper].

What this means for a builder:

- You do not tune the pause length or the interruption point. Behaviour depends on the weights.
- Echo matters. If the model hears its own voice on the input, it can react to it. Kyutai's web client has echo cancellation. Its command-line clients have none [kyutai-gh-moshi].
- Latency comes from the model and the GPU. Kyutai gives a theoretical 160 ms (an 80 ms frame and an 80 ms acoustic delay) and about 200 ms in practice on an L4 GPU. Network delay adds to it. The README notes up to 500 ms from Europe through the Gradio tunnel [kyutai-gh-moshi].
- The model has a single voice per build and cannot clone voices or take a persona.

### Sampling and API parameters

Moshi has no hosted API. You run `python -m moshi.server` (PyTorch), the MLX client on a Mac, or the Rust server. The README says the PyTorch version does not support quantization and needs a GPU with about 24 GB, although it also lists an experimental int8 PyTorch build. MLX offers int4 and int8 builds. The README documents no sampling settings in the parts read [kyutai-gh-moshi].

### Migrating from the previous generation

There is no earlier Moshi model. For the second model of the class, see [MoshiRAG](moshirag.md).

## What the system card reports

The model card and the paper cover safety:

- The model card says Kyutai trained with a few safeguards to limit toxic use. Its toxicity analysis puts the model in the middle of existing models on text generation. It has bias toward topics that are over-represented in the training data [kyutai-card-moshiko].
- The model is for research only. Kyutai does not recommend it for advice or professional duty. It must not be used to impersonate people [kyutai-card-moshiko].
- The paper lists four checks: toxicity, regurgitation of training audio, consistency of the system voice, and identification of generated content by watermarking [kyutai-moshi-paper].

## Behaviour observed in practice

Artificial Analysis measured a model it lists as Kyutai Moshi (read 2026-10-03). The page does not say which build [aa-s2s]:

- Speech reasoning (Big Bench Audio): 4.4%. This is the lowest score among the models on the page that have one.
- Conversational dynamics: 61.0%. The parts are pause handling 83.2, turn-taking 68.1, interruption handling 63.0 and backchannel handling 29.6.

The same page lists NVIDIA's PersonaPlex, built on the Moshiko weights, at 91.0% on conversational dynamics [aa-s2s]. No practitioner report was read.

## Benchmarks

Independent: the two Artificial Analysis results above. Maker: the paper claims the best results among speech-text models of its time for speech modelling and spoken question answering, with streaming. The paper is from 2024 and its comparisons are old [kyutai-moshi-paper].
