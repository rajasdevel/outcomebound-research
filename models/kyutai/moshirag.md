# MoshiRAG

MoshiRAG is Kyutai's open full-duplex speech model with asynchronous retrieval of facts. Its front end is a full-duplex model based on Moshika. It keeps listening and speaking while a separate back end looks up references. The paper is dated 2026-04-14 and was accepted to ICML 2026. The Hugging Face repository was created on 2026-03-19. It is the second model of the class Moshi, after [Moshi](moshi.md). The weights are under CC-BY 4.0. Family-wide rules are in the [Kyutai README](README.md) [kyutai-card-moshirag] [kyutai-moshirag-paper] [hf-kyutai-list].

## How to instruct it

### Setting up the prompt

The released front end takes no system prompt. The model card describes none. What you configure is the retrieval back end: which text model or search method answers the queries, and where it runs [kyutai-card-moshirag] [kyutai-gh-moshirag].

### Reasoning and effort

No reasoning mode exists. The front end is small. The design sends hard questions to a stronger text source, which is the back end's job. The paper reports that the approach also helped on out-of-domain mathematical reasoning [kyutai-moshirag-paper].

### Output: format, length, tone

Output is speech and its text, in one fixed voice (Moshika). While retrieval runs, the model can say short acknowledgments or a coarse first answer. After retrieval ends, the reference text is encoded and injected into the model as a stream. Later parts of the reply use it [kyutai-card-moshirag].

### Tools and agents

The retrieval back end is text-in and text-out. The model predicts a trigger token when a query needs outside knowledge. The conversation context (the model's own text plus the user's transcript) goes to the back end. Choices named in the README are a local vLLM server, which it recommends for low latency, an OpenAI-compatible API, and several back ends set in `MOSHI_RETRIEVAL_LLMS_JSON`. The README also says the system is sensitive to retrieval times above 3 seconds. It runs three services: a reference encoder (port 8001), the main server (port 8998) and the retrieval model (port 8002) [kyutai-gh-moshirag] [kyutai-card-moshirag].

### Coding

Kyutai gives no coding guidance.

### Long context and retrieval

Retrieval is the point of the model. The paper says MoshiRAG reaches factuality comparable to speech models that do not run full duplex, and it keeps full-duplex behaviour. It says any retrieval method plugs in without retraining [kyutai-moshirag-paper]. The card says the safety of the answers depends on the retrieval back end you choose [kyutai-card-moshirag].

### Structured output

Not applicable.

### Images, audio, other inputs

Audio in and out is at 24 kHz mono through the Mimi codec, as for Moshi. A streaming speech-recognition model must transcribe the user for the back end. The card names `kyutai/stt-1b-en_fr`. The README recommends a service named Gradium. The front end also depends on frozen parts of Kyutai's ARC-Encoder [kyutai-card-moshirag] [kyutai-gh-moshirag].

### Voice: turn-taking, interruption and speech style

MoshiRAG has the same full-duplex front end as Moshi, so it has no turn detection and no interruption setting. See [Moshi](moshi.md) for what that means. Three points are new:

- **Filler speech.** The model can talk through the retrieval delay with a short acknowledgment. The card says retrieval must finish within the natural response delay of the conversation [kyutai-card-moshirag].
- **Retrieval time.** Replies that depend on a lookup are late if the back end is slow. The README warns about times above 3 seconds. A slow back end therefore delays the answers.
- **Echo.** The Moshi web client does echo cancellation, and its command-line clients do not. MoshiRAG is built on the Moshi code [kyutai-gh-moshirag] [kyutai-gh-moshi-readme].

### Sampling and API parameters

There is no hosted API. The PyTorch front end needs a GPU with 24 GB or more and has no quantization. A Rust and Candle build exists. The README gives no official Windows support [kyutai-gh-moshirag]. The Moshi README, on which this code is based, says a browser may refuse the microphone on a remote server over plain HTTP, and gives an SSH port forward or the Gradio tunnel as the ways around it [kyutai-gh-moshi-readme].

### Migrating from the previous generation

From Moshi: the front end is a Moshika fine-tune, so its voice is Moshika's. The system also needs the retrieval back end, the reference encoder and a streaming speech-recognition service. In return the model can ground answers in outside sources [kyutai-card-moshirag] [kyutai-gh-moshirag].

## What the system card reports

The card says Kyutai trained the model with a few safeguards, that its toxicity analysis puts it in the middle of existing models for text generation, and that it is trained to produce one voice only. It is for research only. The card adds that the retrieval back end can change what the model says, and that a back end with good safeguards lowers the safety risks and the bias [kyutai-card-moshirag].
