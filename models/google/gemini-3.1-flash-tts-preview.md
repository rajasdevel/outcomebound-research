# Gemini 3.1 Flash TTS Preview

Gemini 3.1 Flash TTS Preview is the generation before [Gemini 3.8 Flash TTS](gemini-3.8-flash-tts.md) in the Gemini Flash TTS class. Google launched it on 2026-04-15 as a preview. It directs delivery with a written prompt and with square-bracket audio tags in the transcript, and it is a voice actor model in this library's sense. Google now calls it a legacy preview and tells new work to use a 3.8 model. This file holds the 3.1 method, which the current guide no longer describes. Family-wide rules are in the [Google README](README.md).


[as-of 2026-10-09] The Gemini API preview is retiring. The deprecations page gives 2026-11-17 as the earliest shutdown and names either 3.8 TTS model as replacement [L: g-deprecations].

## How to instruct it

### Setting up the prompt

The text of the request is the prompt. Google's 3.1-era guide treats a prompt as a system instruction for a language model that knows what to say and how to say it. The guide asks you to think as a director who sets a scene for a virtual voice performer [g-archive-guide].

**A plain request.** The guide's plain form is a short instruction before the words, such as an order to say a line in a spooky whisper. For two speakers the instruction comes first, then one labelled line per speaker, and the instruction can give each speaker a separate direction. The config names up to two speakers, with the same names that the transcript uses [g-archive-guide].

```text
Make Mara sound weary and Tom sound thrilled.
Mara: Another meeting. Great.
Tom: Guess what the topic is.
```

**A structured prompt.** For more control the guide gives six parts, in this order [g-archive-guide]:

| Part | What it holds |
| --- | --- |
| Audio Profile | The persona: a name, a role or archetype, and traits such as age and background. A name helps ground the performance |
| Scene | The place and the mood. It guides the acting in a subtle way |
| Director's Notes | Performance rules: style, breathing, pacing, articulation and accent. The guide calls this the most useful part, and says to skip the others before skipping this |
| Sample context | A starting point so the voice enters the scene naturally |
| Transcript | The words to speak. Its topic and writing style should match the direction |
| Audio tags | Inline modifiers inside the transcript |

The guide's advice on the parts: accent works best when specific, and the guide prefers a named place, for example a district of a city, to a general national accent. Style works best with detail and with voiceover terms such as a vocal smile. Pacing covers the whole piece. The guide also warns against over-specifying: too many strict rules limit the model's creativity and can give a worse performance. It says the transcript, the persona and the direction should agree, so that who is speaking, what is said and how it is said fit together [g-archive-guide].

**Audio tags.** A tag is a word or phrase in square brackets inside the transcript. It changes the delivery of the text after it, up to the next tag. The guide says no list is exhaustive and asks you to experiment. It shows tags for emphasis (excited, bored, reluctant), for pace (very fast, very slow), for combined effects (sarcastic, one painfully slow word at a time), and for free-form character voices (like a cartoon dog, like Dracula). The launch post says audio tags steer vocal style, pace and delivery through natural-language commands in the text, which matches this free-form use [g-archive-guide] [g-blog-31].

```text
[whispers] Hey there, I am a new model, [shouting] and I can say things in many ways. [whispers] How can I help?
```

The tags the guide lists as common are amazed, crying, curious, excited, sighs, gasp, giggles, laughs, mischievously, panicked, sarcastic, serious, shouting, tired, trembling and whispers. A transcript that is not in English should keep English tags for the best results [g-archive-guide].

**The Google Cloud route.** The same model is served by the Cloud Text-to-Speech API and the Vertex AI API, in the global region. The Cloud API splits the request into a `prompt` field for the style and a `text` field for the words, and it takes the voice, language and model in a `voice` object. The Vertex AI API takes one text string, as the Gemini API does. Google's Cloud page is the fullest source on tags [g-cloud-tts].

```json
{
  "input": {
    "prompt": "Say the following in a hushed, nervous way.",
    "text": "Did you hear that? [short pause] Someone is on the stairs."
  },
  "voice": {"languageCode": "en-us", "name": "Kore", "modelName": "gemini-3.1-flash-tts-preview"},
  "audioConfig": {"audioEncoding": "LINEAR16"}
}
```

Google's Cloud page names three levers and says the result is most predictable when all three agree [g-cloud-tts]:

- **The style prompt** sets the overall emotional tone and delivery for the segment.
- **The text content** matters: words that fit the style give much more reliable results than neutral words. A scared tone fits a line such as a worry that someone is in the house, and it fits a meeting time badly.
- **The markup tags** (marked Preview on that page) inject a local action or a change of style. They do not set the overall tone.

Google's Cloud page says square-bracket tags work in four modes, and that behaviour can differ from what a reader expects. The page rates each listed tag's reliability as high [g-cloud-tts]:

| Mode | What happens | Tags the page lists |
| --- | --- | --- |
| Non-speech sounds | The tag becomes a sound and is not spoken. The mood of the sound follows the prompt | sigh, laughing, uhm |
| Style modifiers | The tag is not spoken. It changes the delivery of the text after it | sarcasm, robotic, shouting, whispering, extremely fast |
| Vocalised adjectives | The tag is spoken as a word and also colours the sentence. Google calls this an undesired side effect for most uses and advises the style prompt for these tones | scared, curious, bored |
| Pacing and pauses | The tag adds silence: about 250 ms, about 500 ms, or 1,000 ms and more | short pause, medium pause, long pause |

The page's other advice: use specific prompts (an amused laugh works better than a bare laugh tag, and a 1940s radio news announcer works better than an old-fashioned voice), use emotionally rich text for sarcasm, fear and excitement, and test any new tag, because a tag that you take for a style modifier can be spoken aloud. Google says the page's tag reliability and the tag modes come from its own research. The page does not say which of its Gemini-TTS models each tag was tested on [g-cloud-tts].

**Cloud safety settings.** The Cloud API accepts safety thresholds for four harm categories (dangerous content, harassment, hate speech and sexually explicit content) in `advancedVoiceOptions`. A request that a filter blocks returns a support code for the category [g-cloud-tts].

**Voice choice.** The 30 voices carry short trait labels, for example Puck upbeat, Enceladus breathy and Charon informative. The guide advises a voice whose trait fits the wanted emotion, because the voice and the direction add up. The same 30 voice names exist on the 3.8 models [g-archive-guide] [g-tts-guide].

### Reasoning and effort

None [g-model-31-page].

### Output: format, length, tone

On the Gemini API the model returned headerless raw PCM (24 kHz, 16-bit, mono) by default. Streaming has been supported since 2026-06-17. The Cloud Text-to-Speech API chooses the format in `audioConfig`: LINEAR16 (the unary default), ALAW, MULAW, MP3, OGG_OPUS or PCM, with PCM as the streaming default. Its text field and prompt field are each limited to 4,000 bytes, 8,000 bytes together, and output past about 655 seconds is truncated. Tone comes from the prompt, the tags and the voice [g-changelog] [g-tts-guide] [g-cloud-tts].

### Tools and agents

Not a tool-calling model. The model page lists function calling and the Live API as not supported [g-model-31-page].

### Coding

The same Interactions API and generateContent routes as the 3.8 models. Google's model page for this id has a legacy banner that names the 3.8 models [g-model-31-page].

### Long context and retrieval

The archived guide said a TTS session had a context window of 32k tokens and that quality and consistency can drift once output runs longer than a few minutes. It advised splitting transcripts into chunks [g-archive-guide].

### Structured output

Not supported [g-model-31-page].

### Images, audio, other inputs

Text only. The model has no voice design and no voice replication [g-tts-guide].

### Voice: turn-taking, interruption and speech style

The model is not a conversation model. It has no turn detection and no barge-in. Turn-taking does not apply.

**How to direct delivery.** See "Setting up the prompt". The 3.1 method is a prompt in the text plus square-bracket tags. It has no separate style field. This is the main change that the 3.8 models made [g-tts-guide].

**How strongly it works.** One paper that measures expressive instruction following with human raters gave the preview first place of 31 configurations for Acting / Role-Fit (3.97 on a five-point scale) and for Expressiveness (3.64), each with a standard deviation of 0.04. The authors work at a speech vendor [hume-rwveq]. Google's launch post gave an Artificial Analysis Elo of 1,211 at launch [g-blog-31].

**Known failures, by Google.**

- The output may not match the chosen voice, for example a deep voice asked to speak like a young girl. The guide advises a written tone and persona that fit the voice [g-archive-guide].
- Quality can drift on outputs longer than a few minutes. The guide advises splitting the transcript [g-archive-guide].
- The model sometimes returns text tokens in place of audio. The server then fails the request with a 500 error. This happens in a small share of requests, and Google advises retry logic [g-archive-guide].
- A vague prompt can fail the speech synthesis classifier. The request is then rejected as prohibited content, or the model reads the style notes aloud. Google advises a clear opening instruction to synthesise speech and an explicit label where the spoken transcript begins [g-archive-guide].

**Multi-speaker and long-form.** Up to two speakers per request, with names that match the transcript labels. Long pieces need chunking. The Cloud API takes a list of turns with speaker aliases made of letters and digits, with the dialogue capped at 4,000 bytes [g-archive-guide] [g-cloud-tts].

**Pronunciation and text normalisation.** The guide documents no phoneme tag and no lexicon. A report that quotes a measurer's post gives 88.2 percent for this model on the Artificial Analysis pronunciation test, against 89.5 percent for 3.8 Flash TTS. The post was not read at its source [eesel-g38].

### Sampling and API parameters

None documented for the TTS models [g-model-31-page].

### Migrating from the previous generation

This is the previous generation, and the migration runs from here to 3.8. See the steps in [the 3.8 Flash TTS file](gemini-3.8-flash-tts.md#migrating-from-the-previous-generation). From the older 2.5 TTS previews to this model, Google's changelog says only that it launched with audio tags and better naturalness, control and multilingual output [g-changelog] [g-model-31-page].

## What the system card reports

Google's model card for Gemini 3.1 Flash Audio covers Flash Live and Flash TTS together. It was published in March 2026 and updated in April 2026. It says the model is based on Gemini 3 Pro, takes text up to 16K and gives audio with a 32K token output, and refers to the Gemini 3 Pro card for limits, risks and training. The TTS model is distributed through Google AI Studio, the Gemini API, Google Cloud (Vertex AI) and Google Vids. For frontier safety, Google relies on its tests of 3.1 Pro with Deep Think, which reached no critical capability level. The launch post says all audio carries a SynthID watermark [g-card-31] [g-blog-31].

## Behaviour observed in practice

- **Arena rank (M).** Artificial Analysis gives 1208.55, rank 13 of 93 with a range of 10 to 14, on 3,706 votes and 7 voices [aa-g31] [aa-pv].
- **Throughput (M).** A median of 29.1 characters a second, the lowest of the three Google TTS models [aa-g31].
- **Expressive control (M, vendor paper).** First of 31 configurations for acting and expressiveness [hume-rwveq].

## Benchmarks

Independent: Artificial Analysis Elo 1208.55 and 29.1 characters a second [aa-g31]. A vendor paper: 3.97 for Acting / Role-Fit and 3.64 for Expressiveness on five-point scales [hume-rwveq]. Google's own post: an Elo of 1,211 at launch [g-blog-31].
