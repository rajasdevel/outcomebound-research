# Gemini 3.5 Transcribe Live

Gemini 3.5 Transcribe Live is a distinct selectable model for continuous speech-to-text, generation 3.5 of Gemini Transcribe Live. Google released it to general availability on 2026-08-26. It uses the Live API and fits the transcription scope. No previous dedicated generation was found in the official inventory [L: changelog, models].

## How to instruct it

### Setting up the prompt

Google's setup uses `LiveConnectConfig`, text response modality and `input_audio_transcription`. Language hints, custom vocabulary and transcript mode configure recognition; a system-prompt interface for this dedicated endpoint is not documented [L: transcribe-live-guide].

### Reasoning and effort

The transcription family does not expose thinking or effort controls [L: transcribe-model].

### Output: format, length, tone

`interim_input_transcription` provides an evolving hypothesis; `input_transcription` gives the finalized utterance. Default mode is `VERBATIM`; `SMART` removes fillers and formats the result. A partial hypothesis is not a final transcript [L: transcribe-live-guide].

### Tools and agents

This is speech recognition over a bidirectional connection. Google distinguishes it from a conversational agent with tools, search and system instructions. A separate agent can consume its transcripts; this model does not choose that agent's actions [L: transcribe-live-guide].

### Coding

Google publishes connection examples, not coding-agent prompting guidance, for this model [L: transcribe-live-guide].

### Long context and retrieval

The dedicated session limit is ten minutes [L: transcribe-model]. The shared card says up to 96K context and 32K text output without exact token integers. Conversation-model compression and resumption guarantees are not assumed to extend this transcription limit [L: audio-card, transcribe-model].

### Structured output

Output is transcription events. Unlike [file transcription](gemini-3.5-transcribe.md), Live supports neither speaker diarization nor word-level timestamps. It has no documented general JSON-schema generation control [L: transcribe-model].

### Images, audio, other inputs

The guide specifies raw 16-bit mono little-endian PCM at 16 kHz. It recommends 100 ms chunks, but also gives 1,024 to 2,048 frames: at 16 kHz that range is 64 to 128 ms (arithmetic from the documented rate). The exact frame duration must therefore be chosen by the client. The endpoint guide describes audio input; the shared card additionally lists text [L: transcribe-live-guide, audio-card].

### Sampling and API parameters

Automatic server VAD detects speech by default. Hybrid mode leaves that detection enabled and uses the client's `audio_stream_end` to finalize promptly. Manual mode disables it and signals `activity_start` and `activity_end`. Google provides no endpoint-specific sampling or prefill advice [L: transcribe-live-guide].

### Migrating from the previous generation

No preceding dedicated Gemini Transcribe Live generation was found [L: models]. From [file transcription](gemini-3.5-transcribe.md), choose the Live id and a WebSocket session; do not carry over diarization or word timestamps [L: transcribe-model].

## Benchmarks

Google's August 2026 report gives 4.0% streaming word error rate attributed to Artificial Analysis. This is stored as maker-reported because the current independent page did not expose a Gemini row in the text read. It must not be presented as a newly verified independent score. Google also describes FLEURS across 26 locales; its scores are chart images and no FLEURS value is transcribed here [L: transcribe-eval; M: aa-streaming].

General coding and reasoning benchmarks do not apply to this dedicated recognizer.
