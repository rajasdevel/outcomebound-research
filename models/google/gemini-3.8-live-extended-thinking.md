# Gemini 3.8 Live Extended Thinking

Gemini 3.8 Live Extended Thinking is a second speech-to-speech model of Google for the Live API, generation 3.8. It reasons in the background and calls tools asynchronously while it keeps speaking. Google recommends it when a voice agent needs more reasoning than [Gemini 3.8 Live](gemini-3.8-live.md) gives. It has been generally available on the Gemini API since 2026-09-15 [L: gemini-changelog, gemini-spec-3-8-live-et]. Google's Cloud blog of 2026-09-25 says it remains in private preview on Gemini Enterprise [L: google-cloud-live-avatar-blog].

Evidence tags: L is Google's own text, M is an independent measurement, A is one practitioner's report. Advice that holds for every Gemini Live model is in the [Live API guide in the Google README](README.md#live-api-guide), and the instructions of [Gemini 3.8 Live](gemini-3.8-live.md) apply here too. This file says what differs. Google's deprecations page lists no shutdown date for this model [L: gemini-deprecations].

## How to instruct it

### Setting up the prompt

The system instruction advice of Google's Live guides applies: one instruction for each agent, in the order persona, rules and guardrails. The details are in the [3.8 Live file](gemini-3.8-live.md#setting-up-the-prompt) [L: gemini-live-best-practices]. Google adds nothing prompt-specific for this model. Its launch post says the model uses early verbal cues, such as "Let me check that…", and narrates progress during multi-step background work [L: google-3-8-live-blog]. Google's thinking guide says the model speaks conversational fillers while background reasoning and tool calls run [L: gemini-live-thinking]. The guide gives no wording to tune how often the model speaks them.

### Reasoning and effort

The control is thinking_config in the setup message, with thinking_level low, medium or high. Minimal is not supported [L: gemini-spec-3-8-live-et, gemini-live-thinking]. No page read names a default level or says what each level costs in time. Artificial Analysis ran the model at high [M: aa-speech-to-speech].

Google's examples for this model: technical support across several logs and error codes, travel agents that search flights and hotels in parallel, STEM and code tutoring, and voice agents whose slow tools would otherwise leave silence [L: gemini-live-thinking]. Google's choice rule is in three parts: use 3.8 Live for fast turns and tools that answer in milliseconds, and use this model for complex data, several steps or tools that run for seconds [L: gemini-live-thinking].

Client state changes with this model. turnComplete: true ends one utterance and does not mean that the session is idle. The client keeps listening and reads interaction_status. IN_PROGRESS means the server is still reasoning or waiting for tool results, and more output can follow. IDLE means all processing is done and the session waits for the user [L: gemini-spec-3-8-live-et, gemini-live-thinking]. The Live guide also says a server event can hold several content parts at once [L: gemini-live-capabilities].

### Output: format, length, tone

Output rules are the same as for 3.8 Live: audio at 24 kHz, and text only through output transcription. See the [3.8 Live file](gemini-3.8-live.md#output-format-length-tone). Reasoning tokens count in the output price [L: gemini-pricing]. Because the model can speak several times for one request, one user turn can give several audio segments [L: gemini-live-thinking].

### Tools and agents

Only asynchronous calls work. Each declaration needs behavior NON_BLOCKING. A synchronous BLOCKING declaration returns a hard error. Function scheduling settings are not supported [L: gemini-spec-3-8-live-et, gemini-live-thinking]. The model plans and calls tools in the background and streams speech while they run. Supported tools are function calling and Google Search grounding [L: gemini-spec-3-8-live-et]. As on 3.8 Live, the client sends each FunctionResponse with the call id [L: gemini-live-tools].

Practitioner reports (A): a project reproduced a failure on a raw WebSocket on 2026-09-23. With thinking level low and a NON_BLOCKING tool, the model said it would call the tool. No tool call reached the client, and the model then said a system error occurred [A: gh-theoremai-25]. A LiveKit issue says this model accepts only NON_BLOCKING and that the plugin cannot set behavior for each tool [A: gh-livekit-7302].

### Coding

Google publishes no coding guidance for the Live models. The model has no code execution tool [L: gemini-spec-3-8-live-et]. Google's examples include code tutoring and checking formulas before the model explains them aloud [L: gemini-live-thinking].

### Long context and retrieval

The limits are those of 3.8 Live: 131,072 input tokens and 65,536 output tokens on the model page, and a session context window of 128k tokens. Caching is not supported. Compression, resumption and the session limits are in the [3.8 Live file](gemini-3.8-live.md#long-context-and-retrieval) and the [README](README.md#live-api-guide) [L: gemini-spec-3-8-live-et, gemini-live-capabilities, gemini-live-session].

### Structured output

Structured outputs are not supported [L: gemini-spec-3-8-live-et].

### Images, audio, other inputs

Inputs are text, images, audio and video, with the same formats as 3.8 Live: 16 kHz PCM audio and JPEG frames at most once a second [L: gemini-spec-3-8-live-et, gemini-live-capabilities]. The model card lists Live Avatar video output for this model. Google's Cloud blog describes Live Avatar for 3.8 Live only, and says Extended Thinking stays in private preview [L: gemini-3-8-audio-card, google-cloud-live-avatar-blog].

### Voice: turn-taking, interruption and speech style

The settings for turn detection, silence, chunk size and interruption are the same as for 3.8 Live. See the [voice subsection of the 3.8 Live file](gemini-3.8-live.md#voice-turn-taking-interruption-and-speech-style). Three points are specific to this model.

- Idle signal. Google says turnComplete is not the end of work. It advises to read interaction_status, and to return the interface to idle only when it reads IDLE [L: gemini-live-thinking].
- Interruption. The server cancels generation and sends interrupted: true, as for 3.8 Live. Google's pages give no separate rule for what happens to background reasoning or non-blocking tool calls after an interruption. Google's Live guide says the server discards pending function calls on an interruption [L: gemini-live-capabilities].
- Speech style. The model fills time with short spoken updates while it works. Google says the model narrates progress for multi-step tasks. Google's pages give no setting for the pitch, speed or accent of speech [L: google-3-8-live-blog, gemini-live-thinking].

Proactive audio is always on for this model, and setting it to false returns an error [L: gemini-spec-3-8-live-et]. The sessions rules are the same as for 3.8 Live: 15 minutes for audio-only and 2 minutes with video unless compression and resumption are on [L: gemini-live-session].

### Sampling and API parameters

Google's thinking guide shows the same WebSocket endpoint and API-key authentication for both 3.8 models. The setup changes in two places: the model string, and thinkingConfig [L: gemini-live-thinking]. The Live pages read give no temperature, top_p or top_k setting.

### Migrating from the previous generation

There is no earlier Extended Thinking model. From 3.8 Live, Google lists three integration changes [L: gemini-live-thinking]:

- Read interaction_status in place of turnComplete to find the idle state.
- Declare every function as NON_BLOCKING.
- Set thinking_config with a level of low, medium or high.

From 3.1 Flash Live Preview, the model-string and setup changes of the [3.8 Live file](gemini-3.8-live.md#migrating-from-the-previous-generation) apply. 3.1 also had four thinking levels, with minimal as its default, and this model does not accept minimal [L: gemini-live-capabilities].

## What the system card reports

The card is the one for all 3.8 audio models. Google published it on 2026-09-15. The model is based on Gemini 3 Pro and has a context window up to 128K tokens, and output of 64K tokens (24K with Live Avatar). The knowledge cutoff is January 2025. For frontier safety, Google relies on the Gemini 3.7 Flash evaluation, which reached no Tracked or Critical Capability Level. The card gives no safety numbers of its own for this model. The full summary is in the [3.8 Live file](gemini-3.8-live.md#what-the-system-card-reports) [L: gemini-3-8-audio-card].

Google's evaluation file says Artificial Analysis and tau-Bench ran this model with the Gemini API at high thinking and default sampling, and ServiceNow ran EVA-Bench on Gemini Enterprise Agent Platform. The results are charts in image form. The Sierra tau3-Banking chart shows 35.1 percent for this model at high thinking. The EVA-Bench chart is a scatter plot with no data labels [L: gemini-3-8-live-eval].

## Behaviour observed in practice

- On 2026-10-03 the model had the highest Speech to Speech Index value on the Artificial Analysis leaderboard (82.6; the next two values were 81.5 and 81.3, both for models of other makers). Its tau-Voice agentic score is 68.6. Its conversational dynamics score (91.9) is lower than that of 3.8 Live (96.1), and its arena preference Elo (990) is lower than that of 3.8 Live (1083) [M: aa-speech-to-speech].
- Time to first audio is 1.35 seconds for this model and 1.18 seconds for 3.8 Live [M: aa-speech-to-speech].
- Artificial Analysis computes $3.50 per hour of input audio for this model and $0.84 for 3.8 Live on its benchmark set, although the price table of Google is the same for both. The page does not explain the gap [M: aa-speech-to-speech; L: gemini-pricing].
- The server-side tool failure in the Tools section is a practitioner report [A: gh-theoremai-25].

## Benchmarks

Independent (Artificial Analysis speech-to-speech leaderboard, thinking high, read 2026-10-03) [M: aa-speech-to-speech]:

- Speech to Speech Index: 82.6.
- Speech reasoning (Big Bench Audio): 97.7. Conversational dynamics (Full Duplex Bench subset): 91.9.
- tau-Voice agentic performance: 68.6. Arena preference Elo: 990. Task success rate: 89.1.
- Time to first audio: 1.35 seconds.

Maker-reported: Google's launch post gives 35.1 percent on Sierra's tau-Voice-banking and repeats the 68.6 percent tau-Voice and 97.7 percent Big Bench Audio figures [L: google-3-8-live-blog]. The Sierra tau3-Banking chart in Google's evaluation file shows the same 35.1 percent, against 11.3 percent for 3.1 Flash Live at high thinking [L: gemini-3-8-live-eval].

No SWE-Bench Pro, Terminal-Bench, Artificial Analysis Intelligence Index, Coding Agent Index or METR result exists for this model. These tests do not apply to a speech model.
