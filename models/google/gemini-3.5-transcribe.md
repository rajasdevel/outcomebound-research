# Gemini 3.5 Transcribe

Gemini 3.5 Transcribe is the dedicated non-streaming speech-to-text model, generation 3.5 of Gemini Transcribe. Google released it to general availability on 2026-08-26 alongside the distinct [Live model](gemini-3.5-transcribe-live.md). It fits the library's transcription scope. No earlier dedicated Gemini Transcribe generation was found in the official inventory [L: changelog, models].

## How to instruct it

### Setting up the prompt

Google configures transcription with `generation_config.transcription_config`, not a documented system prompt. Empty or absent `language_codes` selects automatic language detection; known BCP-47 codes provide hints. `custom_vocabulary` biases recognition toward up to 1,000 terms; Google says up to 100 usually works best [L: transcribe-guide].

### Reasoning and effort

Thinking is unsupported; there is no effort setting [L: transcribe-model].

### Output: format, length, tone

The default `verbatim` mode preserves spoken words. `smart` removes disfluencies, resolves spoken corrections and formats prose. It changes the transcript, so it is a different product choice from preserving all speech. No prose length or tone control is documented [L: transcribe-guide].

### Tools and agents

This endpoint transcribes a recording. Its model page lists no function calling, code execution, file search or caching. The dedicated endpoint is not a coding agent [L: transcribe-model].

### Coding

Google publishes client examples for the transcription API, but no model-specific agentic coding guidance [L: transcribe-model].

### Long context and retrieval

The request supports up to one hour of audio, reduced to 30 minutes with timestamps or diarization [L: transcribe-model]. The shared card says up to 96K context and 32K text output; the endpoint page does not give exact token integers, so the card keeps these fields unknown [L: audio-card].

### Structured output

`interaction.output_text` holds the transcript. Verbatim-mode word annotations carry timestamps and speaker labels. They are not a general JSON-schema output control [L: transcribe-guide].

### Images, audio, other inputs

Google's guide uploads a file with the Files API, then passes its URI and MIME type to the Interactions API. Supported audio formats are listed in the card. The endpoint page describes audio input, although the shared card also lists text. The documentation read gives no sample-rate range [L: transcribe-guide, transcribe-model, audio-card].

### Sampling and API parameters

In verbatim mode, `timestamp_granularities` enables word timing and `diarization_mode` enables speaker labels. Custom vocabulary cannot be combined with either. Smart mode also cannot use either. Google warns that timestamps may reduce accuracy and attribution for three or more speakers is experimental [L: transcribe-guide]. Batch, Flex and Priority are unsupported [L: transcribe-model]. No sampling or prefill advice specific to this endpoint was found.

### Migrating from the previous generation

No preceding dedicated Gemini Transcribe generation was found [L: models]. From [Transcribe Live](gemini-3.5-transcribe-live.md), file requests add diarization and word timestamps and allow longer audio, but do not provide live transcript events [L: transcribe-model].

## What the system card reports

The shared [Gemini 3.5 Audio card summary](README.md#gemini-35-audio-model-card) covers safety and ancestry. It names hallucinations, slowness and time-outs as possible transcription limits [L: audio-card].

## Behaviour observed in practice

Artificial Analysis lists 2.6% word error rate and median processing speed of 91.1 audio seconds per processing second. Speed is throughput from recent runs with ten-minute audio, not a response-latency guarantee [M: aa-non-streaming]. No separate practitioner account was included in this pass.

## Benchmarks

Independent: AA-WER v2 is 2.6%, lower is better. It combines about eight hours of audio from AA-AgentTalk (50%), VoxPopuli-Cleaned-AA (25%) and Earnings22-Cleaned-AA (25%), with audio-duration weighting [M: aa-non-streaming].

Google's August 2026 evaluation report also reproduces 2.6% from Artificial Analysis. It describes FLEURS evaluation over 26 locales and gives results in chart images; no FLEURS score is transcribed here [L: transcribe-eval]. Coding and general reasoning benchmarks do not apply to this endpoint.

## Open questions

- Exact context and output token integers; the shared card gives rounded 96K and 32K limits [L: audio-card].
- Accuracy for the target audio domain, accents, noise, speakers and optional annotation features. One aggregate WER does not settle these.
- Cloud route quotas and availability were not reverified; the shared card lists that distribution [L: audio-card].
- Rejection behavior for system prompts and sampling fields is not stated or runtime-tested in this pass.
