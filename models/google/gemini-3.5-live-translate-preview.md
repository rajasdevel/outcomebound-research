# Gemini 3.5 Live Translate Preview

Gemini 3.5 Live Translate is a dedicated speech-to-speech translation model with its own public-preview id. It is generation 3.5 of the Gemini Live Translate class, not a reasoning level of Gemini Live. Its selectable audio-to-audio endpoint fits the voice scope. The API pages date it to June 2026 without an exact release day; the Cloud page gives August 2026 [L: translate-model, deprecations, translate-cloud].

## How to instruct it

### Setting up the prompt

Google describes an interpreter configured through `translation_config`, with no system instructions. `target_language_code` takes a BCP-47 code and defaults to English (`en`). `echo_target_language` defaults to false: speech already in the target language produces no audio; true repeats it [L: translate-guide].

### Reasoning and effort

Thinking is unsupported. No effort or thinking budget is exposed [L: translate-model].

### Output: format, length, tone

Translated speech is the response. Optional input and output transcription settings return transcripts. No text verbosity or tone control is documented [L: translate-guide].

### Tools and agents

The endpoint has no function calling, search or Maps grounding, code execution, file search or URL context. It does not act as a tool-using assistant [L: translate-model].

### Coding

No coding surface or coding prompting guide is published for this dedicated translator [L: translate-model].

### Long context and retrieval

The endpoint page gives 131,072 input tokens and 65,536 output tokens. It supports no caching or retrieval tools. Translation-specific session duration, compression and resumption guarantees are not stated in the sources read; conversation-model limits are not assumed to apply [L: translate-model, translate-guide].

### Structured output

JSON schemas are unsupported. Transcript text is separate from translated audio [L: translate-model].

### Images, audio, other inputs

The endpoint accepts speech audio only. The shared model card also lists text input; the API guide explicitly rules it out. Cloud documents mono little-endian PCM: 16-bit, 16 kHz input and 24 kHz output, with 100 ms input chunks [L: translate-model, audio-card, translate-cloud].

### Voice: turn-taking, interruption and speech style

Translation continues during speech, without waiting for conversation turns. The guide does not specify barge-in or cancellation. Google Cloud warns that overlapping voices can make translation ambiguous and advises disabling echo for one-way interpretation when repeated target-language speech is unwanted [L: translate-guide, translate-cloud].

### Sampling and API parameters

The GenAI SDK uses `LiveConnectConfig` with an audio response modality and translation settings. Raw WebSocket setup places `translationConfig` within `generationConfig`. The guide describes no temperature, top-p, top-k or prefill controls for this model. Browser clients can use a server-created ephemeral token on `v1beta`; its constraints can lock the translation settings [L: translate-guide].

### Migrating from the previous generation

No earlier distinct Gemini Live Translate generation appears in the official inventory read. From a general Live assistant, configuration changes to the dedicated translation pipeline: audio-only input and no tools or system instructions [L: models, translate-guide].

## What the system card reports

The shared [Gemini 3.5 Audio card summary](README.md#gemini-35-audio-model-card) covers ancestry, safety evaluation and limits [L: audio-card]. For translation, Google names speaker-voice drift after pauses or rapid speaker changes, language detection difficulties, and background audio leaking into output. These are maker-reported limits, not measured failure rates [L: audio-card].

## Behaviour observed in practice

No independent translation behavior study was found in the cited sources. Low-latency and translation-quality descriptions here are Google's claims [L: translate-model].

## Benchmarks

Google's evaluation document describes AutoMQM translation-error scoring, initial and aligned word-level latency, and speech-naturalness checks. It says the implementations were internal and outputs came from the Gemini Live API. The two-page document has no numeric results. Its methods do not establish translation quality for a particular language pair or a deployment's latency [L: translate-eval].

The general coding and reasoning benchmarks required by the card format do not apply to this dedicated translator. Their absence is recorded in the card.
