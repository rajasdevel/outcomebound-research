# Gemma 3 270M (instruction-tuned)

Gemma 3 270M is the smallest model of Google's Gemma 3 line: a text-only model with 270M parameters (about 170M of them embeddings because of a 256K-token vocabulary, and 100M in the transformer blocks) and a 32K-token window. It belongs to the class Gemma, generation 3, and was added on 2025-08-14, five months after the larger Gemma 3 sizes. Google presents it as a base for task-specific fine-tuning (classification, extraction, text structuring) with some instruction following already trained in. It is the generation before Gemma 4; weights are open under Google's Gemma Terms of Use. The other sizes are [1B](gemma-3-1b-it.md), [4B](gemma-3-4b-it.md), [12B](gemma-3-12b-it.md) and [27B](gemma-3-27b-it.md).

## How to instruct it

Google publishes one model card and one formatting page for all Gemma 3 sizes, and no prompt-writing guide. This section says what they and the technical report say, with what differs for this size [g3-card] [g3-prompt] [g3-report]. The formatting page is labelled legacy (for Gemma 1, 2 and 3) in Google's navigation.

### Setting up the prompt

- **Roles and turn markers.** The instruction-tuned models were trained with a formatter that marks roles and turn boundaries. The markers are `<start_of_turn>` and `<end_of_turn>`, with the roles `user` and `model`; the turn separator is the end marker plus a newline, and a generation prompt ends with `<start_of_turn>model` and a newline. Text starts with a beginning-of-sequence token that must be added explicitly, because the written string "[BOS]" does not map to it [g3-prompt] [g3-report] (class L).
- **No system role.** Google says the instruction-tuned models work with only two roles and a system turn is not supported. Its guidance is to put system-level instructions at the start of the first user turn [g3-prompt].
- **Instruction following.** Google's own number is IFEval 51.2 (0-shot), against 80.2 for the 1B; its launch post claims a new level of instruction-following performance for its size and says fine-tuning is where the model's value is unlocked [g3-card] [g3-270m-blog] (class L). The model card gives no stronger instruction-following claim.
- **Structure, examples, long documents.** Google gives no advice on tags, Markdown, examples or document placement for Gemma 3.

### Reasoning and effort

Gemma 3 has no thinking mode, no effort setting and no reasoning output; Artificial Analysis lists it among non-reasoning models [g3-card] [aa-gemma-3-270m]. Google gives no step-by-step prompting advice for it. Its technical report says post-training aimed to improve maths, reasoning and chat, using distillation from a larger instruction-tuned teacher followed by reinforcement learning with reward models, code-execution feedback and maths answer checks [g3-report] (class L).

### Output: format, length, tone

- **Length.** No verbosity setting. Output can reach 32K tokens minus the prompt [g3-card].
- **Style.** Google publishes nothing on tone or formatting defaults. Artificial Analysis's page gives no output-volume statement for this size (class M source, nothing read).
- **Prefill.** Not documented; since the generation prompt ends at the start of the model turn, text placed after it continues as the model's reply (an inference from the format, not a Google statement).

### Tools and agents

Google's launch post says Gemma 3 supports function calling and structured output [g3-blog] (class L, marketing claim). The pages read give no tool-call format, no tool-choice or parallel-call behaviour and no agentic benchmark for Gemma 3; later Gemma pages describe function calling for Gemma 4 and for the FunctionGemma model, which are separate. Tool calls from Gemma 3 therefore rest on a text format that the prompt or the serving runtime defines (an inference from the pages read) [g3-card].

### Coding

Google's model card reports instruction-tuned coding scores for this size (see Benchmarks): no agentic coding or terminal benchmark appears. Artificial Analysis's coding-agent index and Scale's SWE-Bench Pro V2 list no Gemma 3 entry. Google presents the 270M as a base for fine-tuning on narrow tasks and does not position it for coding [g3-270m-blog].

### Long context and retrieval

- **Limits.** 32K tokens of input and up to 32K of output per request, the output counted against the same window [g3-card].
- **Quality.** No long-context retrieval score is published for this size; the report's RULER and MRCR table covers the 4B, 12B and 27B only [g3-report].

### Structured output

No JSON mode or schema constraint is documented for the open weights; Google's launch post claims structured-output support [g3-blog]. When the model runs behind a runtime that offers constrained decoding, that is the runtime's feature, not Gemma's.

### Images, audio, other inputs

Text only. This size has no vision encoder; image input starts at the 4B [g3-card] [g3-report]. No audio or video input.

### Sampling and API parameters

Google's pages read give no recommended temperature, top-p or top-k for Gemma 3 [g3-card] [g3-prompt]. The Gemma 4 model card gives one standard setting (temperature 1.0, top-p 0.95, top-k 64); nothing read says the same holds for Gemma 3. For Gemma 4's setting see the [Gemma 4 31B file](gemma-4-31b-it.md).

### Migrating from the previous generation

- **From Gemma 2.** Google's report names the main changes: a 128K window (32K for the 1B; the model card later gives 32K for the 270M too), image input on the 4B, 12B and 27B, a 5-to-1 mix of local and global attention layers with a 1,024-token local window to cut KV-cache memory, QK-norm in place of soft-capping, Gemini 2.0's tokenizer, and a new post-training recipe [g3-report]. Gemma 2 is outside this library's scope.
- **From the larger Gemma 3 sizes.** The window is 32K, input is text only, and the card publishes far fewer benchmarks; quantization-aware-trained checkpoints are available for INT4 use [g3-270m-blog].
- **To Gemma 4.** The [Gemma 4 31B file](gemma-4-31b-it.md#migrating-from-the-previous-generation) lists the generation changes: a system role and a different turn format, thinking, dedicated tool tokens, a 256K window on the larger sizes, new image budgets, video, and Apache 2.0 licensing in place of the Gemma terms.

## What the system card reports

Google's Gemma 3 model card and technical report cover all sizes together; there is no separate system card [g3-card] [g3-report].

- **Evaluation approach.** Structured evaluations and internal red-teaming across child safety, content safety and representational harms, plus arm's-length "assurance" evaluations reported to a release council. Testing ran without safety filters, on English-language prompts only (a stated limitation) [g3-card].
- **Findings.** Google reports minimal policy violations for text and image prompts at all sizes, with clear improvement over earlier Gemma models in the three categories and in ungrounded inferences. The report gives no per-size violation rates [g3-card] [g3-report].
- **Dangerous capabilities.** The report uses a short set of evaluations and, for chemical, biological, radiological and nuclear knowledge, closed multiple-choice sets; it says the knowledge of Gemma 3 models in these areas is low [g3-report].
- **Memorization.** The report says Gemma 3 models memorize significantly less than earlier models [g3-report].
- **Not reported.** Refusal and over-refusal rates, reward hacking, sycophancy, deception, prompt-injection resistance and cyber capability are not covered.
- **Safeguards.** Pre-training data filtering (child-safety and sensitive-data filters), SFT and RLHF against Google's policy areas. ShieldGemma 2 is Google's separate image-safety classifier, announced with Gemma 3 on 2025-03-12 [g3-blog].

## Behaviour observed in practice

- **Index standing (class M).** Artificial Analysis scores the model 5 on its Intelligence Index v4.3.2; the medians of its comparison groups for Gemma 3 sizes are 5 to 6 [aa-gemma-3-270m].
- **Power use (maker test).** Google says an INT4-quantized 270M used 0.75% of a Pixel 9 Pro's battery for 25 conversations in internal tests (class L, maker-run, one device) [g3-270m-blog].
- **Fine-tuning evidence.** Google's post cites fine-tuned Gemma 3 models in production, including a specialised 4B model for multilingual content moderation; it gives no result for a fine-tuned 270M [g3-270m-blog] (class L).
