# Gemini 3.8 Live

Gemini 3.8 Live is the current Gemini Live model of Google, generation 3.8 of the Gemini Live class. It is a speech-to-speech model for the Live API. It takes audio, images and video in, and it speaks its answer over one WebSocket session. It has been generally available on the Gemini API since 2026-09-15. Google calls it the default option for most low-latency voice agents. It replaced Gemini 3.1 Flash Live Preview, which Google now calls a legacy preview [L: gemini-changelog, gemini-spec-3-8-live, gemini-live-capabilities]. On Gemini Enterprise Agent Platform it became generally available on 2026-09-24, and Live Avatar became generally available on Gemini Enterprise on 2026-09-25 [L: gemini-cloud-release-notes, google-cloud-live-avatar-blog]. Google's deprecations page lists no shutdown date for it [L: gemini-deprecations].

Evidence tags: L is Google's own text, M is an independent measurement, A is one practitioner's report. Advice that holds for every Gemini Live model is in the [Live API guide in the Google README](README.md#live-api-guide). This file says what is specific to 3.8 Live. The model that adds configurable background reasoning is [Gemini 3.8 Live Extended Thinking](gemini-3.8-live-extended-thinking.md). The previous generation is [Gemini 3.1 Flash Live Preview](gemini-3.1-flash-live-preview.md).

## How to instruct it

### Setting up the prompt

Google gives one set of advice for all Live models. It advises one system instruction for each agent, with three parts in this order: the persona, the conversational rules and the guardrails. The persona gives the name, the role and the traits. For an accent, Google says to name the output language as well. The rules go in the order the model must follow them. Google says to keep steps that happen once (for example, taking a name) apart from loops (for example, discussing options), and to put each tool call in its own sentence. The guardrails state what the model must not do, with if-then examples. Google says the word "unmistakably" can raise precision when the model is not exact enough [L: gemini-live-best-practices].

The model waits for the user before it speaks. Google says that, to make it speak first, the prompt must tell it to greet the user, and that facts about the user can personalise the greeting [L: gemini-live-best-practices].

Google advises short prompts. It says to avoid prompts of many pages and to chain prompts instead, because the model does best with a single function call for a task [L: gemini-live-best-practices]. The Gemini Enterprise Agent Platform version of the page gives an example: the model gets a function that returns the instruction for the next task [L: gemini-cloud-live-best-practices].

Google's developer guide for 3.8 Live on Gemini Enterprise Agent Platform adds rules it calls mandatory [L: gemini-cloud-live-guide]:

- A tool handler never returns an empty object or null. If a tool fails or finds nothing, the model tries again with other parameters unless told not to. Google says to return a status, a retryable flag and a message that says what to tell the user.
- The system instruction holds a retry limit. Google's example tells the model to inform the user when a tool finds nothing, and never to make more than two tool calls in a row without speaking.
- Each function response carries the exact id of its call.
- The setup omits enable_affective_dialog and proactivity. Google says both are on by default there.
- To load earlier turns with send_client_content, the client waits for the setup_complete frame and sets initial_history_in_client_content to true.

The Gemini API pages differ on two points. They say affective dialogue is removed from the API for 3.8 Live, and that proactive audio is always on, so that setting it to false returns an error [L: gemini-spec-3-8-live].

### Reasoning and effort

This model has no effort control. Google describes interleaved reasoning with a fixed latency profile. thinkingLevel is not supported, and the setup message must omit thinking_config [L: gemini-spec-3-8-live, gemini-live-thinking]. The Gemini Enterprise Agent Platform page lists thinking as not supported for this model [L: gemini-cloud-3-8-live].

Google says to choose this model for conversation that needs fast turns and for tools that answer in milliseconds. It says to choose Extended Thinking when the agent must plan several steps or call tools that run for seconds [L: gemini-live-thinking]. Artificial Analysis measured speech reasoning (Big Bench Audio) at 92 for 3.8 Live and 97.7 for Extended Thinking at high thinking [M: aa-speech-to-speech].

### Output: format, length, tone

Output is audio, 24 kHz. Text comes only from output transcription (output_audio_transcription). Google bills the transcript text at the text output rate on top of the audio [L: gemini-live-capabilities, gemini-live-best-practices].

The model detects the language of the user and follows it. To fix the output language, Google adds a line to the system instruction. Its text is "RESPOND IN {OUTPUT_LANGUAGE}. YOU MUST RESPOND UNMISTAKABLY IN {OUTPUT_LANGUAGE}." On Gemini Enterprise Agent Platform, Google also advises to set language_code in speech_config. Google says that without it the model can change language with the context [L: gemini-live-best-practices, gemini-cloud-live-best-practices].

Google's example persona asks for short replies that disclose more step by step, and for each reply to add something new instead of repeating what the user said [L: gemini-live-best-practices]. The speech-specific settings are in the voice subsection below.

### Tools and agents

Function calls are asynchronous by default (behavior NON_BLOCKING). The audio session keeps running while the tool works. Google says that behavior BLOCKING on a declaration keeps the old behaviour. Scheduling for a response is SILENT, WHEN_IDLE or an interrupt value. The Gemini API pages name the interrupt value both INTERRUPT and INTERRUPTED [L: gemini-spec-3-8-live, gemini-live-tools, gemini-live-capabilities].

The Live API has no automatic handling of tool responses. The client must send each FunctionResponse with the id of the call [L: gemini-live-tools]. When the user interrupts, the server drops pending calls and sends the ids of the cancelled calls [L: gemini-live-capabilities]. On Gemini Enterprise Agent Platform, a pending BLOCKING call is cancelled so that the agent can follow the new request. A tool response with INTERRUPT becomes WHEN_IDLE while the user speaks [L: gemini-cloud-live-guide].

Supported tools are function calling and Google Search grounding. Code execution, URL context, Maps grounding and file search are not supported [L: gemini-spec-3-8-live]. The Live tool-use page read on 2026-10-03 still lists only 3.1 Flash Live and a 2.5 Live model, so it is out of date for this model [L: gemini-live-tools].

Practitioner reports (A) on the async default: an open issue in Google's example repository says that after a user interrupts a BLOCKING call, the server sends no cancellation and the model issues the call again with a new id (opened 2026-10-02) [A: gh-live-examples-59]. A LiveKit issue (opened 2026-09-16) says its plugin cannot set behavior and scheduling for each tool. In the reporter's 15 trials with NON_BLOCKING and WHEN_IDLE, the model made the requested mid-call save in 7 of 15 trials, with a median of 5.1 seconds from the end of the user's sentence to the tool call. With BLOCKING it saved in 3 of 10 trials, in 16.8 seconds [A: gh-livekit-7302].

### Coding

Google publishes no coding guidance for the Live models. The model has no code execution tool [L: gemini-spec-3-8-live].

### Long context and retrieval

The model page gives 131,072 input tokens and 65,536 output tokens. The model card says 128K and 64K. The session context window is 128k tokens [L: gemini-spec-3-8-live, gemini-3-8-audio-card, gemini-live-capabilities]. Audio uses about 25 tokens a second, and Google bills the whole context again on every turn [L: gemini-live-best-practices]. Caching is not supported.

For long sessions, Google advises context window compression. It uses a sliding window and it loses history. Google's examples: a trigger of 100,000 tokens with a window target of 4,000 tokens on Gemini Enterprise Agent Platform, and a trigger of 25,000 with a window of 8,000 in the pricing section of the Gemini API best-practices page [L: gemini-cloud-live-best-practices, gemini-live-best-practices]. To restore a long history, Google advises one summary message instead of many turns [L: gemini-live-capabilities]. Price on the paid plan: audio input $3.00 and audio output $12.00 per million tokens, with text and image or video at other rates. The card holds the full list [L: gemini-pricing].

### Structured output

Structured outputs are not supported on this model [L: gemini-spec-3-8-live].

### Images, audio, other inputs

Audio input is raw 16-bit PCM at 16 kHz. Google's streaming advice gives chunks of 20 to 40 ms and no buffering of about a second. The client-buffering advice on the same page, and Google Cloud's developer guide, give chunks of 20 to 100 ms. Google also says the client must resample microphone audio from 44.1 or 48 kHz to 16 kHz before it is sent [L: gemini-live-best-practices, gemini-cloud-live-guide].

Images and video go in as JPEG frames at most once a second. Turn coverage defaults to audio activity plus all video frames. Google says video frames reach the model by default, so send frames only when needed to control context and cost [L: gemini-spec-3-8-live]. mediaResolution sets the tokens for each frame. Audio tokens do not change with it [L: gemini-live-capabilities]. Google Cloud gives 768 by 768 as the best frame size [L: gemini-cloud-live-guide].

Text goes in with send_realtime_input. Turns with explicit roles go in with send_client_content, which works for the whole session. Setting turn_complete to true always stops the generation in progress [L: gemini-live-capabilities, gemini-spec-3-8-live].

For a browser client, Google recommends ephemeral tokens in place of API keys. A token gives 1 minute to start a session and 30 minutes of messages by default. The client must reconnect about every 10 minutes, and the same token works for that [L: gemini-live-overview, gemini-live-ephemeral].

Gemini Enterprise Agent Platform adds: Live Avatar video output (24 frames a second, MP4, selected with response_modalities VIDEO), custom_vocabulary of up to 1,000 terms in input_audio_transcription, and language_codes for transcription [L: gemini-cloud-live-guide, gemini-cloud-live-best-practices].

### Voice: turn-taking, interruption and speech style

Turn detection. The server detects voice activity by default. Google advises a silence setting (silence_duration_ms) of 500 to 800 ms. It says that 100 to 200 ms splits one utterance into pieces, so the model answers worse, and that 2,000 ms or more adds a long wait. The server default is about 800 ms. The example in Google's guide shows 20 ms of padding and 100 ms of silence, which is outside the advice on the same page. Google says a prefix_padding_ms of 0 can clip the start of words [L: gemini-live-capabilities].

Client-side detection. If automatic detection is off, the client sends activityStart and activityEnd. The server then adds no audio before the speech and waits no extra time. Google advises at least 500 ms of silence in the client's own detector. In hybrid mode, the server finds the start of speech and the client's detector sends audio_stream_end when the user stops. Google warns that a detector that is too eager cuts speech off [L: gemini-live-capabilities].

Sessions. Without compression, an audio-only session ends after 15 minutes and an audio-plus-video session after 2 minutes. With compression and session resumption, a session has no time limit. One connection lasts about 10 minutes, and the server sends GoAway before it closes. The client keeps the latest resumption handle, which stays valid for 2 hours after the session ends [L: gemini-live-session]. On Gemini Enterprise Agent Platform a project has at most 1,000 concurrent sessions on pay-as-you-go [L: gemini-cloud-live-session].

Chunks and silence. Google advises audio chunks of 20 to 40 ms. When the microphone pauses for more than 1 second, the client should send audioStreamEnd to flush cached audio [L: gemini-live-capabilities, gemini-live-best-practices].

Interruption. When the user speaks, the server sends interrupted: true, and Google says the client must drop all queued playback audio at once. Google's troubleshooting page gives three causes when the user cannot interrupt the model: the client does not flush its playback buffer, the client does not stream audio in small chunks, or a custom detector fails to signal the start of speech [L: gemini-live-best-practices, gemini-cloud-live-troubleshooting].

Speaking only when addressed. Proactive audio is always on. The model can decide not to answer speech that is not for it. Google bills input tokens for the whole time the model listens, and output tokens only when it answers [L: gemini-live-best-practices].

Speech style. Google's pages give no setting for pitch, speed or accent. The model chooses the language, and affective dialogue (matching the tone of the user) is on by default on Gemini Enterprise Agent Platform. While a tool runs, the model can speak a short acknowledgement and keep talking. Google's guide gives the example "Let me pull up your account details..." [L: gemini-cloud-live-guide].

Known limits that Google lists for the Live API on Gemini Enterprise Agent Platform, read 2026-10-03 [L: gemini-cloud-live-troubleshooting]:

- The voice can change for one turn.
- The speech rate can grow faster in one long turn, most clearly over 60 seconds. Google advises replies of under 100 words or under 50 seconds of speech, and turn-taking in place of one long reading.
- The model can switch language when it decides that the user speaks another language. Google advises to set language_code and to name the language in the system instruction.
- The model can repeat a spoken digit sequence with wrong or missing digits. Google advises a system instruction that says to read a sequence back one digit at a time and to ask the user to repeat it slowly when digits are unclear.

### Sampling and API parameters

The Live pages read give no temperature, top_p or top_k setting for the Live models. Google says the setup omits thinking_config. Some features need API version v1beta. The model, and most other settings, cannot change after the setup message. On Gemini Enterprise Agent Platform, the system instruction can change during a session [L: gemini-live-capabilities, gemini-cloud-live-session].

The Gemini API WebSocket path in Google's thinking guide uses version v1alpha, with the API key in the query string. Gemini Enterprise Agent Platform uses a regional endpoint with an OAuth bearer token [L: gemini-live-thinking, gemini-cloud-live-session].

### Migrating from the previous generation

From Gemini 3.1 Flash Live Preview, Google lists these changes [L: gemini-spec-3-8-live]:

- The model string becomes gemini-3.8-live.
- thinking_level and thinking_config leave the setup.
- Function calls are asynchronous by default. Behavior BLOCKING on a declaration keeps synchronous calls. Scheduling is supported.
- send_client_content works for the whole session, and turn_complete true always stops generation.
- Proactive audio is always on. Affective dialogue is removed from the Gemini API.
- Turn coverage defaults to audio activity and all video frames.
- Audio is the only response modality. Output transcription gives text.

Google's deprecations page names gemini-3.8-live as the replacement for gemini-3.1-flash-live-preview and for the 2.5 native-audio preview [L: gemini-deprecations, gemini-models-page]. The turn lifecycle and the turnComplete signal stay the same [L: gemini-live-thinking]. Artificial Analysis measured these differences with high thinking on 3.1: speech reasoning 97 for 3.1 against 92 for 3.8 Live, conversational dynamics 74.3 against 96.1, time to first audio 2.99 against 1.18 seconds [M: aa-speech-to-speech].

## What the system card reports

Google publishes one model card for four models: 3.8 Live, 3.8 Live Extended Thinking, 3.8 Flash TTS and 3.8 Flash-Lite TTS. The card was published 2026-09-15 [L: gemini-3-8-audio-card].

- The models are based on Gemini 3 Pro. The card defers to the Gemini 3 Pro card for architecture, training data, processing, hardware, software, policies, risks and acceptable use.
- The live models take audio, images, video and text, with a context window up to 128K tokens. They give audio and text with 64K output tokens. With Live Avatar they give audio, video and text with 24K output tokens.
- The knowledge cutoff is January 2025.
- Known limits: hallucinations, jailbreak resistance that Google is still improving, and occasional slowness or time-outs. A Live Avatar session supports a few minutes of continuous talk, not hours.
- Frontier safety: Google relies on its evaluation of Gemini 3.7 Flash, which reached no Tracked or Critical Capability Level. Google says the 3.8 audio models have no meaningful new capability or material gain over 3.7 Flash.
- Google adds a SynthID watermark to generated audio [L: google-3-8-live-blog].

The evaluation file names three benchmarks: ServiceNow EVA-Bench (full spoken conversations between bots), the Artificial Analysis speech-to-speech evaluation, and Sierra tau3-Banking. ServiceNow ran EVA-Bench on Gemini Enterprise Agent Platform with thinking minimal and high. Artificial Analysis and the tau-Bench runs used the Gemini API with high thinking and default sampling, under the ids gemini-3.8-live-preview and gemini-3.8-live-extended-thinking. The results are charts in image form, not text. The two Artificial Analysis charts repeat the leaderboard values below. The Sierra tau3-Banking chart does not include 3.8 Live. The EVA-Bench chart is a scatter plot with no data labels, so no number is recorded from it [L: gemini-3-8-live-eval]. The card gives no refusal, prompt-injection, sycophancy or reward-hacking results for these models.

## Behaviour observed in practice

- Artificial Analysis scores the model 96.1 on conversational dynamics (pause, turn-taking, interruption and backchannel handling) and 30.1 on tau-Voice agentic performance. Its task success rate is 93.2 [M: aa-speech-to-speech].
- Google says the model took second place in the Speech Agent Arena. The Artificial Analysis leaderboard shows an arena preference of 1083, against 990 for Extended Thinking, which has the stronger reasoning and agentic scores [L: google-3-8-live-blog; M: aa-speech-to-speech].
- An open issue (opened 2026-10-03) says that when a client loses its connection without a close (for example, a phone that moves from Wi-Fi to mobile data), every resume attempt fails with code 1011 for as long as the server keeps the old connection. The server does not ping the silent client [A: gh-live-examples-60].
- The tool-calling reports in the Tools section above are also from practitioners [A: gh-live-examples-59, gh-livekit-7302].
