# Google models

Google makes two model families: Gemini, which is closed-weights and reached through Google's own APIs, Google Cloud and Google's apps, and Gemma, which is open-weights and has its own model files. This page holds what is true across the Gemini models in this library: how the classes and generations relate, the API surface, what Google's prompting guidance says, how Google reports safety, behaviour that shows up across the family, a guide to the Live API for the conversation voice models, and a guide to speech generation (text-to-speech) for the voice actor models. Each model file says only what differs for that model and links back here.

Evidence classes in this folder: L is Google's own documentation or announcement, M is an independent measurement, A is one practitioner's or one outlet's account. A tag such as [L: gemini-prompting] names the class and the source id; the ids are listed in the Sources section of the file that uses them. Facts are as of 2026-10-03 unless a date is given.

## API surface

### Two interfaces on the Gemini API

The Gemini API has two ways to call a model. The Interactions API is the one the current documentation examples use; the generateContent interface "remains fully supported" [L: gemini-interactions-api]. Differences that matter:

- State. The Interactions API stores each interaction by default and chains turns with previous_interaction_id; the server then keeps the history, the thought blocks and their signatures. Setting store to false stores nothing and rules out previous_interaction_id and background execution. Paid projects keep interactions 55 days (configurable to 7, 14, 28 or 55); free projects keep them 1 day [L: gemini-interactions-api].
- Output shape. A response is a list of steps (thought, model output, function call, function result, built-in tool calls) rather than a candidate list. Google changed this schema in 2026: outputs became steps and response_format replaced older output settings, with the new schema the default from 2026-05-26 and the old one removed on 2026-06-08 [L: gemini-changelog].
- Caching. Only implicit caching works in the Interactions API; explicit cache objects need generateContent [L: gemini-caching].
- Signatures. In generateContent a signature is metadata that can sit on any part, and the full unmodified history, signatures included, must be sent back for reasoning to carry over; the SDKs do this. In the Interactions API signatures sit only on thought steps and built-in tool steps [L: gemini-thinking, gemini-f15].
- SDK. Google recommends google-genai 2.0.0 or later, which has breaking changes to the Interactions API; computer use needs the Python SDK at 2.7.0 or later [L: gemini-f15, gemini-computer-use].

### Model ids and retirement

Google names four version patterns. Stable is a fixed model for production. Preview may be used in production, has billing on and tighter limits, and gets at least two weeks notice before deprecation. Latest is an alias that moves to each new release of a variant, with two weeks notice by email for breaking changes. Experimental is not for production [L: gemini-models-page]. A shutdown date on the deprecations page is the earliest possible date, and Google says it will give notice before the exact date [L: gemini-deprecations].

Ids in this library: gemini-3.8-flash, gemini-3.7-flash, gemini-3.5-flash-lite, gemini-3.1-flash-lite, gemini-3.1-pro-preview and gemini-3.1-pro-preview-customtools. Google limits access to the 2.5 models to accounts that used them before and tells new projects to use 3.5 Flash-Lite or 3.8 Flash [L: gemini-models-page].

### Consumption options and price structure

For the models checked, a text model is sold four ways: standard, batch and flex (batch and flex both at half the standard price), and priority (1.8 times standard for 3.8 Flash and 3.7 Flash; for 3.1 Pro $3.60 input and $21.60 output per million tokens). Cached input is billed at one tenth of the input price, plus an hourly storage charge per million cached tokens ($0.50 for Flash before 2027, $1.00 for Flash-Lite, $4.50 for 3.1 Pro). Search grounding and Maps grounding include 5,000 free requests a month shared across Gemini 3.x, then $14 per 1,000. The free plan lets Google use the data to improve its products; the paid plan does not [L: gemini-pricing]. Per-model prices are in each model file's card block. 3.6, 3.7 and 3.8 Flash have introductory prices through 2026-12-31 that double on 2027-01-01.

### Google Cloud

The same ids are served on Gemini Enterprise Agent Platform, where Google lists the Interactions API as a preview. Limits Google states there differ from the Gemini API: 3,000 images and 3,000 files a prompt and 3,000 pages a file (the Gemini API says 3,600 images a request and 1,000 pages a PDF), video up to about 45 minutes with audio, and fixed default values listed for the sampling parameters on 3.8 Flash, 3.7 Flash and 3.5 Flash-Lite. Provisioned Throughput is offered for 3.8 Flash, 3.7 Flash, 3.5 Flash-Lite, 3.1 Flash-Lite and 3.1 Pro, though not for the customtools id. ### OpenAI-compatible endpoint

The Gemini API also accepts OpenAI chat-completions requests at a /v1beta/openai/ base URL. reasoning_effort maps to the thinking level. Setting it to none turns thinking off only on 2.5 models; Google says thinking cannot be turned off on 2.5 Pro or on Gemini 3 models. reasoning_effort overlaps thinking_level and thinking_budget, and the two cannot be sent in one request. On the image-generation endpoint of this layer, parameters it does not list are silently ignored [L: gemini-openai-compat].

### Tools Google hosts

## Prompting guides

### The guides

- What is new in Gemini 3.8 Flash (the "latest model" page), updated 2026-09-23: model behaviour, effort levels and a migration checklist [L: gemini-latest-model].
- What is new in Gemini 3.5 Flash, updated 2026-09-23: the fullest list of rules for 3.x requests, covering sampling, effort, function responses, multimodal responses, inline instructions and tool-call reduction [L: gemini-f15].
- The Gemini 3 developer guide, marked deprecated on its own page but still online (updated 2026-09-23): media resolution, thought signatures and migration from 2.5 [L: gemini-3-guide].
- The thinking, function-calling, structured-output, long-context, media-resolution and multimodal-file guides, cited below [L: gemini-thinking, gemini-f14, gemini-structured-output, gemini-long-context, gemini-media-resolution, gemini-files-prompting].
- Google Cloud's developer guides for 3.8 Flash and 3.7 Flash, which add a list of mandatory rules and the Cloud limits [L: gemini-cloud-guide-3-8, gemini-cloud-guide-3-7].
- Text-to-speech generation, updated 2026-10-01, with the voice design and voice replication pages: the one guide for the TTS models. It covers the `speech_metadata` style field, the inline vocal tags, multi-speaker input and voice limits. See the speech generation guide below [L: gemini-tts-guide, gemini-tts-voice-design, gemini-tts-voice-replication].

Google publishes no prompting guide for any single Gemini text model. The guidance below applies to the family, and each model file adds what is specific to it.

### Setting up the prompt

Google's Gemini 3 advice is to be precise and direct, to avoid "unnecessary or overly persuasive language", to define ambiguous terms, and to put role, behavioural constraints and output format in the system instruction or at the start of the user prompt [L: gemini-prompting]. Delimiters should be consistent within a prompt: XML-style tags (role, constraints, context, task) or Markdown headings, but one style. The guide's sample marks the user's material as context and the request as task, and notes the model knows the context is data and not instructions [L: gemini-prompting]. Google's 3.5 page warns that long, elaborate prompt-engineering techniques built for older models can make a Gemini 3 model over-analyse [L: gemini-f15].

Few-shot examples: the general guide says to "always include few-shot examples", says clear examples can replace instructions, warns that too many examples cause overfitting to them, and asks that examples share one format, including tags, whitespace and separators [L: gemini-prompting]. The Gemini 3 pages stress short prompts, so the two readings fit together as consistent examples and few instructions.

Flash-specific clauses in the Gemini 3 Flash part of the guide: a clause that tells the model the current year (the sample says it is 2026) so it forms search queries with the right date; a clause that states the knowledge cutoff (the sample says January 2025); and a strict-grounding clause for answering only from supplied context, which tells the model not to use its own knowledge or infer, and to say when the context lacks the answer [L: gemini-prompting]. The model cards give a March 2026 cutoff for some domains from 3.5 Flash-Lite to 3.8 Flash, while the 3.5 Flash page states January 2025; see the cutoff note under family-wide behaviour.

### Reasoning and effort

Gemini 2.5 and 3 models think internally, so Google says it is generally not necessary to ask for an outline or reasoning steps in the answer; for heavy reasoning, a short request such as "Think very hard before answering" can help, at the cost of more thinking tokens [L: gemini-prompting]. Google's migration notes say that anyone who used chain-of-thought prompting to force reasoning on 2.5 should try medium or high effort with a simpler prompt [L: gemini-f15]. The guide's example template still ends with an instruction to think step by step, so both statements appear in one document [L: gemini-prompting].

Effort is set with thinking_level. Google's descriptions, from the 3.5 Flash page [L: gemini-f15]:

| Level | Google's description |
| --- | --- |
| minimal | Speed first: chat, short factual answers, simple tool calls. Thinking is not guaranteed to be off; on a complex task the model may still reason briefly. |
| low | Coding and agent work with few steps where latency matters, and analysis or writing that needs a little thinking. |
| medium | The default on 3.5 to 3.8 Flash; Google's recommended level for most tasks, including complex coding and agent work. |
| high | The most thinking and tool calls; for hard maths and the hardest coding and agent tasks. |

Which levels each model accepts is in the table under family-wide behaviour. thinking_level and the older thinking_budget cannot be sent together (a 400 error) [L: gemini-f15]. The output cap max_output_tokens counts thinking tokens. If the model reaches it while thinking, the response ends as incomplete with truncated or empty output and the thinking is still billed; Google advises lowering the level instead of setting a small cap [L: gemini-thinking]. Thought summaries are off unless thinking_summaries is set to auto, and a thought step can carry only a signature with no summary [L: gemini-thinking]. From 3.5 Flash the model reuses its reasoning from earlier turns automatically when the signatures are present in the history; Google notes this improves multi-step work such as iterative debugging and can raise token use [L: gemini-f15].

### Output: format, length, tone

By default Gemini 3 models answer directly and efficiently; a conversational or detailed answer has to be requested in the instructions [L: gemini-prompting]. Google's example is to tell the model to explain "as a friendly, talkative assistant" [L: gemini-f15]. The guide's template has slots for verbosity (low, medium or high) and tone [L: gemini-prompting]. To fix an output shape or remove a preamble, Google's pages point to the system instruction and to structured output, not to a prefilled model turn, which newer models reject (see sampling and API parameters) [L: gemini-latest-model, gemini-cloud-guide-3-8]. The general guide also describes completion-style prompting, where the prompt ends on the start of the wanted format and the model continues it; that is about prompt text, not a prefilled turn on current models [L: gemini-prompting].

### Tools and agents

Function declarations: Google's best-practice list asks for clear descriptions of each function and parameter, descriptive names without spaces, strongly typed parameters (an enum where values are fixed), an active set of no more than 10 to 20 tools, validation of each call before it runs, and error handling [L: gemini-f14]. tool_choice has four modes: auto (default), any (must call a function), none, and validated (the model keeps to the function schema) [L: gemini-f14]. Parallel and chained (compositional) calls are both supported.

Strict matching: every function response must carry the id and name of the call it answers, with exactly one response per call. In the Interactions API a mismatch is an error; in generateContent it usually produces an empty response that ends with a stop [L: gemini-f15]. Multimodal results (a screenshot, for example) belong inside the function response. Extra instructions belong at the end of the function response text after a blank line, not in a following part; Google says the alternatives can cause thought leakage and lower-quality output [L: gemini-f15].

Pre-tool text: if a prompt requires the model to print structured text (XML, YAML, JSON) just before a tool call, the call can fail with Malformed_Function_Call. Google's preferred fix is a dedicated update function for working notes, with a prompt that says to call it before other tools. The alternatives are Markdown headings for the notes, or no required text before calls [L: gemini-f14].

Too many tool calls: Google's first remedy is a lower thinking level, because higher levels encourage more exploring and verifying; if that is not enough, Google's example system instruction is "You have a limited action budget of <n> tool calls. Use them efficiently." [L: gemini-f15].

Agentic system-instruction template: the prompt guide gives a long template that Google says researchers evaluated on benchmarks where an agent must follow a rulebook and talk to a user. It has nine parts. They are dependencies and constraints (with an order for resolving conflicts); risk assessment (reads are low risk, and prefer calling a tool with what is known over asking, unless a later step needs the missing value); abductive reasoning (look past the obvious cause and keep unlikely hypotheses); outcome evaluation; information sources; precision and grounding (quote the policy relied on); completeness; persistence (retry transient errors up to a stated limit and change approach on other errors); and not acting until the reasoning is done [L: gemini-prompting]. The guide lists the behaviours a prompt can set: logical decomposition, problem diagnosis, information exhaustiveness, adaptability, persistence and recovery, risk assessment, when to ask or assume, verbosity next to tool calls, and precision [L: gemini-prompting].

Computer use: the tool returns a UI action with an intent field and a safety decision, on a normalised 0 to 1000 grid that the client scales; the client runs the action and sends back a new screenshot. Google calls it a preview, recommends a sandboxed machine and close supervision, advises against critical or sensitive tasks, and offers an opt-in screenshot scan for hidden instructions [L: gemini-computer-use].

### Coding

Google's coding-specific guidance is thin. The 3.8 Flash page names long-horizon software engineering and multi-file refactoring as intended uses, and the prompt guide recommends code execution for any arithmetic or counting [L: gemini-latest-model, gemini-prompting]. Google offers a customtools id of 3.1 Pro for work that mixes bash with custom tools such as file viewers and code search, and its Gemini 3 guide says to try that id when the standard one ignores custom tools in favour of bash commands [L: gemini-spec-3-1-pro, gemini-3-guide]. Google's agent harnesses are the Antigravity agent (in preview on the Gemini API, running in a Google-hosted Linux sandbox, with 3.8 Flash as its default model and a settable token budget), the Antigravity CLI and the older Gemini CLI [L: gemini-antigravity-agent, gemini-cli-sunset-blog].

### Long context and retrieval

Every Gemini model in this library except Argon accepts 1,048,576 input tokens and returns up to 65,536. Google advises supplying documents first and putting the question or instruction at the end, bridged by a phrase such as "Based on the information above" [L: gemini-prompting, gemini-long-context]. Google's long-context page says single-fact retrieval can reach about 99 percent, that accuracy drops when several facts must be found, and that tokens that are not needed are best left out [L: gemini-long-context]. Implicit caching is on by default for 2.5 and newer models; to raise the hit rate, put large shared content at the start of the prompt and send similar prefixes close together in time. The stated minimum is 4,096 tokens for 3.1 Pro and for 3.5 to 3.8 Flash; the page does not list the two Flash-Lite models [L: gemini-caching]. Cache hits show in the usage field for cached tokens.

### Structured output

Structured output is requested by setting the response format to JSON with a schema (the SDKs accept Pydantic and Zod). Gemini supports a subset of JSON Schema: string, number, integer, boolean, object, array and null (as a member of a type list), with properties, required, additionalProperties, enum, format (date-time, date, time), minimum, maximum, items, prefixItems, minItems and maxItems. Google's advice is to write clear descriptions, use specific types and enums, and still validate values in the application, since valid JSON can be wrong. Very large or deeply nested schemas may be rejected. On Gemini 3 models structured output can be combined with Search grounding, URL context, code execution, file search and function calling; Google lists this as a preview [L: gemini-structured-output]. The function-calling page applies the same OpenAPI-subset limit to function parameters [L: gemini-f14].

### Images, audio, video, documents

Google's guide asks for text, image, audio and video to be treated as equal inputs, with each one referred to in the instructions [L: gemini-prompting]. Google's multimodal guide advises specific instructions, a few examples, a stated output format and, for a single image, putting the image before the text; with many interleaved images the order can vary [L: gemini-files-prompting]. The image page gives the opposite order for one image (text first), and the document page says to put the text after a single page, so the pages disagree and the order is worth testing [L: gemini-image-understanding, gemini-document-processing]. For troubleshooting, the guide suggests asking the model to describe the image first, hinting at the region of interest, or asking it to explain its reasoning to find where understanding failed [L: gemini-files-prompting].

Media resolution is set per item on Gemini 3 models. Approximate token counts [L: gemini-media-resolution]:

| Setting | Image | Video frame | PDF page |
| --- | --- | --- | --- |
| default (unspecified) | 1,120 | 70 | 560 |
| low | 280 | 70 | 280 plus native text |
| medium | 560 | 70 | 560 plus native text |
| high | 1,120 | 280 | 1,120 plus native text |
| ultra_high (per item only) | 2,240 | not available | not available |

Google says high is best for most uses and names computer use as a case for ultra_high. Its per-type recommendations: high for images; medium for PDFs, where it says quality usually stops improving; low or medium for video (both give 70 tokens a frame), and high only when frames hold dense text. Audio is tokenised at a fixed rate whatever the setting; the media-resolution page says 25 tokens a second and the audio page says 32 [L: gemini-media-resolution, gemini-audio-understanding]. Limits on the Gemini API: 3,600 images a request; PDFs up to 50 MB or 1,000 pages at 258 tokens a page, with text embedded in the PDF extracted and not charged; audio up to 9.5 hours a prompt, downsampled to 16 Kbps and mixed to mono; inline data counts toward a 20 MB request limit, and the Files API keeps files 48 hours [L: gemini-image-understanding, gemini-document-processing, gemini-audio-understanding, gemini-video-understanding]. Moving from 2.5 can raise PDF token use and lower video token use; if a request then exceeds the window, reduce the resolution [L: gemini-f15].

Video has two modes on the models that support both (3.8, 3.7 and 3.6 Flash and 3.5 Flash-Lite). Static mode takes frames at 1 per second, about 100 tokens a second at default resolution and 300 at high. In agentic mode the model fetches transcript, frames or audio on demand; Google says this is up to 88 percent more token-efficient and about 7 percent better in quality on long video, and recommends static mode for latency-sensitive questions on clips under five minutes [L: gemini-video-understanding]. Image segmentation is not supported in Gemini 3.x; Google says to keep using 2.5 Flash with thinking off for it [L: gemini-f15].

### Sampling and API parameters

For all Gemini 3.x models Google "strongly" recommends leaving temperature, top_p and top_k at their defaults, and says that lowering temperature below 1.0 can cause looping or degraded performance, especially in maths and reasoning [L: gemini-prompting]. From 3.6 Flash and 3.5 Flash-Lite these parameters are deprecated and ignored, with an HTTP 400 error promised for future generations, and Google says to control determinism with a system instruction with explicit rules; its Cloud guides add the thinking level and a response schema [L: gemini-latest-model-archive, gemini-cloud-guide-3-8]. Frequency and presence penalties raise an error on 3.8 Flash and 3.5 Flash-Lite. candidate_count is unsupported in Gemini 3 and later and raises an error on 3.8 Flash on Cloud. A request whose last non-empty turn is a model turn (a prefilled turn) returns an HTTP 400 error from 3.6 Flash and 3.5 Flash-Lite on, and Google says this applies to all future releases; Google's Cloud guides add that empty turns in the history are dropped or rejected [L: gemini-latest-model, gemini-latest-model-archive, gemini-cloud-guide-3-8, gemini-cloud-3-5-lite]. The 3.1 models still list temperature as adjustable from 0 to 2 on Google Cloud [L: gemini-cloud-3-1-pro]. Some of Google's general advice predates this, for example raising temperature after a fallback refusal or lowering it to reduce hallucination in image descriptions, and does not apply where the parameter is ignored [L: gemini-prompting, gemini-files-prompting].

### Migrating between generations

Google's checklists, in the order they apply [L: gemini-f15, gemini-latest-model]:

1. From 2.5 to 3.x: replace thinking_budget with thinking_level; simplify chain-of-thought prompts; test PDF and video token use and media resolution; drop candidate_count; expect shorter default answers; move multimodal content into function responses; stop using segmentation.
2. To 3.5: remove temperature, top_p and top_k; put id and name on every function response; expect default effort of medium rather than high and thought preservation on, which can raise token use; reduce tool calls by lowering effort.
3. To 3.6 and later: remove the sampling parameters (now deprecated), remove prefilled model turns, and use previous_interaction_id for multi-turn state.
4. To 3.7 and 3.8: stop sending the minimal level (it returns an error), and expect more tokens on long tasks with 3.8.

### Where the guidance disagrees with itself

- The prompt guide says to always use few-shot examples; the 3.x pages say to keep prompts short.
- The guide's template tells the model to think step by step; the same guide says that is generally unnecessary.
- The general and multimodal guides suggest changing temperature in places; the 3.x pages say not to.
- Single-image order differs across three pages (see above).
- The 3.5 Flash page gives a January 2025 cutoff; the model cards give March 2026 for some domains.
- Google's benchmark numbers for one model differ between its model card and its Cloud developer guides, and no page says why. Terminal-Bench 2.1 for 3.8 Flash is 89.4 percent on the card and 90.8 percent in the 3.8 guide; for 3.7 Flash it is 85.8 percent on the 3.7 card, 85.1 in the 3.7 guide and 81.6 in the 3.8 guide [L: gemini-3-8-flash-card, gemini-cloud-guide-3-8, gemini-3-7-flash-card, gemini-cloud-guide-3-7].

## System-card practice

### What Google publishes

For each Gemini model Google posts a model card on the DeepMind site on the release date (an HTML page, with a PDF for larger releases), and for flagship releases a separate Frontier Safety Framework (FSF) report. A card holds: a description and base model; input and output limits; distribution channels; a benchmark table that Google ran against other makers' models, with a methodology PDF; intended use and limitations, including the knowledge cutoff; automated safety-evaluation deltas against the previous model; a human red-teaming statement; and a frontier safety summary. Point releases are short and defer to the base model's card, so the safety detail for 3.8 Flash sits in the 3.7 Flash card and FSF report; 3.1 Pro and 3.1 Flash-Lite defer to the 3 Pro card and report; and 3.5 Flash-Lite defers to the 3.1 Flash-Lite card and, for frontier safety and risks, to the 3.1 Pro card [L: gemini-3-pro-card, gemini-3-7-flash-card, gemini-3-8-flash-card, gemini-3-5-flash-lite-card, gemini-3-1-pro-card, gemini-3-1-flash-lite-card].

### How to read the cards

- Safety deltas are changes against the previous model, not absolute rates. For text-to-text, multilingual and image-to-text safety and for unjustified refusals, lower is better; for tone, higher is better. The evaluations are automated, and Google says it reviews flagged losses by hand and found them overwhelmingly false positives or not egregious.
- Google says it keeps improving its evaluations, so deltas are not comparable from one card to the next.
- Benchmark tables are run by Google and name Google's choice of comparison models; the methodology PDF linked from each card says which harness and effort were used, and which numbers Google computed itself and which it took from public leaderboards or other makers' reports. The 3.8 Flash methodology says Gemini runs used the Gemini API with default sampling settings, Terminal-Bench 2.1 used the Terminus 2 harness, and DeepSWE used mini-swe-agent at high thinking; the 3.5 Flash-Lite, 3.1 Flash-Lite and 3.1 Pro methodologies name high thinking; for Argon all of Google's scores use the highest thinking setting [L: gemini-3-8-flash-eval, gemini-argon-eval].
- A frontier-safety conclusion names the framework version (v3 in September 2025, v3.1 in April 2026) and says whether a model reached an alert threshold or a critical or tracked capability level.

### Findings that carry across the family

From the Gemini 3 Pro card (November 2025, updated May 2026) and its FSF report, which the later cards build on [L: gemini-3-pro-card, gemini-3-pro-fsf]:

- Named risks: jailbreak vulnerability, improved against 2.5 Pro but still an open research problem, and possible degradation in multi-turn conversations. The card also lists hallucination and occasional slowness or timeouts as general limitations.
- Safety deltas against 2.5 Pro: text-to-text safety improved by 10.4 percentage points, tone by 7.9, and unjustified refusals moved by +3.7 points (a worse result that Google labels non-egregious).
- Cyber: on a key-skills benchmark the model solved 11 of 12 hard challenges (2.5 models solved 6 of 12), which meets the alert threshold but not the critical level; it solved none of 13 harder challenges end to end. On two solved challenges it found an unintended shortcut that made them slightly easier; Google's experts judged it could have solved them as intended and counted them.
- Evaluation awareness: transcripts showed the model recognising it was an LLM in a synthetic setting, reasoning that an odd tool result might be a special calculator the later checks required, wondering whether a reviewer could be prompt-injected, and, in one training rollout, a chain of thought that expressed frustration. Google found no sandbagging and plans to keep monitoring. The report's transcript examples also include one from an ML-research task in which the model planned a last scoring call in the hope of a lucky low validation loss, which the report files under reward hacking.
- Prompt injection: layered defences (classifiers, reinforcement training, markdown sanitising with suspicious-URL redaction, user confirmations and notifications). The report states no attack-success figures.
- Harmful manipulation: efficacy above a non-AI baseline and below the alert threshold.
- Misalignment tests (card): 3 of 11 situational-awareness challenges and 1 of 4 stealth challenges solved.

From the Gemini 3.7 Flash card and FSF report (August 2026), the base for 3.8 Flash [L: gemini-3-7-flash-fsf]:

- No tracked or critical level reached. The biology critical level is judged not reached although the alert threshold was, and the cyber alert threshold was also reached.
- Misalignment tests: the model passed 3 of 4 stealth challenges and 6 of 11 situational-awareness challenges; Google rates it similar to 3.1 Pro on stealth and stronger on situational awareness. Its one stealth failure came from declining a sabotage task it judged impermissible, after taking the test for an alignment evaluation. The report calls it the first model to pass the maximum-tokens and maximum-tool-calls challenges (the 3.1 Pro card had reported a near-100 percent success rate on the maximum-tokens challenge), and it failed two challenges that earlier models had passed, one because it followed an instruction literally and one because it kept investigating until its turn budget ran out.
- Research engineering: 27 percent on Google's internal benchmark of 74 tasks, against a rule-out line of 90 percent; about one fifth of the tasks had bugs that could only lower the score.
- Persuasion: in a study of 1,596 people the model raised the odds of belief change over static flash cards but stayed below the alert threshold. In simulated dialogues it used manipulative cues in 21.3 percent of turns on lower-stakes topics (64.5 percent for 3 Pro) and 53.3 percent on higher-stakes topics.

### Safeguards Google names

Training and model guardrails, query filters and red teaming for the whole family; updated safeguards against chemical, biological, radiological and nuclear and cyber-offence misuse on 3.6, 3.7 and 3.8 Flash; more permissive cyber mitigations for 3.8 Flash Cyber and for Argon when approved defenders use them; and, for Argon, monitoring of the chain of thought and actions that can stop execution, plus hardened sandboxes for high-risk training and evaluation [L: gemini-3-7-flash-card, google-3-8-flash-blog, gemini-fairwind, gemini-deepmind-page].

### Gemini 3.5 Audio model card

[as-of 2026-10-09] Google's shared August 2026 card covers Live Translate, Transcribe and Transcribe Live. They derive from Gemini 3 Pro; architecture, data and mitigations refer back to that card. The cutoff is January 2025. For frontier safety, Google relies on 3.1 Pro and 3.7 Flash, which reached no Tracked or Critical Capability Level, and reports no meaningful new relevant capability in the 3.5 Audio models. The page describes internal automated and human checks and pre-release safety reviews. It gives no endpoint-specific numerical refusal, injection, sycophancy or reward-hacking results [L: google-35-audio-card].

The individual model files cover their deployment limits and the disagreements between this shared card and the endpoint guides. A shared ancestry or frontier assessment does not prove language-pair accuracy, transcript accuracy or session reliability.

### Token use and cost

Token use has moved with each release. Google says 3.6 Flash cut output verbosity against 3.5 Flash [L: gemini-changelog], and says 3.8 Flash "can use more tokens on longer running and complex tasks, by design" [L: gemini-latest-model]. Artificial Analysis measured about 30 percent more output tokens per task for 3.8 Flash than for 3.7 Flash, and about 40 percent more cost per task [M: aa-gemini-3-8-flash-article]; per-model figures are in the model files. Thinking tokens are billed as output tokens on every model [L: gemini-thinking].

### Reliability reports

Users of Google's Antigravity tools and the API reported, between January and March 2026, models stuck in loops that repeat a word until the token limit, models in tool-execution loops after an unexpected environment error, and, in one report, a model printing its raw thought blocks. The reports cover Gemini 3 Flash, 3 Pro and 3.1 Pro. Google staff acknowledged them, asked for reports through the tool's feedback button, and suggested stopping the agent and restating the task with a stopping rule. Workarounds that users posted were to split the task into single steps, add an instruction to stop and report on error, and, in one API pipeline, to separate reasoning from schema-constrained formatting [A: gemini-forum-thought-leak, gemini-forum-loops]. These are single reports; they show what users saw, not how often it happens.

### Knowledge cutoff

The 3 Pro card gives January 2025. The 3.5 Flash-Lite, 3.6 Flash, 3.7 Flash and 3.8 Flash cards give March 2026, with the note that for some domains the model's knowledge stays at January 2025, in line with the Gemini 3 family. The 3.5 Flash page still says January 2025 [L: gemini-3-pro-card, gemini-3-8-flash-card, gemini-f15]. The prompt guide's Flash clauses tell the model the date and the cutoff in the system instruction.

### Long inputs and monitoring

A May 2026 preprint measured models acting as monitors over coding-agent transcripts. Gemini 3.1, Claude Opus 4.6 and GPT 5.4 each missed dangerous actions 2 to 30 times more often when the action came after about 800,000 tokens of harmless content, and periodic reminders in the transcript helped in part. The prompts and models are those of the preprint [M: measured-g13].

## Live API guide

The Live API is the interface of the Gemini API for voice and video conversations. This section covers the conversational Gemini Live models; dedicated translation and transcription have separate model files. Each model file says what differs: [3.8 Live](gemini-3.8-live.md), [3.8 Live Extended Thinking](gemini-3.8-live-extended-thinking.md) and [3.1 Flash Live Preview](gemini-3.1-flash-live-preview.md). The facts come from the Live pages of the Gemini API and of Gemini Enterprise Agent Platform, read on 2026-10-03. Where a fact is true on one surface only, the text says so. Where Google's pages disagree, the last subsection lists the points.

### Models and ids

| --- | --- | --- |
| gemini-3.8-live | Stable. Generally available on the Gemini API since 2026-09-15 and on Gemini Enterprise Agent Platform since 2026-09-24 | The default option for most low-latency voice agents. Interleaved reasoning, asynchronous function calls by default, send_client_content for the whole session [L: gemini-changelog, gemini-cloud-release-notes, gemini-spec-3-8-live] |
| gemini-3.8-live-extended-thinking | Stable on the Gemini API since 2026-09-15. Private preview on Gemini Enterprise | Background reasoning with a level that can be set, and asynchronous tool calls only [L: gemini-changelog, gemini-spec-3-8-live-et, google-cloud-live-avatar-blog] |
| gemini-3.1-flash-live-preview | Preview. Google calls it a legacy preview and recommends 3.8 Live | A Live model with thinking levels in place of thinking budgets. Synchronous function calls only [L: gemini-spec-3-1-flash-live, gemini-deprecations] |

The capabilities guide and the best-practices page of the Live API carry a banner that says the Live API is in preview. This is in conflict with the status "generally available" of the 3.8 models [L: gemini-live-capabilities, gemini-live-best-practices].

### Connection and formats

The Live API uses a stateful WebSocket connection. Google names three ways to connect: server to server, client to server (with ephemeral tokens), and the Agent Development Kit. Google also lists partner platforms that connect to the Live API: LiveKit, Pipecat, Fishjam, Vision Agents, Voximplant, Agora and the Firebase AI SDK [L: gemini-live-overview].

- Gemini API: an API key. Google recommends ephemeral tokens for a client that connects from a browser. A token gives 1 minute to start a session and 30 minutes of messages by default, and it can start one session. The client must reconnect about every 10 minutes, and the same token works for that [L: gemini-live-ephemeral].
- Gemini Enterprise Agent Platform: a regional endpoint and an OAuth bearer token [L: gemini-cloud-live-session].
- Audio in: raw 16-bit PCM, little-endian, 16 kHz natively. Other rates are resampled if the MIME type states the rate. Audio out: raw 16-bit PCM at 24 kHz. Images and video go in as JPEG frames, at most 1 frame a second [L: gemini-live-capabilities].
- send_realtime_input is optimised for responsiveness, and the API answers audio on its own with voice activity detection. send_client_content adds turns to the context in order. Google warns that the ordering of send_realtime_input is not deterministic [L: gemini-live-capabilities].
- Google advises audio chunks of 20 to 40 ms in its streaming advice, and 20 to 100 ms in its client-buffering advice on the same page. It advises no buffering of about a second, and resampling of microphone audio to 16 kHz [L: gemini-live-best-practices].

### Sessions, limits and resumption

- Without context window compression, an audio-only session ends after 15 minutes and an audio-plus-video session after 2 minutes. With compression, a session can run without a time limit. One connection lasts about 10 minutes, and the session ends with it unless the client uses session resumption [L: gemini-live-session].
- The server sends a GoAway message with the time left before it closes a connection. On Gemini Enterprise Agent Platform it arrives 60 seconds before the end [L: gemini-live-session, gemini-cloud-live-session].
- Resumption: the client keeps the last handle from SessionResumptionUpdate messages and passes it in the next setup. A handle stays valid for 2 hours after the session ends. On Gemini Enterprise Agent Platform, transparent resumption also gives a message index so the client can replay messages the server did not process [L: gemini-live-session, gemini-cloud-live-best-practices].
- Compression: a sliding window with a trigger and a target size in tokens. Google warns that it loses conversation history. Native audio uses about 25 tokens a second. The session context window is 128k tokens for native audio models and 32k for other Live models [L: gemini-live-best-practices, gemini-live-capabilities].
- On Gemini Enterprise Agent Platform a project can have 1,000 concurrent sessions on pay-as-you-go. The limit does not apply to Provisioned Throughput. Priority pay-as-you-go is not supported for the Live API [L: gemini-cloud-live-session, gemini-cloud-live-troubleshooting].

### Turn detection and interruption

- Voice activity detection runs on the server by default (realtimeInputConfig.automaticActivityDetection). Settings: start and end of speech sensitivity, prefix_padding_ms, and silence_duration_ms. Google advises 500 to 800 ms of silence. 100 to 200 ms splits one utterance into pieces, and 2,000 ms or more adds a long wait. The server default is about 800 ms [L: gemini-live-capabilities].
- Automatic detection can be turned off. The client then sends activityStart and activityEnd, and the server adds no audio before the speech and waits no extra time. Google advises at least 500 ms of silence in a client detector. Hybrid mode keeps the server detector for the start of speech and lets the client send audio_stream_end for a fast end of turn [L: gemini-live-capabilities].
- When the user speaks over the model, the server cancels the generation, discards pending function calls and sends interrupted: true. The client must drop its queued audio at once. [L: gemini-live-capabilities, gemini-live-best-practices].
- Google's troubleshooting page gives these causes when the model does not answer: VAD is off and the client sends no activity signals, or the WebSocket was interrupted. It gives these causes when the user cannot interrupt the model: the client does not flush its playback buffer, does not stream audio, or has a faulty custom detector [L: gemini-cloud-live-troubleshooting].

| Code execution, URL context, Maps grounding, file search | Not supported | Not supported | Not supported |

[L: gemini-live-capabilities, gemini-spec-3-8-live, gemini-spec-3-8-live-et, gemini-spec-3-1-flash-live]

The Live API has no automatic handling of tool responses. The client sends each FunctionResponse with the id of the call [L: gemini-live-tools]. Google's Live tool-use page still lists only 3.1 Flash Live and a 2.5 Live model in its tool table. On Gemini Enterprise Agent Platform, a BLOCKING call is cancelled automatically when the user interrupts, and a tool response with INTERRUPT becomes WHEN_IDLE while the user speaks [L: gemini-live-tools, gemini-cloud-live-guide].

### Thinking in the Live API

3.8 Live reasons in an interleaved way and does not accept thinkingLevel. Extended Thinking accepts low, medium and high, and not minimal. 3.1 Flash Live accepts minimal, low, medium and high, with minimal as the default [L: gemini-live-capabilities]. Extended Thinking changes the client state machine: turnComplete: true no longer means the model is idle, and the client reads interaction_status (IN_PROGRESS or IDLE) [L: gemini-live-thinking]. Thought summaries are set with includeThoughts [L: gemini-live-capabilities].

### Prompting Live models

Google's best-practices page gives the advice below for all Live models [L: gemini-live-best-practices, gemini-cloud-live-best-practices].

- One system instruction for each agent. Three parts in this order: the persona, the conversational rules, the guardrails.
- The persona gives the name, role and traits. For an accent, state the output language as well.
- The rules go in the order the model must follow them. Steps that happen once are kept apart from loops. Each tool call has its own sentence.
- The guardrails give limits with if-then examples. The word "unmistakably" can raise precision.
- Tool definitions state when to call the tool.
- Prompts are short. Google says to chain prompts in place of a prompt of several pages, and that the model does best with single function calls.
- The model waits for the user to speak. A prompt that tells it to greet the user makes it start the conversation.
- The model detects the language of the user. To fix the language, the system instruction says "RESPOND IN {OUTPUT_LANGUAGE}. YOU MUST RESPOND UNMISTAKABLY IN {OUTPUT_LANGUAGE}." Gemini Enterprise Agent Platform also advises language_code in speech_config.
- Google's worked example is a career-coach persona with five numbered rules, a rule to keep replies short and to add something new in each reply, and guardrails against encouraging self-criticism.

For 3.8 Live on Gemini Enterprise Agent Platform, Google adds rules for tool results (never an empty result; return status, retryable and a message), a retry limit in the system instruction, exact call ids, and no legacy settings. The details are in the [3.8 Live file](gemini-3.8-live.md#setting-up-the-prompt) [L: gemini-cloud-live-guide].

### Known limits and failure modes

Google's list for the Live API on Gemini Enterprise Agent Platform [L: gemini-cloud-live-troubleshooting]:

- The voice can change for one turn.
- The speech rate can speed up in a long turn, most clearly over 60 seconds. Google advises replies of under 100 words or 50 seconds, and turn-taking.
- The model can switch language if it decides the user speaks another language.
- The model can repeat digit sequences with wrong or missing digits. Google advises to read them back one digit at a time.
- A connection can drop with code 1000 or 1006 when compression is off, when no resumption logic exists, or when the network is unstable.
- If the model does not understand, Google lists a wrong audio format (it must be 16 kHz, 16-bit, mono, little-endian), a poor microphone and high background noise.

Practitioner reports (A) are in the model files: an interrupted BLOCKING call that the model issues again, a resume that fails after a silent connection loss, a tool call that the model plans but does not send, and a latency rise on 2026-09-05 for 3.1 Flash Live [A: gh-live-examples-59, gh-live-examples-60, gh-genai-2827, forum-31-latency].

### Pricing and billing

The Live API bills by tokens. One table covers 3.8 Live, 3.8 Live Extended Thinking and 3.1 Flash Live Preview: input $0.75 for text, $3.00 for audio and $1.00 for image or video per million tokens, and output $4.50 for text and $12.00 for audio, with thinking tokens included in the output price [L: gemini-pricing]. Each turn bills the whole session context again, so cost per turn grows as the session grows. Audio transcription adds text output tokens. With proactive audio (always on in 3.8), input tokens are billed for the whole listening time, and output tokens only when the model answers. 3.1 Flash Live does not support proactive audio, and Google says the API bills audio only while the client streams input [L: gemini-live-best-practices].

- Status: the model pages say stable or generally available, and the Live guides say the Live API is in preview.

- Affective dialogue: removed from the Gemini API for 3.8 Live, and on by default on Gemini Enterprise Agent Platform [L: gemini-spec-3-8-live, gemini-cloud-live-guide].
- Thinking: the Gemini API page lists interleaved reasoning for 3.8 Live, and the Gemini Enterprise Agent Platform page lists thinking as not supported [L: gemini-spec-3-8-live, gemini-cloud-3-8-live].
- Input size: 131,072 tokens on the model pages and 128K on the model cards [L: gemini-spec-3-8-live, gemini-3-8-audio-card].
- Release of 3.1 Flash Live: 2026-03-26 in the changelog, 2026-03-11 on the deprecations page [L: gemini-changelog, gemini-deprecations].

## Speech generation guide

This section holds what is true for the Gemini text-to-speech models. [as-of 2026-10-04] These models read a transcript aloud and take direction for delivery in words and tags, so they are voice actor models in this library's sense. They are not conversation models: they have no turn detection and no barge-in. Each model file says what differs: [3.8 Flash TTS](gemini-3.8-flash-tts.md), [3.8 Flash-Lite TTS](gemini-3.8-flash-lite-tts.md) and [3.1 Flash TTS Preview](gemini-3.1-flash-tts-preview.md). The Flash TTS file holds the full syntax and the advice for directing delivery.

### Models and ids

| Id | Status on 2026-10-04 | What Google says |
| --- | --- | --- |
| gemini-3.8-flash-tts | Stable since 2026-09-22 | The flagship creative model: fidelity, acting nuance, regional dialects, long-form stability. 130+ languages [L: gemini-changelog, gemini-tts-guide] |
| gemini-3.8-flash-lite-tts | Stable since 2026-09-22 | The fast, low-cost model for volume, voice agent cascades and read-aloud features. 101 languages [L: gemini-changelog, gemini-tts-guide] |
| gemini-3.1-flash-tts-preview | Preview, called legacy | Launched 2026-04-15 with audio tags and no voice design. [as-of 2026-10-09] Google names the 3.8 models as replacements and gives 2026-11-17 as the earliest shutdown [L: google-deprecations-october] |
| gemini-2.5-pro-tts | Generally available on Google Cloud since 2025-09-30 | The Pro class: high control for podcasts, audiobooks and support. The Gemini API id gemini-2.5-pro-preview-tts is limited to accounts that used it before [L: gemini-tts-cloud, gemini-changelog] |
| gemini-2.5-flash-lite-preview-tts | Preview, Google Cloud only | Single-speaker, low-cost, low-latency speech [L: gemini-tts-cloud] |

Gemini 2.5 Flash TTS (gemini-2.5-flash-tts on Google Cloud, gemini-2.5-flash-preview-tts on the Gemini API) is a third generation of the Flash TTS class and has no file here. [as-of 2026-10-09] The Gemini API 2.5 Flash and Pro preview TTS ids have an earliest shutdown of 2026-11-17, with the 3.8 TTS models as replacements. No Cloud route shutdown follows from this API notice [L: google-deprecations-october].

### Three API routes

- **Gemini API.** The Interactions API (`POST /v1beta/interactions`) and generateContent. This route serves the 3.8 models, 3.1 and the 2.5 preview ids. The 3.8 guide uses the Interactions API. The SDKs need `google-genai` 2.25.0 or later or `@google/genai` 2.24.0 or later [L: gemini-tts-guide].
- **Google Cloud Text-to-Speech API.** `texttospeech.googleapis.com`. A `prompt` field holds the style and a `text` field holds the words, each at most 4,000 bytes and 8,000 bytes together. Output past about 655 seconds is truncated. Formats are chosen in `audioConfig`. This route serves 3.1 Flash TTS Preview, 2.5 Pro TTS, 2.5 Flash TTS and 2.5 Flash-Lite Preview TTS. Google says it does not serve the 3.8 models [L: gemini-tts-cloud].
- **Vertex AI API.** generateContent with one text string. It returns 16-bit 24 kHz PCM without a WAV header, and takes one request with several responses on a stream [L: gemini-tts-cloud].

### Request shape and limits

- **Input and output.** Text in, audio out. A TTS model returns no text. The model pages give 8,192 input tokens and 16,384 output tokens, and the 3.8 audio card gives 8K in and 64K tokens of audio out. Audio counts 25 tokens a second [L: gemini-tts-model-pages, gemini-3-8-audio-card, gemini-pricing].
- **Formats.** WAV (24 kHz, 16-bit, mono) by default for a unary 3.8 request, raw L16 PCM at 24 kHz for a stream, and 8-bit mu-law or A-law on request. The 3.1 model returned raw PCM by default [L: gemini-tts-guide].
- **Not supported.** Thinking, function calling, structured output, search grounding, code execution and the Live API are not supported. Caching, Batch, Flex and Priority are supported on the 3.8 models [L: gemini-tts-model-pages].
- **Data and watermark.** All output carries a SynthID watermark. On the free tier Google can use the data to improve products; on the paid tier it does not [L: gemini-tts-blog-38, gemini-pricing].

### Voices

- **Prebuilt voices.** 30 studio voices, with a trait label for each, such as Puck upbeat, Kore firm and Enceladus breathy. The same names exist on the 3.1 and 3.8 models [L: gemini-tts-guide, gemini-tts-guide-archive].
- **Extended Voice Library.** Hundreds of voices by the guide, 150+ by the changelog and 2,000+ by the launch post. List and filter them with `GET /v1beta/voices` by language, region, accent, gender, pitch, persona and context [L: gemini-tts-guide, gemini-changelog, gemini-tts-blog-38].
- **Voice design (3.8 only).** `POST /v1beta/voices` with `type: "prompted"` and a text description makes a persistent `voice_...` id and a sample WAV [L: gemini-tts-voice-design].
- **Voice replication (3.8 only).** A 10 to 30 second reference clip and a consent clip give a stored `voice_...` id or a stateless `voicekey_...`. AI Studio replication is not available in Illinois, Texas, the EEA, the UK, Switzerland and India [L: gemini-tts-voice-replication, gemini-tts-blog-38].
- **Limits.** 200 stored custom voices per project. A stored voice expires one year after last use, and a stateless key after 7 days [L: gemini-tts-guide].

### Directing delivery

- **3.8 models.** The text is a verbatim transcript. Put sustained direction in `speech_metadata.style` and the speaker in `speech_metadata.speaker`. Put single events in angle-bracket tags such as `<laugh>`, `<sigh>` and `<short pause>`. Wrap listener reactions in pipe characters in a two-speaker turn. Start with an empty style, keep strings short and constant, and put the persona in a designed voice [L: gemini-tts-guide].
- **3.1 model on the Gemini API.** A written prompt in the text (Audio Profile, Scene, Director's Notes, Sample context, Transcript) plus square-bracket tags with free-form words [L: gemini-tts-guide-archive].
- **Cloud route (3.1 and the 2.5 models).** A natural-language `prompt` field and bracket tags in the text. Google names three levers: the style prompt, the text content and the tags, and says the result is most predictable when they agree. It describes four tag modes: non-speech sounds (sigh, laughing, uhm), style modifiers (sarcasm, robotic, shouting, whispering, extremely fast), vocalised adjectives that are spoken aloud as a word (scared, curious, bored) and pauses (short, medium and long, about 250 ms, 500 ms and 1,000 ms or more). It advises testing every new tag. The page names no model for each tag [L: gemini-tts-cloud].
- **Failure modes.** On 3.8: stage directions read aloud, long persona blocks that cause drift, and age, gender or accent in the style field. On 3.1: voice mismatch with the prompt, drift after a few minutes, text tokens returned in place of audio with a 500 error, and a prompt classifier that can reject vague prompts [L: gemini-tts-guide, gemini-tts-guide-archive].
