# Gemini 3.1 Flash Live Preview

Gemini 3.1 Flash Live Preview is the previous generation of the Gemini Live class of Google, generation 3.1. It is a speech-to-speech model for the Live API. Google released it on 2026-03-26. Google now calls it a legacy preview and recommends [Gemini 3.8 Live](gemini-3.8-live.md) [L: gemini-changelog, gemini-spec-3-1-flash-live]. [as-of 2026-10-09] Google's deprecations page gives 2026-11-17 as its earliest possible shutdown, with gemini-3.8-live as replacement [L: gemini-deprecations]. Google's model page gives a migration path from the 2.5 Flash native-audio preview to it [L: gemini-spec-3-1-flash-live].

Evidence tags: L is Google's own text, M is an independent measurement, A is one practitioner's report. Advice that holds for every Gemini Live model is in the [Live API guide in the Google README](README.md#live-api-guide). This file says what differs for 3.1 Flash Live.

## How to instruct it

### Setting up the prompt

The system instruction advice of Google's Live guides applies: one instruction for each agent, in the order persona, rules and guardrails; each tool call in its own sentence; the model waits for the user unless the prompt tells it to greet [L: gemini-live-best-practices]. The details are in the [3.8 Live file](gemini-3.8-live.md#setting-up-the-prompt). Two limits of this model change what a prompt can ask for. Function calls are synchronous only, so a flow that needs speech during a tool call does not work. Proactive audio and affective dialogue are not supported, so this model has none of the controls that 3.8 Live has for staying silent or for matching tone [L: gemini-spec-3-1-flash-live, gemini-live-tools].

### Reasoning and effort

The control is thinkingLevel, with minimal, low, medium and high. The default is minimal, which Google says gives the lowest latency. It replaces thinkingBudget from the 2.5 model [L: gemini-spec-3-1-flash-live]. The thinking level changes the scores a lot. Artificial Analysis measured speech reasoning at 71 with minimal and 97 with high, and time to first audio at 0.96 and 2.99 seconds [M: aa-speech-to-speech]. Google's own table for Scale's Audio MultiChallenge shows 26.8 percent with minimal and 36.1 percent with high [L: gemini-3-1-flash-live-eval]. Thought summaries can be turned on with includeThoughts [L: gemini-live-capabilities].

### Output: format, length, tone

Output is audio at 24 kHz. Text comes only from output transcription. A single server event can hold several content parts at once, for example audio and a transcript, and Google says the client must read all parts of each event [L: gemini-spec-3-1-flash-live, gemini-live-capabilities]. Language and style advice is the same as for 3.8 Live; see the [3.8 Live file](gemini-3.8-live.md#output-format-length-tone).

### Tools and agents

Function calling is synchronous only. The model does not start to answer until the client sends the tool response. Asynchronous calls and scheduling are not supported. Google Search grounding is supported. Code execution, URL context and Maps grounding are not [L: gemini-spec-3-1-flash-live, gemini-live-tools]. The Live API has no automatic tool-response handling [L: gemini-live-tools].

Practitioner reports (A): an issue opened 2026-08-06 describes a failure with thinking on (level low) and several tools. The model plans a call in its thoughts and composes the arguments. It never sends the call, and it speaks made-up data as if the tool had answered. The reporter measures this at about 20 to 35 percent of multi-turn conversations with a tool decision, found no trigger, and confirmed with a capture of more than 6,000 wire messages that no call frame was sent [A: gh-genai-2827]. This is one report with no maker answer found.

### Coding

Google publishes no coding guidance for the Live models. The model has no code execution tool [L: gemini-spec-3-1-flash-live].

### Long context and retrieval

The model page gives 131,072 input tokens and 65,536 output tokens, and the model card says 128K and 64K. Caching is not supported. The session rules are those of the other Live models: 15 minutes for audio-only and 2 minutes with video unless compression and resumption are on. See the [README](README.md#live-api-guide) [L: gemini-spec-3-1-flash-live, gemini-3-1-flash-audio-card, gemini-live-session]. The price table is shared with 3.8 Live: audio input $3.00 and audio output $12.00 per million tokens. The model has no separate price [L: gemini-pricing]. Google does not charge for silent listening on this model, because proactive audio is not supported: Google says the API bills audio only while the client streams input [L: gemini-live-best-practices].

### Structured output

Structured outputs are not supported [L: gemini-spec-3-1-flash-live].

### Images, audio, other inputs

Inputs are text, images, audio and video, with 16 kHz PCM audio and JPEG frames at most once a second [L: gemini-spec-3-1-flash-live, gemini-live-capabilities]. Turn coverage defaults to audio activity and all video frames, where the 2.5 model sent only activity. Google says that an application that sends a steady stream of frames may want to send frames only during audio activity, to avoid extra cost [L: gemini-spec-3-1-flash-live].

### Voice: turn-taking, interruption and speech style

The server voice activity detection, the silence advice (500 to 800 ms), the hybrid mode, the chunk size (20 to 40 ms) and the interruption handling (interrupted: true, and the client drops queued audio) are the same as for 3.8 Live. See the [voice subsection of the 3.8 Live file](gemini-3.8-live.md#voice-turn-taking-interruption-and-speech-style) [L: gemini-live-capabilities, gemini-live-best-practices].

What is specific to this model:

- The model does not support proactive audio or affective dialogue. Google's capabilities guide still describes both features in general, and says to use API version v1beta for them. The 3.1 model page says to remove their configuration [L: gemini-spec-3-1-flash-live, gemini-live-capabilities].
- With synchronous function calls, speech stops while a tool runs. Google's page says the model will not start to respond before the tool response arrives [L: gemini-live-tools].
- Latency depends on the thinking level (see Reasoning and effort). A forum report of 2026-09-05 says time to first audio rose from about 1 second to 9 to 15 seconds on the Live API serving path for this model, with about one session in three giving no audio in 15 seconds. The reporter's test used a plain WebSocket, and the same setup on the 2.5 native-audio model answered in 1.9 to 2.4 seconds. The AI Studio playground answered normally [A: forum-31-latency]. No maker answer was found.

### Sampling and API parameters

The Live pages read give no temperature, top_p or top_k setting for this model. The setup uses thinkingLevel in place of thinkingBudget [L: gemini-spec-3-1-flash-live].

### Migrating from the previous generation

From the 2.5 Flash native-audio preview, Google lists these changes [L: gemini-spec-3-1-flash-live]:

- The model string becomes gemini-3.1-flash-live-preview.
- thinkingLevel (minimal, low, medium, high, with minimal as the default) replaces thinkingBudget.
- One server event can hold several content parts. Client code must process all of them.
- send_client_content works for the whole session with explicit roles. turn_complete true always stops generation.
- Turn coverage defaults to audio activity plus all video frames.
- Asynchronous function calls, proactive audio and affective dialogue are not supported.

The move to 3.8 Live is in the [3.8 Live file](gemini-3.8-live.md#migrating-from-the-previous-generation). Google says to move [L: gemini-spec-3-1-flash-live, gemini-deprecations].

## What the system card reports

Google published the model card on 2026-03-26 and updated it in April 2026. It covers 3.1 Flash Live and 3.1 Flash TTS together as "Gemini 3.1 Flash Audio" [L: gemini-3-1-flash-audio-card].

- The models are based on Gemini 3 Pro. The card defers to the Gemini 3 Pro card for architecture, training data, hardware, software, limitations, acceptable use, risks and mitigations.
- 3.1 Flash Live takes audio, images, video and text with a context window up to 128K tokens, and gives audio and text with 64K output tokens.
- The card lists the safety policy areas: child sexual abuse material, hate speech, dangerous content, harassment, sexually explicit content, and medical advice against consensus.
- Frontier safety: Google relies on its evaluation of Gemini 3.1 Pro with Deep Think mode, which did not reach a Critical Capability Level. It says 3.1 Flash Audio is less capable than 3.1 Pro and so unlikely to reach one.
- The card gives no knowledge cutoff in the text read, and no refusal, prompt-injection, sycophancy or reward-hacking results.

Google's evaluation file for 3.1 Flash Live names three benchmarks. Audio MultiChallenge (multi-turn spoken dialogue, run by Scale AI), Big Bench Audio (1,000 audio questions, run by Artificial Analysis) and ComplexFuncBench Audio (travel-booking function-call chains, with synthesized speech, run by Google on the Live API) [L: gemini-3-1-flash-live-eval].

## Behaviour observed in practice

- Artificial Analysis finds a large gap between the two thinking settings: speech reasoning 71 and conversational dynamics 72.3 with minimal, against 97 and 74.3 with high. The agentic tau-Voice score is 26.2 with minimal and 37.7 with high [M: aa-speech-to-speech].
- Scale's leaderboard lists the model at 36.06 percent (plus or minus 4.41) with thinking and 26.77 (plus or minus 4.06) without, for audio output on Audio MultiChallenge. The 2.5 native-audio preview of December 2025 scores 21.46 and 13.90 on the same board [M: scale-audiomc].
- The tool-call and latency reports in the sections above are from practitioners [A: gh-genai-2827, forum-31-latency]. A LiveKit issue also lists this model as synchronous only, with a save rate of 4 in 10 trials and a median of 19.2 seconds for a mid-call save in its test [A: gh-livekit-7302].

## Benchmarks

Independent [M: aa-speech-to-speech, scale-audiomc]:

- Artificial Analysis Speech to Speech Index: 71.5 at high thinking, 63.9 at minimal.
- Speech reasoning (Big Bench Audio): 97 at high, 71 at minimal. Conversational dynamics: 74.3 and 72.3.
- tau-Voice: 37.7 and 26.2. Arena preference Elo: 1063 and 1096. Task success rate: 71.8 and 74.6.
- Time to first audio: 2.99 and 0.96 seconds.
- Scale Audio MultiChallenge (audio output): 36.06 with thinking, 26.77 without.

Maker-reported: Google's evaluation file for the 3.8 models shows 11.3 percent for this model at high thinking on its Sierra tau3-Banking chart [L: gemini-3-8-live-eval]. ComplexFuncBench Audio 90.8 percent at high thinking, against 71.5 percent for the 2.5 native-audio preview. Google's table of March 2026 also shows Audio MultiChallenge 36.1 and 26.8 percent (2.5: 21.5 and 13.9) and Big Bench Audio 95.9 and 70.5 percent (2.5: 90.7 and 69) [L: gemini-3-1-flash-live-eval].

No SWE-Bench Pro, Terminal-Bench, Artificial Analysis Intelligence Index, Coding Agent Index or METR result exists for this model. These tests do not apply to a speech model.
