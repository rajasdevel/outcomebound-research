# Speechify Simba 3.5

Speechify Simba 3.5 is the current generation of the Speechify Simba speech synthesis class. It speaks 48 languages under one model id. The API marks it as the recommended model from 2026-10-18, and Speechify launched it on 2026-10-21. It does not replace the API default: a request that names no model still gets `simba-3.0`. Simba 3.2 stays available for English. Family-wide rules are in the [Speechify README](README.md).

## How to instruct it

### Setting up the prompt

- **No system prompt.** A request carries `input` (text or SSML), `voice_id`, `model` and `language`, and optional format and `pronunciations` fields [sp-models-1031] [sp-chlog-1018].
- **Name the model.** Set `model` to `simba-3.5`. Without it the request goes to `simba-3.0` [sp-models-1031] [sp-blog-35].
- **Set the language.** Set `language` to the language of the text, as a bare code (`ja`) or with a region (`ja-JP`); any regional variant of a listed language is in scope. Without it, the locale of the voice decides. The maker says to set it on every request whose text is not in the voice's own language [sp-lang-1031] [sp-blog-35].
- **Languages outside the list.** The API does not reject them, and does not validate them either. Estonian and Cantonese, which Simba 1.6 had as beta languages, are not among the 48 [sp-lang-1031] [sp-models-1031].

### Reasoning and effort

None.

### Output: format, length, tone

- **Formats.** The 23 `output_format` values (see the card). `output_format` wins over `audio_format` on the speech endpoint and over the `Accept` header on the stream endpoint [sp-formats-1031].
- **Length.** 2,000 spoken characters on `/v1/audio/speech` and 20,000 on the streaming endpoints. SSML tags do not count toward these limits, and the input as sent has its own ceiling of 20,000 and 32,000 characters [sp-limits-1031].
- **Billing.** Spoken characters only; tags are not billed, and `pronunciations` entries are not billed [sp-blog-35] [sp-chlog-1018].

### Tools and agents

Not applicable. For text that an LLM streams, the WebSocket input stream `GET /v1/audio/stream/ws` takes text in pieces, speaks each sentence once it is complete, and bills each segment as one stream request. It is server-side only, because a browser cannot set the `Authorization` header on a WebSocket [sp-ws].

### Coding

The same SDKs, docs MCP server and index file as the other Simba models; see the [README](README.md). The maker's code samples set `model="simba-3.5"` [sp-models-1031].

### Long context and retrieval

Long text goes to `POST /v1/audio/stream` (20,000 spoken characters). On the WebSocket, at most 20,000 characters can wait to be spoken, and a sentence of more than 1,000 characters without an end is cut at its last word boundary [sp-limits-1031] [sp-ws].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. A voice clone takes an audio sample on a paid plan, and the clone keeps its voice id on Simba 3.5 [sp-models-1031].

### Voice: turn-taking, interruption and speech style

Simba 3.5 is not a conversation model. It has no turn detection and no barge-in. A client stops its own playback.

**How to direct delivery.**

- **What the model applies.** `<break>` for pauses, `<prosody rate>`, `<prosody pitch>` and `<prosody volume>`, and `<sub alias>`. Pitch and volume are applied from the changelog entry of 2026-10-20; before that the model accepted them and did not apply them [sp-ssml-1031] [sp-chlog-1020].
- **What the model ignores.** `<emphasis>` and `<speechify:style emotion="...">` return `200` and the text is spoken without the change. The emotion guide says only the retired Simba 1.6 models apply emotion styles [sp-ssml-1031] [sp-emotion-1031].
- **Prosody values.** `rate` from x-slow to x-fast or -50% to +9900%; `pitch` from x-low to x-high or -83% to +100%, without a change of speed; `volume` from silent to x-loud, -60 dB to +20 dB, or -100% to +900% relative to the voice. `volume="100%"` doubles the gain; omit `volume` or use `medium` for no change. Nested values multiply [sp-ssml-1031] [sp-chlog-1020].
- **A span costs intonation.** A `prosody` around a whole block costs nothing extra. A `prosody` around part of a sentence is synthesized on its own, so the intonation of the sentence can break where the value changes [sp-ssml-1031].
- **Misspelt attributes.** An unknown attribute name or value is ignored and the request returns `200`; malformed XML returns `400` [sp-ssml-1031].
- **No emotion control.** The pages read describe no emotion tag that acts and no natural-language instruction field. Delivery comes from the words, punctuation, prosody and the choice of voice.

**Voice choice and cloning.** Every catalogue voice speaks all 48 languages, and so does a clone made on a paid plan. A voice keeps the accent of the recording it came from: an English voice reading German sounds like an English speaker. The maker advises starting with the staff-pick voices of each language, which `GET /v1/voices` ranks with `staff_pick_rank`, and cloning from a recording in the language the clone will speak. The maker says it plans to make this more flexible in a later release [sp-lang-1031] [sp-chlog-1021].

**Pronunciation and text normalisation.** The `pronunciations` list gives, for a word or phrase, IPA phones (`ipa`) or replacement text (`alias`). It works in every language Simba 3.5 speaks except English. Entries ignore case unless `case_sensitive` is true, match whole words (anywhere in Chinese, Japanese, Korean, Thai, Lao, Khmer and Burmese text), and the longest match wins. Limits: 200 entries, 64 characters of text, 64 phones, 160 characters of alias. A model or language without support returns `400 pronunciations_unsupported`. On the WebSocket the list goes in one `session.pronunciations` message before the first text [sp-chlog-1018] [sp-pron] [sp-ws].

**Multi-speaker dialogue.** Not on this model: `POST /v1/audio/dialogue` stays on `simba-dialogue-1.0` [sp-chlog-1018].

**Turn-taking.** Not applicable to a synthesis model.

### Sampling and API parameters

`model`, `voice_id`, `language`, `audio_format` or `output_format`, `pronunciations`, and SSML in `input`. The pages read list no temperature or seed [sp-chlog-1018] [sp-formats-1031].

### Migrating from the previous generation

From Simba 3.2 [sp-blog-35] [sp-models-1031] [sp-chlog-1021]:

- Change `model` from `simba-3.2` to `simba-3.5`. Voice ids, output formats, speech marks and the SSML that 3.2 applies carry over. No API version change is needed.
- Set `language` on each request whose text is not in the voice's own language.
- The list price is twice that of 3.2. Until 2026-11-21 it bills at the 3.2 rate.
- `simba-3.2` and `simba-3.0` stay available and are not deprecated, so calls can move one at a time.
- `simba-multilingual` is served by Simba 3.5 from 2026-11-21 on every API version that can still name it; `simba-english` is served by `simba-3.2` for English and by Simba 3.5 for other languages [sp-models-1031].

## Behaviour observed in practice

- No independent measurement was found. Artificial Analysis does not list Simba 3.5 on its text-to-speech leaderboard on 2026-10-31 [aa-tts-board-1031].
- No practitioner report was read.
- **The maker's own pages disagree on pitch and volume.** The launch post's FAQ, dated 2026-10-21, says pitch and volume are accepted and not applied. The changelog entry of 2026-10-20, the SSML page and the models page say they are applied. This file follows the later reference pages [sp-blog-35] [sp-chlog-1020] [sp-ssml-1031].

## Benchmarks

Maker figures only, as of October 2026 [sp-blog-35] [sp-models-1031]:

- In blind side-by-side listening in English, listeners preferred Simba 3.5 over Simba 3.2 in 63% of comparisons (95% CI 60 to 67%).
- In the six locales that both models speak, native listeners preferred Simba 3.5 over Simba 3.0 Multilingual in 62% of comparisons.
- 72 ms time to first audio for 95% of streaming requests under production load, in English.
- Throughput per serving instance of 1.8 times Simba 3.2 and 1.4 times Simba 3.0 Multilingual. This is a cost figure of the maker, not a quality figure.
