# Speechify Simba 3.0

Speechify Simba 3.0 is the generation before Simba 3.2 in the Speechify Simba class, and the API default. It covers English and five other languages. It takes the same SSML emotion tag, prosody and pause tags; the models page lists full SSML and emotion-control support for it. This file says what differs from the [Simba 3.2 file](simba-3.2.md). Family-wide rules are in the [Speechify README](README.md).

## How to instruct it

### Setting up the prompt

- **Default model.** `simba-3.0` is used when a request omits `model`. It covers six languages across seven locales. `language` selects the language, and when it is absent the voice's locale decides [sp-models] [sp-lang].
- **Controls.** The same tags as Simba 3.2; the models page lists full support for SSML and emotion control on 3.0 [sp-models]. At launch on 2026-05-09 the maker also named per-voice speaking-rate and arousal, dominance and valence (ADV) emotion controls that the model inherits from the voice catalogue; these are voice properties, not request fields [sp-chlog-30].

### Reasoning and effort

None.

### Output: format, length, tone

The same limits and formats as Simba 3.2 [sp-limits] [sp-formats].

### Tools and agents

Not applicable. Speechify offers LiveKit, Pipecat, Vapi and Deepgram integrations, and a docs MCP server [sp-index].

### Coding

Official SDKs for Python and TypeScript, a docs MCP server and a coding-agent index file [sp-index].

### Long context and retrieval

Long text goes to `POST /v1/audio/stream` (20,000 characters). Latency guidance advises sending each complete sentence as soon as it exists when text arrives from an LLM, and splitting only at sentence ends [sp-limits] [sp-latency].

### Structured output

Not applicable.

### Images, audio, other inputs

Text only. A voice clone takes an audio sample and a consent recording [sp-clone].

### Voice: turn-taking, interruption and speech style

Simba is not a conversation model. It has no turn detection and no barge-in. A client stops its own playback.

**How to direct delivery.**

- **Emotion tag.** Wrap text in `<speechify:style emotion="...">` inside `<speak>`. The API detects SSML in the `input` field by itself. Thirteen values: angry, cheerful, sad, terrified, relaxed, fearful, surprised, calm, assertive, energetic, warm, direct and bright [sp-emotion] [sp-ssml].
- **Advice from the maker.** The words must match the emotion, because an angry sentence works with `angry` and not with `cheerful`. Short sentences give stronger emotion. Punctuation helps: an exclamation mark for anger or excitement, a question mark for uncertainty, an ellipsis for hesitation or sadness. Emotion tags can sit beside `prosody` and `break` tags [sp-emotion].
- **Mixed emotions.** The maker's example puts a cheerful span, a 500 ms break and a calm span in one document [sp-emotion].
- **Illustration, written for this library and not taken from the maker.** `<speak><speechify:style emotion="warm">You made it.</speechify:style><break time="400ms"/><speechify:style emotion="direct">Sit down.</speechify:style></speak>`. This shows the syntax; it is not a sample from the guide. It was not run against the model.
- **Prosody.** `prosody` takes `pitch` (x-low to x-high, or -83% to +100%), `rate` (x-slow to x-fast, or -50% to +9900%) and `volume` (silent to x-loud, a dB value, or -100% to +900%) [sp-ssml].
- **Emphasis and pauses.** `emphasis` has `reduced`, `moderate` and `strong`. `break` takes a strength (none to x-strong, 0 to 1250 ms) or a time up to 10 seconds. A document can insert at most 30 seconds of silence in total; further pauses are dropped without an error [sp-ssml].
- **Coverage and limits.** The models page lists full support for SSML and emotion control on both Simba 3.2 and Simba 3.0. The pages give no figure for how strongly an emotion tag acts. No natural-language instruction field exists in the pages read [sp-emotion] [sp-models].

**Voice choice and cloning.** The catalogue and clones are the other levers. A clone comes from 10 to 30 seconds of audio, and the cloned voice captures accent, style and tone. A consent step runs first: the speaker reads a single-use phrase aloud, and Speechify verifies the recording. No voice design from a description is documented [sp-clone].

**Multi-speaker dialogue and long-form consistency.** The pages read describe no multi-speaker request. Each request uses one voice. Long text goes to the streaming endpoint (20,000 characters). The speech marks endpoint returns word timing [sp-limits] [sp-index].

**Pronunciation and text normalisation.** SSML `sub` replaces text with an alias. The pages read describe no phoneme tag and no normalisation switch [sp-ssml].

**Turn-taking.** Not applicable to a synthesis model.

### Sampling and API parameters

`model`, `voice_id`, `language`, `audio_format` or `output_format`, and SSML in `input` [sp-index] [sp-formats].

### Migrating from the previous generation

From the earlier Simba 1.6 models to 3.0 [sp-models]:

- `simba-english` and `simba-multilingual` are not selectable from API version 2026-09-21. From 2026-11-21 their ids are served by current models.
- Most workspaces on `simba-multilingual` send only English, German, Spanish, French, Italian or Portuguese, which 3.0 covers.
- Languages outside those six often give usable audio on 3.0 but are not validated [sp-lang].

## What the system card reports

As for Simba 3.2: no system card; a content policy applies; cloning needs verified consent [sp-clone].

## Behaviour observed in practice

- **Rank (M).** Artificial Analysis gives a quality Elo of 1124.54, against 1241.95 for Simba 3.2 [aa-tts-board].
- No practitioner report was read.

## Benchmarks

Independent: Artificial Analysis quality Elo 1124.54 [aa-tts-board]. Maker: median first byte 161 ms on 2026-09-15 [sp-latency].
