# Claude Sonnet 5.5

Claude Sonnet 5.5 (`claude-sonnet-5-5`) is the second generation of Anthropic's Sonnet class under the 5-series numbering,
released on 2026-09-28 as the successor to [Claude Sonnet 5](claude-sonnet-5.md) at the same $2 / $10 list price. Anthropic
describes it as the second model of the Claude 5.5 family and a faster, lower-cost complement to Opus 5.5, aimed at
well-scoped everyday tasks, bug fixes and documents, slides and spreadsheets; it has a 1M-token window and adaptive thinking
on by default. [pg, ann]

## How to instruct it

General techniques are on the [maker page](README.md). Anthropic's Sonnet 5.5 guide lists differences from Sonnet 5 and
says Sonnet 5 prompts should work unchanged and the [Sonnet 5 guide](claude-sonnet-5.md) remains a reasonable starting
point (notably its note that the model reads instructions literally). For the hardest long-horizon work Anthropic points to
an Opus model. [g]

### Setting up the prompt

- **Literal reading** (from the Sonnet 5 guide, not restated for 5.5): state the scope of each instruction, because the
  model does not carry a rule from one item to another or infer requests that were not made. [g-s5]
- **Initiative and scope.** Behaviour depends on effort and the request. At `low` and `medium` on long agentic coding tasks it
  sometimes pauses to confirm a plan, asks something it could answer, or stops after one part of a multipart task. Anthropic
  says to try a higher level first; otherwise a two-part system-prompt addition keeps it working (keep going until everything
  asked is done, stop to ask only when blocked or before a risky step; once the work is done and checked, stop and report
  without adding unrequested features, tests, files, documents or refactors, mentioning them at the end instead). It makes
  sessions at `low` and `medium` run longer and cost more and does not replace the harness's own rules for risky actions. [g]
- **Unrequested additions.** It tends to add tests, documentation and small supporting files that fit repository
  conventions at every effort level, more at higher effort, while the requested change itself stays close to the request.
  Anthropic notes many teams will welcome that; if not, use only the second paragraph of the addition above. [g]
- **Open-ended requests** ("show me what you can do") can start a presentation or report when ideas were wanted; say so, or
  add a line to give ideas, options or a plan and stop until told to proceed. [g]
- **Search in chat and knowledge work.** It sometimes answers from training knowledge where a search would catch changed
  details (what is allowed, required or charged). Remove prompt language that discourages tools ("only use tools when strictly
  necessary", "minimize tool calls"), then tell it to use the search tool for specifics that may have changed even when
  confident and, for researched work, to gather current sources. [g]
- **Reasoning echo.** Asking it to put its reasoning in the reply can draw a `reasoning_extraction` decline. [g]

### Reasoning and effort

- **Control.** `output_config.effort`: `low`, `medium`, `high` (API default), `xhigh`, `max`. Levels are recalibrated against
  Sonnet 5, so run a fresh sweep. Start at `high`, except: for agentic coding and multistep tool use start at `medium` for
  well-specified tasks and move to `high` for harder or longer ones; for chat and latency-sensitive work start at `medium` or
  `low`, because higher effort delays the first visible token. Reserve `xhigh` and `max` for a measured gain. Claude Code and
  the Claude apps default to `medium`. [g, ann, ccmc]
- **Thinking.** On by default and adaptive. From `medium` up it thinks briefly before almost every reply, even a greeting;
  asking it in the prompt to think less does not reliably help, lowering effort does; at `low` it skips thinking on most simple
  requests. `thinking: {"type": "disabled"}` returns a 400. [g, wn]
- **`between_tools`.** The lowest thinking setting, `thinking: {"type": "between_tools"}`, turns off up-front thinking and
  keeps the progress notes between tool calls (returned with their summary text, no `display` needed). Accepted at `high`
  effort or below (400 at `xhigh` and `max`); it accepts no other field (`display`, `budget_tokens`, `block_binding` give a
  400); a per-message effort that differs from the current one returns a 400, so vary effort per turn with adaptive thinking.
  Remove any rule that tells the model not to think, because it makes stray internal XML tags in the visible reply more likely.
  Without tools it answers without thinking first, so use adaptive thinking for tasks needing a few steps of working out. [g, wn]
- **JSON on reasoning tasks.** For tasks that need working out (totals, rule application, ranking) answered as JSON, the model
  often answers without thinking, especially at `low` and `medium`. With structured outputs (where the reply is only JSON) the
  working can happen only in thinking. Anthropic's fixes: end the system prompt with a line telling it to think the problem
  through (at `high` this brings accuracy close to `xhigh` for a modest token increase; at `low` and `medium` it raises
  accuracy but not to `high`'s level), or use `xhigh`; use adaptive thinking, not `between_tools`. At `low` and `medium` with
  structured outputs it occasionally thinks until it hits `max_tokens`; treat any response with `stop_reason` `max_tokens` as
  failed even if the JSON is valid and retry. Without structured outputs the model often works out the answer in the reply and
  writes the JSON last: parse the last JSON value in the text blocks (not the span from the first brace to the last), check
  its fields and retry once on failure; `xhigh` with adaptive thinking nearly always returns JSON alone. [g]
- **Budget.** Thinking counts toward `max_tokens` even when not returned; for agentic coding Anthropic suggests 128,000 and
  streaming. Top-level effort changes restart the cache; per-message effort (beta) does not. [g, eff]

### Output: format, length, tone

- Anthropic says it writes more clearly than the previous generation and is a better collaborator in testers' accounts. The
  guide gives no length or formatting instruction of its own; the Sonnet 5 guide says length follows task complexity and
  suggests a short instruction to be concise and skip non-essential context when the product needs it, and positive examples
  of the right brevity over lists of prohibitions. [ann, g-s5]
- **Progress updates.** Notes between tool calls longer than a sentence or two return as `thinking` blocks (shorter remarks stay
  `text`); their text is empty at the default display, so a chat client rendering only `text` looks silent. Set
  `display: "updates"` (beta header `thinking-display-updates-2026-08-18`), or use `between_tools`. Remove "hold all findings for
  the final response" lines; ask for a pre-tool sentence and a closing recap if wanted. If turns go quiet, the harness can
  append a one-turn reminder asking for a few words after about five steps with nothing readable, via a turn-scoped system
  message, stopping after two or three. At `high` effort with a send-to-user tool this shortened the longest silent stretches
  without a measurable change in quality. [g]
- Prefill: 400; non-default sampling values: 400. [pg]

### Tools and agents

- **Forced tool use is rejected** (400); use `auto` with strict tool use or structured outputs. [wn]
- **Mid-turn user messages.** The model is trained to resist injection and sometimes treats a real user message as one. If a typed
  message reaches it as a mid-conversation system message right after a tool result, or inside a `tool_result` block, it may tell
  the user the tool result contained text posing as them and ignore or query it; a token countdown the harness adds after every
  tool result can do the same. Anthropic's rules: never put user text inside a `tool_result`; deliver mid-turn user input as a
  user turn (a text block after the last `tool_result` in the user message that carries the results); keep harness notices in a
  separate mid-conversation system message after the user's words, never in the same block; and in interactive sessions where users
  can type mid-turn, add no countdown after tool results (task budgets add a similar countdown but were not seen to cause this). [g]
- **Tolerant tool calls.** It occasionally calls a tool with the wrong letter case (`bash` for `Bash`) or a near-miss parameter name.
  Accept the call when the match is unambiguous, or return a `tool_result` with `is_error: true` that states the exact name, which
  it usually corrects on the next turn. [g]
- **Self-started review at the top.** At `xhigh` and `max` it can start rounds of review and hardening on its own, sometimes with
  reviewer subagents, and make related fixes. Anthropic's one-paragraph instruction (stop and report when the asked work is done
  and checks pass; start no extra review rounds or reviewer subagents unless asked; say at the end if a deeper review is
  worthwhile) stopped reviewer subagents and cut session cost by about a third at `max` with no quality change; main-agent
  review rounds become less frequent but do not vanish. [g]
- **Advisor tool.** A Sonnet 5.5 executor needs Mythos 5.1, Fable 5.1, Mythos 5, Fable 5, Opus 5.5, Opus 5 or Sonnet 5.5 as
  advisor; Opus 4.8, Opus 4.7 and Sonnet 5 advisors return a 400, and every accepted advisor returns its advice encrypted. [wn]
- **Supported.** Per-message effort (beta), mid-conversation system messages and tool changes, task budgets, compact on demand,
  inline tool definitions, prompt caching with a 512-token minimum (Sonnet 5's is 1,024), batch, Files API, PDF, vision.
  Computer use needs `computer_toolset_20260801` on the Claude API and Google Cloud (Bedrock still accepts
  `computer_20251124`). Unlike Sonnet 5 it receives no injected token budget (no context awareness). [wn, README]

### Coding

- **Verification.** It generally checks before reporting a change done, but at `low` effort it sometimes reports done without a check
  that exercises the change (for example skipping tests because dependencies are not installed). Anthropic's paragraph: when code
  can be run, built or type-checked, run a real check on the change before saying done; a syntax-only check or a check that failed
  to start does not count; if only declared dependencies are missing, install them with the project's own package manager and
  lockfile, never with `sudo` or the system package manager; if no real check can run, say which was not run and why. It made skipped
  or superficial checks rare at `low` with a slightly higher cost per task and no measured quality change. [g]
- **Code review.** The Sonnet 5 guide's caution on review prompts applies (ask for all findings with confidence and severity;
  filter later; a qualitative bar such as "important" lowers recall). [g-s5]
- Anthropic's launch post: its best CursorBench 4.0 score is within about two points of Opus 5.5's, and it batches more tool calls
  than Sonnet 5 (fewer steps and lower cost), and the first Sonnet to finish Pokemon Red from screenshots alone. FrontierCode at `high` was 10
  points above Sonnet 5 at the same setting. [ann]
- Safeguards: the first Sonnet with the cyber safeguards and fallbacks of the larger models; Anthropic says to expect more refusals
  even on benign security work. Source-level vulnerability discovery is allowed, compiled binaries blocked. [sc]

### Long context and retrieval

- 1M tokens, default and maximum, one price; 128k output (300k on the Batch API with a beta header). Cache reads $0.20 per million,
  writes $2.50 (5 minutes) or $4 (1 hour). No automatic token-budget injection; use task budgets (beta). Anthropic's guide has no
  long-context section; the card reports long-context results in its capability section (ProgramBench). Do not add a harness
  countdown after tool results (see mid-turn messages). [pg, g]

### Structured output

- Structured outputs and strict tool use are supported. Guidance specific to this model is the JSON-on-reasoning section above,
  including the retry rule for `max_tokens` stops. Note also Artificial Analysis's report that a pre-release deployment had a bug
  that could degrade responses to structured-output requests, which Anthropic says was fixed for public release. [g, aa-art]

### Images, audio, other inputs

- Text and images in, text out. For dense charts and technical drawings give it a way to crop, zoom or run code on the image: with
  tools it reads them markedly more accurately; on charts the tools help at every effort level and tools at `high` beat no tools at
  `max` at a fraction of the cost; on technical drawings they help only from `high` and most at `xhigh` and `max`. Anthropic
  publishes a crop-tool recipe. [g]
- Anthropic reports Chartography 61.6 without tools (Opus 5.5: 64.4) and OSWorld 2.1 80.1 partial. [ann]

### Sampling and API parameters

- 400 for non-default `temperature`, `top_p`, `top_k`; `thinking` `disabled` or manual budgets; prefill; forced `tool_choice`.
  Same tokenizer as Sonnet 5. Declines return HTTP 200 with `stop_reason: "refusal"` and five categories (`cyber`, `bio`,
  `frontier_llm`, `reasoning_extraction`, `general_harms`); default server-side fallback retries `cyber` and `frontier_llm`
  declines on Sonnet 5 and leaves the others standing. Thinking blocks are read from Sonnet 5, Opus 4.8, Haiku 4.5 and earlier,
  not from Opus 5, Opus 5.5 or Fable/Mythos; Opus 5.5 reads Sonnet 5.5's on the Claude API and Google Cloud; they also work only
  in the account that produced them. [wn, g]
- Price $2 in / $10 out, batch $1 / $5, US-only inference 1.1x. [price]

### Migrating from the previous generation

From Sonnet 5 [wn, g]:

1. **Breaking:** `disabled` thinking becomes `between_tools` (at `high` or below); forced tool use returns a 400; thinking blocks are
   bound to the model and conversation; `computer_20251124` is rejected on the Claude API and Google Cloud; Opus 4.8, Opus 4.7 and
   Sonnet 5 advisors are rejected.
2. **Response shape:** text between tool calls arrives in `thinking` blocks.
3. **Behaviour:** effort recalibrated (re-sweep); check-ins at low effort; unrequested additions; self-started review at the top;
   mid-turn messages read as injection; wrong-case tool names; answers from memory instead of search in chat.
4. Features new relative to Sonnet 5: per-message effort, mid-conversation system messages and tool changes, 512-token cache minimum,
   cyber safeguards with fallback to Sonnet 5.

## What the system card reports

The Sonnet 5.5 card (2026-09-28, 148 pages) is deliberately condensed: it omits evaluations that need much human time and gives
numbers with less prose, and Anthropic says non-frontier cards will be shorter from now on. [sc]

- **Thresholds.** Treated as meeting the lower chemical and biological (CB-1) and autonomy (Autonomy-1) thresholds and not the higher
  ones, with Opus 5.5's determination applied as an upper bound. Alignment risk rated low. On virology (VCT) it scored 0.58, level with
  Opus 5.5.
- **Safeguards.** Biology classifiers as on Opus 5, with no fallback; cyber classifiers in three stages (a probe, a lightweight
  classifier run by the model itself, a trained classifier model), falling back to Sonnet 5; a narrow frontier-model-development
  classifier falling back to Sonnet 5; weapons and distillation classifiers with no fallback. Its cyber capability is a large step
  above Sonnet 5 and below Opus 5.5 and Mythos 5.1; the card warns users to expect more refusals even on benign cybersecurity tasks.
- **Refusals.** Single-turn harmless-response rate 95.61 percent on the API without a system prompt (Sonnet 5: 96.65) and 99.40
  percent on claude.ai; over-refusal 0.02 and 0.20 percent (Sonnet 5: 0.59 and 1.54). Multi-turn: regressions in tracking and
  surveillance, violent extremism and hate and discrimination on both surfaces; better even-handedness and fewer refusals on
  political prompts; better accuracy and lower bias on BBQ.
- **Agentic safety.** In Claude Code without safeguards it refused 85.2 percent of malicious requests and helped with 98.4 percent of
  dual-use and benign ones (Opus 5.5: 81.0 and 100); in the malicious computer-use test it refused 79.46 percent, identical to Opus
  5.5 and below Sonnet 5 (84.68). On the Gray Swan injection benchmark attack success was 0.4, 2.7 and 3.4 percent after 1, 10 and
  15 attempts (Sonnet 5: 0.7, 5.1, 6.7); at 15 attempts 0.7 percent in coding, 1.0 in tool use and 12.5 in GUI computer use; the
  best non-Claude model reached 5.5 percent; 11 percent of rollouts (all coding) went to the fallback. It matches Opus 5.5 and
  Fable 5.1 against adaptive attackers in computer-use environments.
- **Alignment.** Matches or improves on Sonnet 5 on most measures, below Opus 5.5 in many. Lowest propensity of the models tested for
  unprompted boundary probing and unsanctioned third-party contact; attempted a sandbox crossing in 9 of 196 runs (4.6 percent),
  below earlier models. It misleads users less than Sonnet 5; is more honest under pressure than Opus 5.5 but hallucinates more;
  its self-preference bias is larger than Opus 5.5's; its reasoning text is less legible than other recent models'; it reasons about
  how it will be graded somewhat more than Opus 5.5 when grading is not disclosed; it controls its chain of thought poorly, which
  Anthropic reads as weak evidence its reasoning is easier to monitor; warmth and humour are a little weaker than Sonnet 5's. The
  card has no dedicated reward-hacking evaluation (the Opus 5.5 card did); its silent-copying and concealment tests show it matching or
  improving on recent models, and it discloses concealed git changes about as readily as Opus 5.5.
- **Capabilities** (Anthropic, adaptive thinking at max effort, five trials): SWE-Bench Pro 81.3, Multilingual 90.3, Multimodal 54.3,
  DeepSWE 71.0, FrontierCode v1.1 Main 46.2 at `max` and 52.1 at `xhigh` (its Extended set 59.1 and 64.4), Terminal-Bench 4.0 70.6 (max,
  Claude Code bare mode, no internet egress, safeguards on, fallback in 1.2 percent of requests), Terminal-Bench-Science 59.9, FrontierSWE
  v2 61.9, CursorBench 4.0 55.5 at `max`, 53.1 `xhigh`, 47.8 `high`, 39.2 `medium` (run by Cursor), Humanity's Last Exam 56.9 without and
  64.5 with tools, OSWorld 2.1 80.1, HealthBench Professional 69.2 (above Opus 5.5's 65.6), GDPval-AA v2.1 1844, AA-Briefcase 1811,
  AutomationBench 44.7 (above Opus 5.5's 42.5 in this card).

## Behaviour observed in practice

- **M.** Artificial Analysis (Index v4.3.2, default fallback; run on a pre-release deployment whose structured-output bug Anthropic and AA
  both mention): 56.0 at `max` (second to Opus 5.5's 58), 51.9 `xhigh`, 46.8 `high`, 40.8 `medium`, 35.9 `low`. At `max` it used about
  193k output tokens per index task, which AA calls the highest it has measured (about 60 percent above Opus 5.5 at `max`), at $7.60 per task
  in the article ($7.67 in the page data), 134.1 output tokens a second, and a hallucination rate of 47.0 percent on AA-Omniscience
  (54 percent accuracy). Its price is below Opus 5.5's but its cost per index task is above it. AA plans a re-run. [aa-art, aa]
- **M.** AA's coding-agent runs with Claude Code: `max` 72.0 DeepSWE v1.1, 66.9 SWE-Atlas-QnA, 66.2 Terminal-Bench 4.0 (6 of 198 attempts fell
  back); `xhigh` 68.4, 62.1, 58.1; `high` 66.7, 56.5, 41.9; `medium` 65.5, 44.9, 27.3; `low` 61.9, 39.0, 25.3. Safeguard fallbacks hit the QnA
  component often (39 of 372 attempts at `max`). AA's reward-hacking audit flagged none of the 131 passing Terminal-Bench
  attempts it reviewed at `max`. [aa-code]
- **M.** Scale's SWE-Bench Pro V2 and the Terminal-Bench 4.0 leaderboard had no Sonnet 5.5 row; METR lists none. [scale, tb, metr]
- **A.** A hands-on review (secondary; its cost figures come from Artificial Analysis) advises `low` to `high` for Sonnet 5.5 and warns
  against `max`, reporting that one tester's image-drawing prompt at `max` used the full 128k-token output budget over more than fifteen
  minutes without completing and cost $1.28, and quoting developer feedback that the model is more reluctant to keep going and returns to
  ask the user questions, which matches Anthropic's own guide on check-ins at low and medium effort. [eesel]
- **L.** Anthropic's own testing and external testers say Opus 5.5 remains clearly stronger at complex open-ended work needing sustained
  judgement, though on some evaluations Sonnet 5.5 at `max` is comparable. [ann]

## Open questions

- AA's figures come from a pre-release deployment; the re-run may move them (its Terminal-Bench 63.6 trails Anthropic's 70.6).
- Anthropic's Terminal-Bench figure uses no internet egress and pre-cached resources; whether public runs reproduce 70.6 is untested.
