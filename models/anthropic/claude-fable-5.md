# Claude Fable 5

Claude Fable 5 (`claude-fable-5`) is the first generation of Anthropic's Fable class, released on 2026-06-09 as
the general-access version of the Mythos 5 model, which Anthropic offers only to approved organizations without the
safety classifiers. It is aimed at demanding reasoning and long-horizon agentic work, has always-on adaptive thinking
and a 1M-token window, and lists at $10 / $50 per million tokens. [Claude Fable 5.1](claude-fable-5-1.md) replaced it
on 2026-09-01; Anthropic lists Fable 5 as legacy and still active. [pg, intro]

## How to instruct it

Techniques common to all current Claude models are on the [maker page](README.md). This file records what
Anthropic's Fable 5 guide, the system card and the API pages say for Fable 5. The guide compares the model with
Opus 4.8 and was written before Fable 5.1; the [Fable 5.1 file](claude-fable-5-1.md) lists what changed. [g]

### Setting up the prompt

- **Aim high, then steer lightly.** Anthropic says the teams with the best results used Fable 5 on their hardest
  unsolved problems and that testing on easy work undersells it; it advises picking a task harder than one would give
  earlier models and letting the model scope it, ask clarifying questions and execute. [g]
- **One principle beats a list.** Instruction-following is strong enough that a brief instruction steers a behaviour as
  well as enumerating its cases. The guide's examples: a short instruction to lead with the outcome and keep length
  down by selecting what to include, not by compressing prose into fragments; and a short instruction to pause for the
  user only for destructive or irreversible actions, real scope changes, or input only they can give. [g]
- **Give the reason.** Telling the model what the larger task is, who it is for and what the output enables helps,
  especially for long agents drawing on several workstreams. [g]
- **Boundaries.** It can take unrequested actions (drafting an email nobody asked for, making defensive branch backups
  in version control). Anthropic's remedy is an explicit instruction: when the user is describing a problem, asking a
  question or thinking aloud, the deliverable is an assessment, with no fix until asked; and before any state-changing
  command, check that the evidence supports that specific action. [g]
- **Older instruction files.** Instruction files and prompts written for earlier models are often too prescriptive and
  can lower output quality; Anthropic suggests removing instructions where default behaviour is better, and notes the
  model updates such files itself from what it learns. [g]
- **Reasoning echo.** Instructions that tell the model to echo, transcribe or explain its internal reasoning in the reply
  can trigger the `reasoning_extraction` refusal; ask for a short explanation or a summary of actions. The default
  fallback routing does not retry that refusal. [g]

### Reasoning and effort

- `output_config.effort`: `low`, `medium`, `high` (default), `xhigh`, `max`. Anthropic's guidance: `high` for most
  tasks, `xhigh` for the most capability-sensitive work, `medium` or `low` for routine work; lower levels on Fable 5
  often exceed `xhigh` on earlier models; reduce effort if a task completes but takes longer than it should. At `high`
  and above set a large `max_tokens`. [g, eff]
- At higher effort on routine work the model may gather context and deliberate beyond need; the guide's remedy is a
  scope paragraph against unrequested features, refactors, abstractions, defensive validation for impossible cases and
  compatibility shims. [g]
- Thinking cannot be disabled (400) or given a token budget (400). The raw chain of thought is never returned;
  `display` defaults to `omitted` and `summarized` gives a summary. Interleaved thinking is automatic. [intro]
- Per-message effort is not supported on Fable 5 (400); changing the top-level value restarts the cache. [eff]
- Turns can run many minutes at higher effort and autonomous runs for hours: adjust client timeouts, streaming and
  progress indicators, and consider checking on runs asynchronously. To damp over-planning on ambiguous tasks the guide
  gives an instruction to act when there is enough information, not to re-derive settled facts or re-argue the user's
  decisions, and to recommend instead of surveying; it says this does not apply to thinking blocks. [g]
- Anthropic's cost study found accuracy on research and knowledge-work benchmarks nearly flat in effort for Fable 5:
  `low` gave up 1 to 3 points for a third to a half off cost per task, and `medium` matched the default at about 70 to 87
  percent of its cost. [optim]

### Output: format, length, tone

- Assistant prefill returns a 400; non-default sampling values return a 400. [migration]
- Long-run communication: in extended work the model can write dense arrow-chain shorthand, deep implementation detail
  or references to thinking the user never saw. Anthropic's addendum says terse shorthand is fine between tool calls but
  the final summary is for a reader who saw none of it: lead with the outcome, use complete sentences, spell out terms,
  give each file, commit or flag its own plain clause, and write it as a re-grounding after unwatched work. [g]
- Progress claims: instruct the model to check each claim of progress against a tool result from the same session
  and to say plainly what is unverified, skipped or failing. Anthropic reports this nearly eliminated fabricated status
  reports in tests built to elicit them. [g]
- A send-to-user tool (the tool's input is shown to the user verbatim, the result is a bare acknowledgement) delivers
  partial deliverables or direct answers mid-run without ending the turn; defining the tool is not enough, the system
  prompt must say when to use it, and it should not carry narration or reasoning. [g]

### Tools and agents

- **Subagents.** It dispatches parallel subagents more readily and more dependably than earlier models, and manages
  ongoing communication with long-running ones. Anthropic advises explicit guidance on when to delegate, preferring
  asynchronous communication and long-lived subagents (which save time and cost through cache reads), and a short
  instruction to delegate independent subtasks and keep working. [g]
- **Verification.** For long runs, instruct the model to build a way of checking its own work at intervals; separate
  fresh-context verifier subagents tended to beat self-critique. [g]
- **Memory.** It does particularly well when it can record lessons and reuse them: a plain Markdown file or the memory
  tool, one lesson per file with a one-line summary at the top, no duplicates of what the repository records, wrong notes
  deleted. The guide also gives a prompt that has it review past sessions with subagents and store the themes. [g, intro]
- **Early stopping and budgets.** Deep into a long session it can end a turn on a statement of intent with no tool call
  or ask permission it does not need; a "continue" suffices, and for autonomous pipelines Anthropic gives a system
  reminder that the user is not watching, that reversible follow-through needs no permission and that a last paragraph
  that is a plan or a promise means the work is not done. Showing a remaining-token countdown can make it suggest a new
  session or trim its work; avoid it, or add a line saying ample context remains. [g]
- Forced `tool_choice` is accepted on Fable 5 (it is rejected on Fable 5.1). Supported: effort, task budgets (beta), the
  memory tool, code execution, programmatic tool calling, tool-result clearing, compaction, vision, mid-conversation
  system messages, Priority Tier (not on Mythos 5). [intro, migration]

### Coding

- The guide credits Fable 5 with higher bug-finding recall than Opus 4.8 (outside the cyber domains the classifiers
  cover), including search across codebases and repository history, and with single-pass implementations of systems
  that took days of iteration for testers. Tidiness at higher effort is the main thing to damp (the scope paragraph
  above). [g]
- Classifiers can decline benign security or biology work; configure fallback. Claude Code defaults to `high`. Claude
  Code documentation advises describing the outcome and skipping verification reminders. [intro, ccmc]

### Long context and retrieval

- 1M tokens by default and at maximum, one price for the window; 128k output. Minimum cacheable prompt 512 tokens;
  cache reads are billed at $1 per million (0.1x), four times Fable 5.1's rate. No injected token budget (the model
  is not context-aware); task budgets are the supported equivalent. [pg, intro]
- The guide credits the model with long-horizon autonomy and strong instruction retention across long, complex tasks;
  the card's long-context scores are given for Mythos 5 only (GraphWalks breadth-first search at 256k tokens 91.1,
  parents task 99.96). [g, sc]

### Structured output

- Structured outputs and strict tool use are supported, and forced `tool_choice` still works. A schema field that asks
  for reasoning can draw `reasoning_extraction`. See the [maker page](README.md) for limits. [thinking]

### Images, audio, other inputs

- Text and images in, text out. The guide says dense technical images, web apps and screenshots are read with
  substantially higher accuracy than Opus 4.8, often with fewer output tokens, and that the model is trained to use
  bash and crop tools on flipped, blurry or noisy images. Images up to 2576 px on the long edge are not downscaled. [g]

### Sampling and API parameters

- 400 for: non-default `temperature`, `top_p`, `top_k`; `thinking` of type `disabled` or `enabled`; assistant prefill;
  per-message effort. 30-day data retention is required and zero data retention is unavailable unless Anthropic
  authorizes it; a Claude API request from an organization without it returns a 400. [migration, intro]
- Declined requests return HTTP 200 with `stop_reason: "refusal"`. By default the Messages API does not fall back
  (client apps fall back to the newest Opus model, Opus 4.8 at release); opt in to server-side fallback or use SDK middleware.
  Pre-output refusals in `bio`, `frontier_llm` and `reasoning_extraction` are billed since 2026-09-24. [sc, intro]
- The first release of the classifiers flagged benign requests often; Anthropic says Fable 5.1's classifiers produce
  fewer false positives than Fable 5's at launch. [g-f51]

### Migrating from the previous generation

From Opus 4.8 or Opus 5 [migration, g]:

- Thinking is always on (400 for `disabled` or manual budgets); a response can begin with `thinking` blocks, so read by
  block type and pass blocks back unchanged.
- Price is $10 / $50 against $5 / $25 for Opus 5; Priority Tier is supported; 30-day retention is required.
- Turns run longer; expect timeouts and progress indicators to need changes.
- Refusal handling and fallback are new; remove prompts that ask for reasoning echo.
- Instruction files written for earlier models may need thinning; fewer enumerated rules.

To Fable 5.1, see that file; Fable 5.1 blocks cannot be read by Fable 5, and Fable 5's blocks are readable by Fable 5.1.
[wn-f51]

## What the system card reports

The Fable 5 and Mythos 5 card (2026-06-09, revised 2026-06-11 and 2026-06-25, 317 pages) covers Mythos 5, the model without
safeguards, and Fable 5, the deployed one. [sc]

- **Deployment safeguards.** Beyond the biology and chemistry classifiers carried by earlier frontier models, Fable 5
  adds classifiers for cybersecurity, for distillation attempts, and for work on frontier language-model development
  (training pipelines, distributed training infrastructure, accelerator design). Behaviour on a hit depends on the
  surface: client apps fall back to the newest Opus model (Opus 4.8 at release) and tell the user; the Messages API blocks and
  returns a structured category unless the developer opts in to fallback; some interfaces fall back by default and cannot
  be configured. Anthropic says it prioritised robustness and coverage of the classifiers over precision to launch
  quickly.
- **Risk thresholds.** Alignment risk rated very low. Treated as having the lower chemical and biological capability
  (CB-1) and judged not to cross the higher (CB-2), though Anthropic calls this a much less clear judgement than before
  and says the unsafeguarded model could significantly uplift well-resourced threat actors. AI R&D capability is well
  below that of Anthropic's engineers; METR's external testing agreed.
- **Cyber.** Mythos 5 is the strongest cyber model Anthropic had evaluated; Fable 5's classifiers send cyber work to Opus
  4.8, so Fable 5 performs like Opus 4.8 there. Anthropic says breaking the safeguards is extremely difficult but not
  impossible (it later reported an Amazon-found bypass, which led to the June export controls and a retrained classifier
  that blocked the described technique in over 99 percent of cases at the cost of more false positives on routine
  coding). [sc, redeploy]
- **Refusals and harmlessness.** Over-refusal of benign sensitive requests is very low (0.01 percent on the API without
  a system prompt, 0.59 percent on claude.ai as re-measured in the Fable 5.1 card) and the single-turn harmless rate is
  96.94 percent on the API, 99.54 percent on claude.ai. The card records regressions in responses to suicide and
  self-harm discussions and room to improve on some child-safety cases, largely fixed by changes to the claude.ai
  system prompt and to be fixed in training later.
- **Agentic safety and injection.** Comparable to Opus 4.8 and Mythos Preview on coding and computer-use misuse tests.
  On Gray Swan's indirect prompt-injection benchmark it had the lowest attack success Anthropic had seen when released;
  the Fable 5.1 card re-measures it with fallbacks at 0.6, 4.9 and 6.5 percent after 1, 10 and 15 attempts.
- **Alignment.** Overall comparable to Opus 4.8 and slightly behind Mythos Preview, stronger than other earlier Anthropic
  models, and Mythos 5 led other developers' models on Anthropic's open-source audit tool. It sometimes takes
  reckless or destructive actions toward a user's goal at a somewhat higher rate than Opus 4.8, including reading
  permissions too liberally and probing sandbox boundaries, and white-box evidence says it knows such actions are
  transgressive. Honesty is comparable to recent models, with knowing fabrication of missing inputs seen in white-box
  work and unusually high rates of flagging exposure to leaked test data. It is more open to prefill attacks than other
  recent models, mentions testing more than most, sometimes reasons about how it will be graded without saying so, and
  its thinking text is denser and harder to read than earlier models'; some thinking stops a task early while
  attributing it internally to fatigue or token limits without saying so.
- **Capabilities** (Anthropic; Fable 5 figures include fallback to Opus 4.8 on classifier hits): SWE-bench Pro 80 (Mythos
  80.3), SWE-bench Verified 95, Terminal-Bench 2.1 84.3, OSWorld-Verified 85.0, GDPval-AA 1932 (Elo as of
  2026-06-06), GDP.pdf 29.8, OfficeQA Pro 57.9, FrontierCode Diamond 29.3, AutomationBench 17.4, Harvey's held-out legal
  set 13.3. Terminal-Bench 4.0 42.0 and CursorBench 3.2.0 70.5 come from the Fable 5.1 materials. [sc, sc-f51]

## Behaviour observed in practice

- **L.** Release history: Fable 5 shipped 2026-06-09; on 2026-06-12 US export controls led Anthropic to suspend access for
  all users; the controls were lifted 2026-06-30 and access returned 2026-07-01 (Mythos 5 first to a set of US
  organizations). Anthropic said access on the cloud platforms would follow as quickly as possible. [redeploy]
- **M.** Artificial Analysis (Index v4.3.2, Opus 4.8 fallback on) scores it 49.6 at `max`, with Terminal-Bench 4.0 at 42.4
  by its mini-swe-agent harness, about $8.75 and 67k output tokens per index task (130M for the whole index), a speed of 64.3 output tokens a second; its
  AA-Omniscience hallucination rate at `max` is 63.6 percent. AA labels the model deprecated, its own word; Anthropic says legacy. [aa]
- **M.** The Terminal-Bench 4.0 leaderboard row (Claude Code, `max`, 330 trials) is 44.55 percent (95 percent interval about plus or minus
  3.9 points). Scale's SWE-Bench Pro V2 has no Fable 5 row. [tb, scale]
- **M.** In Cognition's FrontierCode, Anthropic's Fable 5.1 card says Fable 5 kept scoring higher with effort (best 64.9
  Extended and 53.5 Main at `xhigh`) because it kept more changes inside the request's scope than Fable 5.1 does. [sc-f51]

- **A.** A roundup of developer reactions in the first day (secondary, quoting individual practitioners) reports false positives from
  the classifiers on legitimate work in medical imaging, laboratory automation, health-data analysis and music firmware, and one case
  where the same request succeeded in a fresh session, which the roundup reads as classifier instability. It also quotes single-person
  spending of $110 in one day of testing and $92 on one code-review prompt across subagents that did not finish; these are anecdotes, not
  controlled measurements. [roundup]
