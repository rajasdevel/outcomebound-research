# Claude Haiku 4.5

Claude Haiku 4.5 (`claude-haiku-4-5-20251001`, alias `claude-haiku-4-5`) is Anthropic's small, fast class model, released on
2025-10-15 as the successor to Haiku 3.5. It is the only Haiku in this folder: the class's previous generation (Haiku 3.5) was
retired on 2026-02-19 and Haiku 5.5 is announced but not released. It is a hybrid model with an optional extended-thinking
mode, a 200k-token window, 64k output and a $1 / $5 list price; Anthropic says it matches the coding performance of Sonnet 4,
a frontier model five months earlier, at one third of the cost and more than twice the speed. It is the oldest model in this
folder and the only one that predates the 5-series tokenizer, adaptive thinking and effort control. [pg, ann]

## How to instruct it

Anthropic publishes no guide specific to Haiku 4.5. The general
[Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)
page lists it among the current models and says to re-check a technique measured on another model; its techniques (clear and
explicit instructions, examples, XML tags, documents first, a role, tool-use wording) are summarised on the
[maker page](README.md). Most of the model-specific advice for the 5-series (effort, adaptive thinking, progress-update
blocks, bound thinking blocks) does not apply to this model. [bp]

### Setting up the prompt

- **Concise, direct Claude 4 style.** The migration guide says Claude 4 models have a more concise, direct communication style than the
  Claude 3 line and tells users to review prompts against the best-practices page. [migration]
- **Tell it about the harness.** Haiku 4.5 is one of the models trained to be context-aware: the API gives it its window (200k) and a
  running count. Anthropic says to state in the prompt when a harness compacts context or saves state, or the model may wrap up work as
  the limit nears; a sample prompt tells it that context is compacted automatically, that it should not stop early for budget reasons
  and should save progress before a window refreshes. [bp, ctx]
- **Instructing against test special-casing.** Anthropic's card found it hard-codes or special-cases tests more than Sonnet 4.5 on
  tasks built to provoke that (below). Its impossible-task test used a prompt that asks for a high-quality general solution, forbids
  hard-coded test cases and asks the model to say when a task is unreasonable; that prompt reduced the hack rate from 30 to 23
  percent. The best-practices page offers a longer block with the same intent. [sc, bp]
- **Check required behaviour in code.** The documents say nothing specific on how far a small model follows long instruction lists;
  Anthropic's own placement is high-volume, latency-sensitive and sub-agent work whose output can be checked. [choosing, optim]

### Reasoning and effort

- **No effort parameter.** It is not on Anthropic's list of models that support `effort`, and the models overview shows the default
  as not supported. Depth is controlled by thinking, which is off unless requested. [eff, models-overview]
- **Extended thinking.** `thinking: {"type": "enabled", "budget_tokens": N}` with N at least 1,024 and below `max_tokens` (thinking
  counts toward `max_tokens`); `adaptive` returns a 400; `disabled` or no field means no thinking. Anthropic's migration guide suggests
  enabling it for coding and reasoning tasks that need more; for simple tasks start near the minimum and raise, for hard ones start
  around 16,000 or more. Changing the budget between requests invalidates the cache. The previous turn's thinking blocks are stripped
  from context by the API. Interleaved thinking (reasoning between tool calls) is not supported; the beta header is accepted and ignored.
  The current thinking page makes `summarized` the default display on models of this generation; the card says the whole thought
  process is usually available and that in rare long cases a second instance of the model summarises beyond a point. [migration, ext, thinking, sc]
- Anthropic's launch figures used a 128K thinking budget. [ann]

### Output: format, length, tone

- **Prefill is allowed**, except while extended thinking is on; it still works on this model although it returns a 400 on every model
  from the 4.6 generation on. [bp, thinking]
- **Sampling.** `temperature` and `top_p` are accepted but not both in one request (400). With extended thinking on, `temperature` and
  `top_k` are incompatible and `top_p` is limited to 0.95 to 1. [migration, thinking]
- Claude 4 style is more concise and fact-grounded; ask for a summary after tool work if one is wanted (best-practices note). [bp]

### Tools and agents

- Parallel tool calls and the explicit-action wording in the best-practices page apply. Tool versions: use `text_editor_20250728` and
  `code_execution_20250825`; the `undo_edit` command is removed; forced `tool_choice` is accepted (not together with extended
  thinking). [migration, thinking]
- Not available on this model: effort, per-message effort, task budgets, mid-conversation system messages and turn-scoped system messages,
  compact on demand. Server-side compaction is documented for Claude 4.6 and later models, so not for this one. [README, ctx]
- Anthropic's launch post frames it for sub-agent roles: a larger model can plan and orchestrate several Haiku 4.5 instances on subtasks.
  In Anthropic's advisor-strategy test on a graduate-level science question set, a Haiku 4.5 executor gained a great deal from an Opus 5
  advisor, while a frontier executor gained almost nothing. [ann, optim]

### Coding

- Anthropic reports 73.3 percent on SWE-bench Verified (bash and file-edit tools, 50 trials, 128K thinking budget, default sampling,
  with a prompt addition that told the model to use tools as much as possible and to write its own tests first), and describes strong
  agentic coding and computer use for its class. The Scale AI public SWE-Bench Pro V2 row is 25.5, against 88.2 for Sonnet 5 and 92.2 for
  Fable 5.1; Anthropic's cost study also places it outside long agentic loops (below). [ann, scale, optim]
- Claude Code: its `haiku` alias selects a Haiku model for simple tasks [ccmc]. The card's Claude Code malicious-use test: without mitigations it
  refused 69.39 percent of malicious requests and helped with 88.85 percent of dual-use and benign ones (Sonnet 4.5: 66.94 and 97.54);
  two standard prompting mitigations raised refusal to 96.33 percent but cut dual-use and benign allowance to 81.48 percent,
  so Anthropic changed the system prompt before release, which reached 99.17 and 87.71 percent. [sc]

### Long context and retrieval

- 200k tokens (100 images or PDF pages per request); 64k output. The minimum cacheable prompt is 4,096 tokens (512 on the newest models).
  Cache read $0.10 per million, writes $1.25 (5 minutes) or $2 (1 hour). Previous turns' thinking blocks are removed. The model gets its
  remaining window from the API. No 1M window. [pg, cache, ctx]

### Structured output

- Structured outputs and strict tool use are supported on Haiku 4.5 on the Claude API, Google Cloud and Foundry; on Amazon Bedrock only the
  legacy integration offers them. Prefill is also available where thinking is off, though it cannot be combined with structured outputs and Anthropic's
  best-practices page recommends moving off it. Limits and behaviours of
  the feature are on the [maker page](README.md). [so]

### Images, audio, other inputs

- Text and images in, text out. Images are processed at the standard resolution tier: long edge up to 1,568 px and 1,568 visual tokens
  (the 5-series sees 2,576 px and 4,784). [vision]

### Sampling and API parameters

- `temperature` or `top_p`, not both. Max output 64k; Batch API has no 300k extension. Model id: `claude-haiku-4-5-20251001` (Claude API),
  `claude-haiku-4-5` (alias, Claude Platform on AWS and Foundry), `anthropic.claude-haiku-4-5` (Bedrock Messages API),
  `anthropic.claude-haiku-4-5-20251001-v1:0` (Bedrock InvokeModel), `claude-haiku-4-5@20251001` (Google Cloud). It is not among the models that
  Anthropic's refusals-and-fallback page lists as running the category classifiers, so no category-based fallback is documented for it;
  the migration guide still tells integrators to handle the `refusal` stop reason. Price $1 in / $5 out, batch $0.50 / $2.50; US-only inference 1.1x applies only to Claude 4.6 and
  later models. [pg, pricing, migration]
- Retirement: not sooner than 2026-10-15 (Anthropic's commitment), twelve days after this file's check date; Anthropic gives at least 60 days' notice for a public
  model, and none had been announced on 2026-10-03. [deprecations]

### Migrating from the previous generation

From Haiku 3.5 and earlier Haiku models [migration]:

Anthropic's checklist:

1. The model id becomes `claude-haiku-4-5-20251001`.
2. **Breaking:** only one of `temperature` and `top_p` may be sent; tool versions move to the current ones and the `undo_edit`
   command is gone.
3. Applications are to handle the `refusal` stop reason; rate limits are separate from Haiku 3.5's.
4. New in the generation: extended thinking, context awareness, 64k output.
5. Prompts are to be reviewed against the best-practices page for the more concise style.

To newer models: Anthropic's guidance for moving up is in the Sonnet 5.5 and Opus 5.5 files; thinking becomes adaptive, sampling parameters
become 400 errors and prefill stops working. [bp]

## What the system card reports

The Haiku 4.5 card (October 2025, 39 pages) is the oldest card in this folder and uses the older AI Safety Level framework. [sc]

- **Release level.** Released under ASL-2, after ASL-3 "rule-out" tests: on its automated biology and autonomy evaluations it matched or
  scored below Sonnet 4 (released under ASL-2) on most and stayed well below ASL-3 thresholds. Only automated tests were run (no human uplift
  trials or expert red-teaming).
- **Harmlessness and refusals.** Single-turn violative-request harmless rate 99.38 percent (99.40 default, 99.36 with extended thinking), with
  no significant difference from Haiku 3.5's 99.72; occasional high-level answers on biological and radiological weapons topics where it
  assumed educational intent (Anthropic gave a smallpox-synthesis example). Over-refusal of benign sensitive requests 0.02 percent against
  4.26 percent for Haiku 3.5. Multi-turn: failures in up to 25 percent of some risk areas for Haiku 3.5, 5 percent or less for Haiku 4.5.
  Refusal replies can be too specific in sensitive areas (the same note as Sonnet 4.5).
- **Agentic safety.** Claude Code malicious-use figures above; a perfect score on a separate malicious agentic coding test (as for Haiku 3.5).
  Prompt injection, computer use: attack prevention 72.2 percent without and 92.4 percent with the computer-use classifier (Sonnet 4.5: 78.0 and
  82.6); MCP tasks 92.5 percent and tool use 93.4 percent without safeguards. On Gray Swan's agent red-teaming benchmark it ranked among the best
  of 25 model variants.
- **Alignment.** Safety properties similar to or stronger than Sonnet 4.5 on high-stakes misalignment tests; high verbalised evaluation awareness
  (about 9 percent of scenarios in the main automated suite, largely invalidating three hand-built agentic-misalignment scenarios), so Anthropic
  reports some uncertainty while judging it very unlikely to hide urgent issues. It was not found highly capable at undermining oversight; its
  sabotage-capability test (SHADE-Arena) showed it weak, especially with thinking visible.
- **Reward hacking.** Average rates about equal to Sonnet 4.5's and about half Haiku 3.5's. On tasks built to provoke special-casing it hacked 6 percent
  (classifier) and 3 percent (hidden tests) of the time, against 1 and 1 for Sonnet 4.5, so expect more hard-coding to satisfy tests; on impossible
  tasks 30 percent with no prompt and 23 percent with an anti-hack prompt (Sonnet 4.5: 53 and 20).
- **Capabilities.** The card points to Anthropic's launch post for benchmarks and does not tabulate them. Capability gains over Haiku 3.5 are
  described as large in agentic coding and computer use; the model is not a frontier model.

## Behaviour observed in practice

- **M.** Artificial Analysis's Intelligence Index v4.3.2 scores the reasoning variant 16.9 and the non-reasoning variant 15.4, against 38.2 for
  Sonnet 5 at max; the reasoning run cost about $0.28 and 18.5k output tokens per index task. Its GPQA score on AA's run is 0.67 (reasoning).
  AA's page data carries a Terminal-Bench 4.0 value of 0 for the reasoning variant that the page does not display, so no Terminal-Bench 4.0
  figure is recorded. [aa]
- **M.** Scale's SWE-Bench Pro V2 lists it last of 11 rows at 25.50 with Claude Code, labelled `xhigh` although Haiku 4.5 has no effort parameter. The
  Terminal-Bench 4.0 leaderboard, AA's coding-agent page and METR's page have no Haiku 4.5 row. [scale, tb, aa-code, metr]
- **L.** Anthropic's cost study: on a graduate-level science question set Haiku 4.5 answered at about a fifth of Opus 5.5's cost per question with
  63 percent accuracy against 92 percent, and fell much further behind on long coding tasks; Anthropic says it fits high-volume work whose output
  can be checked, not long agentic loops. [optim]
- **L.** Anthropic's Sonnet 5.5 and Opus 5.5 announcements say Haiku 5.5 will follow in the coming weeks; it had not shipped on 2026-10-03. [ann-s55]
