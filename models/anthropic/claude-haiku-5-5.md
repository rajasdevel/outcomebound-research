# Claude Haiku 5.5

Claude Haiku 5.5 is Anthropic's current small-model generation, released on 2026-10-07 as the successor to
[Haiku 4.5](claude-haiku-4-5.md). Anthropic targets classification, extraction, routing and bounded subagent
work. It has adaptive thinking, adjustable effort and a larger window; its low price depends on prompt
length. These are maker specifications and positioning, not proof for every workload. (L) [ann, page]

## How to instruct it

### Setting up the prompt

Family techniques are on the [maker page](README.md). Anthropic advises a clear task and output contract,
a system role, relevant examples, and XML tags when instructions and data are mixed. (L) [bp]
For search, the Haiku guide supplies the date and targets changeable facts; its tests found blanket search
mandates wasteful. (L) [g]

### Reasoning and effort

`output_config.effort` accepts `low`, `medium`, `high`, `xhigh` and `max`. Anthropic starts most work at
`medium`, also Claude Code's default; `low` suits brief, cheap tasks, `high` longer work and strict
instructions. It recommends comparing the top levels with Sonnet 5.5 on task quality, speed and cost.
Effort affects thinking, reply length and tool use, and is not a token cap. (L) [eff]

Adaptive thinking is on when `thinking` is absent or `type` is `adaptive`. Manual `enabled` with
`budget_tokens`, and `between_tools`, return 400. `disabled` works only through `high`. The default
`display: omitted` hides thinking text but bills its tokens; `summarized` returns a summary, never raw
reasoning. Thinking and answer share `max_tokens`. Select response blocks by `type`, and preserve signed
thinking blocks unchanged across turns. (L) [think]

Top-level effort changes restart the message cache. Per-message effort needs adaptive thinking and
`mid-conversation-output-config-2026-07-01`; the effort guide documents it on the Claude API and Google
Cloud. A different per-message effort with thinking disabled returns 400. (L) [eff]

### Output: format, length, tone

Anthropic's overview says to specify the desired length. An assistant prefill is rejected even with
thinking disabled; use a user turn for continuations and a system instruction for a direct opening. (L) [page, mig]
The Haiku guide suggests adaptive medium to reduce visible reasoning-like prose. At xhigh in chat it
can leave the answer in thinking with no visible reply. (L) [g]

### Tools and agents

Forced `tool_choice` (`any` or a named tool) is accepted, but suppresses pre-tool thinking. `auto` lets the
model reason before choosing a tool. This differs from Sonnet 5.5's forced-choice rejection. (L) [mig]

Anthropic sends mid-task user words as user text after tool results and puts harness notices separately.
A user message inside a tool result can be ignored as injection. (L) [g]

On the Claude API and Google Cloud, computer use requires `computer_toolset_20260801`; browser use is
`browser_toolset_20260801`. The previous `computer_20250124` is rejected. Toolset results identify each
member call by name and `toolset_name`. (L) [mig]

Classifiers return a normal response with `stop_reason: refusal`, not a successful task. Haiku has no
server-side fallback: `fallbacks: default` leaves a refusal standing, and a model list returns 400. It
mints no fallback credit, so a client retry on another model pays its cache write. (L) [refuse]

### Coding

Anthropic reports missed checks at low/medium and early stops in long prompts. Its completion and
verification instructions improve these behaviors at greater token cost. (L) [g]
The maker positions Sonnet 5.5 and Opus 5.5 ahead for complex agentic coding, and Haiku for narrower work.
This is a deployment suggestion, not a measured universal routing rule. (L) [ann]

### Long context and retrieval

The window is 1M tokens; synchronous output is 128k. The Batch API permits 300k output with
`output-300k-2026-03-24`. These limits do not guarantee retrieval accuracy. (L) [page]
Anthropic's family guide puts long documents first and the question last, with source metadata and
relevant evidence extraction for document analysis. (L) [bp]

Unlike Haiku 4.5, it receives no automatic remaining-context tags. (L) [ctx] Messages API task budgets
are supported with `task-budgets-2026-03-13`, with a 20,000-token minimum. They advise pacing across a
loop; only `max_tokens` enforces an output cap per request. Task budgets are unavailable in Claude Code
and Cowork. (L) [budgets]

The cache minimum is 512 tokens, down from Haiku 4.5's 4,096. Thinking blocks remain preserved when later
user content is added, unlike the older Haiku behavior. System/tool/thinking changes can invalidate
cached prefixes; check `cache_read_input_tokens` and `cache_creation_input_tokens`. (L) [cache]

Standard input/output/cache-read rates are $0.10/$0.50/$0.01 per Mtok through 100,000 prompt tokens and
$0.50/$2.50/$0.05 above. The threshold includes all input, including cache reads and writes; a cache hit
does not keep a longer request in the lower tier. Each request is priced separately. (L) [price]

### Structured output

`output_config.format` constrains final JSON; `strict: true` constrains tool inputs. These are separate
controls. Refusals and `max_tokens` stops need handling even with a schema. Haiku 5.5 is listed on the
Claude API, Platform on AWS, Google Cloud and Foundry; Claude in Amazon Bedrock lacks structured
outputs. Schema limits and the older Bedrock integration are on the maker page. (L) [json]
With thinking off and JSON output, Anthropic reports missed tools. Its alternatives are adaptive
thinking, removing JSON format, or forced tool choice. (L) [g]

### Images, audio, other inputs

Text and images go in; text comes out. The API supports JPEG, PNG, GIF and WebP through base64, URL or
Files API sources where the platform supports them. Anthropic advises placing images before their
question, and warns that counting and precise spatial tasks can be unreliable. No native audio output
is specified. (L) [page, vision]

### Sampling and API parameters

Anthropic advises omitting `temperature`, `top_p` and `top_k`. The migration page permits temperature
only at 1 or top_p only at 0.99; any top_k, any other value, or both temperature and top_p return 400.
A top_p of 1 is also rejected. This is fixed sampling, not a temperature-tuning model. (L) [mig]

Thinking blocks are bound to their earlier conversation prefix. Changing `system`, `tools` or earlier
messages while replaying them can return 400; accounts before 2026-08-31 need the binding option to
trigger that error. Blocks replayed from an unrelated account are dropped while the request succeeds.
This matters to shared conversation stores. (L) [wn, mig]

### Migrating from the previous generation

Anthropic's migration checklist from Haiku 4.5 changes the model id to `claude-haiku-5-5` (Bedrock adds
`anthropic.`), replaces manual thinking budgets with adaptive thinking, removes sampling settings and
prefill, and moves computer use to the toolset. Clients must read blocks by type, leave room for
thinking, handle refusals and keep replayed history valid. Priority Tier commitments on 4.5 do not
transfer to 5.5. (L) [mig]

The new tokenizer counts about 30 percent more tokens for the same input, depending on content. The
request shape stays the same, but limits and cost estimates must use Haiku 5.5 counts. (L) [wn]

## What the system card reports

The 2026-10-07 maker card finds no new RSP threshold and rates catastrophic misalignment risk low. (L)
[sc, sections 2–3] Its cyber classifiers are narrower than larger models; CB safeguards match Sonnet 5
and Opus 5, without fallback. (L) [ann]

Its automated audit has the highest over-refusal among models tested, despite improved single-turn
benign refusals. Undisclosed leaked-answer use is 17 percent versus 4.5's 2 percent; concealed-change
disclosure is 96 versus 10 percent. Out-of-sandbox file/credential use is 4.0 percent in a dedicated test.
These are evaluation rates. (L) [sc, section 6]

Gray Swan Q1+Q2 injection success is 7.1 percent at 15 attempts without product protections; GUI tasks
reach 24.4 percent. Shade coding succeeds on 0.08 percent of attempts across 6/40 scenarios without
probes, and 0/40 with probes. Other models' fallbacks affect comparison. (L) [sc, section 5]

## Behaviour observed in practice

Artificial Analysis's release analysis finds about 162k output tokens per Intelligence Index task at
max. Moving xhigh to max gains two index points for about 1.8 times the tokens. It reports a pre-release
AutomationBench-AA over-refusal issue and plans a re-run; its cost figures do not yet model the higher
prompt-length tier. These limits matter when comparing quality per dollar. (M) [aa-art]

No independently reproduced general agent reliability, long-running production behavior or migration
failure rate is established by the sources read for this entry. Customer accounts in the launch post
are selected by the maker and are not a substitute. [ann]

## Benchmarks

Independent results are recorded before the maker result in the card. Artificial Analysis reports
Intelligence Index v4.3.2 43 at max and Terminal-Bench 4.0 33 percent. AA documents mini-swe-agent,
all 66 tasks and pass@1 averaged across three repeats/task; the release article does not separately
restate effort for its terminal row. (M) [aa-tb-method] Scale's displayed Haiku row is
52.94 with an interval of 13.01 at high in mini-swe-agent, but the text view does not settle the
full/HARD selection, sample count or interval method. Keep that qualification with the result. (M)
[aa-model, aa-art, scale]

Anthropic's 39.2 percent Terminal-Bench result uses Claude Code; settings differ from AA's run.
The card preserves the maker's settings. (L) [sc, section 8.4]
