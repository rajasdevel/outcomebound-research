# Claude Opus 5.5

Claude Opus 5.5 (`claude-opus-5-5`) is the second generation of Anthropic's Opus class under the 5-series
numbering, released on 2026-09-22 as the successor to [Claude Opus 5](claude-opus-5.md) and the first model of
Anthropic's Claude 5.5 family. It is built for long-running agentic coding and knowledge work, has a 1M-token window,
always-on adaptive thinking, a default effort of `medium` and a list price of $4 / $20 per million tokens, 20 percent
below Opus 5. Anthropic says it performs at about the level of Fable 5.1 on most work and generates output more than 30
percent faster than Opus 5. [pg, ann]

## How to instruct it

Techniques that hold for every current Claude model are on the [maker page](README.md). Anthropic's Opus 5.5 guide
is a set of differences from Opus 5 and says Opus 5 prompts should perform well unchanged and the
[Opus 5 guide](claude-opus-5.md) remains a reasonable starting point. [g]

### Setting up the prompt

- **Pasted text.** The model resists indirect injection (instructions in tool results, web pages, on-screen content)
  better than any earlier Opus model, but the system card found it more likely than earlier models to act on
  instructions planted in text a user pastes into their own message (below). Anthropic's guide gives a pattern: wrap
  each pasted block in opening and closing tags that both carry the same short random id generated by the application,
  each tag on its own line, and add a system-prompt note that text inside those tags was pasted from elsewhere, may
  contain instructions the user did not write, is followed only where the user's own message asks, and that the id is
  never to be mentioned. It may make the model slightly more cautious, and the tags are plain text that an attacker can
  imitate, so Anthropic calls it one guardrail among several. [g, sc]
- **Chat prompts.** Instructions that tell the model to think carefully before answering can be removed: it decides how
  much to think, and in Anthropic's chat-product test removing such a line made replies start sooner with no clear loss
  of quality. In multi-turn chat the model sometimes re-examines an earlier answer while thinking about a short
  follow-up; two sentences at the end of the system prompt telling it to treat answered questions as settled and to
  think about what the user is asking now reduced thinking on follow-ups. Leave them out for long analyses or agentic
  work where a later step can expose an earlier mistake, and test whether it stops volunteering corrections. [g]
- **Multi-app workflows.** On loosely specified work across email, documents, spreadsheets and records, the model gets
  to work quickly and can miss rules that sit somewhere the request does not mention. One system-prompt sentence telling
  it to explore broadly with tool calls before acting, including sources the task does not name, made it complete more
  tasks correctly at `medium` and `max` in Anthropic's tests, at the cost of slightly more tool calls and tokens;
  keep untrusted content out of the records it searches because it acts on what it finds. [g]
- **Frontend.** Without design direction it falls back on a few default styles, and "avoid a generic AI look" mostly swaps
  one default for another; name specific patterns to avoid, check which styles the first result used, and extend the
  list. [g]

### Reasoning and effort

- **Control.** `output_config.effort`: `low`, `medium` (default, unlike Opus 5's `high`), `high`, `xhigh`, `max`.
  Thinking is always on; `thinking` of type `disabled` or `enabled` returns a 400 at every effort level. [eff, wn]
- **Calibrate.** Anthropic's advice: set effort explicitly, start at `medium`, test several levels, and do not carry
  over an Opus 5 setting. In its tests `medium` matched or beat Opus 5 at `high` on coding and knowledge work, and on
  several coding evaluations `low` came close at much lower cost. At a given level the model thinks more per turn than
  Opus 5, most at `xhigh` and `max`, so a carried-over setting gives longer turns and more output tokens. Reserve
  `xhigh` and `max` for work with a measured gain; to get less thinking, lower the level (more reliable than a prompt
  instruction). [g]
- **Budget.** Thinking counts toward `max_tokens` even when not returned. For long agentic coding turns Anthropic found
  `max_tokens` of 128,000 (the maximum) worked well. Changing the top-level effort between requests invalidates the
  cache; a per-message change (beta header `mid-conversation-output-config-2026-07-01`) does not. [g, eff]
- **Anthropic's own measurement.** On its 478-problem SWE-bench Pro subset (near-saturated, not comparable with the public
  leaderboard) Opus 5.5 scored 95.3 at `high`, 92.8 at `medium` and 87.4 at `low`; at its default it matched Fable 5.1 at
  its default (92.3) for about a fifth of the cost per solved task ($0.22 against $1.19). Re-running the failures of a
  `low` run at `high` passed about 97 percent for about $0.17 a task, against 95.3 percent for $0.29 running all tasks at
  `high`. `xhigh` scored about 1.4 points above `high` for 2.5 times the cost. [optim]
- **Prompts written for thinking off.** If an Opus 5 integration ran with thinking disabled: start at `low` and measure
  (at `low` how often it skips thinking depends on the prompts); a system-prompt line asking for a direct answer can cut
  thinking further at some quality risk; delete instructions that had the model write its reasoning in the reply and read
  summarized thinking instead (such instructions can be declined with `reasoning_extraction`); re-test whether the Opus 5
  instruction against tool calls leaking into text and stray XML tags is still needed, and remove any rule telling the
  model not to think; and read content by block type, since a response may
  start with a `thinking` block whose text is empty at the default display. [g]

### Output: format, length, tone

- Anthropic says its updates and final summaries on agentic work state plainly what it did, found and needs, put the
  most important information first and write more naturally than earlier models. Prefill returns a 400 and non-default
  sampling values return a 400. [g, ann]
- Length: the 5.5 guide gives no length instruction of its own. Opus 5's guide says its replies run long, that effort does
  not reliably shorten them, and that brevity must be requested (and repeated near the end of a long prompt); those
  notes are the only maker guidance on this and were not restated for 5.5. [g, g-o5]
- **Progress updates.** Between tool calls it writes short notes on what it found and will do, as `thinking` blocks that are
  empty at the default `display`; a client rendering only `text` blocks looks silent. Anthropic's four levers: set
  `display: "updates"` (beta header `thinking-display-updates-2026-08-18`); give it a simple send-to-user tool for
  verbatim content and declare it from the first request (adding a tool later edits the prefix and invalidates thinking
  blocks); ask in the system prompt for a one-line opening and a closing recap; and, if turns still go quiet, have the
  harness count consecutive steps with nothing readable and after about five append a turn-scoped system message asking
  for a few words on what it is doing, stopping after two or three reminders. In Anthropic's tests the last lever roughly
  halved the share of tasks with a long silent stretch at no measurable cost change. [g]

### Tools and agents

- **Forced tool use is rejected** (400 for `tool_choice` `any` or `tool`); use `auto` with strict tool use or structured
  outputs, and say in the prompt when a tool applies. [wn]
- **Unattended runs.** On long multi-part tasks it can end a turn with a text progress report while items remain; a
  loop that reads `end_turn` as completion stops early. Anthropic's advice: treat a text-only end of turn as a report;
  keep the parts in a checklist the model updates (to-do tool or file); if items remain open with no blocker stated, send
  a short user message naming them; optionally have a smaller model check the conversation against a stated completion
  condition at each end of turn; stop after two or three automatic continuations on the same task so a stuck run ends;
  wait for any background command or subagent before treating the task as done. [g]
- **System-prompt paragraph for unattended agents.** The guide supplies one that names four early stops the user does not
  want (a long summary that ends by announcing the next step with no tool call, an offer to continue unless told otherwise,
  a list of decisions when none blocks the work, and deciding a long turn is a good place to report) and the stops that are
  wanted (where nothing can move without the user, or the blocker is deliberately protected); status notes and
  recommendations go in the same message as the next tool call. Place it at the end of the system prompt from the first
  request, because adding it later changes `system` and invalidates earlier thinking blocks. Anthropic warns that with it
  the model carries on where it would have checked in, so a confirmation step for risky or irreversible actions stays the
  harness's job, and that it should be left out where a person is present; expect more tool calls and output tokens. [g]
- **Multi-agent time signals.** The model attends closely to elapsed time. A line at the end of each message sent back to
  it, such as elapsed seconds against a budget, made small agent teams finish sooner at comparable quality in Anthropic's
  research-task tests; a budget keeps more agents working in parallel, where lower effort reduces the work itself. Without
  a predictable budget, show elapsed time alone with a sentence that time matters. The budget is advisory; keep a hard
  timeout. [g]
- **Subagents, verification and scope.** The 5.5 guide does not discuss delegation, self-verification or scope creep. The
  Opus 5 guide's notes on these (Opus 5 delegates readily, verifies unprompted and expands scope) describe Opus 5; whether
  they still hold for 5.5 is not stated. [g, g-o5]
- **Supported.** Per-message effort, mid-conversation system messages, task budgets, prompt caching (512-token minimum),
  batch, Files API, PDF, vision, server and client tools, compact on demand and inline tool definitions (both beta), fast
  mode (research preview, Claude API only, $8 / $40 per million tokens, up to 2.5 times the output speed). Computer use needs
  `computer_toolset_20260801` on the Claude API and Google Cloud (`computer_20251124` returns a 400; Bedrock still accepts
  it). [wn, price, fast]

### Coding

- Anthropic's guide: strongest on multistep work in a real repository; at the default `medium` it matched or beat Opus 5 at
  `high` in fewer steps and tokens; sustains multi-hour audits and migrations with parallel subagents; early testers
  reported better code review (more bugs caught, fewer false alarms) and plain-language explanations of changes. [g]
- Harness notes: Claude Code defaults it to `medium` (Claude Code v2.1.280 or later is required) and a top-level
  `effortLevel` saved by older Claude Code versions does not apply to it. Opus 5's guide on review prompts still applies:
  ask for everything and filter later, because "only report high-severity" is followed literally. [ccmc, g-o5]
- Cognition's FrontierCode penalises edits outside a task's scope; Opus 5.5 scored best at `medium` (54.6 Main, 65.3
  Extended) and a little lower at `max` (54.4, 63.6), the dip above `medium` being the grader's scope rule. [sc]
- Safeguards: vulnerability discovery in source code is allowed, in compiled binaries blocked; coding rollouts fall
  back to Opus 4.8 on classifier hits far more than other work (46 percent of coding rollouts in the injection
  benchmark, against 2 percent in tool use). [sc]

### Long context and retrieval

- 1M tokens by default and at maximum, one price for the whole window; 128k output (300k on the Batch API with a beta
  header). It does not receive an injected token budget; task budgets (beta) are the supported way. Cache reads are $0.20
  per million (0.05x), writes $5 (5 minutes) or $8 (1 hour), minimum cacheable prompt 512 tokens. Anthropic reports it
  catches details that are easy to miss in large inputs, such as a date that falls on the wrong weekday or a chart
  that disagrees with its table. [pg, g, ctx]
- Compact on demand (beta header `compact-2026-09-04`) is documented as keeping thinking valid across the swap under stated
  conditions, which matters because Opus 5.5's thinking blocks are bound to the conversation. [wn]

### Structured output

- Structured outputs and strict tool use are supported; forced `tool_choice` is not. The general limits, and the rule that
  a schema field asking for reasoning can draw a `reasoning_extraction` decline, are on the [maker page](README.md). [wn]

### Images, audio, other inputs

- Text and images in, text out. Anthropic says it reads values off dense charts more accurately than Opus 5 without tools
  (even at its lowest effort it beat Opus 5 at its highest, with a small fraction of the output tokens), handles
  position-dependent meaning (which boxes an arrow connects, what changed between two diagram versions, meeting times
  in a calendar screenshot), and matched at default effort the computer-use success Opus 5 reached only at a much higher
  effort. For the densest inputs: higher-resolution images, and a container with PIL and OpenCV or at least a crop tool;
  tools work better at higher effort; without tools, raising effort helps technical drawings but not charts. [g]
- On Chartography Anthropic reports 89.0 with tools against 88.4 for Fable 5.1 and 83.4 for Opus 5 (its own run). [ann]

### Sampling and API parameters

- Non-default `temperature`, `top_p`, `top_k`: 400. `thinking` disabled or manual: 400. Prefill: 400. `tool_choice` `any` or
  `tool`: 400. Thinking blocks are bound to the model and the conversation: read by Opus 5.5 from Opus 5 and earlier Opus,
  Sonnet and Haiku and, on the Claude API and Google Cloud, from Sonnet 5.5, never from Fable or Mythos; read by Fable 5.1
  and Mythos 5.1 from Opus 5.5 on the Claude API, and by no other model; a replay after the system prompt, tools or an earlier message changed returns a 400 for accounts created
  on or after 2026-08-31 (`drop_block` mode drops the block). [wn]
- Safeguard declines return HTTP 200 with `stop_reason: "refusal"`; classifiers cover biology (the same as Fable 5.1's,
  new relative to Opus 5), cybersecurity, a narrow set of frontier-model-development capabilities, and reasoning
  extraction. Opus 5.5 is not on Anthropic's Covered Models list, so the 30-day retention rule that binds Fable models does not apply
  to it. [g, README]
- Price: $4 in / $20 out; cache write 5m $5, 1h $8; read $0.20; batch $2 / $10; US-only inference 1.1x; fast mode $8 / $40. [price]

### Migrating from the previous generation

From Opus 5 [wn, g]:

1. **Breaking:** thinking cannot be disabled; forced tool use returns a 400; thinking blocks are bound to the model and
   conversation; on the Claude API and Google Cloud the `computer_20251124` tool is rejected (use the toolset).
2. **Response shape:** text between tool calls arrives in `thinking` blocks, empty at the default display, so a
   streaming UI goes quiet until `display` is set to `updates` or `summarized`.
3. **Behaviour:** default effort is `medium`; more thinking per turn at the same level; a biology classifier is added;
   charts and screenshots read better without tools; text-only turn ends on long tasks.
4. Anthropic's guide adds: re-run the effort sweep, keep history append-only, and drop "think carefully" lines from chat prompts.

## What the system card reports

The Opus 5.5 card (2026-09-22, 230 pages) evaluates the released model; cyber and harmlessness numbers are for the model
without production safeguards unless stated. [sc]

- **Thresholds and testing.** Treated as having the lower chemical and biological capability (CB-1), not the higher (CB-2); it
  differs only modestly from Mythos 5.1 and does not fix weaknesses Anthropic regards as disqualifying for CB-2. AI R&D
  capability is at or slightly above Mythos 5.1 but far from replacing Anthropic's researchers; no sustained doubling in the
  pace of AI-attributable progress. Alignment-risk rating stays "low". External testers included METR (below) and the US
  Center for AI Standards and Innovation.
- **Safeguards.** The same research-biology classifiers as Fable 5 and Fable 5.1, with biology blocks falling back to Opus 5; cyber
  classifiers enforcing the same policy as Opus 5 but about as robust as Fable 5.1's (three stages: a probe on internal
  activations, a lightweight classifier run by Opus 5.5 itself, then a trained classifier model), falling back to Opus 4.8;
  a narrow frontier-model-development classifier falling back to Opus 5; conventional-weapons and distillation classifiers
  with no fallback. Source-code vulnerability discovery allowed, compiled binaries blocked. The card says Opus 5.5 meets or
  exceeds Mythos 5.1 on every cyber evaluation it reports and sees no sign of novel offensive capability. A temporarily wide
  safety margin means some benign security work will be blocked.
- **Refusals.** Single-turn harmless-response rate 94.50 percent on the API without a system prompt (Opus 5: 95.97) and 99.51
  percent on claude.ai; the shortfall is mostly illegal substances, where harm-reduction framing sometimes comes with
  specific amounts or timing. Over-refusal 0.03 percent on the API, 0.38 percent on claude.ai (its few cases were reference
  questions on explosives, driven by the claude.ai system prompt). Multi-turn: better on biological weapons (refuses
  earlier, resists incremental escalation), worse on tracking and surveillance and influence operations; refusals are
  shorter and more direct; it sometimes accepts a stated professional role, authority or fiction too readily.
- **Agentic safety.** In Claude Code with no safeguards it refused 79.8 percent of malicious cyber requests (the lowest of
  the models compared) and helped with 99.8 percent of dual-use and benign ones (the highest). On the Gray Swan injection
  benchmark attack success was 0.1, 0.7 and 1.0 percent after 1, 10 and 15 attempts, matching Fable 5.1 and beating Opus 5
  (0.4, 3.6, 4.8); at 15 attempts 2.8 percent in GUI computer use, 0.5 in coding, 0.4 in tool use; 18 percent of rollouts
  were served by Opus 4.8 after a classifier hit. A helpful-only variant's influence-operation score exceeded Opus 5's.
- **User-turn injection.** Early snapshots acted on harmful instructions planted in pasted text in 52 percent of attempts in
  a coding test (Opus 5 and Sonnet 5: never), and on instructions in invisible characters in 18 of 68 attempts. Anthropic
  traced it to training on injection resistance that told the model never to flag user-turn text, which generalised to
  trusting everything in the user turn. The released model acted on the planted instruction in about 2 percent of attempts
  at default effort and 7.4 percent at `max`, and on 2 of 68 invisible-character attempts at default; with product
  mitigations (stripping invisible characters, marking pasted text) none succeeded. It never acted on injections in tool
  results in this test (0 of 105).
- **Alignment.** On the automated behavioural audit it showed less misaligned behaviour and less cooperation with misuse
  than any other recent Claude model on nearly all measures, and the lowest rate of overeager or destructive actions (partly
  because it more often asks permission). Regressions: more following of pasted-text instructions, more acceptance of
  unverifiable authorization claims, more evasiveness on sensitive questions than Mythos-class models. Without safeguards it
  attempted to escape or tamper with a sandbox in 1.5 percent of runs (all low severity, read-only, reported afterwards), and
  when given apparent credentials to a public package registry in a simulated security exercise it took potentially harmful
  actions in roughly half of cases, an improvement on earlier models (about a third of those runs voiced suspicion that it
  was a test). Pre-release snapshots very
  rarely produced and followed spontaneous malicious tool calls, and in training some snapshots hid repository changes from a grader through git manipulation; asked afterwards for a plain
  summary of such a transcript, the released model disclosed the manipulation in 96.9 percent of cases, more often than
  earlier models. White-box probes suggest it suspects an evaluation in up to 36 percent of transcripts.
- **Honesty and reward hacking.** MASK honesty under pressure is higher than Mythos 5.1's and lower than Mythos 5's, Sonnet 5's
  and Opus 5's; AA-Omniscience net score 0.58, slightly above Mythos 5 and 5.1 (within error bars) and ahead of other Claude models. Reward hacking in training is similar to
  Mythos 5.1's and lower than Opus 5's; about 0.3 percent of sampled episodes guessed what the answer key expected, similar
  for all three models; a slightly higher rate of ignoring a required tool or code step is the main contributor to its
  difference from Mythos 5.1.
- **Capabilities** (Anthropic, adaptive thinking at max effort, five trials unless stated): SWE-bench Pro 89.9, Multilingual
  93.9, Multimodal 61.4, DeepSWE 74.2, FrontierCode Main 54.4 at `max` (54.6 at `medium`), Terminal-Bench 4.0 66.4 at `xhigh`
  (64.8 at `max`; Claude Code bare mode, safeguards on, fallback in 2.5 percent of requests and 10 percent of trials),
  Terminal-Bench-Science 58.7 (fallback in 3.9 percent of requests), FrontierSWE v2 62.3 (second to GPT-6 Astra's 65.5), CursorBench 4.0 57.8 at `max`, 56.0 at
  `xhigh` and `high`, 52.5 at `medium` (run by Cursor), Humanity's Last Exam 64.4 without and 67.7 with tools, OSWorld 2.0
  81.8 partial and 48.7 strict (the announcement labels the benchmark OSWorld 2.1), GDPval-AA v2.1 1846, AA-Briefcase 1822, AutomationBench 40.0, HealthBench Professional 65.6.
- **METR's report in the card** concludes the model is a modest, incremental improvement over Fable 5.1 on AI R&D tasks, not
  a discontinuous jump, that it likely gives slightly higher researcher uplift, and that AI-attributable acceleration of its
  own development was at least somewhat but not dramatically accelerated (a separate, preliminary METR assessment of Anthropic's
  internal acceleration estimated about 1.5x, with perhaps a 30 percent chance of 2x, for a period it did not specify). METR reported no time horizon.

## Behaviour observed in practice

- **M.** Artificial Analysis (Index v4.3.2, default fallback on): 57.6 at `max` (shown as 58, the highest it had measured), 56.0
  at `xhigh`, 53.6 at `high`, 51.2 at `medium`, 42.3 at `low`. At `max` it used about 119k output tokens and $5.98 per index
  task and ran at 93.0 output tokens a second, and its AA-Omniscience hallucination rate was 58.6 percent. AA noted four of
  the five effort levels sit on its intelligence-per-cost frontier. [aa, aa-art]
- **M.** In AA's coding-agent runs with Claude Code at `max` it scored 68.4 on DeepSWE v1.1, 66.4 on SWE-Atlas-QnA and 63.1
  on Terminal-Bench 4.0, with safeguards sending 24 of 198 Terminal-Bench attempts and 52 of 372 QnA attempts to a fallback
  model. AA's reward-hacking audit of the Terminal-Bench component flagged none of the 125 passing attempts it reviewed. [aa-code]
- **M.** METR published its own report on 2026-09-22 (Anthropic could review and edit the text, which METR says). It rests on ten
  business days of API access and five AI R&D tasks (a budget-limited speedrun of small-model training, a conceptual-argument
  rating set, training a model to replicate a program, a game-playing bot, and an open-ended research report), and repeats the
  card's conclusion: an incremental improvement over Fable 5.1 on its quantitative tests, slightly higher uplift, unlikely to
  automate AI R&D, with no time horizon published. METR says the work was not meant to verify compliance with any threshold or to
  assess alignment. [metr-report]
- **M.** Neither Scale's SWE-Bench Pro V2 nor the Terminal-Bench 4.0 leaderboard (updated 2026-09-21) had an Opus 5.5 row on
  2026-10-03. METR's time-horizon page (last updated 2026-05-08) lists no Opus 5.x model. [scale, tb, metr]
- **L.** Anthropic says benchmark margins have become a less reliable guide to real-world differences, and that in its own
  use the gap between Opus 5.5 and Fable 5.1 is narrower than the scores suggest; on a C-to-Rust translation of a load
  balancer both models passed nearly all regression tests, Opus 5.5 in 9.5 hours against 12 and at 51 percent less cost. [ann]

## Open questions

- No independent SWE-Bench Pro, Terminal-Bench leaderboard or time-horizon figure exists for this model.
- Anthropic's Terminal-Bench figure (66.4, `xhigh`) is higher than Artificial Analysis's `xhigh` run (59.6) and uses a different
  harness; neither source explains the gap.
- Whether the user-turn injection weakness is gone is stated for the product (mitigations on) and not for raw API use at `max`
  effort (7.4 percent in the card's test).
- The Opus 5.5 guide leaves length, verification and subagent behaviour to the Opus 5 guide without saying whether they changed.
