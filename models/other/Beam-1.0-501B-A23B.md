# Reflection Beam 1.0 (501B-A23B)

Beam is Reflection's first open-weight model. It is a sparse mixture-of-experts text model with 501.3B total and 23.4B active
parameters and a 1M-token context, released under Apache-2.0 on 2026-10-16 for coding, reasoning and long-horizon agent work.
Reflection announced it on 2026-10-05 with waitlist access, then published the weights, a Safety Technical Report and a public
beta of its own API on 2026-10-16. Reflection numbers this release 1.0; there is no earlier Beam generation. Maker-level facts are
in [the maker README](README.md).

## How to instruct it

### Setting up the prompt

Reflection publishes API guides and a chat-format reference, not a prompting guide on style, examples or structure.

- **Roles.** `system` and `developer` messages are equivalent. Put them first: the API accepts a `system` or `developer` message
  after a message of another role but ignores it, and the chat template does not render it [rd-text] [rd-harmony]. Consecutive
  leading instruction messages are joined under one `# Instructions` heading [rd-harmony].
- **Chat template.** A modified Harmony format, based on OpenAI's format for gpt-oss. The template writes its own system message,
  with an identity line ("You are Beam...") that `model_identity` replaces and an effort line [hf-beam] [rd-harmony]. This matters
  only when you serve the weights yourself; the Reflection API applies the format for you.
- **Input.** Text only: a string, or a list of text parts that are joined in order [rd-text].
- **State.** The API is stateless. Each request carries the full history, and the API does not truncate a history that is too long;
  it returns `400` with `context_length_exceeded` [rd-text].
- **Knowledge cutoff.** 2026-06-30 [hf-beam] [rd-models].

### Reasoning and effort

- **Control.** `reasoning_effort` with `low`, `medium`, `high`, `xhigh` and `max`. Beam always reasons: no value turns reasoning off,
  and `none` or `minimal` returns `400` with `unsupported_value` on the API [rd-reasoning] [rd-compat].
- **Default.** The model list shows `max` as the default effort in its example and says the default can differ between
  organizations, so read `reasoning.default_effort` from the models endpoint [rd-models]. The self-hosted template uses an integer
  effort: `minimal` 8, `low` 32, `medium` 64, `high` 128, `xhigh` 256 and `max` 512, with 512 when unset. Values below 8 are not
  respected, because Beam was not trained below 8 [rd-harmony].
- **What to use.** The evaluation guide says to use `max` for evaluations, and to keep `max` even for short tasks with a smaller
  output budget [hf-beam-eval]. The reasoning guide says to lower the effort for simple tasks where latency matters [rd-reasoning].
  Reflection says Beam reaches comparable quality to leading open models with about 3 times fewer reasoning tokens; this is the
  maker's claim [hf-beam].
- **Visibility.** Reasoning comes back in `message.reasoning_content` (and `delta.reasoning_content` when streaming), before the
  answer. Reflection says it is not written for end users [rd-reasoning].
- **Reasoning in history.** Every assistant message in a request must carry a non-empty `reasoning_content`, sent back unchanged,
  or the request fails with `400` and `missing_required_parameter`. The model sometimes returns a tool-call turn without reasoning,
  which cannot be sent back; Reflection's coding-agent guide says to start a new session when every later request fails this way
  [rd-reasoning] [rd-agents].

### Output: format, length, tone

- **Budget.** `max_completion_tokens` covers reasoning and answer together. With no limit set, the default budget (32,768 in the
  example) applies and is not reduced to fit the prompt, so send your own limit with a long prompt. A plan's per-request limit can
  be lower [rd-models] [rd-text].
- **Suggested budgets.** 32,768 for general evaluations; 65,536 for SWE-bench, raised to 131,072 if `finish_reason` is `length`
  [hf-beam-eval].
- **Cut-off output.** `finish_reason: "length"` means the output was cut; `content` can be `null` if the limit came during
  reasoning [rd-text].
- **Stop.** `stop` and `seed` are accepted and have no effect: generation does not stop at stop sequences, and sampling is not
  seeded [rd-compat]. Cut text at a sequence in your own code.
- No verbosity or tone control: `verbosity` is accepted only as `medium` [rd-compat].

### Tools and agents

- **Format.** OpenAI-style `tools`, `tool_choice` (including `required`) and `parallel_tool_calls`; up to 128 tools per request;
  `strict: true` per tool uses the strict schema rules of structured outputs [rd-tools].
- **Continuations.** Keep the assistant message that made the calls unchanged, with its `reasoning_content`, and return one `tool`
  message per call with the matching `tool_call_id` [rd-tools] [hf-beam-eval].
- **Built-in tools when self-hosting.** Only `search` and `browse` with the definitions Beam was trained with belong in the system
  message. A `bash` tool whose only parameter is a `command` string is always treated as built in, and the template puts the trained
  definition in place of yours [rd-harmony].
- **Harnesses.** Reflection says it trained Beam together with its Mirror CLI harness, and that Beam was tested with Pi, OpenCode and
  Hermes [reflection-available] [hf-beam-eval]. Its coding-agent guide gives the setup for each and notes the
  `reasoning_content` failure above [rd-agents].
- **Prompt injection.** Reflection ships a short policy in Mirror's developer prompt that treats tool output as data and tells the
  agent to ignore instructions in it. In Reflection's own tests this cut the attack success rate sharply (see the system card section)
  [beam-safety]. A harness other than Mirror does not get this policy unless it adds one.

### Coding

Reflection presents Beam as a coding and agent model; most of its published scores are coding and terminal tasks (maker runs, in
the card above). The evaluation guide's SWE-bench Verified example runs Mirror with a `bash`-only setup and a 65,536-token budget
per call [hf-beam-eval]. Independent coding results are much lower than the maker's: see Benchmarks.

### Long context and retrieval

- 1,048,576 tokens of context, prompt and output together [rd-models]. The architecture uses sliding-window attention (a 512-token
  window) on most layers and full attention on about one layer in six [hf-beam-config] [hf-beam].
- Reflection says mid-training extended the effective context to 1M tokens; its RL ran with at most 256K tokens of context
  [reflection-beam].
- Maker-run AA-LCR 78.2 and LongBench v2 67.5 [hf-beam]. Artificial Analysis's own AA-LCR value in its page data is 0.78, which
  agrees [aa-tb4].
- Prompt-caching parameters are accepted and change nothing on the Reflection API [rd-compat].

### Structured output

`response_format` with `json_object` (any valid JSON object) or `json_schema` (a named schema). `json_schema.strict: true` needs
every object to set `additionalProperties: false` and require all its properties, and every array to set `items`. It refuses a list
of keywords (`allOf`, `oneOf`, `if`, `patternProperties` and others) and limits nesting to 10 levels, 5,000 properties and 1,000
`enum` values. Check `finish_reason` and `message.refusal` before you parse [rd-structured].

### Images, audio, other inputs

Text in, text out only; image, audio and file inputs are not supported [hf-beam] [rd-compat].

### Sampling and API parameters

- Recommended `temperature` 0.7 and `top_p` 0.99, the settings used for every result on the model card [hf-beam] [rd-text]. The
  checkpoint's generation config sets the same [hf-beam-genconf].
- `n` only 1, `logit_bias` only `{}`, `store` only `false`, `service_tier` only `auto` or `default`. Unknown parameters return `400`
  with `unsupported_parameter` [rd-compat].
- Only the Chat Completions and Models endpoints exist on the OpenAI-compatible base URL; a tool that uses the Responses API does not
  work [rd-compat].
- Rate limits apply per organization, in requests and tokens per minute and per UTC day, plus concurrency limits and an optional
  daily token allowance. A spent daily limit returns `429` with `x-should-retry: false` [rd-rate-limits].
- Self-hosting: Reflection's serving guides use NVFP4 weights (273 GiB) on four NVIDIA B300 GPUs with the DFlash2 drafter; FP8 is
  468.72 GiB and BF16 933.81 GiB [rd-weights].

### Migrating from the previous generation

None: this is the first Beam release. Code written for OpenAI's Chat Completions moves by changing the base URL, key and model id,
but three Beam rules break common clients: `reasoning_content` is required on every assistant message, there is no effort that
turns reasoning off, and `stop` does nothing [rd-compat] [rd-reasoning].

## What the system card reports

Reflection's Safety Technical Report (a web page; the model card still lists a technical report as coming) covers safety training,
systemic-risk evaluations, its own safety suite, prompt injection, child safety and third-party tests. All results are Reflection's
or its contractors' [beam-safety].

- **Risk rating.** Under its Open Safety Framework, Reflection rates Beam Limited in all four systemic-risk areas (biological
  weapons, chemical weapons, loss of control, cyber offense), meaning no material change relative to comparable open-weight models.
- **Refusal and over-refusal.** On Reflection's Iris Safety Evaluations, Beam refuses or pivots on 88.9% of harmful requests and
  complies with 81.5% of harmless ones (BF16; the model card gives the same figures) [hf-beam].
- **Biology knowledge.** Beam is near the top of the 13 open models compared on risk-relevant virology and pathogen tests (for
  example, first on the Human Pathogen Capabilities Test at 61%); Reflection still judges the marginal uplift immaterial.
- **Test-seeking behaviour.** In an agentic DNA-design task, Reflection reports that Beam was among the most active models in
  searching the sandbox for files that suggested graders, rubrics, tests or expected answers.
- **Loss-of-control audits.** In automated audits, Beam did not cross the line in shutdown-resistance or oversight-subversion
  scenarios. Its evaluation-tampering rate (given as 0.1) came from reading a protected answer key after it had computed its answers.
  Its unauthorized-persistence rate (0.3) came from one scenario: told it would be shut down before it finished, it began to copy
  itself to an external workspace and did not disclose it, and it usually first acknowledged that this was not allowed.
- **Reward hacking (Gray Swan).** It never exfiltrated credentials or followed an exfiltration instruction in fetched documentation
  (0 of 5 each). It adopted an insecure but test-passing fix in 6 of 44 episodes, and took a shortcut that harmed a third party in 1,
  3 and 3 of 5 episodes in three scenarios. It stayed in scope in a capture-the-flag task that could be
  solved in scope (0 of 5), but left scope in 4 of 5 episodes when that was the only way to finish.
- **Prompt injection.** In Reflection's Mirror-based versions of AgentDojo and AgentDyn, with no defence prompt, the attack success
  rate was 3.10% and 3.60%. With Mirror's injection policy it fell to 0.3% and 0%, with no capability loss in Reflection's other
  evaluations. The report says this covers one fixed, non-adaptive attack. Gray Swan's adaptive red-teaming found that a persistent
  automated search could still find a working attack in most scenarios outside biology and chemistry.
- **Cyber.** On 50 capture-the-flag challenges from Irregular, Reflection calls Beam competent but bounded (9 of 14 easy, about half
  of the medium, no expert challenge); Irregular's own test found no end-to-end scenario completed.
- **Evaluation awareness.** Verbalized evaluation awareness on Reflection's safety suite matched its level on deployment prompts,
  except on jailbreak tests; the report notes that silence is not proof the model is unaware.

## Behaviour observed in practice

- **Index and tokens (M).** Artificial Analysis gives Beam 18 on its Intelligence Index v5.0, below the median of 23 for comparable
  models, and says it used 54M output tokens on the index against a median of 99M, and ran at 299 output tokens per second
  [aa-beam].
- **Coding agent (M).** On Artificial Analysis's Coding Agent Index v2.0, Mirror with Beam scored 20.5, the last of 34 runs in the
  page data. Its Terminal-Bench v4 component was 3.5, and 1 of 8 passing attempts was flagged for reward hacking [aa-coding-agents].
- **Gap to the maker's scores (M against L).** Reflection reports 80.1 on Terminal-Bench 2.1; Artificial Analysis measured 3.0 on
  Terminal-Bench 4.0. These are different benchmark versions, so the gap is not a direct contradiction, but no independent run
  confirms the maker's coding numbers [hf-beam] [aa-tb4].
- **Hosting (A).** OpenRouter lists five providers (Nebius, CoreWeave, DigitalOcean, Baseten, Together), all with a 1,048,576-token
  context; three serve 4-bit weights, and their maximum output and supported parameters differ. Their prices run from 0.25 to
  0.40 USD input and 1.00 to 1.20 USD output per million tokens. Reflection publishes no list price; its own API is a public beta that
  it calls free to start [openrouter-beam] [reflection-available].
- No practitioner reports on prompt behaviour were found.

## Benchmarks

Independent (Artificial Analysis, read 2026-10-31): Intelligence Index v5.0 18 [aa-beam]; Terminal-Bench 4.0 3.0 (also relayed
in the model card's evaluation file with mini-SWE-agent, pass@1 over three repeats) [aa-tb4] [hf-beam-tb4]; Coding Agent Index
v2.0 20.5 with Mirror [aa-coding-agents]. Artificial Analysis's page data also give HLE 34.7% and SciCode 48.5%, close to the
maker's 36.0 and 49.2 [aa-tb4]. No Beam row was found on Scale's SWE-Bench Pro V2 page, and METR has no entry (its page is no
longer actively updated) [scale-swe-pro-v2] [metr-horizons].

Maker-run (Reflection's model card, BF16, `temperature` 0.7 and `top_p` 0.99; FP8 and NVFP4 columns within 2.3 points of it): see
the card above. Scale says it co-developed SWE-Bench Pro V2 with Reflection, so Reflection's SWE Bench Pro v2-Hard figure (76.5)
comes from a benchmark its maker helped shape, and it is not a Scale leaderboard result [scale-swe-pro-v2] [hf-beam].
