# Orpheus 3B 0.1 finetuned

Orpheus 3B 0.1 finetuned is an open-weight speech synthesis model of Canopy Labs, class Orpheus, generation 0.1, built on a Llama 3B backbone. It speaks English in eight named voices and takes eight inline emotive tags. It is a voice actor model in a narrow sense: the tags add sounds and some intonation, and there is no free-form instruction. Canopy Labs released it in March 2025. This is the oldest model in this folder. The maker has released no model since April 2025, and its repository changed last on 2025-12-05 with a packaging fix, so it is kept as the current generation of a class with no newer generation.

## How to instruct it

### Setting up the prompt

- **Voice name first.** For the finetuned model the text is formatted as the voice name, a colon and the line. The name options in the README, in order of conversational realism by the maker's subjective tests, are tara, leah, jess, leo, dan, mia, zac and zoe. The Python package adds the prefix for you [gh-orpheus].
- **Emotive tags.** Eight tags go in angle brackets inside the text: laugh, chuckle, sigh, cough, sniffle, groan, yawn and gasp. The README gives no placement advice [gh-orpheus].
- **Emotion by words.** The README lists guided emotion and intonation through simple tags as an ability and gives no tag for named emotions [gh-orpheus].
- **The pretrained model.** It is a base model. It can generate from text alone or from one or more earlier text and speech pairs in the prompt. The README says it was not explicitly trained for zero-shot voice cloning [gh-orpheus].

### Coding

The repository has a streaming inference example and a Colab notebook for the tuned model. It has a llama.cpp route for inference without a GPU, a watermark option and a Baseten deployment guide. It also ships data scripts and sample datasets for making your own finetune [gh-orpheus].

### Structured output

### Images, audio, other inputs

Text only for the finetuned model. The pretrained model can take speech and text pairs as conditioning.

### Voice: turn-taking, interruption and speech style

Turn-taking does not apply.

**How to direct delivery.** Two levers: the voice name and the eight inline tags. There is no instruction field and no description of tone. Pace moves with the sampling settings: the README says a higher repetition penalty or temperature gives faster speech. The README does not say how strongly the tags act [gh-orpheus].

**Strength, failures.** Not measured on the pages read. The README claims human-like speech that is superior to closed models; it gives no test [gh-orpheus].

**Voice design and cloning.** No voice design. Cloning is via the pretrained model's conditioning on speech and text pairs.

**Multi-speaker dialogue, long-form consistency, pronunciation.** Not documented.

**Latency.** About 200 ms streaming, about 100 ms with input streaming, as the maker states [gh-orpheus].

### Sampling and API parameters

The README says ordinary language-model settings such as `temperature` and `top_p` apply. It says `repetition_penalty` of 1.1 or more is required for stable output, and that a higher `repetition_penalty` or `temperature` makes the voice speak faster. The streaming example also passes a `voice` argument [gh-orpheus].

### Migrating from the previous generation

There is no earlier or later Orpheus generation. The multilingual research family (April 2025) uses a standard prompt format across languages, with tags that differ by language [gh-orpheus].
