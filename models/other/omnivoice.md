# OmniVoice

OmniVoice is an open-weight zero-shot speech synthesis model from the k2-fsa group (the Next-gen Kaldi project), with about 0.6B parameters and support for more than 600 languages. It clones a voice, designs a voice from a fixed list of attributes, and adds 13 non-verbal and intonation sounds through inline tags. It is a weak voice actor model: its delivery controls are the whisper attribute, an accent attribute and the tags. It is in this folder because accent and non-verbal sounds fall inside the definition. It was released in March 2026. The code is Apache-2.0, and the model card licenses the weights CC BY-NC because of the training data [hf-omnivoice]. Maker-specific facts are in this file.

## How to instruct it

### Setting up the prompt

- **Voice design string.** `instruct` takes a comma-separated string of attributes. Each attribute belongs to one category. Only one attribute per category is allowed. The categories are gender (male, female), age (child, teenager, young adult, middle-aged, elderly), pitch (very low to very high), style (whisper only), an English accent (American, British, Australian, Canadian, Indian, Chinese, Korean, Japanese, Portuguese, Russian) or a Chinese dialect (12 listed). The model detects the language of the string and accepts English, Chinese or a mix [gh-omnivoice-vd].
- **Examples from the maker's page.** An attribute string for a female young adult with high pitch and a British accent; another for an elderly male with low pitch and the whisper style. Commas separate attributes, and the case does not matter [gh-omnivoice-vd].
- **Tips from the maker.** The maker says attributes combine across categories and that unneeded ones can be left out. An English accent works only on English text and a Chinese dialect only on Chinese text. Some combinations do not work well because of training data, so the maker says to simplify the string when the result is wrong [gh-omnivoice-vd].
- **Tags in the text.** Tags go where the sound should occur: laughter, sigh, confirmation, five question intonations, four surprise intonations and a dissatisfaction sound. The README names 13 [gh-omnivoice].
- **Pronunciation.** Pinyin or phoneme markers can replace words; normalisation keeps tags and markers [gh-omnivoice].

### Output: format, length, tone

- **Tone.** Only the whisper attribute and the tags change delivery. The model has no emotion control on the pages read.
- **Speed.** Real-time factor as low as 0.025 [gh-omnivoice].
- **Text normalisation.** Off by default; `normalize_text=True` turns it on. Chinese and English then use WeTextProcessing, and other languages fall back to a library for integers. The README advises writing Arabic numerals as words, or turning normalisation on [gh-omnivoice].

### Voice: turn-taking, interruption and speech style

Turn-taking does not apply.

**How to direct delivery.** Attributes choose the voice, including an accent and a whisper style. Tags add sounds. There is no instruction for emotion, pace or role [gh-omnivoice-vd] [gh-omnivoice].

**Strength.** Boson's table, which ran no tags, gives OmniVoice 61.07 percent on emotions against a baseline row, the highest of its six rows, and 40.82 percent overall [boson-blog-tts3d].

**What fails.** Some attribute combinations are ignored. Accent and dialect depend on the text language [gh-omnivoice-vd].

**Voice design and cloning.** Both are in the model. Design uses a closed vocabulary.

**Multi-speaker dialogue, long-form consistency.** Not documented.

**Pronunciation.** Pinyin and phoneme markers [gh-omnivoice].
