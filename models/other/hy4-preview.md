# Tencent Hy4 preview

Hy4 preview is Tencent's fourth-generation Hy model, released on 2026-08-28 as open weights (Apache-2.0) and still labelled a preview. It is a
text-only mixture-of-experts model with 770B total and 49B active parameters and a 1M-token context, built for software engineering, office
and data work, game development and research, with reasoning on by default. It follows Hy3 (July 2026, 295B with 21B active, 256K context) and
the Hy3-preview before it. Tencent describes it as an early version with known issues. Maker-level facts are in [the maker README](README.md).

## How to instruct it

### Setting up the prompt

Tencent publishes no system-prompt, role, structure or example guidance for Hy4 preview. The card's Quickstart is an OpenAI-client example with
the sampling and reasoning settings below [hf-hy4]. Two product families use the model (the CodeBuddy coding assistant and the WorkBuddy agent
workspace); how they load instruction files was not read.

### Reasoning and effort

- **Control.** `reasoning_effort` in `chat_template_kwargs`, with `high` as the default for complex tasks and `no_think` for direct answers [hf-hy4].
  The card names no other level. Its predecessor accepted `no_think`, `low` and `high` with `no_think` the default [hf-hy3].
- **Cost of thinking.** The card's known-issues paragraph says the model spends longer than necessary reasoning on complex tasks and tends to
  over-verify its own work; a gateway vendor's blog post says that makes it a poor fit for latency-sensitive use (A) [hf-hy4] [orcarouter-hy4-vllm].
- **Interleaving and history.** Not described. The serving recipes use a `hy_v4` reasoning parser [hf-hy4].

### Output: format, length, tone

No verbosity, formatting or tone controls are published. Aggregators list a 64K output limit, which Tencent's pages do not state [cloudprice-hy4].
The card describes office outputs (documents, spreadsheets, presentations) and playable game prototypes as target outputs; it gives no format advice.

### Tools and agents

Tool calling and reasoning each need a parser in self-hosted serving: `--tool-call-parser hy_v4 --reasoning-parser hy_v4 --enable-auto-tool-choice`
on vLLM; `--tool-call-parser auto --reasoning-parser auto` on SGLang [hf-hy4]. An aggregator lists function calling and web search [cloudprice-hy4]. Maker-run
agent results (highest reasoning setting, Tencent's own runs): Toolathlon-Verified 74.1, MCP-Atlas public 83.7, APEX-Agents pass@1 37.1, GDPval-AA V2
1,678 Elo, Agents' Last Exam (CLI) 22.8 [hf-hy4-page]. Harnesses named in the card's notes: Toolathlon on an internal scaffold with some MCP tools reimplemented and a
2-hour timeout; MCP-Atlas with a 100-tool-call budget and a Gemini 3.1 Pro Preview judge; BankerToolBench through OpenCode with a Gemini 3 Flash judge; Apex-Agents with
the official ReAct Toolbelt harness at up to 250 steps; Agents' Last Exam through Claude Code with up to 12 hours per task. No guidance on parallel calls, tool choice,
context management or subagents.

### Coding

Maker-run (highest reasoning setting): Terminal-Bench 2.1 85.4 using the Claude Code harness with up to 500 turns, a 12-hour timeout, 16 CPUs and 32 GB RAM per trial; SWE-bench Pro 65.7 and
SWE-bench Multilingual 82.9 with a swe-agent scaffold; DeepSWE 64.3 with mini-swe-agent; NL2Repo, SWE-Marathon, SWE Atlas and ProgramBench rows also published
[hf-hy4-page]. The footnotes give the turn budgets Tencent used in Claude Code: 256 turns for SWE Atlas (with a network allowlist added against hacking), 1,000 for NL2Repo
(with added anti-hacking prompt constraints and tool-call monitoring) and 2,000 for ProgramBench, where DeepSeek V4 Pro was run in mini-swe-agent instead because its thinking
kept looping. The card also notes that some Hy3 scores may differ from those reported earlier, because the evaluation harness, judge model and anti-hacking checks changed. The CodeBuddy product is the first-party coding harness; its instruction-file loading was not read.

### Long context and retrieval

1M tokens, with a gated sparse-attention design and an index cache that lets layers reuse sparse indexes; aggregators quote 1.0M or 1.05M
[hf-hy4] [cloudprice-hy4]. The model has a multi-token-prediction layer (about 10B parameters, 0.7B active) for speculative decoding, enabled in the vLLM and SGLang recipes
[hf-hy4]. The vLLM recipe needs a sparse-attention backend (`FLASHMLA_SPARSE`) [hf-hy4]. A third-party write-up puts the baseline at 8 B300 GPUs for the
FP8 build or 16 B200 for BF16, and a compressed GGUF at roughly 200 GiB (A) [orcarouter-hy4-vllm]. No long-context benchmark appears in the text read; the images
carry agentic rows only. No retrieval results are published.

### Structured output

Tencent's card says nothing. An aggregator lists native JSON-schema structured output (A) [cloudprice-hy4]. Nothing from Tencent confirms it.

### Images, audio, other inputs

Text only [hf-hy4].

### Sampling and API parameters

Recommended `temperature=0.9`, `top_p=1.0`, the same as Hy3 [hf-hy4] [hf-hy3]. Docker images named in the card: `vllm/vllm-openai:hy4-preview` and `lmsysorg/sglang:hy4-preview`
[hf-hy4-page]. The vLLM recipe uses tensor parallel 8, MTP with three speculative tokens and the FP8 build; SGLang uses NEXTN speculation with three steps, top-k 1 and four draft
tokens [hf-hy4].

### Migrating from the previous generation

From Hy3 (the generally available release of 2026-07-06) to Hy4 preview, as the two Hugging Face cards state [hf-hy3] [hf-hy4]:

- Reasoning default flips: Hy3 answers directly unless asked (`no_think` default, `low` and `high` available); Hy4 preview thinks (`high`) unless told `no_think`.
- Size: 295B total and 21B active with 256K context becomes 770B and 49B with 1M.
- Parsers: vLLM `hy_v3` becomes `hy_v4`; SGLang `hunyuan` becomes `auto`.
- Sampling is unchanged (0.9, 1.0).
- On Tencent's own table Hy4 preview is above Hy3 on every row published: Terminal-Bench 2.1 70.8 to 85.4, DeepSWE 28.0 to 64.3, SWE-bench Pro 57.9 to 65.7, Toolathlon-Verified 56.2 to 74.1,
  HLE (no tools) 34.4 to 43.4, GPQA Diamond 90.9 to 92.3, CyberGym 51.8 to 78.4 [hf-hy4-page].
- List price rose from the Hy3 figures a relay gives (about 0.18 in, 0.59 out) to 0.834 in and 2.50 out [nyu-hy3] [cloudprice-hy4].
- Hy3-preview (April 2026, 295B/21B) was scored by Artificial Analysis at 23 on index v4.3.2 and is listed there as deprecated [aa-hy3-preview].

## What the system card reports

Tencent publishes no system card. The Hugging Face card is a model card with a capabilities description, an expert evaluation, a benchmark appendix and one paragraph of known limitations,
and no safety, refusal, injection, sycophancy or deception evaluation [hf-hy4]. What it does state:

- **Expert evaluation.** On 203 engineering tasks blind-rated by 163 Tencent experts, Hy4 preview averaged 2.99 against 2.92 for GLM 5.3 (46.8% wins, 40.4% losses) and 2.94 for Kimi K3
  (51.2% wins, 40.9% losses). A relay reads the scale as out of 4 [hf-hy4] [tencent-hy4-news].
- **Cyber capability.** CyberGym 78.4 against 51.8 for Hy3 (Tencent's runs); no usage policy or classifier is described [hf-hy4-page].
- **Known issues.** Over-long reasoning and over-verification. Tencent calls the release an early version and says both pre-training and post-training still have room to improve [hf-hy4].
- **Anti-hacking measures in evaluation.** The benchmark footnotes name a network allowlist (SWE Atlas), anti-hacking prompt constraints and tool-call monitoring (NL2Repo) and
  updated anti-hacking checks behind the restated Hy3 scores; no reward-hacking rate for the model is given [hf-hy4-page].

## Behaviour observed in practice

- **Vendor claims only (A).** A third-party write-up dated 2026-08-31 notes that every published benchmark is vendor-reported and unreproduced, and that no independent lab had a score
  [orcarouter-hy4].
- **Serving (A).** vLLM merged support on launch day, and SGLang and an Ascend path also shipped; the sparse-attention backend is required [orcarouter-hy4-vllm].
- **Slow start (A).** The same write-up cites Tencent's acknowledgment of slow-start and over-verification behaviour on complex tasks [orcarouter-hy4-vllm].
- **Price and access (A).** TechNode relays Tencent's API price as $0.834 in and $2.501 out per million tokens; a price aggregator lists $0.042 for cached input on the OpenRouter and Vercel
  routes; Tencent made the model free in CodeBuddy and WorkBuddy for two weeks at launch [tencent-hy4-news] [cloudprice-hy4].

## Benchmarks

Independent: none. Scale's SWE-Bench Pro V2 table has no Hy4 row, Terminal-Bench 4.0's rows did not render for the fetcher, METR lists no entry (its latest update shown is 2026-05-08), and Artificial
Analysis has no page for Hy4 (it lists Hy3-preview) and no Hy4 run on its Coding Agent Index page [scale-swe-pro-v2] [tbench-4-leaderboard] [metr-horizons] [aa-coding-agents]. Maker-run, highest reasoning setting, Tencent's own harness choices as noted above:
Terminal-Bench 2.1 85.4, SWE-bench Pro 65.7 (a swe-agent scaffold, split not named, not Scale's V2 leaderboard), SWE-bench Multilingual 82.9, DeepSWE 64.3, MCP-Atlas 83.7, Toolathlon-Verified 74.1, GPQA Diamond 92.3, HLE
without tools 43.4 [hf-hy4-page]. Against the comparison models in the same appendix (DeepSeek V4 Pro 0813, Qwen 3.8 Max, GLM 5.3, Kimi K3, GPT 5.6 Sol, Claude Opus 5; mostly Tencent's own runs) the picture is mixed: Hy4 preview is above five of the six on
SWE-bench Multilingual and above four on SWE-bench Pro; on Terminal-Bench 2.1 it is below the first figure of every comparator (comparator figures 80.3 to 88.8, with two figures given for every
comparator and the pair not defined on the card); on DeepSWE it is above DeepSeek V4 Pro and Qwen 3.8 Max and below the other four (comparators 55.6 to 74.7).
