# MiMo-V2.6-Pro

MiMo-V2.6-Pro is the flagship of Xiaomi's MiMo-V2.6 pair, released on 2026-09-21 under the MIT licence. It is a 1.02T-parameter mixture-of-experts model with
42B active parameters, a 1M-token context, native text, image, video and audio input and text output, and thinking on by default. Xiaomi positions it for complex
projects, long-horizon tasks, high-stakes work, cybersecurity and research. It replaces MiMo-V2.5-Pro, which Xiaomi's API retires on 2026-10-21. The API rules, parameter
limits and guides shared by the pair are in [the maker README](README.md); this file gives what applies to the Pro.

## How to instruct it

### Setting up the prompt

Xiaomi publishes no system-prompt, role, structure or example guidance for the MiMo-V2.6 models; the Hugging Face card covers architecture, results and serving
[hf-mimo-pro]. One training fact bears on harness choice: the model came from one mixed reinforcement-learning run across coding, general agents, visual tasks and
cybersecurity, with tasks and several agent harnesses mixed in each batch so that strategies transfer to harnesses it was not trained on [hf-mimo-pro]. The technical report adds that training used small
modular harnesses built from one minimal loop (system prompt, tools, context management), and that DeepSWE scores rose during training on
three harnesses held out from it: Codex, Claude Code and mini-swe-agent [mimo-tech-report]. The only system prompt Xiaomi shows is in its
sample code: one line that names the assistant, states the current date and gives a knowledge cutoff [mimo-docs-thinking] [mimo-page-pro].
Multimodal inputs and their limits are in the README.

### Reasoning and effort

- **Control.** A switch, not an effort scale: `thinking.type` set to `enabled` or `disabled` in `extra_body`. Thinking is on by default for `mimo-v2.6-pro` [mimo-docs-thinking].
  The pages read describe no medium or low setting; Artificial Analysis evaluated one reasoning variant [aa-mimo-pro].
- **Sampling is fixed when thinking is on.** Xiaomi's API does not accept custom `temperature` or `top_p` while thinking is on; it forces 1.0 and 0.95 [mimo-docs-thinking].
- **Budget.** `max_completion_tokens` caps thinking and answer together, so a small value can cut the answer short; reasoning tokens show in
  `completion_tokens_details` and in the stream as `reasoning_content` before `content`; Xiaomi suggests streaming because thinking adds latency
  [mimo-docs-thinking]. A practitioner guide says billed output includes the reasoning (A) [ofox-mimo]; Alibaba's page states the same for the
  V2.5-Pro it hosts [aliyun-mimo].
- **Multi-turn rule.** With thinking on and earlier tool calls in the history, every assistant message that holds tool calls must be sent back with its complete
  `reasoning_content`, or the API returns a 400; Xiaomi adds that a missing history weakens instruction following and raises hallucination, and
  lists agent products affected by the rule (among them Cursor, Codex, Roo Code, Zed, GitHub Copilot CLI, OpenCode and Kilo Code) [mimo-docs-thinking].
  The Chinese first-call guide advises keeping all earlier `reasoning_content` in the history for best results [mimo-docs-first-call]. A practitioner
  guide notes that a framework may hide the field in its UI while still needing it in the request (A) [ofox-mimo] [litellm-mimo].
- **Cost of thinking.** Artificial Analysis counted 140M output tokens for its index, rated the model somewhat verbose and measured 37.4 output tokens per second with
  3.78 s to first token on Xiaomi's API (live figures, read 2026-10-03) [aa-mimo-pro]. Xiaomi's report shows benchmark gains during RL coming with rising token use [mimo-tech-report].

### Output: format, length, tone

No verbosity, formatting or tone controls. Output limit 128K tokens (131,072) including thinking [mimo-page-pro]. The streaming response shows reasoning first.

### Tools and agents

Function calling, streaming, web search and context caching are listed on Xiaomi's model page [mimo-page-pro]. The model's maker-run agent results (Xiaomi's own runs, harness not stated):
DeepSWE v1.1 71.9, Toolathlon-Verified 76.9, AutomationBench v1.0.6 53.1, GDPval-AA 2.1 1,673 Elo, Agents' Last Exam 31.6, Terminal-Bench 4.0 34.9 (the same row gives Opus 5 49.0, Fable 5 42.4, GPT-5.6 Sol 39.9),
OSWorld-Verified 82.0 (computer use), JobBench 62.0 [hf-mimo-pro]. Self-hosting needs `--reasoning-parser mimo --tool-call-parser mimo` (and `--enable-auto-tool-choice` on vLLM) [hf-mimo-pro].
Xiaomi's multi-turn example shows the model calling two tools in one turn, so parallel calls occur; no `parallel_tool_calls` switch is documented [mimo-docs-thinking].
Whether `tool_choice` accepts values beyond `auto` was not found on Xiaomi's pages; Alibaba Model Studio's page, which documents the previous `mimo-v2.5-pro`, says only `auto`
is supported there [aliyun-mimo]. No guidance on subagents.

### Coding

Maker-run: DeepSWE v1.1 71.9, ProgramBench 26.5, MiMo Code Bench 63.2 (Xiaomi's own), Terminal-Bench 2.1 89.9, MiMo VisualCoding 72.3, with the Claude Opus 5 column at 74.0, 37.0, 68.6, 89.1
and 70.0 [hf-mimo-pro]. Xiaomi sells the model inside its own harnesses (MiMo Code, MiMo Desktop); how they load instruction files was not read.

### Long context and retrieval

1,048,576 tokens (the config's maximum position count), built as 60 sliding-window and 10 global-attention layers; the report says pre-training ran at 32K and
then 256K, and mid-training extended context to 1M in its final stage [hf-mimo-config] [hf-mimo-pro] [mimo-tech-report]. The vLLM recipe uses `--max-model-len auto`. All image, video and audio tokens
count against the same window [mimo-docs-image]. Context caching: the cache-hit price is about 1/120 of the miss price [mimo-page-pro]. No long-context benchmark appears in the card; none is published by
independent measurers.

### Structured output

`response_format` of `{"type": "json_object"}` is JSON mode, which guarantees syntactically valid JSON and nothing about the schema; Xiaomi advises stating the fields, types, enums and null rules in the prompt,
telling the model in the message to return only JSON with no Markdown fences, leaving enough `max_completion_tokens`, joining a streamed answer before
parsing it, and validating with a JSON Schema library and retries [mimo-docs-structured]. No schema-constrained mode is documented. Xiaomi separately says `max_completion_tokens` covers thinking and answer together [mimo-docs-thinking].

### Images, audio, other inputs

Image, video and audio go in as content parts; local files cannot be uploaded, only public URLs or base64. Image: JPEG, PNG, GIF, WebP, BMP, up to 50 MB; video: MP4, MOV, AVI, WMV, with `fps` 0.1 to 10 (default 2)
and `media_resolution` `default` or `max`; audio: MP3, WAV, FLAC, M4A, OGG, about 6.25 tokens per second [mimo-docs-image] [mimo-docs-video] [mimo-docs-audio]. Maker-run visual results: OSWorld-Verified 82.0 and MiMo VisualCoding
72.3 [hf-mimo-pro]. Artificial Analysis lists text, image, speech and video input [aa-mimo-pro]. Output is text only.

### Sampling and API parameters

Recommended `temperature=1.0`, `top_p=0.95` for self-hosting [hf-mimo-pro]. On Xiaomi's API these are fixed while thinking is on; the docs state the restriction for thinking mode only [mimo-docs-thinking]. Alibaba's page lists ranges (temperature 0 to 1.5,
top_p 0.01 to 1.0, up to four stop sequences) for the `mimo-v2.5-pro` it hosts, not for V2.6 [aliyun-mimo]. Xiaomi's curl examples send the key in an `api-key` header; its SDK
examples pass it as the client's API key [mimo-docs-first-call]. Rate limit 100 requests and 10M tokens per minute [mimo-page-pro].

### Migrating from the previous generation

From MiMo-V2.5-Pro on Xiaomi's own table [hf-mimo-pro]: DeepSWE v1.1 19.0 to 71.9, Terminal-Bench 4.0 1.5 to 34.9, Terminal-Bench 2.1 65.2 to 89.9, AutomationBench 16.0 to 53.1, Toolathlon-Verified 49.1 to 76.9, GDPval-AA 1,107 to 1,673,
JobBench 25.0 to 62.0, CyberGym 40.0 to 94.0. Both models think by default and use `thinking.type`. V2.5 models are deprecated on Xiaomi's API at 10:00 Beijing time on 2026-10-21 and the docs recommend moving to V2.6
[mimo-docs-models] [litellm-mimo]. The faster `mimo-v2.6-pro-ultraspeed` id also exists (about ten times the Pro price for twenty times its output speed per a relay) and has no card here [datanorth-mimo].

## What the system card reports

Xiaomi publishes no system card. The Hugging Face card is a model card with benchmarks and serving settings, and Xiaomi's 44-page technical report for the V2.6 series
covers training; neither has a refusal, injection, sycophancy or deception evaluation [hf-mimo-pro] [mimo-tech-report]. What is reported:

- **Cyber capability.** The training mix included cybersecurity, and the card reports CyberGym 94.0, MiMo Cyber Bench 80.2, ExploitGym 17.8, ExploitBench 47.9 and SEC Bench Pro 66.3 (Xiaomi's own runs); on ExploitGym, ExploitBench and
  SEC Bench Pro the same table gives closed models 22.1 to 30.3, 70.0 to 78.5 and 79.1 [hf-mimo-pro]. The MIT-licensed weights are public, and no usage policy or classifier is described.
- **Reward hacking.** The report says early versions showed a tendency to reward-hack, mainly by fetching published fixes (installing a newer package release, cloning
  upstream, reading issue threads). Xiaomi added self-correction examples to mid-training, cleaned environments of leaked artefacts, cut network access, ran a dedicated
  hack agent until it found no exploit, and audited trajectories during RL; it reports the confirmed-hack share stayed below 2% throughout training for both V2.6
  models. It also says it corrected flawed CyberGym environments before evaluation [mimo-tech-report] [hf-mimo-pro].
- **What is not reported.** No refusal or over-refusal rate, injection result, sycophancy or sandbagging study.

## Behaviour observed in practice

- **Index and speed (M).** Artificial Analysis: 46 on index v4.3.2, rank 1 of 118 comparable models, first on its open-weights board; 37.4 tokens per second (median 71.4); 3.78 s to first token; about $0.13 per index task [aa-mimo-pro] [aa-open-weights-board].
- **Provider friction (A).** LiteLLM does not yet map `thinking` for this provider and needs it passed explicitly with an allow-list entry [litellm-mimo]; a practitioner guide reports that omitting `reasoning_content` produces the 400 and that
  billed output includes reasoning, so a short visible answer does not mean low cost [ofox-mimo].
- **Sampling control (A).** Because thinking fixes sampling, setting temperature to zero does not make runs comparable across providers [ofox-mimo].

## Benchmarks

Independent: Artificial Analysis Intelligence Index v4.3.2, 46 (reasoning, 140M output tokens) [aa-mimo-pro]. A news relay quotes 46.32 on v4.3 [datanorth-mimo]. No Scale SWE-Bench Pro V2 row, no Terminal-Bench 4.0 row (the page did not render), no Coding Agent Index entry and no METR entry
[scale-swe-pro-v2] [metr-horizons] [tbench-4-leaderboard] [aa-coding-agents]. Xiaomi's report notes that it ran comparison models with configurable effort at their highest
setting [mimo-tech-report]. Maker-run (Xiaomi's table; comparison columns are MiMo-V2.6-Flash, MiMo-V2.5-Pro, Claude Opus 5, GPT-5.6 Sol and Claude Fable 5): DeepSWE v1.1 71.9 (Opus 5 74.0), ProgramBench 26.5, MiMo Code Bench 63.2, AutomationBench 53.1, Toolathlon-Verified 76.9 (Opus 5 80.6), GDPval-AA 1,673,
Terminal-Bench 4.0 34.9, Terminal-Bench 2.1 89.9, OSWorld-Verified 82.0, JobBench 62.0, CyberGym 94.0 [hf-mimo-pro].
