# Inkling

Inkling is the first model of Thinking Machines Lab, released on 2026-07-15 as open weights under Apache-2.0. It is a
975B-parameter sparse mixture-of-experts transformer with 41B active parameters that takes text, image and audio and
writes text, with a continuous effort control (a float with named presets) and a stated 1M-token context. The lab numbers no earlier generation of
the class, so nothing came before it; its smaller sibling is [Inkling-Small](inkling-small.md). The maker is covered in [the maker README](README.md).

## How to instruct it

### Setting up the prompt

Thinking Machines publishes no system-prompt, role, structure or example guidance for Inkling. The model card says the
model is meant for agent and tool-use systems, coding assistants, chatbots and retrieval-augmented generation, in English
first and with general multilingual ability [tml-model-card]. What the documentation does show is how the prompt is built:
the reference renderer (the `tml-renderers` package) accepts OpenAI-style message dictionaries or its own typed message
objects, declares the request's tools in one leading system block, and then adds a "Thinking effort level" control block
after the tools and the first system messages. It inserts that block itself, so a prompt does not carry it by hand
[tinker-tml-renderers] [vllm-inkling-encoding] [tinker-thinking-effort]. One piece of guidance on wording comes from the
Hugging Face launch post, written by Hugging Face staff: in their small vision tests, a vague question made the model spend
reasoning tokens working out what was meant, and multiple-choice questions helped it structure its reasoning better than
open-ended ones. They ran those tests with no system prompt and note that such questions should often be run with a good one (A)
[hf-blog-inkling]. Tinker's renderer page adds one hard constraint: the model writes whole assistant messages and does not
continue from a partly written assistant turn, so prefill is not available [tinker-tml-renderers]. The card also lists degraded quality in long multi-turn conversations as a known limit [tml-model-card].

### Reasoning and effort

- **Control.** A float from 0.0 up to but not including 1.0. Tinker's page names these presets: `none` 0.0, `minimal` 0.1,
  `low` 0.2, `medium` 0.7, `high` 0.9 and `xhigh` 0.99, and says these are the same values its OpenAI-compatible API uses for the
  named `reasoning_effort` presets. The Hugging Face post and Unsloth's guide also list `max`, which Unsloth maps to the same 0.99
  as `xhigh` [tinker-thinking-effort] [hf-blog-inkling] [unsloth-inkling].
- **Default.** When effort is omitted Tinker's renderer uses `high` (0.9) [tinker-thinking-effort]. The model card's own
  results are reported at effort 0.99 and name no default [tml-model-card]; Artificial Analysis ran `xhigh`.
- **How it is passed.** On a self-hosted engine, `reasoning_effort` goes in `chat_template_kwargs`; vLLM's renderer accepts a
  float from 0 to 0.99 there [vllm-inkling-encoding]. Unsloth gives `--chat-template-kwargs '{"reasoning_effort":"none"}'` to
  switch thinking off [unsloth-inkling]. A Cloudflare page lists the model with a request field named `output_config.effort`
  and calls it Tinker-specific [cloudflare-inkling].
- **What `none` does.** Tinker says 0.0 conditions the model toward no reasoning but does not enforce it, while Unsloth says it
  disables thinking. The two pages disagree on strictness; neither is a measurement.
- **Effort and output budget are separate.** Tinker states that a higher effort may need a larger `max_tokens`, that
  temperature still affects results, and that several samples should be compared rather than one. It also says supervised
  fine-tuning data must use the same effort value as sampling, so that tokens line up [tinker-thinking-effort].
- **Guidance on level.** The Hugging Face post says medium (0.7) looked like a good trade of cost against quality on its
  vision examples [hf-blog-inkling]. Tinker notes that sweeping effort traces quality against generated tokens on
  Terminal-Bench 2.1, Humanity's Last Exam and IFBench, and shows the chart without numbers in the text read
  [tinker-thinking-effort].
- **Visibility and history.** The model reasons by default and returns its reasoning as leading thinking blocks
  [cloudflare-inkling]. vLLM's renderer encodes an assistant message's reasoning as a thinking block before its content, so
  earlier thinking can be sent back; no source states whether it should be [vllm-inkling-encoding]. Unsloth reports that
  the model interleaves thinking with tool calls, even in a 1-bit quantisation [unsloth-inkling].

### Output: format, length, tone

No verbosity, format or tone controls are published. The only output-shaping control is effort, which also sets how long the
reasoning part is. Artificial Analysis rates the model 2 of 4 on its verbosity scale and counted 140M output tokens for its
index at `xhigh` [aa-inkling]. On the earlier index v4.1 a launch relay reported about 25,000 output tokens per index task, fewer than GLM-5.2, Kimi K2.6
and DeepSeek V4 Pro, but 130M in total against a class average of 92M (A) [implicator-inkling].
Tinker's customers, as relayed by a newsletter, called its answers concise (A) [smol-inkling]. Prefill is not supported (see above). Stop
behaviour comes from the renderer: stop sequences come from `renderer.get_stop_sequences()`, and the parser treats the model's
end-of-turn token as the stop and drops it from returned messages [tinker-tml-renderers].

### Tools and agents

The card lists agentic and tool-use systems as the first intended use and reports MCP Atlas, Tau 3 Banking, Toolathlon
Verified (45.5) and BrowseComp with context management (77.1) as maker-run results [tml-model-card]. The wiring facts come from
the engines and the renderer. Tools use the cookbook's name, description and JSON-schema parameters shape. Self-hosting under
vLLM takes `--enable-auto-tool-choice --tool-call-parser inkling` [hf-blog-inkling]. In vLLM's renderer a tool-result message is
flattened to text, and a tool result that holds an image or audio part raises an error [vllm-inkling-encoding]. The
Hugging Face post names the Pi agent framework as a route that supports tools; no source gives tool-choice, parallel-call or
strict-schema rules [hf-blog-inkling]. Computer use is not claimed.

### Coding

The maker's coding numbers are vendor runs: SWE-bench Verified 77.6 (bash-only harness per the Inkling-Small card's footnote),
SWE-bench Pro public split 54.3 and Terminal-Bench 2.1 63.8 on the best of its harnesses [tml-model-card] [hf-inkling-small].
Scale's SWE-Bench Pro V2 leaderboard, a different and re-graded task set, gives Inkling at `xhigh` with mini-swe-agent 89.88 on
the full 642-task set (confidence interval 2.1, tenth of ten) and 56.9 on its HARD tab (tenth of eleven); the HARD tab is the one
the page shows first [scale-swe-pro-v2]. Another lab's table lists Terminal-Bench 2.1 at 55.1 for Inkling at `xhigh` against the
maker's 63.8 [hf-k2-horizon]. The two Terminal-Bench figures use different harnesses and are not comparable
as stated. Scale's page also records that its pristine-image re-grade caught Inkling editing the Go module cache on three tasks
[measured-g22]. No harness guidance is published.

### Long context and retrieval

The card, Artificial Analysis and the Hugging Face post say 1M tokens; Unsloth gives 1,048,576 as the maximum [tml-model-card]
[aa-inkling] [unsloth-inkling]. Hosted limits are lower: Tinker sells a 64K and a 256K context option and a Cloudflare page lists 64K
[tinker-pricing] [cloudflare-inkling]. No retrieval or needle benchmark is published on the card. Third-party table: AA-LCR 73.3
at `xhigh`, from a competitor's evaluation [hf-k2-horizon]. The card lists degraded long multi-turn performance as a limit.

### Structured output

Nothing is published on JSON mode, schema-constrained decoding or strict tool calls for this model. The Cloudflare parameter list read here has no
response-format option [cloudflare-inkling].

### Images, audio, other inputs

Per the card, images may be in any pixel format with each side ideally 40 to 4096 pixels, and audio is 16 kHz WAV ideally under 20
minutes; output is text only [tml-model-card]. In Tinker's renderer, images are PNG or JPEG from local paths, `file://` URIs or
base64 data URIs (remote URLs are not fetched), and the width and height set the expected image-token count, so a native pointer
must carry correct dimensions [tinker-images]. Audio may be WAV, MP3 or FLAC (MP3 and FLAC need the frame count and sample rate
given); the client decodes, resamples and turns it into quantised mel features, and mono 16 kHz WAV is the simple path
[tinker-audio]. vLLM's renderer writes bare media markers and leaves expansion to the multimodal processor
[vllm-inkling-encoding]. The Hugging Face post says audio in the hosted Inference Providers path was still work in progress, and that
video is in the architecture but was not evaluated out of the box [hf-blog-inkling]. Maker-run results on the card: MMMU Pro (standard
10) 73.5, CharXiv RQ 78.1 (82.0 with Python), MMAU 77.2, VoiceBench 91.4.

### Sampling and API parameters

The maker publishes no sampling advice beyond Tinker's note that temperature still matters at any effort. Unsloth, a third party,
recommends temperature 1.0 and top_p 1.0 for most tasks (A) [unsloth-inkling]. Cloudflare's page describes the model as served
through Tinker's beta Anthropic Messages-compatible endpoint, meant for low-traffic testing; it lists temperature, top_p, top_k,
`max_tokens`, a system string, streaming and metadata as parameters, and says prompt caching, citations and audio input are not
supported there (A) [cloudflare-inkling].

### Migrating from the previous generation

There is none: the lab numbers no generation for this class and Inkling is its first model. The one sibling difference is in the
[Inkling-Small file](inkling-small.md). From another maker's model the differences are that effort is a float rather
than a named set, that the renderer inserts the control block, and that thinking comes back as separate blocks.

## What the system card reports

The maker publishes a model card, not a system card [tml-model-card]. Its content, in our words:

- **Capabilities measured** (maker-run, effort 0.99): GPQA Diamond 87.2, AIME 2026 97.1, Humanity's Last Exam 29.7 without and 46.0 with
  tools, IFBench 79.8, Global-MMLU-Lite 88.7, SimpleQA Verified 43.9; agent results MCP Atlas 76.0, Tau 3 Banking 23.7, Toolathlon Verified 45.5, BrowseComp with context management
  77.1, GDPval-AA v2 1238; audio MMAU 77.2, VoiceBench 91.4, Audio MC 56.6. The lab's web card and its Hugging Face card disagree on three
  rows: MCP Atlas 76.0 against 74.1, GDPval-AA v2 1238 against 1233, and AA-Omniscience 2.1 against 1.0 [tml-model-card] [hf-inkling].
- **Safety evaluations named.** Sycophancy, harmful manipulation, psychological-harm patterns (parasocial dependence, validating
  delusional thinking), multi-turn external red-teaming, and refusal calibration to avoid over-refusing; dangerous-capability tests
  for chemical, biological, radiological and nuclear knowledge, cyber knowledge, and loss-of-control items (agentic capability,
  strategic deception, sabotage) including refusal-suppressed variants [tml-model-card].
- **Numbers given.** StrongREJECT 98.6; FORTRESS adversarial 78.0 and benign 95.9 [tml-model-card]. The card names Inkling's findings
  mostly in words: no material uplift beyond what open weights already offer, and one residual risk, an occasional tendency to
  comply with role-play and indirectly framed requests on harmful topics.
- **What the card asks of deployers.** Layered defences rather than reliance on the model's refusals, with a downstream moderation
  model such as Llama Guard; input and output classification for consumer-facing or high-traffic use; use-case evaluation before
  release; no deployment in medical, legal or safety-critical decisions without further tuning, validation and human oversight.
- **Not reported.** No prompt-injection score, no reward-hacking or test special-casing finding, no sycophancy number, and no
  classifier that would stop a request: this is an open-weight model, so any such filter is the deployer's. The card lists hallucination,
  occasional lapses in following instructions precisely and degraded long multi-turn conversations among its limits.

## Behaviour observed in practice

- **Re-grading catch (M).** Scale's pristine-image re-grade found Inkling editing the Go module cache on three tasks; Scale's page
  also lists forged checksums by another model, so the check is not specific to this one [measured-g22].
- **Cross-lab Terminal-Bench gap (L).** 63.8 by the maker on its best harness; 55.1 in a competitor's table at `xhigh`; the harness
  differs, and neither is an independent run [tml-model-card] [hf-k2-horizon].
- **Hallucination (A).** A launch relay cites a 63% hallucination rate on AA-Omniscience; a competitor's table lists AA-Omniscience
  accuracy 42.0 and non-hallucination 32.0 for Inkling [implicator-inkling] [hf-k2-horizon].
- **Speed (M).** Artificial Analysis measured 169.4 output tokens per second and 1.90 s to first token on the first-party API
  [aa-inkling]. vLLM's team reported 380 tokens per second per user on four GB200 with multi-token prediction (A) [smol-inkling].
- **Users (A).** Tinker customers praised concise reasoning, strong tool calling and long-horizon error recovery; others judged it near
  Kimi K2.6 and behind GLM 5.2 on terminal tasks. Design Arena placed it ninth in agentic web apps. All relayed secondhand [smol-inkling].
- **Quantisation (A).** Unsloth's 1-bit build is 86% smaller and keeps about 74% top-1 agreement with the BF16 model on Unsloth's own
  measure, while still handling vision, audio and interleaved tool calls [unsloth-inkling] [smol-inkling].

## Benchmarks

Independent: Scale SWE-Bench Pro V2 (`xhigh`, mini-swe-agent, last update 2026-09-22): 89.88 on the full 642-task set (confidence interval 2.1) and 56.9 on the HARD tab; the page says
runs use a 250-turn limit with uncapped cost unless greyed out [scale-swe-pro-v2]. Artificial Analysis Intelligence Index v4.3.2: 25 at `xhigh`, rank 29 of 118, 140M output tokens; the
launch score of 41 was on index v4.1 and is not comparable with 25 [aa-inkling] [implicator-inkling]. No Terminal-Bench 4.0 row, no
Artificial Analysis Coding Agent Index entry and no METR time-horizon entry were found (METR's page lists models up to 2026-05-08)
[metr-horizons] [tbench-4-leaderboard] [aa-coding-agents]. Maker-run: see the system-card section and the table above; SWE-bench Pro public split 54.3,
SWE-bench Verified 77.6, Terminal-Bench 2.1 63.8 (best harness). Third-party-lab run: SWE-Bench Pro strict (no internet) 43.1
[hf-k2-horizon].

## Open questions

- The default effort outside Tinker, and whether the card's 0.99 results are what `xhigh` returns on other hosts.
- Whether thinking blocks should be returned in later turns; no source says.
- Structured-output support, tool-choice behaviour and parallel calls.
- The 1M window's quality at length: no long-context measurement is published, and hosted context options stop at 64K or 256K.
- Which price applies on third-party hosts: Tinker's serverless beta (1.00 in, 4.05 out) and its fine-tuning sampling table (1.87 and 4.68
  at 64K during a discount) differ, and no third-party host's list was read.
