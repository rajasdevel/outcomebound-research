# Amazon Nova 2 Sonic

Amazon Nova 2 Sonic is the current speech-to-speech model of Amazon, generation 2 of the Nova Sonic class. It listens and speaks over one Amazon Bedrock bidirectional stream. It has been generally available since 2025-12-02, and it replaced [Nova Sonic](nova-sonic.md). Amazon updated it in place in March 2026 and in May 2026 without a new model id [L: bedrock-card-nova-2-sonic, nova2-whats-new, nova2-release-notes].

Evidence tags: L is Amazon's own text, M is an independent measurement, A is one practitioner's or one outlet's report. Advice that holds for both generations is in the [Amazon README](README.md). This file says what is specific to Nova 2 Sonic.

## How to instruct it

### Setting up the prompt

Amazon's page "Voice conversation prompts" separates two inputs. The system prompt sets the behaviour, personality and style of the assistant. A speech prompt only controls how Hindi is transcribed [L: nova2-sonic-prompts].

- Baseline. Amazon's baseline system prompt asks for a warm, professional and helpful assistant that sounds natural, direct and human. It asks for a clear answer in the first one or two sentences, then only as much more as is needed, in three to five short sentences in all, and no lecture or essay. A second version asks for complete answers that cover each part of a question with a short definition and two or three key facts or steps.
- Language. A "language mirroring" rule tells the model to reply in the language it hears, with no mixing of English, except that an English speaker gets English.
- Gender. For Hindi, Portuguese, French, Italian, Spanish, Russian and Polish, Amazon says the prompt should state whether the assistant is female or male, to match the voice. Hindi always needs it. Amazon lists kiara, carolina, ambre, beatrice, lupe and tiffany as feminine-sounding and arjun, leo, florian, lorenzo, carlos and matthew as masculine-sounding.
- Phrase lists. Amazon says Nova 2 Sonic is more sensitive to suggested phrases than Nova Sonic v1. A list of filler or emphasis phrases leads the model to use them very often. For predictable, on-brand wording this helps. For natural variation, Amazon advises general guidance such as "sound natural and conversational", or one or two example exchanges that show the tone.
- Speech prompts. For Hindi code-switching there are three fixed texts, for Latin script, Devanagari script or mixed script. Amazon says to use them exactly as written, after the system prompt, in a SYSTEM_SPEECH block, and only for Hindi transcription. All other instructions go in the system prompt.

The service card gives a worked system prompt for a hotel-cancellation agent. It fixes the role and says the model must never change it. It lists the steps in order, sets replies to one to three sentences, and uses conversational markers such as "Well" and "Now" and the phrase "Let me check that for you". It asks the model to confirm the name and date before it acts, to ask again when it mishears, to speak numbers clearly, and to refuse topics outside its scope. This example uses phrase suggestions, and the voice-prompt page warns about overuse of phrase lists [L: nova2-service-card, nova2-sonic-prompts].

### Reasoning and effort

There is no reasoning control, and no thinking mode is documented [L: nova2-sonic-overview, nova2-sonic-prompts]. Amazon's page gives a prompt for reasoning aloud, in three rules. For a simple question or sum, give the answer with no explanation. For a complex problem, think through the steps and explain them, then sum up the decision in one sentence. For a subjective comparison, explain step by step. Amazon says that, if the model should not reason in every reply, a few example exchanges in the prompt help. Its examples show a one-word answer for "What is 7 + 5?" and a step-by-step answer for a budget question [L: nova2-sonic-prompts].

### Output: format, length, tone

The model gives speech and text. The text holds transcripts of what the user said and of what the model said. The guide's example prompt asks the model to avoid formatted lists and numbering and to keep its output as a spoken transcript [L: nova2-sonic-prompts, nova2-sonic-output-events]. Length is set by prompt, as in the baseline above. Amazon says the system prompt cannot change pitch, tenor, accent or speaking rate [L: nova2-service-card].

Each answer has two transcripts. The speculative one is a preview of what the model plans to say, made before audio synthesis. The final one is a sentence-level record of what was spoken. Amazon says to save only the final one in chat history [L: nova2-sonic-chat-history].

### Tools and agents

Tools are declared in the promptStart event, each with a name, a description and a JSON schema. Amazon advises clear descriptions, snake_case action names, enums and typed fields in place of open strings, validation of parameters, and meaningful error messages [L: nova2-sonic-tools].

- toolChoice: auto (default; the model decides and can call several tools), any (at least one tool at the start of the answer) or tool (one named tool exactly once at the start) [L: nova2-sonic-tools].
- The model sends a toolUse event with an id, the tool name and a JSON string of parameters. The client returns a toolResult. The model expects a toolResult after every toolUse, even for an error. With none, the model waits and can stop responding [L: nova2-sonic-tools].
- Asynchronous calls need no setting. The model keeps listening and speaking while a tool runs and can handle several calls. If the user changes the request, the pending call is not cancelled and its result still arrives. The model uses its context to decide what to do with an old result [L: nova2-sonic-async-tools].
- Amazon's flight example: a user asks for Chicago, then says "Actually, Seattle". The agent starts a second search, and then handles the Chicago result in context [L: nova2-sonic-async-tools].
- Text can be sent during a tool call so the model says something while it waits (see the voice subsection) [L: nova2-sonic-cross-modal].

Practitioner reports (A): a LiveKit issue against this model id (opened 2026-02-18) says the model sometimes keeps speaking after it emits a tool call. The plugin made a new generation for each sentence and held the tool result until the user spoke. The reporter calls the failure intermittent. The issue is marked closed [A: gh-livekit-4887]. An AWS re:Post question of 2025-08-15 reports a tool that was not called in about 25 percent of tests, after the model had gathered the parameters. It was asked before Nova 2 Sonic was released, so it concerns [Nova Sonic](nova-sonic.md) [A: repost-inconsistent-tools].

### Coding

Amazon publishes no coding guidance for this model. The guides describe it as a voice model for conversation, customer service, learning and agents [L: nova2-service-card].

### Long context and retrieval

The Bedrock card gives a context window of 1M tokens and a maximum output of 64K tokens [L: bedrock-card-nova-2-sonic]. A connection lasts at most 8 minutes, so long conversations use renewal with saved chat history. Chat history goes in once, after the system prompt and before audio. It can be 200 KB in all, with at most 50 KB in one text input, and larger text is split or trimmed. Each message has the role USER or ASSISTANT. The service card says the model is not a retrieval tool and defines no knowledge cutoff, and advises tools for grounded facts. Knowledge grounding with RAG is listed as a feature, and the Bedrock card lists knowledge bases as not supported for this model [L: nova2-sonic-chat-history, nova2-service-card, nova2-sonic-overview, bedrock-card-nova-2-sonic].

### Structured output

The guides document no structured-output setting. Tool results go back as JSON, and tool inputs follow a JSON schema [L: nova2-sonic-tools].

### Images, audio, other inputs

Audio in is linear PCM, 16-bit, mono, at 8,000, 16,000 or 24,000 Hz, in frames of about 32 ms. Text can also go in during a voice session (cross-modal input). It uses a contentStart with type TEXT, interactive true and role USER, then a textInput, then a contentEnd, and each message needs a new contentName. The session must keep streaming audio, or the normal time-outs end the connection. Amazon lists these uses: a typed message in a client app, a text prompt that makes the model start speaking, a message that guides the model while an asynchronous tool runs, and keypad digits that a system has converted to text [L: nova2-sonic-input-events, nova2-sonic-cross-modal]. The Bedrock card marks speech and text as the supported inputs and outputs, and marks the separate audio modality, image and video as not supported [L: bedrock-card-nova-2-sonic].

### Voice: turn-taking, interruption and speech style

Turn detection. sessionStart takes turnDetectionConfiguration.endpointingSensitivity. Amazon's levels [L: nova2-sonic-turn-taking, nova2-sonic-input-events]:

- HIGH, a pause of 1.5 seconds: the fastest response. Amazon suggests it for quick questions, commands and time-sensitive use. It can cut off slow speakers.
- MEDIUM, a pause of 1.75 seconds: balanced. It is the recommended default for general conversation and for customer service with complex questions.
- LOW, a pause of about 2 seconds: the most patient. Amazon suggests it for thoughtful talk, for older or speech-impaired users and for complex problems.

Interruption. Barge-in is on. When the user speaks over the model, the model stops, keeps the context and sends an interruption signal. Audio is generated faster than it plays, so the client holds queued audio. Amazon lists four client steps: detect the signal, stop the audio that is playing, clear the queue and start the new audio [L: nova2-sonic-barge-in].

Speech style. The model adapts delivery to the prosody of the input. There is no pitch, accent or speed control. Voices are chosen with a voiceId in promptStart. Tiffany and Matthew are polyglot voices that speak all seven supported languages. Other voices are tied to a locale. A March 2026 refresh added voices that are compatible with Amazon Polly [L: nova2-sonic-input-events, nova2-sonic-languages, nova2-release-notes].

Fillers and silence. Because tools are asynchronous, the model can keep speaking while a tool runs. Amazon's example text to send is a short hold message such as asking the user to wait while the data is processed. Text sent in this way needs an active streaming session [L: nova2-sonic-cross-modal, nova2-sonic-async-tools]. The model speaks first only if the client prompts it, for example by sending text [L: nova2-sonic-cross-modal].

Telephone audio. The March 2026 refresh improved turn-taking on 8 kHz telephone speech. Amazon says the model does not process DTMF tones [L: nova2-release-notes, nova2-sonic-cross-modal].

Drift and errors. AWS says the May 2026 refresh cut speaker drift by 52 percent and speech generation hallucinations by 88 percent on internal data sets. The service card says that switching to an unsupported language can make the voice drift [L: nova2-release-notes, nova2-service-card].

### Sampling and API parameters

sessionStart takes inferenceConfiguration with maxTokens, topP (0.0 to 1.0) and temperature (0.0 to 1.0). Amazon's example uses 2048, 0.9 and 0.7. The page gives no recommended values [L: nova2-sonic-input-events]. Output audio settings (mediaType audio/lpcm, sample rate 8,000, 16,000 or 24,000, 16-bit, one channel, a voice id) go in promptStart. A cross-Region inference id is not listed on the Bedrock card [L: nova2-sonic-input-events, bedrock-card-nova-2-sonic].

### Migrating from the previous generation

From [Nova Sonic](nova-sonic.md) the model id changes to amazon.nova-2-sonic-v1:0. What changes [L: nova2-whats-new, nova2-sonic-prompts, nova2-sonic-languages, nova1-voices]:

- New: Portuguese and Hindi, polyglot voices, endpointingSensitivity, text input during a voice session, asynchronous tool calls without a setting, speech prompts and a context window of 1M tokens.
- Voices: v1 had 11 voice ids and v2 has 16. The feminine German voice is greta in the v1 guide and tina in the v2 guide.
- Prompts: v2 is more sensitive to phrase lists, so a prompt that lists fillers or emphasis phrases for v1 can make v2 repeat them.
- Regions: v2 adds us-west-2. The v2 guide gives chat history limits (50 KB for a message and 200 KB in all); the v1 pages read give none.

A consultancy's test in an AWS-blog post gave 2.7 for v2 and 2.4 for v1 with the same baseline prompt, on a 1 to 5 scale judged by a model [A: aws-blog-voice-agent].

## What the system card reports

AWS calls it an AI service card. It applies to the release of 2025-12-02 and covers use through the Bedrock bidirectional streaming API and the console playground [L: nova2-service-card].

- Intended use: customer service call automation, learning, conversational agents. Core features: low latency, understanding of speech in several languages, expressive voices, dialog handling, cross-modal input, tool use and asynchronous tasks.
- Limits: official support only for English, Spanish, German, French, Italian, Portuguese and Hindi. No real-time speech translation. Not a source of medical, legal or financial advice. No control of pitch, tenor, accent or rate. No fine-tuning on your own labelled data. No knowledge cutoff defined. The safety filters cannot be set or turned off.
- Results, on AWS's own data sets: more than 96 percent safe replies on harmful prompts, which AWS says is more than 61 percent better than Nova 1 Sonic. Every request to clone a voice was deflected. More than 95 percent safe replies on 8.5 thousand toxic prompts. Unbiased replies on 97 percent of bias prompts. No sign of added CBRN uplift against search and expert sources. Small differences in speech fairness across demographic groups.
- Methods: public data (Multilingual LibriSpeech, FLEURS, VoiceBench IFEval and CommonEval, and a function-calling set converted to speech), human review, red teaming by outside firms. The text read has no scores for the capability tests.
- Privacy and transparency: Bedrock does not store or review prompts or speech, and AWS does not train on inputs or outputs. All generated audio carries an inaudible watermark. IP indemnity covers outputs of generally available Nova models.

The card was not updated for the 2026 refreshes in the text read. The refresh results are in the release notes [L: nova2-release-notes].

## Behaviour observed in practice

- Artificial Analysis (the March 2026 version): speech reasoning 88, arena preference Elo 974, task success rate 57.1, time to first audio 1.14 seconds. The page shows no conversational dynamics or agentic score, so the model has no Speech to Speech Index value [M: aa-speech-to-speech].
- A consultancy's AWS-blog post reports speech reasoning 87.0 and 1.39 seconds to first audio on the same Big Bench Audio set, and says the model costs about $0.27 per hour of input audio. In its LLM-judge test, a first prompt revision raised the overall score from 2.7 to 3.1 and a second to 3.8. Its changes were templated variables, bullets under labelled headings, behaviour examples and a checklist before each reply [A: aws-blog-voice-agent].
- The tool-calling report in the Tools section is from a practitioner [A: gh-livekit-4887].

## Benchmarks
