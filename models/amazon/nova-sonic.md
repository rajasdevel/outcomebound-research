# Amazon Nova Sonic

Amazon Nova Sonic is the first speech-to-speech model of Amazon in this library, generation 1 of the Nova Sonic class. Amazon announced it on 2025-04-08 with the Bedrock bidirectional streaming API. [Nova 2 Sonic](nova-2-sonic.md) replaced it. The Bedrock card lists it as Legacy since 2026-03-13 with an end-of-life date of 2026-09-14, and that date has passed [L: nova1-whats-new, bedrock-card-nova-sonic, bedrock-lifecycle-legacy]. Whether the model still answers requests was not tested.

Evidence tags: L is Amazon's own text, M is an independent measurement, A is one practitioner's or one outlet's report. Advice that holds for both generations is in the [Amazon README](README.md). This file says what is specific to Nova Sonic. Amazon's Legacy rules say that new customers cannot adopt a Legacy model and that existing customers may lose access after 15 days of inactivity [L: bedrock-lifecycle-legacy].

## How to instruct it

### Setting up the prompt

Amazon's guide for this generation says the system prompt steers wording and style and cannot change speech attributes such as accent and pitch. The model picks those from the context of the conversation. It says to write for listening, not for reading [L: nova1-prompting].

- Baseline: a short role line such as "You are a friend", and a line that says the user and the model have a spoken dialog that exchanges transcripts of a natural real-time conversation.
- Length: add a limit, such as two or three sentences for chat, or allow thorough explanations when the topic needs them.
- Human tone: describe the dialog as user, agent, user, agent turns, and ask for emotion, wit, playfulness and empathy where it fits, in simple and helpful language.
- Speech-friendly text, with Amazon's examples: a pause is shown with an ellipsis; emphasis uses spoken phrases such as "The key thing to remember is" instead of bold type; points are numbered in words ("first", "second", "finally"); long answers end with a summary; a signpost such as "I'm thinking of three reasons" comes before a list.
- Clarity: Amazon says instructions that are clear in text may need rewording for speech, and that prompts should seek confirmation before a tool acts. Roles should sound natural when spoken, such as "friendly advisor" in place of "information retrieval system", with traits such as warm, patient and concise.
- What to avoid, by Amazon's list: visual formatting (bullets, tables, code blocks), voice changes such as accent, age or singing, sound effects and onomatopoeia, and content that depends on being seen.
- Examples in the guide: an algebra tutor with a fixed role ("never change your role"), a conversation structure and a warm style.

[L: nova1-prompting, nova1-prompting-system, nova1-prompting-practices, nova1-prompting-examples]. The v2 guide says that v2 is more sensitive to lists of suggested phrases than v1, and that such lists make v2 use them very often [L: nova2-sonic-prompts].

### Reasoning and effort

There is no reasoning control. Amazon's chain-of-thought advice for speech: keep chains shorter than for text, split a complex answer into small spoken parts, and use more explicit spoken signposts. Its example prompt gives the same three rules as the later guide: a direct answer for simple questions, step-by-step thinking for complex ones, and a one-sentence summary [L: nova1-prompting].

### Output: format, length, tone

The model gives speech and text. The Bedrock card marks speech and text as outputs. The text includes transcripts. Amazon says to write prompts for what is heard, so lists and visual formats do not help [L: bedrock-card-nova-sonic, nova1-prompting]. Output audio is linear PCM, 16-bit, mono, at 8,000, 16,000 or 24,000 Hz, and the prompting examples use 24 kHz [L: nova1-output-events].

### Tools and agents

The v1 guide says to design tool calls that can cope with speech recognition errors, to remember that users cannot see which tools run, and to give spoken confirmation while a tool is consulted. It documents tool use and RAG in its own section [L: nova1-prompting, nova1-speech-guide]. Amazon lists asynchronous tool calling as new in Nova 2 Sonic [L: nova2-whats-new]. An AWS re:Post question that does not state the version reports a tool that was not called in about 25 percent of tests after the model had gathered the parameters. The question was asked on 2025-08-15, before Nova 2 Sonic was released on 2025-12-02, so it concerns this model [A: repost-inconsistent-tools].

### Coding

Amazon publishes no coding guidance for this model [L: nova1-service-card].

### Long context and retrieval

The Nova guide gives a context window of 300K tokens for this model. It gives no maximum output [L: nova1-model-specs]. A connection lasts at most 8 minutes. Amazon says to end the request and start a new one before the limit, with the saved chat history in the new request. The history goes after the system prompt and before new user input, uses USER and ASSISTANT roles, and must start with a user message [L: nova1-errors].

### Structured output

The v1 pages read document no structured-output setting [L: nova1-speech-guide].

### Images, audio, other inputs

The only input is speech. The Bedrock card marks text, audio files, image and video as not supported as inputs. Input audio is linear PCM, 16-bit, mono, base64, at 8,000, 16,000 or 24,000 Hz. The sample code captures 16 kHz. Cross-modal text input is a v2 feature [L: bedrock-card-nova-sonic, nova1-input-events, nova2-whats-new].

### Voice: turn-taking, interruption and speech style

Turn detection. The v1 pages read document no way to tune the end-of-turn detection. The setting endpointingSensitivity appears only in the Nova 2 guide [L: nova1-speech-guide, nova2-sonic-turn-taking].

Interruption. The v1 output events describe barge-in. The model stops speaking, switches to listening and sends a notice. The model generates audio faster than real time, so the client must clear queued audio when the notice arrives. The basic Python sample does not implement barge-in, and the full-featured sample does [L: nova1-output-events, nova1-code-examples].

Speech style. Voices are 11 ids: tiffany and matthew (US English), amy (British English), ambre and florian (French), beatrice and lorenzo (Italian), greta and lennart (German), and lupe and carlos (Spanish). The prompt cannot change accent, pitch or speed. Style comes from wording, such as ellipses for pauses and spoken emphasis. Languages are English (US, UK), French, Italian, German and Spanish [L: nova1-voices, nova1-service-card, nova1-prompting].

Sessions. The connection ends after 8 minutes. Up to 20 connections can run at once for each customer. On an error, Amazon says to send promptEnd, then sessionEnd, then contentEnd if audio streaming has started, which also frees GPU resources and memory [L: nova1-model-specs, nova1-errors].

### Sampling and API parameters

The v1 pages read give inference settings for the Nova text models and no values for Nova Sonic. The event reference for audio uses audio/lpcm at 8,000, 16,000 or 24,000 Hz [L: nova1-input-events, nova1-output-events].

### Migrating from the previous generation

There is no earlier model in this class. The move to the next generation is in the [Nova 2 Sonic file](nova-2-sonic.md#migrating-from-the-previous-generation). New customers cannot adopt this Legacy model [L: bedrock-lifecycle-legacy].

## What the system card reports

The AWS AI service card applies to the release of 2025-07-16 [L: nova1-service-card].

- It describes a unified speech understanding and speech generation model. Features: low latency, eleven expressive voices (feminine and masculine in US English, Spanish, German, French and Italian, and one feminine voice in British English), and dialog handling.
- Officially supported languages: English, Spanish, German, French and Italian. No fine-tuning on your own data. The model is not an information retrieval tool. Real-time speech translation is not supported.
- Privacy: the model replies only in pre-selected voices and does not replicate voices from the input. The card says Bedrock does not store or review customer prompts, and that prompts and outputs are never shared between customers.
- The Nova 2 Sonic card says its model is more than 61 percent better than Nova 1 Sonic at avoiding harmful replies on AWS's own data set [L: nova2-service-card].

## Behaviour observed in practice

- Artificial Analysis lists no row for Nova Sonic v1 [M: aa-speech-to-speech].
- A consultancy's AWS-blog post tested both generations on one voice-agent task with an LLM judge (1 to 5). Nova Sonic scored 2.4 overall and Nova 2 Sonic 2.7 with the same baseline prompt. On its own data, completeness was 1.8 for v1 and 2.5 for v2 [A: aws-blog-voice-agent].
- The re:Post question above is a practitioner report [A: repost-inconsistent-tools].

## Benchmarks

No independent measurement was found. Third party: an overall LLM-judge score of 2.4 on one dealership scenario, in an AWS-blog post, with Nova 2 Sonic at 2.7 [A: aws-blog-voice-agent]. No maker scores were found in the pages read.

No SWE-Bench Pro, Terminal-Bench, Artificial Analysis Intelligence Index, Coding Agent Index or METR result exists for this model. These tests do not apply to a speech model.
