# Microsoft Foundry

cloud platform; Microsoft's model, agent and tooling service on Azure, formerly Azure AI Foundry and, before that, Azure AI Studio. One Azure resource holds projects, model deployments, agents, tracing and access control. Microsoft sells the Azure OpenAI models and a selection of other makers' models itself ("Foundry Models sold by Azure"), and lists more than 10,000 further models from partners and the community, among them Anthropic's Claude, which Anthropic sells and operates through the Azure Marketplace. Microsoft lists the successor names itself: the Assistants API became the Responses API (Agents v2), monthly `api-version` parameters became stable `/openai/v1/` routes, and the old hub-based projects live on in a classic portal. Everything below was read on 2026-10-03 from Microsoft and Anthropic documentation (class L) unless it says otherwise. This file replaces the earlier Azure and Claude-on-Foundry notes.

## Models offered

Two catalogue categories decide who supports and bills a model (L). Models sold by Azure are hosted and operated by Azure, billed on the Azure subscription and covered by Azure's service agreements. Partner and community models are supported by their provider; for Claude, a partner model, Microsoft's overview page directs help requests to Microsoft Support. A third route, Fireworks on Foundry, runs open-weight models on Fireworks AI's infrastructure inside a Foundry project (see the last bullets below).

- **OpenAI (sold by Azure).** [GPT-6.1 Sol](../models/openai/gpt-6.1-sol.md), [GPT-6 Astra](../models/openai/gpt-6-astra.md), [GPT-6 Sol](../models/openai/gpt-6-sol.md), [GPT-6 Luna](../models/openai/gpt-6-luna.md), GPT-5.6 Sol, [Terra](../models/openai/gpt-5.6-terra.md) and [Luna](../models/openai/gpt-5.6-luna.md), with GPT-5.5, 5.4 (including mini, nano and pro), 5.3 Codex, 5.2, 5.1, 5, GPT-4.1, o-series, Sora, image, audio and embedding models, a preview `gpt-chat-latest` and the open-weight [gpt-oss-120b](../models/openai/gpt-oss-120b.md) and [gpt-oss-20b](../models/openai/gpt-oss-20b.md) (both preview, chat completions only, 131,072-token window).

## API surface

- **One OpenAI-shaped endpoint for most models.** `https://<resource>.openai.azure.com/openai/v1/` takes the deployment name in the `model` field, with no `api-version` query parameter. Microsoft says the Responses API works with Azure OpenAI models and with sold-by-Azure models that support it (DeepSeek, Llama and Grok are named); a model that does not support it returns 400 and takes Chat Completions instead. A Foundry project endpoint and the `azure-ai-projects` 2.x client wrap the same models. Deployments are aliases: a name, a model and version, a capacity type, a content-filter setting and a rate setting.
- **Claude endpoint.** `https://{resource}.services.ai.azure.com/anthropic/v1/*` with Anthropic's Messages shape; the request uses the deployment name as the model. Anthropic's SDKs support Foundry in C#, Go, Java, PHP, Python and TypeScript; the Ruby SDK has no native Foundry support. Response headers carry `request-id` and `apim-request-id` for support.
- **Auth.** Resource API keys (full access to the resource, which Microsoft advises replacing with keyless access in production) or Microsoft Entra ID tokens with RBAC roles such as Foundry User.
- **Claude hosting options.** Chosen when deploying, and shown as separate model versions in the portal (for example version 1 on Anthropic, version 2 on Azure). Hosted on Azure is an Anthropic-operated service on Azure infrastructure: Global Standard and US Data Zone Standard, and only these models: Opus 5.5, Opus 5, Opus 4.8, Sonnet 5.5 (Global only), Sonnet 5 and Haiku 4.5. Hosted on Anthropic runs on Anthropic's infrastructure, Global Standard only, and is the only option for Fable 5.1, Fable 5, the Mythos models, Opus 4.7, 4.6 and 4.5, and Sonnet 4.6 and 4.5. The Default settings choice picks hosted on Azure where both exist, so a deployment called `claude-opus-5` can be either.
- **Id naming.** OpenAI deployments default to the model id (`gpt-6-sol`); Claude deployments default to `claude-opus-5-5` style ids; sold-by-Azure partner models use catalogue names such as `Kimi-K2.7-Code` or `grok-4.6`. A custom deployment name replaces any of them in requests.
- **Instant access (preview)** lets a supported model be called by name without creating a deployment.
- **Fireworks on Foundry** is generally available but an administrator must register the `Fireworks.EnableDeploy` feature on the subscription first, and deploying needs the Foundry Owner role on the project. Deployments return a chat-completions endpoint; Microsoft says the Responses API for these models goes through the Foundry project endpoint and SDK.

## Feature parity

- **Reasoning controls.** GPT-6 and GPT-6.1 list reasoning effort and verbosity; GPT-5.6 supports reasoning, and Microsoft notes that Chat Completions with function tools needs `reasoning_effort` set to `none` for these models, so tool calling goes through the Responses API. `gpt-chat-latest` has a fixed non-zero reasoning level that `reasoning_effort` does not change. Claude's thinking and effort are listed as available on Foundry (Anthropic's overview).
- **Tools and server-side features.** For OpenAI models: functions, parallel tool calls, computer use, a preview multi-agent orchestration mode, and, for GPT-6.1 Sol, tools through the Responses API only. For Claude hosted on either option: tool search, bash, memory, text editor, citations, PDF support, and the MCP connector (beta). Not supported on Foundry under either hosting: the Admin, Compliance and Models APIs, Message Batches, the advisor tool, Managed Agents, server-side fallback, and the `computer_toolset_20260801` and `browser_toolset_20260801` toolsets (beta computer-use versions remain). Not supported when hosted on Azure, returning 400 by design: code execution, web search and web fetch versions after `web_search_20250305` and `web_fetch_20250910`, Agent Skills, programmatic tool calling and the Files API.
- **Structured output.** Listed for the GPT-6, GPT-5.6, GPT-5.5 and gpt-oss families; JSON response format for the Mistral, DeepSeek, Grok 4.6 and other partner entries; Anthropic's overview marks Claude structured outputs available on Foundry.
- **Prompt caching.** For OpenAI models, an `implicit` default mode plus, from GPT-5.6, `prompt_cache_key`, `prompt_cache_options.mode` (`implicit` or `explicit`), a 30-minute `ttl` (the only value) and `prompt_cache_breakpoint` blocks on both Responses and Chat Completions. A request can create up to four cache writes; the cache considers up to the latest 50 breakpoints; the prefix must reach 1,024 tokens; more than about 15 requests per minute on one key and prefix can miss. Models before GPT-5.6 charge nothing extra to write the cache; GPT-5.6 and later can. Provisioned (PTU-M) deployments do not support breakpoints. Anthropic's caching page says Claude caches on Foundry are isolated per workspace, as on Anthropic's own API, and its Foundry page says the `usage` object matches the other platforms. Fireworks deployments document prompt caching keyed by an `x-session-affinity` header, the `user` field or `prompt_cache_key`.
- **Batch.** Global Batch and Data Zone Batch deployment types give a 50 percent discount and a 24-hour turnaround. In the region table Microsoft updated on 2026-09-04, the batch tabs list nothing newer than `gpt-5.4` and `gpt-5.4-mini`: no GPT-5.5, GPT-5.6 or GPT-6 model has a batch type there. The GPT-6, GPT-6.1 and GPT-5.6 models all appear under Global and Data Zone Standard, all but GPT-6 Luna appear under the provisioned types, and none appears under the regional Standard type. Anthropic's Message Batches API is unsupported for Claude.
- **Long context.** The GPT-6 and GPT-5.6 families list 1,050,000-token windows with 922,000 input and 128,000 output. GPT-6 and GPT-5.6 standard deployments price short and long requests separately by input length per request. 1M windows apply to Claude Fable 5.1, Fable 5, Opus 5.5 to 4.6, Sonnet 5.5, 5 and 4.6 on Foundry.
- **Vision, audio, streaming.** Text and image input with text output for the GPT-6 and GPT-5.6 entries; streaming is listed. Claude supports images and PDFs.
- **Other differences.** Anthropic's page on mid-conversation system messages lists the Claude API, Bedrock and Google Cloud as supported and does not list Foundry. Foundry returns none of Anthropic's `anthropic-ratelimit-*` headers.

## Pricing

- **Standard (pay per token).** Billed through the Azure subscription for sold-by-Azure models. Global Standard launches first and is the lowest price; Data Zone and regional types come later (L).
- **Deployment types.** Global, Data Zone and regional-geography versions of Standard, Provisioned (reserved capacity in PTUs) and Batch (50 percent discount, 24-hour turnaround); a Developer type for evaluating fine-tuned models with a 24-hour life and no service agreement. Global Standard also supports request-level Flex processing (lower cost, delay-tolerant) and Priority processing (faster, pay as you go).
- **Observed meters.** The Azure Retail Prices API carries separate meters for Standard, Data Zone, Priority Processing and Flex, with short- and long-context categories and cache-write meters for GPT-5.6 and GPT-6. On several GPT-5.6 and GPT-6 meters read in eastus2, the Data Zone price was 1.1 times the Global one, and a Flex meter was half the matching Standard meter for one SKU checked; other SKUs were not compared.
- **Claude.** Billed through Azure Marketplace in Claude Consumption Units, metered hourly and invoiced monthly in arrears; there is no prepaid balance or commitment (Anthropic's page).
- **Other partner models.** Pay per token through the subscription or the Marketplace depending on the offer.
- **Fireworks on Foundry.** Pay per token (Global or Data Zone Standard, depending on the model) or provisioned throughput billed per unit-hour; the Retail Prices API lists these under an "Azure Fireworks Models" product, and in eastus2 its provisioned Data Zone unit was 1.1 times the Global one.

## Limits and data

- **Quotas.** Since after 2026-05-07 Foundry tracks quota per subscription for onboarded models (it started with Realtime Translate and Realtime Transcribe, with other models to follow; the portal's Quota page shows the scope per model): Global Standard deployments of one model and version share one pool across all Regions, and Data Zone Standard deployments share a pool per data zone. Models not yet onboarded are limited per Region, per subscription and per deployment type. For sold-by-Azure models outside Azure OpenAI the default is 400,000 tokens per minute, 1,000 requests per minute and 300 concurrent requests (FLUX image models aside). Fireworks pay-per-token deployments have separate Global Standard and Data Zone Standard pools with a default of 10 million tokens per minute per region and subscription for enterprise customers, shared across Fireworks models, with adaptive limits that Fireworks enforces below that. A resource holds up to 32 deployments, a Region and subscription up to 100 resources. GPT-6 and GPT-5.6 deployments need quota requests below subscription tiers 5 and 6, which have quota by default. Quota increases are processed for sold-by-Azure, Azure OpenAI and Anthropic models; other partner models are not given increases.
- **Regions and processing.** Global types may process in any Azure region. Data Zone types process within the US, EU or Asia-Pacific zone. Standard and regional types process within the chosen geography and may move between its regions. Data at rest stays in the chosen geography, including the abuse-monitoring store.
- **Sold-by-Azure data handling.** Microsoft states that prompts, completions, embeddings and training data are not available to other customers or to OpenAI and other model providers, and are not used to train or improve their models or Microsoft products without permission. The models are stateless, but stateful features (the Responses API, stored completions, files, batch) persist data in the customer's resource in the same geography, encrypted at rest with an option for customer-managed keys. Abuse monitoring can sample prompts and completions for automated review and, when needed, human review by authorized Microsoft staff; approved customers can have storage and human review turned off, which shows as `ContentLogging` set to false on the resource. Preview models may follow different practices.
- **Claude data handling.** Anthropic is the independent processor for Claude on both hosting options. Hosted on Azure, prompts and completions are processed on Azure infrastructure with data at rest in the selected geography, and only usage metadata and content flagged by Anthropic's safety systems go to Anthropic, where staff review on an exceptions basis. Hosted on Anthropic, data may be processed outside Azure and outside the selected Region. Anthropic recommends an activity log kept on at least a rolling 30-day basis.
- **Fireworks data handling.** Data is shared between Microsoft and Fireworks AI. Microsoft states that Fireworks on Foundry is outside its EU Data Boundary commitments, has no FedRAMP authorization, is not for payment-card data and is not available in Azure Government; its Data Zone deployments run in six US regions.
- **Rate-limit signals.** HTTP 429 with backoff. For Claude there are no Anthropic rate-limit headers.

## Notes for agents and harnesses

- Where a feature is missing the failure is a 400, and a deployment name alone does not reveal the hosting option, so record which version a Claude deployment uses. Claude Code detects a deployment hosted on Azure and trims its feature set (Anthropic's page).
- The deployment name, not the model id, goes in requests; quotas, content filters and capacity belong to the deployment.
- Anthropic's page says Claude on Foundry follows the Claude API's deprecation and retirement schedule; for Google Cloud the same source says Google sets the dates.
- A GPT-5.6 or later request that combines Chat Completions, function tools and any effort other than `none` is rejected; the Responses API is the documented path for tool calling.
- No batch type exists for the GPT-5.6 and GPT-6 families as of the 2026-09-04 table; asynchronous bulk work on them has only Global or Data Zone Standard, Flex (listed for GPT-5.6 Sol) or provisioned types.
- Microsoft notes that GPT-6 Astra may apply stronger safety controls when its systems detect elevated risk, including changed classifier thresholds and system-generated safety instructions added to the prompt; a prompt can therefore reach the model with text the caller did not send.
- Microsoft's timeout guidance: up to 29 minutes for reasoning models and for non-streaming requests, up to 60 seconds for streaming requests to non-reasoning models.
- `/openai/v1/` is implicit-versioned; code that still sends `api-version` follows the older route family. Custom header passthrough is limited to 10 headers (more returns HTTP 431) and Microsoft says future API versions will not pass custom headers through.
- A deployment's data zone, not the resource's region alone, decides where inference runs.
